# 动画素材：导入、原始时间与 stable 输出方案

2026-11-03，按用户确认补充的设计约定。**尚未实现动画导入、逐帧播放、动画状态持久化或序列导出；下列验收全部待实施。** 本轮只改文档，不增加类型、命令、解码依赖、功能开关或文件字段，不提升现有schema／API版本。完整动画创作时间轴不因此成为首批实现承诺。

## 1. 当前能力与目标

当前[AssetKind](../crates/domain/src/assets.rs)只有RasterImage、Audio、Opaque，[图层](../crates/domain/src/layers.rs)引用单一图片素材或嵌套组；[PNG入口](../desktop/infrastructure/src/lib.rs)只取得一份静态RGBA，没有动画帧表。编号PNG逐张入库不会自动成为动画；GIF／APNG／WebP没有受测多帧导入。某种动画PNG能显示默认图也不能计为支持动画，目前没有防止该类静态误读的完整回归。

目标采用：**导入时识别并保管完整多帧来源与时序，编辑时按需读取，导出时按目标stable元素规则重采样并生成独立PNG帧。** 不等到导出才发现源时长，也不要求导入时把所有帧写成独立磁盘文件或一次全部解码进内存。

## 2. 三层数据与原始时间保留

以下名称仅表示职责，不是已存在的Rust类型或冻结的字段名。

| 层 | 必须保留／表达 | 不承担的职责 |
| --- | --- | --- |
| 原始动画来源 | 原文件字节，或输入PNG序列的全部原字节及明确顺序；原始逐帧时长／时基与来源、画布／帧矩形、合成／处置、循环声明及解释器版本 | 不因目标skin.ini改写原始帧或平均成一个FPS |
| 项目播放配方／实例 | 对来源的引用、用户指定的时间覆盖／速度／偏移／循环意图、目标元素／兼容profile绑定及导出策略；图层保持独立变换与显隐 | 不存当前播放位置、worker、GPU纹理或全量解码帧 |
| 派生输出计划 | 指定项目截面、目标元素规则／版本、采样时刻及源帧映射、输出帧数／命名／尺寸、时序损失和不支持诊断 | 不修改SkinProject或覆盖历史；不是原始素材 |

一个动画作为一个逻辑素材供图层引用，不把每帧自动变成普通可见性图层或N条素材库记录。内部可以共享帧字节／索引；多个实例共享来源，但变换和播放实例状态独立。一个ElementDocument仍代表一个皮肤元素，将来可输出该元素的帧文件族；不是每帧自动新建文档。跨元素组件保留成员各自输出边界，音效组件继续独立。

原始帧时长不能只保存平均FPS。保留原时基／延时声明，规范化时间使用有界整数ticks加明确时基或精确有理数，实际编码在实现前定稿；不靠浮点FPS倒推并覆盖原时长。大整数沿用明确文本编码，检查分母、范围、累计时长、乘法与索引溢出。源格式允许的零／缺省延时先按有版本、有依据的格式解释；有歧义或缺失时保留声明并诊断／请求用户指定，不统一改成浏览器习惯的最小延时。

PNG序列本身没有逐帧时长：由用户明确给定，或保留从已有皮肤取得的播放规则及来源。后者描述导入皮肤的实际播放，不声称还原其制作前原生FPS。AI生成的静态条带／帧图也没有天然FPS；用户指定时长应标为创作设定，不能冒充文件内嵌元数据。

局部帧必须按来源格式合成为逻辑画布后再取样；丢弃显示采样不等于可以跳过解码所需的依赖帧。APNG含帧区域、延时分数及dispose／blend信息，[PNG第三版规范](https://www.w3.org/TR/2025/REC-png-3-20250624/)是解释依据；GIF与WebP的时间／背景／处置分别参考[GIF89a](https://www.w3.org/Graphics/GIF/spec-gif89a.txt)和[WebP容器规范](https://developers.google.com/speed/webp/docs/riff_container)。格式差异不由一个通用默认值抹平；完整读取或浏览器观感相似不等于原时序已保存。

## 3. 导入、缓存与命令

1. 用户显式选择动图或组成序列的文件／布局和时间来源。序列按明确数值索引解释，不按字符串字典序；重复索引、缺帧、大小写冲突、SD／HD混杂或无时长时给出诊断，不猜测补帧、跳帧或把所有同名图片自动归组。
2. infrastructure在事务外受限读取／探测，固定完整原字节，验证实际格式、帧数、画布、时序和引用闭包。帧数、累计像素／解码量、元数据、文件字节、时长、后台任务分别准入；小压缩文件也可能有很大解码成本。
3. 准备完成后核对session、基础修订、目标文档／组和请求代次。仅入库走登记命令；同时入库并加入图层时走application一次原子事务。失败、取消、Busy、历史切换或目标失效不留下部分登记／图层／节点，迟到结果不写入新分支。
4. 原始输入及原时序保持不可变来源；重排、变速或时长覆盖形成新项目配方／历史状态，不回写原文件。当前头删除动画也不回收旧分支仍需要的原字节。

“拆帧”首先是可寻址的逻辑帧表，物理解码／独立PNG物化按需进行。派生RGBA／GPU采用有界窗口／缓存，必要解码检查点也计费；缓存键包含来源、帧序、解码／合成语义，不能只用文件名或帧号。历史固定原始来源，不固定全部展开帧。取消须等实际worker／租约及在途GPU回执释放才归还相应额度。

未知或暂不能正确解释的动画须明确未支持；未来可提供独立“只保管原件”模式，但不能把Opaque保管、静态缩略图或首帧解码称为动画导入／编辑成功。禁止只接纳前N帧、丢弃延时或为满足当前预算默默缩图。

## 4. 按元素解析stable播放规则

以下只记录2026-11-03核对的**官方文档线索**，不是本项目真实客户端验收结果：

| 来源 | 对设计的约束 |
| --- | --- |
| [skin.ini文档](https://osu.ppy.sh/wiki/en/Skinning/skin.ini) | AnimationFramerate控制依赖它的播放帧率，不是统一的帧数上限；正整数与默认-1含义不同，后者让相关动画全部帧在一秒播放完；有不受它控制的元素 |
| [动画FAQ](https://osu.ppy.sh/wiki/en/Skinning/FAQ) | 输出使用独立图片帧，命名形式和时间驱动因元素而异；存在配置、客户端固定和BPM相关规则 |
| [界面元素说明](https://osu.ppy.sh/wiki/en/Skinning/Interface) | 例如hit0动画记为固定60FPS、非循环、末帧保留至淡出；不能推广为所有元素的规则 |

未来compatibility负责有来源／适用玩法、皮肤版本、客户端范围和回归样例的规则；当前没有该实现包。规则描述须覆盖是否可动画、命名／分辨率变体、驱动时基、有效帧计数、循环／末帧及事件生命周期，不只记录一个FPS。未知时拒绝宣称兼容输出，不把猜测散入UI、domain或素材制作skill。

源时长和目标规则独立。导入一个24FPS素材不自动把整个皮肤AnimationFramerate改为24。用户显式改全局配置须经Command，并重新检查所有受影响元素。固定帧率元素使用自己的规则；BPM／事件驱动须有对应时间上下文，不能用一个固定秒制FPS保证所有谱面／事件下都保持源时长。

对文档所述-1模式，重复帧会同时改变帧数与该模式的有效播放速率，不能据此把一秒周期延长成两秒。无法保持源设计时长时，说明限制；用户可显式调整项目配置或选择改变播放速度等派生方案，不能在导出时偷偷改全局配置。

## 5. 重采样与预览／导出共用计划

默认目标是**尽量保持设计时长和速度**，使用原帧持有／选择，不默认混帧、光流或AI补帧。后者会改变视觉，须作为另外的显式编辑能力。不能默认取所有来源FPS的最小公倍数，造成输出帧数和资源开销膨胀。

仅当目标规则允许任意帧数、固定正帧率F且生命周期可容纳时，采用以下建议基线：

- 以配方后的单周期时长T决定输出帧数；N取T×F最近整数，半值向较大整数，至少1帧，先检查输出规模上限。
- 第j个输出位置在t=j/F求值，j从0到N-1；在源半开时间区间中选择当时的完整画布帧。速度／偏移／循环先按配方解释，端点／循环交界和末帧行为明确测试。
- 输出实际周期为N/F，报告与T的差值、持帧分布、被跳过源帧及时间边界量化。短于一个目标时间格的片段也不能谎称精确保留。
- 严格模式对不能满足用户已声明时序要求的转换明确失败；近似模式交付可核对的损失报告和兼容预览。不用“无损”形容不能整除或丢帧的转换。

这不是所有stable元素的统一公式。-1、BPM、事件或受限帧数规则须由各自profile编译，不套固定F分支；缺少规则／上下文时不可伪造最终计划。

| 算术示例（目标规则允许时） | 固定F分支的预期 |
| --- | --- |
| 30FPS、1秒 → 60FPS | 60输出帧，源图各持有2帧 |
| 24FPS、1秒 → 60FPS | 60输出帧，源图持有2／3帧，显示边界存在量化 |
| 60FPS、1秒 → 30FPS | 30输出帧，部分源显示帧被跳过，依赖它们的解码合成仍须正确 |

素材编辑预览保留原生时序；stable兼容预览使用与导出相同、版本绑定的输出计划。模式和诊断可见，不能拿原生播放冒充导出后效果。图层组的静态变换、alpha／色彩与隔离合成语义继续共用：每个输出时刻先求各动画实例的帧，再合成所属元素；不能绕过嵌套组或把不同源FPS逐帧按同一索引硬拼。

计划固定内容截面、配方／配置、目标元素、规则版本、采样策略及输出尺寸，不随上游规则更新静默改变旧项目含义；改变结果的规则升级需明确解释及迁移／用户选择。运行取样依据模拟／素材时间，不按GUI绘制次数逐帧加一。冻结不推进游戏时间／动画／输入，仍允许素材更新；恢复不补跑暂停时间。热替换保留场景与时间关联，不在解码完成时隐式从首帧重播，具体新旧配方相位映射须有明确策略和回归。

导出时才合成并编码元素帧文件族，预检全部名称、路径／大小写、SD／HD冲突和帧数。输出事务成功前旧目录保持可用；帧数变少时处理本次产物所拥有的旧帧，不能残留多余尾帧或删除用户无关文件。元素隐藏的有效透明序列／占位依目标规则验证，不用缺失或零字节；静态与动画文件并存／回退也单列验证。损坏、取消、未知规则不能产生“成功但少了动画”的皮肤。

## 6. 持久化与模块责任

工程须包含全部动画原始来源和时间声明、配方、目标绑定与影响输出的策略，包括未使用素材和仅旧分支引用的内容。帧RGBA、解码检查点、GPU对象和已导出PNG是可重建派生资源；生成的帧若被用户显式采纳为新的独立原始素材，则按新的项目资源保管。

帧顺序／时长覆盖、速度／循环意图、来源替换、全局配置及持久输出策略的有效修改经Command进入历史；草稿取消、失败和NoChange不留节点。当前播放／浏览帧、编辑器预览模式、任务状态不进入项目历史。编译计划本身是派生结果，不为每次播放或导出创建内容节点。

当前schema1中的sequence只是分页索引，不是动画帧表；现有asset／layer／output语义没有动画。实现前须确定新增来源／配方／帧文件族字段、资源闭包、必要能力及版本／迁移fixture，评估模型／内容schema／捕获与命令端口需怎样演进，不预填新版本号。旧静态素材保持静态，不因默认FPS变成一秒循环；追加新表示，不重写旧节点的原始状态／操作／摘要。旧程序不能理解必要动画语义时拒绝覆写，不删除帧、改成首帧或用未声明扩展绕开版本。详见[数据约定](DATA_COMPATIBILITY.md)与[当前内容schema](PROJECT_STATE_SCHEMA.md)。

| 模块 | 未来责任，当前未接入 |
| --- | --- |
| domain | 来源引用、精确时间／配方、实例及输出关系的不变量；不解析文件或持有播放器 |
| application | 导入登记／编辑／草稿／历史／保存捕获及窄查询控制端口；唯一活动写入口 |
| infrastructure | 受限读取／格式解码、原字节与帧缓存租约、状态codec、存储和PNG输出适配 |
| compatibility（未来模块） | 经过验证的元素命名、时基、循环／生命周期与转换约束 |
| rendering | 在明确采样时刻合成像素；预览与导出共同语义 |
| preview／desktop | 场景／模拟时间、请求来源、后台任务与原生资源生命周期 |
| UI／AI／素材skill | 展示来源时间／转换损失，提交同一应用用例；不直接写项目或解释未知游戏规则 |

这是职责预留，不改变当前Cargo图或新增模块。动画按需加入共享计划／窄端口，不能为此建立通用事件总线或工作流框架。

## 8. 实施顺序与未实现范围

本轮只完成设计记录。P3先明确动画在文件演进中的语义与拒绝边界，当前静态保存／导出子集可继续按原计划推进，但不能声称已保存或导出动画。启用动画前先完成类型／Command／精确时间与资源闭包，再做PNG序列及逐种受测容器、原生取样与持久化；P4按元素验证时间profile并接共用输出计划／序列导出，P5协调真实场景／歌曲定位。具体小增量以用户后续任务为准，不自动扩大当前范围。

静态首批并不要求同时完成全部GIF／APNG／WebP或动画创作UI。正式新增动画数据时再冻结字段／版本／依赖与迁移；未通过对应AN项的格式、元素、平台和时间规则继续标为未支持／未验。相关入口：[架构](ARCHITECTURE.md)、[路线图](ROADMAP.md)、[编辑器交接](HANDOFF_EDITOR_CONTINUATION.md)、[素材skill交接](HANDOFF_SKIN_ASSET_SKILL.md)。
