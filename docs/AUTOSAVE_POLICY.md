# 操作历史自动保护：周期、触发与资源调度建议

2026-11-10与保存闭环对齐：[P3保存／关闭／重开闭环规格](P3_SAVE_LOOP_SPEC.md)先实现手动／退出保护及重开基础，周期自动保护仍是本页待实施建议。当前capture_history遇活动草稿Busy，且同会话只有一捕获槽；AP04草稿期间捕获、AP05在途外再冻结待处理手动截面尚无实现前提。P3-2初始方案明确第二手动请求Busy，不能声称已实现本页完整队列；后续须先审阅有界捕获能力或等价方案，不能偷偷改用户已接纳的截面。2／30／5秒、100事务及退避保持未启用。

2026-11-02，**设计方案，参数仍待实施验证，尚未实现或启用**。用户本轮明确历史不允许被任何用户／AI／后台删除或覆盖，节点标签可独立修改；下表沿用上一轮推荐数值。本文补充[数据兼容第4节](DATA_COMPATIBILITY.md#4-保存整棵树保存标记与未保存状态)，保持完整历史、同文件增量事务、退出补存、默认手动位置／主动恢复最新规则。不启动计时器、不创建后台自动化、不提交Git。

P3-0已验证[增量存储原型](P3_0_REVIEW.md)，但没有实现本调度器、fake时钟调度验收或GUI／音频组合保存；以下周期与资源目标仍不能称为已通过。

## 1. 推荐默认值与取舍

采用“有变化才调度，短暂停顿后保护，持续编辑不无限延期，普通自动写入限流”的组合，不采用每个操作立即刷盘，也不只依赖用户完全空闲。

| 项目 | 推荐候选值／规则 | 目的与边界 |
| --- | --- | --- |
| 编辑期间自动保护 | 默认启用 | 已命名工程写入工程文件；未命名工程按既定恢复区约定保管，不要求用户先选保存路径 |
| 停顿窗口 | 最后一次相关有效变更后2秒 | 合并连续参数／图层操作；这里的停顿指项目变更暂停，不是鼠标／键盘完全静止 |
| 最久等待 | 最早尚未受保护的已完成变更出现后30秒 | 持续编辑仍会提出保护；新操作不能重新推迟这个起点 |
| 普通自动任务间隔 | 上一个同目标保存任务实际结束后至少5秒，再启动普通自动任务 | 避免连续小停顿／导入／失焦引起高频写入；手动保存及退出保护不受此普通限流限制 |
| 未保护事务数量 | 累计100个有效内容事务时提前提出保护 | 防止批量AI／快捷操作积压；仍受普通间隔、队列、预算及故障门控约束；不按GUI帧／草稿Replace次数计数 |
| 新原始资源／首次新分支 | 成功提交后提出优先保护 | 不等30秒或2秒停顿，但仍遵守普通5秒间隔与同目标串行，不同步阻塞导入／编辑 |
| 退出补存 | 不受周期及普通间隔限制，按既定关闭流程完成 | 选择“不保存”仍保护关闭时完成的工作，不推进手动位置；不能等下一次周期才关窗 |

这些数值是可测的初始建议，不是已获得性能证据的常量。2秒兼顾短操作组合与快速保护；30秒给持续编辑保留独立调度目标；5秒避免频繁停顿触发过多事务。在不考虑其他提前事件的持续编辑模型中，30秒规则约对应每小时120次逻辑保护；普通5秒间隔给出不高于约720次／小时的频率上界，实际还包括任务耗时。它们不是设备物理写入次数、磁盘寿命预测或成功提交保证。

**30秒是无故障且执行资源可用时的发起目标，不是“最多只会丢30秒”的保证。** 排队、主线程停顿、长写入、锁冲突、退避或设备故障可能使完成更晚；未提交草稿本来就不在已完成编辑的保护范围。须分别报告最早未保护变更的年龄、触发到捕获、排队、写入与真实提交时间，不能把发起请求当成数据已落盘。

## 2. 哪些事件参与调度

| 事件 | 推荐处理 |
| --- | --- |
| 有效项目事务：变换、图层／组、配置、音效配方、素材库管理等 | 置脏；启动／保持最早未保护时间，更新停顿时间和事务计数 |
| 从旧节点成功创建第一条新分支，或首次提交含新原始字节的工程变更 | 在普通调度上增加一次优先保护意图；“字节已经准备好但Command未成功”不算工程变更 |
| 成功Undo／Redo／Checkout，或改变需持久化的导航／历史元数据 | 标记相应持久状态变化，按停顿／最久等待处理；不新增内容节点，不累计内容事务数量 |
| 用户显式手动保存 | 优先安排已捕获的手动请求；成功后只清除其覆盖范围内的待保护变化，后续编辑仍保留原等待年龄 |
| 窗口失焦、最小化、准备进入全屏测试 | 有待保护变化时提出一次机会性请求；不强制同步等待磁盘，不因重复焦点事件绕过5秒限流 |
| 用户关闭工程／退出，或确认切换到另一工程 | 按关闭门控先协调已接受的显式保存，再保护最后完成的工作；周期调度不能替代该流程 |
| 可处理的休眠／关机通知 | 有机会时尽力请求保护；不假定一定有通知或足够时间，强制终止／断电不承诺能补存 |
| 恢复／唤醒 | 仅重新评估一次当前待保护工作，不重放睡眠期间的每一个计时周期 |
| 失败、取消、NoChange、旧回执重放、草稿Replace | 不产生新的项目变更计时／事务数量；既有待保护工作按原计划继续，不能因这些事件被误清除 |
| 选择、视口、面板、播放／暂停、模拟时间、Z／X游戏输入、显式试听、监听音量 | 不触发项目历史保护；偏好与工作区保存走独立用例 |

“优先”表示免等普通停顿窗口，不表示可抢断在途原子事务、绕过内存预算／文件锁或替代手动保存。失焦不是每个鼠标离开控件事件；普通打开旧手动位置也不是一次显式历史编辑，不能据此覆盖已有较新保护头。

新分支提前保护针对每条新分支的首次有效事务，不是该分支之后每一个普通编辑；多个相邻触发只合并为一次意图。新资源提前保护针对尚未在该工程代次中保管的原始字节，复用已有素材不必因此增加写入。

音频持续播放不应导致永远等不到保护机会，也不能为自动保存停止声音、降低预览帧率、丢输入或提前清掉资源。重负载下仍通过短捕获／后台增量写入处理；确实无法准入时保留待办并标出延迟，不反复重置30秒起点。

## 3. 调度状态与时间计算

未来由application管理每个工程的待保护状态和纯策略计算；desktop提供单次时钟唤醒及受控存储任务。策略接收显式`now`，便于fake时钟测试；不让domain、preview、音频回调或UI绘制负责定时写文件。

最小状态包括：会话／目标绑定、有效持久变更序号、最早未保护时间、最后相关变更时间、未保护内容事务数、普通下次允许时间、失败重试时间、在途捕获范围及一条合并意图。它们是用例／运行状态，不变成SkinProject内容节点。

计时使用同一运行时的单调时间，不靠用户可调整的日期时间排序；持久提交顺序由SaveId／明确代次关联。单调时钟值不写入项目并跨重启复用。时钟暂停／恢复的具体平台语义在适配器验证，唤醒后只做一次当前状态评估。

普通请求满足任一触发即可候选执行：

1. 距最后相关变更达到停顿窗口；或
2. 最早未保护变化达到最久等待；或
3. 未保护事务达到数量阈值；或
4. 有一次机会性／优先保护意图。

随后统一经过普通最短间隔、重试门控、同目标单任务、资源预算及安全捕获检查。30秒到期不绕过这些约束；受阻时显示逾期／待处理，依赖任务完成、资源可用、一次期限通知或退避唤醒继续，而不是用零延迟定时器反复轮询。

未受保护变化按实际捕获范围划分：

- 在途捕获q期间出现q之后的新变更，保留独立的最早时间与计数；q成功不清空它们，也不把起点改成收到回执的时刻。
- q失败／取消时，其未覆盖变化仍待保护；合并回最早时间，而非重新获得30秒。
- 可用“在途范围＋后续范围”的有界摘要表达，不每帧保存全部事件时间戳。
- 成功手动保存也按捕获范围确认覆盖；新文件绑定、过期会话、旧回执和结果未知不得清掉当前待保护状态。内存中的活动头也不因后台保护完成被切回捕获头。

若没有待持久化差异，计时器撤销，不写空代次。默认打开A且较新保护C仍存在，未产生新编辑／显式导航时不能凭定时器制造保护A；这既避免写入，也保持主动恢复C的入口。

## 4. 草稿、队列与任务优先级

自动保存只读捕获application已经提交的项目／完整历史，不提交、取消或抢占用户草稿。即使长手势跨过30秒，仍可在安全点捕获此前已经完成的变化，草稿继续编辑；若当时根本没有新的已提交内容，不为草稿造空保存。尚未提交的配置文本同理，不能承诺它已被保护；若以后要恢复编辑器输入草稿，应另立恢复需求。

每个工程目标采用一条有界串行保存通道：

- 最多一个在途保存任务。
- 最多一个待处理保存项；普通自动项只保留“需要再次评估最新状态”的轻量意图，不在每个计时点冻结一份项目／资源快照。
- 用户手动保存替代尚未启动的普通自动意图时，须保留手动请求时明确捕获的截面，不能延迟到执行时偷偷改成更晚内容。已有待处理显式请求占位时返回明确Busy／正在保存状态，不无限排队或静默合并不同手动保存意图。
- 在途截面之外，后续自动需求用一个有界合并标记保留；如果待处理项是显式截面，该标记仍可记录有更新，但不增加额外快照／任务。
- 不强行抢断已经进入存储事务的任务。接受的手动请求先按真实顺序协调，退出流程再捕获最终截面；待执行手动优先于普通自动。手动／退出保护可跳过普通间隔与自动退避，但不能越过文件冲突／损坏／预算等安全检查。

合并的是保存请求，**不是合并／删除历史节点**。后续捕获包含所有新分支及资源闭包，不能只保留队列末尾一个节点。文件内部增量分批写入可以有阶段进度，但未完整提交新入口前不能把目标截面标为已保护。

每次自动提交还须保留目标文件已有的全部节点与不可变内容；同ID不同内容拒绝，旧截面不能缩减已持久化集合，不能以容量不足／性能优化／用户选择为由裁剪。允许修改的标签是独立元数据写集，可进入本次增量保护，但不改变节点本体、不新增内容节点；保存类系统标签仍取自真实手动保存事实。具体规则见[不可变历史与标签](DATA_COMPATIBILITY.md#11-不可变历史与可变标签)。

## 5. 编辑流畅度与资源边界

推荐把主线程工作限制为校验来源、取得不可变捕获引用和更新小型状态；编码、哈希、压缩、文件I/O和等待提交由受控后台工作执行，不在GUI绘制／输入处理内运行。安全捕获不能靠克隆整棵10000节点树实现“后台保存”。

常规自动保护不额外触发整库解码、图层合成、GPU回读或皮肤导出；它保存可编辑状态与原始资源，不为每次保护制作新的预览图。复用已验证块，新增字节按入库／写入协议校验，不能每轮重新读取／哈希全部原图和音频。

候选工程目标：代表性项目的主线程捕获p95≤2 ms，同时报告最大值与分配量；这是**待验证目标，未替代现有预算**。后台采用流式增量I/O，先以4 MiB额外流式暂存上限做原型验证；共享原始字节不重复复制／计费。捕获元数据、存储引擎页缓存、日志、压缩及旧代次租约另有明确额度并计入进程总量，不能把4 MiB说成全部新增内存或排除驱动／引擎成本。

保存任务不得借用音频供给／原生回调去执行I/O，也不阻塞这些线程等待会话锁。新任务准入前预留额度，取消后等实际任务／租约释放再退款；不能每个周期创建一组新线程或积压多个大副本。

保持[现行资源预算](RESOURCE_BUDGET.md)：零欠载、已就绪短音提交p95≤20 ms、帧／编辑刷新、内存／GPU和回收门槛不豁免；播放CPU≤15%仍是优化目标。P2既有结果没有包含未来保存器，必须在P3接入后重新测量同构建组合负载，不从历史余量推断新路径通过。

调度只设置下一次必要唤醒；无变更／已保护后不常驻轮询，不借GUI每帧检查截止时间，不以反复request_repaint驱动存储。状态变化才请求必要界面刷新；等待年龄可在详情查询时计算，不让一个持续走秒的“已保存”时钟破坏稳定空闲门槛。

## 6. 慢写入、失败与用户可见状态

写入较慢时，只保留当前任务和一次合并需求，继续显示待保护范围；不在原任务未实际结束时宣布超时并并行重开另一个写者。不因连续编辑把旧捕获反复取消，避免始终不能完成一次提交。普通5秒间隔从同目标任务实际结束计；长任务造成30秒逾期如实记录，不通过重置起点隐藏。

推荐的暂时性I/O失败退避为依次等待5、15、30、60秒，随后最多每60秒尝试一次；退避从真实失败／任务结束后计算。普通计时器、继续编辑、焦点或数量阈值不能绕过退避制造重试风暴。此组数值同属待审参数。

权限／磁盘空间／只读／未知必要格式、外部修改冲突、损坏或清理未完成等需要处理的条件，不自动反复全量尝试；保留待保护状态，等待用户重试、目标可用的明确通知或另存恢复副本。结果未知先按SaveId协调，不盲目重复提交。用户主动重试可立即重新检查，但不能跳过安全门控。

首个失败显示持续可见的保护状态和原因，不反复弹对话框或抢焦点；恢复成功只确认对应截面并清除已解决错误。至少区分：待保护、正在保护、已保护、逾期／等待资源、暂停／只读、失败；另显示手动保存位置，不能用“已自动保护”冒充已手动保存。

退出保护沿用最新规则：失败保留工程及已提交历史，允许取消退出／重试／另存完整副本，不提供“丢弃已提交历史后强退”的产品入口。不能用普通自动退避让关窗无提示地无限等待，须显示进度与可选动作；取消未提交草稿按原规则处理。

## 7. 偏好与可配置范围

首版建议只暴露两个用户设置：

| 设置 | 推荐 | 兼容约定 |
| --- | --- | --- |
| 编辑期间自动保护开关 | 默认启用 | 关闭后停止停顿／年龄／数量／机会事件触发的后台保护；手动保存和已确认的退出补存仍有效，界面明确说明。不能标成关闭一切保护 |
| 持续编辑最长等待 | 默认30秒；建议允许10–120秒 | 这是调度目标；验证与最短间隔等策略关系。用户显式值不随升级被新默认覆盖 |

2秒停顿、5秒间隔、100事务及退避先作为有版本的应用策略参数，不在存储引擎硬编码，也不急于制作全部高级选项。候选稳定设置键可用`editor.historyProtection.backgroundEnabled`、`editor.historyProtection.maxPendingSeconds`，名称／schema冻结前仍需审阅；不直接序列化Rust字段名或控件ID。

这些属于用户偏好，不进入SkinProject／skin.ini／内容历史；解析失败／未知设置仍遵守原字节保护与诊断。修改偏好后重新计算现有待保护工作，不把已等待年龄归零；启用时若已逾期则按门控请求，禁用时保留脏范围跟踪但撤销普通唤醒，不能否认已提交事实，已经进入事务的任务按正常归还／取消规则协调。

## 8. 推荐验证方式与审阅项

本轮只制定要求，下面**均不是已运行通过的测试**。先用fake时钟、受控存储门闩和明确事件验证，不依赖真实sleep或GUI帧数；通过后才用选定容器做真实I/O及图形／声音组合验证。

| 编号 | 应验证的行为 |
| --- | --- |
