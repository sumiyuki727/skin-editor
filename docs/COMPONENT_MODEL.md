# 嵌套组、组件与输出边界

2026-10-20，设计基线 v1。P1-1 已实现模型与不变量，Command、控制柄、像素合成及导出尚未实现。用户已确认组本身可作为节点选择、嵌套及整体变换，组件也包括 hitcircle＋hitcircleoverlay 等多个独立皮肤元素。这里的组件是编辑器概念，不代表 stable 存在对应组件文件。

## 两种组共用变换语义

| 节点 | 成员与作用范围 | 输出边界 |
| --- | --- | --- |
| LayerGroup | 一个 ElementDocument 内的图像图层／子组；组有自身 ID 和局部仿射变换 | 在该文档内合成，可使用已定义的隔离组透明度 |
| ComponentGroup | ComponentTree 中的元素文档引用／子组件组；组同样有 ID、局部仿射变换和父节点 | 各 ElementDocument 仍按自己的 OutputMapping 分别导出 |

UI 统一呈现可嵌套、可选择、可展开的组；节点能力和输出边界明确可查询。共用小型仿射值类型和变换运算，不为统一显示强迫两种树使用同一存储结构，也不提前建立通用节点框架。

例如一个“单击对象”组件下有 hitcircle 文档、overlay 文档及可选子组件组。每个文档内部仍可有任意已支持的图层／组，原始 Asset 可继续跨文档共享。

## 整体变换

- 组有整体控制框和参数，可平移、缩放、旋转；父组变换与子节点局部变换按顺序组合。修改父组不改原始图片，子组仍可独立编辑。
- 选择框依据成员的几何范围及明确坐标映射计算，不能把 alpha 判定区、GUI 命中区或游戏判定区当作选择框。空组没有可绘制的包围框，但仍可通过参数编辑有效变换；不得产生 NaN／无限边界。
- 单文档组的边界来自后代几何在组空间中的合并。跨元素组件使用显式的共同编辑坐标系，每个成员记录到自身文档空间的映射；不能因文件名相似就假定尺寸、锚点或中心一致。
- 首版一个 ElementDocument 只能在权威 ComponentTree 中出现一次，允许未分组文档；重复预览实例不重复登记文档。重叠多选属于 EditorState，不形成第二条会影响同一输出的组件变换链。需要两个独立结果时复制文档并分配新 ID，原始 Asset 仍可共享。
- 嵌套无环、单父、顺序及映射有效性由 domain 校验；迁移保持明确的几何语义，不可逆目标映射时拒绝。组创建、成员迁移和整体变换均经 Command；跨文档变化作为一个原子事务和历史节点。

这些限制保证每个输出有唯一可解释的变换来源，而不是让一个文件同时服从两个互相矛盾的父组。

## 预览与导出一致

rendering 为成员文档解析同一份有效合成计划，其中包含其组件祖先变换和成员坐标映射；预览与导出都消费该计划。跨文件整体变换不能只改变场景纹理位置、导出时再忽略，也不能把所有成员强制压成一个 PNG。

P1-1 将成员映射 M 明确为文档像素到未变换组件基准空间，节点局部仿射按父到子组合为 W；提供文档内容变换 `M⁻¹ × W × M`，让同一结果进入后续预览／导出合成计划。成员映射必须可逆，组的普通编辑变换可为零缩放；迁移到不可逆父空间仍拒绝。组件包围框是 W×M 作用后的文档画布范围；文档内图层包围框使用源图完整矩形，在组件内容变换前计算，包含隐藏图层，不分析 alpha，也不等同于最终裁切结果或判定区。

组件编辑坐标、文档像素坐标和游戏场景坐标仍然不同。修改图片内容的几何不会自动改变游戏对象位置或判定线；涉及 stable 布局／skin.ini 的操作，必须有对应 compatibility 能力与原子命令。未知成员映射、不可表达的变换、画布裁切或输出冲突需说明并拒绝不支持的部分，不能伪装整个操作成功。组件编辑视图可使用明确的自有映射；stable 组件预设另按证据验证。

跨输出的组件组先支持几何变换。隔离组透明度、蒙版和混合模式不能直接推广到多个独立输出：将两张图先合成后统一降透明度，通常不等于分别降透明度再由游戏叠加。此类跨输出效果暂标未支持，后续必须证明能表达或改变明确的导出结构后再开放；单文档 LayerGroup 的既有合成语义不变。

## 阶段与测试

| 阶段 | 交付与验收 |
| --- | --- |
| P1-1 | 组件／成员的类型区分 ID、树与唯一成员约束、显式坐标映射及变换组合；不使用 stable 文件名决定几何 |
| P1-2／4 | 原子组操作、事务后段失败回滚、多级组草稿／取消／一次提交，历史往返还原关系与变换 |
| P2 | 单图、嵌套组、跨文档组件整体框与控制柄，自有坐标 fixture；空组、非对称图及父子变换测试 |
| P3/P4 | 同一组件的多个输出分别存在，预览／导出像素及裁切一致；真实元素映射有证据后才声明 stable 支持 |

P1-1 的多成员测试验证不同映射下的预期几何和独立输出关联，未执行 PNG 合成或真实 stable 映射。项目文件 schema 未冻结，像素／裁切一致性仍在 P2/P3 验收，不把模型测试当成渲染结果。
