# P1 核心 CPU／内存基线

2026-10-21，Windows x64、Rust 1.95.0 release。机器记录：[P1_CORE_COSTS.json](P1_CORE_COSTS.json)。这是一组核心元数据诊断，不是完整应用预算、最低硬件或跨平台成绩。

## 可重复入口与范围

```text
python tools/check_core_cost.py --output artifacts/p1/core-cost-new-run
```

默认依次运行 minimal／standard／pressure，各两个独立进程。输出目录必须是 artifacts 下尚不存在的目录，拒绝覆盖。可用 `--profiles`、`--repetitions` 和 `--toolchain-dir` 选择已明确标记的诊断范围；减少重复或负载不能沿用本表成绩。

独立工具工程在 `tools/core-cost/`，只依赖 application→domain 和标准库，有自己的锁文件／workspace；产品 workspace 仍只有两个纯库且无第三方依赖。运行入口先检查该工具格式、Clippy 并离线构建 release，不自动安装工具。时钟、标准输入输出与 Windows 计量仅在工具侧；核心无额外线程或 OS 调用。核心默认检查中的 5 个工具回归保护完整次数、阶段、数值与输出路径约束。

| 负载 | 原始资源引用／文档／图层 |
| --- | --- |
| minimal | 0／0／0，固定大小配置记录修改，作为协议与历史开销参考 |
| standard | 100／10／500，每文档 50 层（两层嵌套组＋48 图像层），引用 10 张源图，含跨文档组件与独立输出 |
| pressure | 1000／100／5000，同样每文档 50 层，含组件／输出；不是单文档 5000 层 |

图像只有 1024² RGBA 的 BlobRef／尺寸元数据和模拟生命周期租约，**不读取或分配对应图片字节，不进行摘要校验或解码**。初始化通过公开 Command 建立内容；随后 5000 次有效单命令事务形成 A 分支，检出第 2500 次编辑处，再进行 5000 次事务形成 B 分支。两叶之间完整往返一次，核对目的内容与历史节点数量；最后 300 次草稿替换后取消，核对已提交内容完全未变。所有分支和资源租约一直保留到会话释放。

## 测量口径

- 子进程用 Instant 计每次公开 submit／草稿 Replace／检出，给出最近秩 p50／p95／p99／最大值。事务阶段总 wall 还包含少量断言与边界快照；往返 wall 包含两个检出及内容核对。
- Windows GetProcessTimes 给出阶段 kernel＋user CPU 时间，百分比以单逻辑核为 100%。记录保留原始值；短阶段受 CPU 记账粒度与工具开销影响，可能超过 100%，不把 minimal 的百分比当作精确占用或实际并行度。
- 父工具目标每 10 ms 采样子进程工作集和 PrivateUsage（私有提交）；边界在子进程等待确认时再采样。采样峰值可能漏掉瞬时分配，另列 OS 累计 PeakWorkingSet／PeakPagefileUsage（进程历史提交高水位）。二者不可相加或混成同一个峰值。
- 当前父监控进程／编译器是诊断工具，不计入产品；子进程数字含 release Rust 运行时、诊断计时数组、快照、回执、补丁、存活租约和分配器保留。未做分配器级别逐字节归因，不用释放后工作集冒充仍可达逻辑数据。
- 机器 JSON 保存各组源码／可执行哈希、各轮阶段值及环境；before 运行期间有其他开发检查，先前组的 wall 波动不能归为单一原因。after 两轮顺序运行，无并行其他测量负载；不把不同构建峰值合并成一个成绩。

## 结果与采用的优化

首测发现文档补丁反复深拷贝不可变图层树／派生索引。改为 LayerTree／ComponentTree 私有 Arc 存储：创建时完整校验，查询仍只返回不可变值，编辑构造新树，历史与候选共享旧存储。没有提供 Arc 的可变入口或引入持久化集合框架。

恢复过去逐补丁构造并校验整个项目，压力分支往返耗时约 41–44 秒。现在沿相同公共祖先路径将**既有已提交补丁**应用到私有 ProjectDefinition，最终完整校验目的状态一次后发布；缺失补丁、非法最终引用及租约错误仍拒绝。普通 Command 和草稿的每条基础命令校验没有省略。

## 结论与后续关口

10000 次事务、保留分支往返、300 次草稿取消与资源租约数量断言全部通过；after 标准和压力各两轮已形成相同源码的成本基线。原始失败／高成本组与其快照保留在本地 artifacts，JSON 分开保存 before 与最终 after；另保留同优化二进制的初轮 after_initial_runner，正文使用最终 after，数值不混合。

已确认的取舍：仍以改变文档的完整不可变树为补丁粒度，回执保存请求元数据；50 层文档的长历史仍占约 294 MiB，不能将“地址有界”理解为历史免费。没有自动裁剪、驱逐回执、降低素材质量或回收旧分支字节。单文档极多图层、巨大命令载荷、更多草稿更新、真实字节存储、内存压力准入及历史持久化尚未计量。

P1 的元数据基线完成；[完整产品预算](p0/RESOURCE_BUDGET.md)的 B01–B09 不能据此标通过。P2 加入 eframe／wgpu、解码图片和派生缓存时需同版本复测，按实际负载决定是否细化文档补丁／缓存；原图字节与 GPU 成本可能远高于这里的租约元数据。Linux／macOS 未测，GUI、真实帧率、输入到显示延迟、实际音频和 stable 兼容均不在本记录内。
