# 历史节点身份与有界地址

2026-10-21 更新。P1-3 已在 application API v3 实现撤销、重做、检出、追加分叉、两种有界地址及分页查询，通过 Windows 无窗口检查。历史只在编辑会话中保留；没有历史 UI、磁盘持久化或 AI 传输服务。

## 身份、位置与显示分开

- 内部 NodeId 使用会话内不复用的非零 u64；HistorySessionId 单独标识会话。跨会话引用使用二者组成的结构化键；裸 NodeId 不宣称全局唯一。计数溢出须在发布修改前返回 ResourceLimit，不回绕或复用。
- UI／AI 的规范短标识为 `n`＋小写 base36 的 NodeId，例如 `n1`、`n2s`；最长 14 个 ASCII 字符，长度不依赖树深。请求已携带会话身份，无需在每个短地址重复整个项目路径。
- 分支坐标为 `b<branchId>:<ordinal>`，两个数同样为 u64/base36，最长 28 个 ASCII 字符。根为 `b1:0`；第一个子节点沿用分支且 ordinal 加一，之后追加的同级节点分配新分支、ordinal 从零开始。坐标不因排序或检出重编号，经索引返回稳定节点 ID。
- 节点保存父 ID、深度、固定大小坐标及按创建顺序追加的子 ID；坐标索引每节点一项，每条边保存父引用与一个子引用。内部不保存格式化地址或祖先数组。未来标签与事务摘要不得拼接进规范地址，当前尚无命名接口。

首版根节点示意：

```text
n1 根 b1:0
└─ n2 A b1:1
   ├─ n3 B b1:2
   └─ n4 C b2:0
```

`n3`、`n4` 的身份不含祖先字符串。树位置由父子关系得到，UI 可以折叠、排序或以省略号显示祖先，均不改变地址。

`NodeId::parse_address`／`BranchCoordinate::parse_address` 仅校验语法和数值；适配器应调用带 HistorySessionId 的 `resolve_history_address` 完成会话与存在性校验。拒绝大写、前导零、空字段、非法字符、零身份、溢出和超长输入。相同裸地址可以出现在不同会话，不能脱离会话当作全局引用。

## 控制与查询契约

`navigate(HistoryRequest)` 和内容 submit 由同一个 ProjectSession 串行管理，共用版本、会话、期望 head／revision、RequestId 命名空间及去重容量。相同请求返回原回执；用同一 ID 更改操作或在两类请求间复用均拒绝。失败回执保留，不把重新尝试当作已获成功。

- Undo 进入父节点；根上返回 NoChange。
- Redo 在叶节点返回 NoChange，只有一个直接子节点时可省略目标；多个后继返回 AmbiguousRedo 和数量，调用方分页查看后明确指定直接子节点，不自动猜测分支。
- Checkout 可跳转任意存在的节点。切换头时 revision 单调加一，即使两个节点内容相同；同头检出不增加修订。
- 控制不产生内容节点。恢复沿最近公共祖先迭代撤回／应用补丁，候选校验及资源租约核对成功后才发布。错误、修订溢出或丢失固定资源时保留原项目与活动头。
- 旧节点内容与补丁不改写；追加分叉只为父节点追加子关系。返回旧节点后继续 submit，原子树、对象身份准入记录和资源租约仍保留。

| 查询 | 结果及限制 |
| --- | --- |
| history_summary／history_entry | 单节点身份、父关系与摘要；entry 另含保守失效对象集合 |
| history_children | 按追加顺序返回摘要；offset 游标，允许等于子数量的空页，越界拒绝 |
| history_ancestors | 包含起始节点；next_ancestor 是下页首节点，不重复上页内容 |
| history_snapshot | 只读物化指定节点，不改变活动头／修订；不是有界大小的列表查询 |
| history_statistics | 节点／边／坐标索引／分支／深度及租约／回执数量，不是内存字节 |

两种列表每页须为 1–256 项。查询均校验会话；页内仅复制摘要，不隐式返回补丁或整棵树。子列表追加后原 offset 仍对应原顺序；本期没有删除、排序或裁剪历史接口。

## 成本边界

深度为 N 的链上逐节点保存完整路径，会使地址存储随累计深度增长；改为固定 ID、父引用和有界辅助索引后，关系与地址元数据按节点／边数量线性增长。此结论只针对寻址元数据，不代表历史补丁、资源字节或项目快照总内存已符合预算。

实现使用 BTreeMap 索引，节点／坐标定位为 O(log N)，有界页按返回数量查询；地址编解码有固定字符上限。检出临时路径按到共同祖先的距离分配，迭代执行，不保留在节点中。非活动节点的只读快照从根迭代恢复，成本随路径和补丁内容增长；当前节点直接克隆元数据。单次查询完整快照、文档粒度补丁、回执及租约的实际成本仍需 P1-4 计量。

## 已验证与后续边界

- `crates/application/tests/history.rs` 覆盖 10000 层连续历史：10001 节点／10000 边／10001 坐标项、深度 10000；逐节点两类地址解析、祖先分页、旧快照及根／叶往返通过。
- 同一父节点下追加 10000 个子节点：连同根与父共 10002 节点／10001 边／10002 坐标项，10000 个分支；子分页无遗漏、原后继仍可重做、坐标不变。
- 跨分支资源删除／替换、存储不可用时切换、租约直到会话结束才释放；固定种子 1500 步序列与独立快照模型对照。错误范围、规范解析及最大 u64 地址编码通过。
- 内部故障注入覆盖恢复中途失败、丢失租约、修订和深度／分支／序号耗尽；失败不发布中间项目或头。已有内容命令继续覆盖节点 ID 与容量边界。

规模测试使用固定大小配置修改，验证关系与寻址行为，不代表大型图层文档或完整资源内存预算通过。具体计数与运行边界见 [P1 记录](P1_PROGRESS.md)；草稿和完整成本基线在 P1-4。
