# 历史节点身份与有界地址

2026-10-21 更新，设计基线 v1。P1-2 已实现会话身份＋固定 u64 节点、父关系和最小追加历史；以下短标识、分支坐标及完整控制仍待 P1-3。保留分叉与稳定寻址，不把完整祖先路径复制到每个节点中。

## 身份、位置与显示分开

- 内部 NodeId 使用会话内不复用的非零 u64；HistorySessionId 单独标识会话。跨会话引用使用二者组成的结构化键；裸 NodeId 不宣称全局唯一。计数溢出须在发布修改前返回 ResourceLimit，不回绕或复用。
- UI／AI 的规范短标识为 `n`＋小写 base36 的 NodeId，例如 `n1`、`n2s`；最长 14 个 ASCII 字符，长度不依赖树深。请求已携带会话身份，无需在每个短地址重复整个项目路径。
- 预留可选分支坐标 `b<branchId>:<ordinal>`，两个数同样为 u64/base36，最长 28 个 ASCII 字符；一旦分配不因排序或检出重编号。仅在对应分支索引实际实现后开放，解析结果始终返回稳定节点 ID。
- 节点保存父 ID、追加子序号及必要的子引用；每条边只记录有限次。标签、事务摘要有独立长度／分页限制，不拼接进地址。用户命名与规范标识分开。

首版根节点示意：

```text
n1 根
└─ n2 A
   ├─ n3 B
   └─ n4 C
```

`n3`、`n4` 的身份不含祖先字符串。树位置由父子关系得到，UI 可以折叠、排序或以省略号显示祖先，均不改变地址。

## 成本边界

深度为 N 的链上逐节点保存完整路径，会使地址存储随累计深度增长；改为固定 ID、父引用和有界辅助索引后，关系与地址元数据按节点／边数量线性增长。此结论只针对寻址元数据，不代表历史补丁、资源字节或项目快照总内存已符合预算。

不预先物化所有节点的祖先数组或面包屑；按需、迭代、分页查询。连续编辑、检出及回放不得依赖递归拼接无限深的路径。短标识解析先检查长度、字符、数值范围、会话及存在性，拒绝非规范编码；不接受超长字符串作为内部 ID。

## P1-3／4 必须覆盖

- 至少 10000 层连续历史和宽分叉，地址仍符合长度上限，创建／解析／查询不因祖先字符串复制而累积平方级存储。
- 分叉后保留原后代；显示排序、检出往返及继续编辑不改变 ID／辅助坐标。
- 不同会话相同本地序号不能互相解析；未知、过长、非法编码及溢出明确拒绝。
- 大深度遍历不耗尽调用栈；记录关系／索引／补丁／资源成本，不能以短地址替代完整历史预算测试。

公开契约采用带版本的结构化身份；项目文件及历史持久化策略仍按原计划处理，首版历史只在会话中保留。
