## 哪些操作必须记录（2026-10-30）

会让导出皮肤内容发生变化的有效修改必须记录，这是充分条件，不是唯一筛选条件。图片／组变换、合成与隐藏占位，音频绑定／增益／隐藏静音，以及导出的配置、文件内容或输出结构变化都在此范围。有效事务只提交一个内容节点，无效操作和取消草稿仍不创建节点。

未改变当前导出不意味着一律不记录；素材库管理、未引用素材、名称及其他项目组织操作需另行明确产品语义。当前资源登记仍遵守已有Command与历史规则，本轮不移除导入节点。预览场景、显式试听、监听音量和编辑器选择属于独立运行状态，不因此进入历史。

该原则不要求每次操作前后实际导出整个皮肤或逐像素比较。后续按明确的命令语义、输出依赖和校验结果分类，区分内容节点与临时状态；任何调整都须覆盖Undo／Redo、分支和资源可达性，不能仅在UI中隐藏或跳过仍存在的内容节点。

## 当前P2历史面板的范围（2026-10-29）

当前面板只查询从head向上的最多12个节点，以及head直接子节点的前16项；尚未使用查询回传的`next_ancestor`／`next_offset`继续分页，也没有全树视图或按地址跳转控件。其他位置的分支不会全局列出，这属于UI导航限制，不是历史裁剪。

M07后续[显示修正](P2_HISTORY_PANEL.md)将子分支置于祖先之前，参数／子分支／祖先使用限高滚动区，并显示本页数量、空态、错误及截断。900×480深祖先显示问题已先复现后修复；用户原窗口已关闭，实际head未知，不将该复现冒充其现场的唯一原因。条目数量上限和未接查询分页的范围不变。

有限分支的现有操作路径是先Undo或点击祖先节点回到共同分叉点，再在“当前节点的重做分支”中选择直接子节点；较远祖先可反复Undo或分段点击列表最早节点。直接子分支超过16个时，这个面板不能完整访问全部分支，不能把底层分页API可用描述为UI已接完。普通Redo仍遵守下文的撤销路径记忆，不能因其他分支未显示而切错路径。

创建新分支只追加节点和父子边，保留旧后代及跨分支原始资源；撤销、检出也不删除它们。三项现有回归（旧后代保留、跨分支资源、分叉Undo／Redo记忆）已再次通过；这证明实现行为，不是对用户正在运行窗口的内存树进行读取。当前P2历史仍只在各自内存会话，尚无磁盘保存；首版目标已改为完整历史恢复，不能拿既有会话内回归冒充新目标通过。后续历史面板需要可达性完整的有界导航，最终树形布局仍未固定。

## 六类标签

| 名称 | 含义及来源 | 数量／变化 |
| --- | --- | --- |
| 保存标签 | 当前文件绑定最后一次成功手动保存的捕获节点 | 当前文件最多一个，只有手动保存真实提交才移动；不随编辑、自动／退出保护或打开最新移动 |
| 保存标记标签 | 该文件曾成功手动保存过的节点 | 曾手动保存集合保留，之后继续编辑／保存不抹除旧记录；保护事实独立记录 |
| 分支标签 | 直接子节点数≥2 | 第二条出边成功创建后自动成立，按拓扑推导，不数全部后代 |
| 当前节点标签 | 当前编辑会话／视图的活动head | 每个活动头一个，undo／redo／checkout后移动 |
| 末端节点标签 | 没有直接子节点的叶节点 | 每条实际分支的叶端；给叶节点添加子节点后自动取消 |
| 起始节点标签 | 历史树的根节点，即所有操作之前的起点 | 每棵持久历史树一个，重开不另建根，不随排序、分叉或当前头移动 |

标签可以叠加，但遵守拓扑约束：末端不会同时是分支节点。空白新项目只有一个节点时，它同时是起始、末端和当前节点；没有实际保存成功前不带保存类标签。

“曾保存集合”在事实层也包含当前手动保存节点。默认展示可在该节点使用保存标签，在其余曾手动保存节点使用保存标记，避免重复图标；这不删除历史保存事实。一个分支／起始节点也可以同时被保存或成为当前节点。自动／退出保护事实不冒充曾手动保存，其具体显示另议；Git Commit与这些项目文件保存标签无关。

## 保存回执与范围

P3保存用例必须先捕获确定的历史身份、当前节点、整棵树／全部分支、导航元数据、文件绑定及全部可达资源租约，再在事务外执行增量写入；原子提交真实成功后才更新application拥有的相应保存元数据。期间用户继续编辑到B、手动捕获的A截面最终成功保存时，保存标签落在A，当前标签仍在B，后加节点不冒充已写入，不能以收到回执时的head代替A，也不能仅因head变化就否认已发生的成功写入。

保存失败、尚未完成，或在文件提交前成功取消时，不移动标签、不增加曾保存集合；文件已经真实提交后，后来的取消不能撤销这个事实。相同文件绑定的写入须有界串行并关联操作序号，让回执与实际提交一致；迟到手动保存成功回执可补齐曾手动保存事实，但不能覆盖更新的手动保存指针，更不能误标其他文件或新会话。自动／退出保护回执只更新其保护事实。另存为切换文件绑定时，不拿旧指针冒充新目标。具体端口／schema在P3实现并验证，不提前开放“UI／AI直接标记保存成功”的接口。

打开已验证的文件时恢复完整树、手动／保护检查点及各自经过校验的头／Redo偏好，始终建立新的运行会话／epoch。普通打开激活最近手动保存检查点；用户显式选择时才激活最新保护位置。文件中提交事实随待提交代次一起写入，真实提交后才成立；重开不复活旧请求／草稿／声音。保存指针和曾保存集合按文件绑定／谱系区分，另存为不混淆旧目标；标签不按节点复制文件或完整祖先地址。具体持久ID和绑定结构待数据契约审阅后实现。

完整历史保存后，`head == saved_node`不足以表示全部数据已保存：建出B分支再撤回已保存A，B仍需落盘。application须分别跟踪内容及历史／持久元数据差异，关闭／另存／恢复流程不能据相同head丢掉新分支；预览和工作区变化仍不进入内容历史。

历史自动保存、手动保存和退出保护共用增量事务，新增节点所需的状态／新素材一并落盘，不只保存拓扑。“不保存”退出不前移传统手动保存位置，但关闭前补存最后已完成的编辑；补存失败先保留工程打开／协调恢复。普通打开A且无新编辑／导航，不覆盖原最新保护C；从任一位置继续编辑都保留其他分支。周期／触发见[待审推荐](AUTOSAVE_POLICY.md)，具体界面未定，已确认规则见[关闭／重开约定](DATA_COMPATIBILITY.md#42-不保存退出默认重开与主动恢复)。

## 普通 undo／redo

用户无需管理分支时，普通Undo沿真实直接父节点返回；再次Redo须到达刚才Undo前的那条直接子分支，不能按创建顺序、最新分支、UI排序或文件名猜测。连续多次Undo后连续Redo，在每个分叉处恢复同一条撤销路径。

API v6的具体规则：

- 成功Undo进入有多个直接子节点的父节点时，记住`父NodeId → 刚撤销的子NodeId`。单子节点无需额外记忆。每个已记忆分叉最多一个固定大小条目，计数通过history_statistics公开，不存整条路径。
- Redo未指定child时优先使用该分叉记忆；单后继直接进入，叶节点保持NoChange。没有撤销记忆的多后继节点仍返回结构化AmbiguousRedo，不能选错分支。
- 显式Redo指定child时仍要求真实直接子节点。成功检出其他节点表示用户进入新的导航上下文，清除普通撤销路径记忆；同头检出NoChange不清除。检出后再执行Undo会重新记录该次真实路径。
- 冲突、Busy、失败恢复、无效操作及缓存回执重放不改变路线记忆或项目内容。恢复和资源校验全部成功后才一起发布head／修订与导航元数据。新编辑继续追加新分支，旧后代不删除。

这不是新的项目内容，也不新增历史节点，不将路线记忆塞进不可变历史补丁。当前v6地址仍为会话内稳定NodeId及原有有界短坐标，六类标签和显示名称不改变地址；首版持久路线将导航偏好作为独立可校验元数据保存，不靠复用运行会话恢复。

v5曾在多后继时无条件拒绝隐式Redo；此次语义扩展及统计字段将API_VERSION提升至6，旧请求明确拒绝，客户端须查询版本并适配，不静默解释v5请求。项目领域模型版本和未来磁盘格式未因此变更；旧阶段证据保留原版本事实。

## 折叠只影响显示

后期UI可保留六类关键节点，把无标签的线性区间折叠成带数量的连接段，并以有界分页／按需展开应对大量节点。分支、起始和末端保持关系可辨认；当前节点落入折叠区间时应可定位并显露。

折叠、筛选、排序不是历史裁剪，也不改变撤销粒度：一次Undo仍经过一个真实操作节点，不能直接跳到上一个可见标签。被折叠的节点仍能按内部ID／短地址被UI和AI查询或检出，原始资源仍受历史引用保护。未来多视图各自拥有当前头，不能将一个全局current标签用于所有视图。

禁止删除历史不是禁止用户删除当前图层／素材：后者仍通过正常Command追加新节点，旧状态可恢复。更新合法标签、保存／导航指针或重建索引不改写节点；任何节省空间的措施都不能让被隐藏或旧分支中的节点变成不可达数据。
