## 已实现接口

| 接口／类型 | 行为 |
| --- | --- |
| [request_freeze](../crates/gameplay/src/run/control.rs) | 先校验完整来源及F不早于开始／已提交位置／完整截面，随后立即进入Freezing并关闭新游戏输入；使普通推进令牌过期，不分配请求ID、事件槽或新InputEpoch |
| settle_freeze | 调用者以正工作预算结算F；未封口到F时BeyondSeal且不做工作。只在F的全部前缀和投影完成后返回Frozen，预算不足或事件背压仍Pending／Freezing |
| resume | 仅Frozen可恢复，返回新的InputEpoch；RunId、TransportEpoch、事件序号、判定、MapTime及封口水位保留。更新当前完整帧的来源元数据，旧按值快照不变 |
| ReleaseObservation／observe_release | 当前输入来源的无时间释放事实，用于重新武装；不入游戏队列、不推进时间、不清除已消费按住态，序号与游戏输入共用接纳栅栏及有界重试窗口 |
| RearmReport | 新事实返回Observed及是否新武装；原样重试返回Repeated，不能因重试再改变槽状态 |
| sound_intent_allowed | 只查询仍保留的合成声音意图是否允许后续交接；Freezing／Frozen／Failed均否。恢复设置已发行事件的取消水位，旧声音意图不因恢复再次有效 |
| [Observation](../crates/gameplay/src/run.rs) | 区分Freezing／Frozen与普通Pending；增加每槽armed、封口水位、最近FreezeInfo及声音取消水位。FreezeInfo记录来源、F及本次实际取消的已接纳未来输入数量，不是完整测试成绩 |

普通`advance`在关闭状态拒绝，冻结期间读取不推动模拟。`settle_freeze`是对当前冻结操作的显式分步执行，不使用普通AdvanceCursor；不同操作不能互用令牌。同一来源重复请求相同F不重置进度，不同F拒绝；恢复后旧输入来源、释放、普通继续／取消和旧冻结调用均不能影响新来源。

## 前缀、背压与完成边界

关闭入口可以先于SealThrough(F)，以表达“冻结先于新按下”的控制顺序；此时只有Freezing，没有Frozen承诺。最终Frozen必须受有效封口保护。无效F不关闭入口，结算调用的无效预算／旧来源也不提交工作。

已经接纳且MapTime≤F的输入资格由运行器私有记录保留。关闭入口不把这些记录当新请求重新接纳，也不因门控而丢失它们。普通推进的未提交搜索／投影若在F之后则丢弃，已提交前缀不回滚；F之内的计算和同刻下一位置继续保留。

进入Freezing后，每工作单位先从时间有序输入尾部取消一条F之后的旧输入，明确累计数量；不会因为“F已经有完整帧”就跳过仍排队的未来输入。之后通过与普通推进共用的有界pump结算≤F的前缀。Hit仍先预留全部两个事件槽／序号，缺一个槽就保持真实背压，不先消耗边沿、不写半份判定或伪报Frozen。语义事件不被自动删除／确认；受控消费者可在关闭期间按连续前缀确认，退休不表示音频已经播放或释放。

Frozen后逻辑按住态清零，未来已取消输入不会恢复执行。`resume`不接受新的时间参数，不快进、不重建对象、不补墙钟时间；宿主重新锚定及真实捕获完整性仍须后续接线验证。先前封口若已超过F，恢复也保留它，不能借换InputEpoch倒插该水位以内的输入。

关闭／取消不要求还可分配新代次或普通请求身份。若结算所需工作计数耗尽则明确Failed，无新的完整帧；已经完成F时仍可关闭为Frozen。恢复前核对代次及后续推进计数是否可用，耗尽时拒绝并保持Frozen，不回绕或擅自重新开放。

## 重新武装与身份规则

初始运行的四个槽已知释放，初始armed为真。冻结立即撤销接纳权限，恢复时物理状态一律视为未知，四槽均未武装；当前来源的可信释放事实／释放边沿才能分别重新武装。旧InputEpoch的释放不能解除隔离，一个槽的释放也不能武装另一个槽。这里验证的是合成输入事实及来源协议，不证明实际硬件状态。

新的游戏按下命中未武装槽时返回非故障的RearmRequired。普通带时间释放仍遵守C1，只能在有效封口之后进入队列；整批按入口序号模拟armed变化，只有全部校验成功才一起提交，未来释放的接纳不提前清除较早输入的消费按住态。物理槽的逻辑聚合继续沿用SyntheticTest-v1。

`observe_release`是单独的无时间捕获事实，不是向已关闭的游戏前缀倒插Release。它消耗当前InputEpoch中的新输入序号并保存完整种类／载荷；例如被拒绝的按下seq1，不能在释放事实seq2之后重新执行。窗口内相同序号但不同槽、或游戏输入与释放事实互换种类，仍为InputConflict并进入既有故障清理。重试不刷新窗口，也不重复占游戏队列；已接纳后被取消的旧输入，其原样重试只陈述接纳事实，不重新排队。

释放事实在槽已经武装时不清除游戏按住态；真正的游戏释放仍须按时间消费。失败运行不通过resume恢复准确连续测试，须显式建立新运行；本轮没有增加故障恢复、失焦或驱动切换的宿主入口。

## 事件与资源范围

InputEpoch变化不改变玩法事件键的RunId／TransportEpoch／EventSequence，已有判定／声音语义记录仍可稳定读取及确认。Freezing起关闭声音意图交接，恢复把该次结算前已发行的全部事件纳入取消水位；新运行前缀不因旧记录仍留在队列而补播。声音门控只是纯合成资格查询，没有设备触发、Voice取消、排程或C3原生回执保证。

新增状态仍为固定大小值及内联数组：armed四槽、最近一次FreezeInfo、声音水位、带种类的有界输入回执。无堆分配、新线程、项目写权限或第三方依赖；现有`static_storage_bytes()`随运行布局变化重新核对，Tiny的64KiB断言通过。该数字不包含全部调用栈、进程工作集或设备预算，不能宣称性能／内存验收通过。旧运行／候选共享池和10000对象Reference-v1仍未实现。
