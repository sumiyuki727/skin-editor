## 范围与实际所有权

新增SyntheticCoordinator，独占一个活动ManagedRun及一个**有效候选身份**。创建、纯预编译载入验证、同谱面检查均从此入口申请；保留的已取消／已失败任务可以有多个，但没有激活资格，而且仍受同一组有限预算约束。任务由调用者同步分步执行，没有线程、异步执行器或通用任务引擎。

协调器的current()只返回只读SyntheticRun。输入、封口、推进／继续／取消推进、事件确认、冻结／恢复通过具名方法委托已有运行实现，不能经可变运行引用绕过候选隔离；编译拒绝回归覆盖该边界。原有独立SyntheticRun／MapPreparation仍可用于独立模型及fixture，不是协调器受管活动运行的写入口，也不算在某个协调器的池内。

| 操作 | 前置条件 | 准备完成与激活结果 |
| --- | --- | --- |
| request_create(source, circles, S) | 尚无活动运行、候选位空闲；原始条目不超过4 | 分步MapPreparation校验后初始化运行；显式激活为Prepared，没有完成截面、Ready帧或输入封口。S处输入仍可在首次封口前接纳 |
| request_load(base, source, circles, S) | 完整base匹配，旧运行Frozen或Failed，候选位空闲；新的RunId不同于当前RunId | 同样完整校验／初始化后显式激活新Prepared运行；准备、失败及取消期间保留旧来源／帧／账本／事件。它不读取任何文件 |
| request_inspection(base, Q) | 完整base匹配且为Frozen，候选位空闲，输入／传输代次可检查递增 | 共享当前不可变预编译来源，在私有候选中有界重建；显式激活才共同发布新来源、关闭Q截面、Frozen帧与Inspection统计来源 |

协调载入延续SyntheticTest新运行的“初始槽释放”约定，不代表原生捕获已确认物理键状态。原生载入／捕获门控仍须K3另验。检查恢复继续沿用现有逐槽重新武装，Q及更早输入不能倒插；检查跳过判定Unavailable，不补Miss／声音，也不伪造累计score／ACC。

## 身份、继续与取消契约

- CoordinatorId为调用者注入的独立非零128位身份，在其管理的在途任务生命周期内不复用，不借用RunId或项目／节点ID。已发布RunId同样须由调用者保持在途生命周期内唯一；当前载入入口额外拒绝直接复用当前RunId，不提供无界的已用ID日志。
- PreparationKey含协调器身份、非回绕的独立u64请求代次、完整基准RunSource及状态、操作类别／目标时间和拟激活RunSource。检查即使面向相同的下一TransportEpoch，也由完整键隔离；输入代次变化、改目标、改操作类别、旧结果均不能成为新候选。
- PreparationTask不提供Clone，其继续值PreparationCursor与MapPreparation、AdvanceCursor及InspectionCursor是不同类型。step先核对当前资格及准确进度，再核对准备工作预算；旧游标、超预算调用不推进有效工作或清理新候选。
- activate(key, &mut task)同时核对当前有效键、完整基准、操作／目标、任务键、实际所属池及Ready。未完成／外国任务拒绝时保留当前运行及有效候选；成功后任务保留的工作区仍计费至其Drop。stage只描述保留工作的进度，不单独证明其仍有激活资格。
- cancel(key)只撤销资格，不清空任务持有的资源；不分配新请求／代次、不等待完整数组处理，也不要求输入／事件空槽。Drop仍有效的任务会撤销自身资格；过期任务的Drop不会取消新候选。
- 活动来源或状态改变会使不匹配基准的候选失效。准备期间恢复返回Busy；事件确认可正常进行。旧基准发生故障会使原Frozen基准的检查失效；可另行显式载入新的运行恢复，不复制故障账本。

协调器关闭立即撤销全部候选资格；仍持有的任务保留池及资源所有权，旧工作不能继续或被其他协调器接纳。没有将任务“已取消”的观察值当作释放回执。

## 工作量与存储预留

创建／载入直接复用MapPreparation的逐记录／逐ID比较预算，预算1不会隐藏一次全图校验。检查在私有新运行先评估最早可见截面（无输入／到期判定），再复用K1-3分步检查／内部激活；最后的协调激活才替换当前运行。私有中间帧及准备来源均不对外发布。

准备的WorkBudget独立于运行推进；PreparationLimits::tiny()为工作上限1及两个64KiB池，reference()为256及两个8MiB池。仍只接受4对象，Reference名称仅表示本次工作量／容量参数，不是10000对象实现。初始化／固定数组清理、固定大小值移动和发布是明确的有界管理步骤；未把该四对象实现推广为可扩展的Reference准备器。

| costs()／resources() | 计量内容／生命周期 |
| --- | --- |
| pool_bytes | 私有池状态的已知payload，随最后一个池所有者保留 |
| coordinator_bytes | 协调器已知管理值；关闭释放时归还该保留额 |
| task_bytes | 任务固定管理存储加一个已知SyntheticRun初始化临时值；按最大需要预留，取消、失败或已激活但仍被保留的任务均不提前归还 |
| run_bytes | SyntheticRun固定存储及已知运行草稿／检查移动空间；在准备前预留，随实际运行所有者迁移／释放 |
| source_bytes | 完整固定容量的CompiledSource payload及已知租约记录；共享Rc来源只计一次，不按当前len冒充容量 |

新任务同时核对两池的全部预留后，才改变额度、创建准备值或发布请求代次；加法溢出也拒绝，不留下半份预留。配置必须至少容纳协调器／池、一个完整任务和运行及一个来源；零／超出256的工作上限或差一个字节的最低容量均拒绝。

本次为协调器增加标准库Box、Rc和私有Cell：Box持有运行，Rc共享不可变来源和每协调器的私有额度状态，Cell只管理候选资格及额度，没有全局可变状态、项目引用、跨模块容器或新依赖。任务的借用输入最多4圆圈，生命周期保证校验期间可读；调用者原始slice不属于协调器托管分配。已知受管payload／管理值及初始化临时值按costs预留；Rc控制头、分配器开销、编译器其他临时副本、完整调用栈及进程工作集未计入，不能据此宣称全部原生内存预算通过。

规范化来源共享一个Rc；既有四对象SyntheticRun仍持有自己的固定Map值，该独立值已计入run_bytes。这是当前小模型的明确复制成本，不是10000对象的零复制方案。

任务先销毁所持运行／来源，再由不可复制的额度记录归还；最后一个共享来源所有者才释放来源额度。旧候选在途持有资源时，新任务可能明确拒绝预算不足；调用者须实际释放旧任务或诊断，不静默放大限额、驱逐有效运行或丢弃旧资源。少数多任务保留正例使用按公开costs计算的显式测试限额，未改Tiny的64KiB默认值。
