## 容量、存储和完整观察

完整Reference目标沿用K0-A：对象10000，输入／事件／去重／确认窗口各64，运行及准备工作量上限各256，两个池各8MiB。Tiny仍为4对象、输入4、事件2、窗口4／2、工作量1及两个64KiB池。对象上限与输入／事件容量是独立配置，不能因放大地图放大队列；自定义更小工作预算仍合法。限额及字节计算用检查算术，超量在扫描／分配前拒绝，不裁剪输入。

对象上限是显式正数，不能超过该增量已支持的硬上限；空地图仍合法，不能把“0对象”误作“对象上限为0”。K1-6A所有入口继续拒绝第5个对象；K1-6B才开放Reference的10000。直接MapPreparation／便捷构造、独立SyntheticRun、协调创建／载入和检查都须核对实际内容与所用配置：大来源不能借共享句柄装入Tiny运行，准备池较大也不能覆盖运行的对象限制。便捷构造只保留明确的至多4对象有界路径，大输入使用分步准备，不隐含同步循环至完成。独立fixture与协调池的配额作用域分别说明，不把外国池或未托管结果视作已在本池登记。

单运行storage_bytes是该运行的限制，PreparationLimits的运行池是所有活动／候选／保留任务的合计上限；前者包含在后者的核算内，不为每份运行另赠一池。先检查调用来源／操作、原始长度和配置，再做相应预算／分配／分步内容校验，保留既有错误优先级；拒绝原始超限时不扫描元素、不推进请求号或占候选位。输入／事件配置的既有最低迁移容量和Automatic至少2输入槽保持。

K1-6A可以采用固定4槽的受管来源及运行存储，以静态类型布局给出容量上界；先去掉来源重复持有和整份Copy观察，不强制在该步引入变长容器。保留的四槽空壳及固定输入／事件数组构造须列出已知初始化与临时值成本，不能将其报为零；这一步仍是有声明的四对象固定管理切片，不证明变长数组已逐项初始化。K1-6B放大前必须替换所有随N增长的初始化／复制，并另行提供固定工具链／目标的分配请求布局及容量证明。不能由方法名推断精确容量：[Rust的通用Vec文档](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.try_reserve_exact)明确不保证try_reserve_exact得到精确最小capacity；该API说明不是本机Rust1.95或其他平台的分配实测，也不能替代上界证明。无法证明时不采用该路径，不能分配后发现超额才补预留。

不可变来源保存一次规范化圆圈存储；当前运行、检查候选及其在途任务共享同一来源级租约。账本／检查跳过标记是各运行独立的O(N)状态；不得共享可变数组。不要为每个圆圈引入Rc、任务或独立资源租约。调用者借入的原始slice单列，不混算为内部所有权；生成式fixture的源数组也属于测试驱动成本。

按以下契约替代整份Copy投影，具体Rust名字在K1-6A实现审阅时冻结：

- 固定大小观察摘要包含完整RunSource、driver、状态、完成／已提交／请求／封口时间、统计来源及队列／计数，不携带N条账本或对象数组。
- 已完成帧采用借用只读视图；按索引查询一个对象，或按显式页长读取，单页最多64项。对象总数与活动／可见数分别表达，不把原来“全部对象”的len静默改成可见数。全量导出观察必须显式逐页，成本和调用者保留的结果另计。
- 帧视图固定在一个完整截面，绑定来源、完成时间及发布代次。借用期间不能修改运行；脱离借用的分页继续值须核对上述身份。新发布、检查激活或输入来源换代后拒绝旧继续值，不能跨帧拼页。
- Pending期间保留既有上一完整截面，对象／账本查询只能使用该截面已有事实；例如晚于该截面的新判定不得渗入旧帧。统计摘要也在同一完成边界发布。仅首次评估尚未完成等原有无帧状态返回无帧，不能因重构而丢弃已有完整帧，也不返回混合截面；实时状态仍明确标为Pending／Failed等。
- 同源同截面的重复摘要／单对象读取不推进玩法、不发事件、不分配或扫描全谱；生命周期可由不可变记录、该截面及有来源的判定／跳过信息求出，不要求存一份全谱帧副本。新的表示仍须覆盖Future、VisibleUnjudged、ResolvedVisual、Retired及InspectionSkipped。

单对象索引超出对象总数返回明确空结果；分页长度只允许1至64，零／超限或无效位置返回结构化调用错误。页结果分别给出数据、继续位置及是否到末尾，空图的成功末页不与过期来源／查询失败混淆。读取错误不改变运行或把新来源置为Failed。发布代次采用固定大小、检查递增且不回绕的身份；耗尽不得继续发布同一身份或将半完成截面冒充成功，停止／取消仍可执行。

### 完整截面与实时前缀的读取契约

现有Observation的committed_judgements可包含Pending中的已提交前缀，ready_frame则只代表上一完整截面。新接口须保留两种能力并明确区分，不能把它们合为一份带Ready标志的账本。

| 读取种类 | 约束及结果 |
| --- | --- |
| 实时摘要／单项已提交判定 | 固定大小摘要可报告Pending、最后已提交位置及实时队列；单项账本读取至多返回该对象当前已原子提交的判定，允许早于整帧完成被观察。它明确是实时前缀，不提供完整帧时间／累计完整成绩的保证 |
| 完整帧头 | 同时固定RunSource、Evidence／profile、完成时间T、从1开始且不回绕的u64发布号、统计来源和T处计数；准备完成但未首次评估时无帧。摘要中实时计数与T处计数分别命名，不能混用 |
| 完整帧对象／账本 | 只使用T处事实。若从实时单次判定记录派生，必须核对判定时刻≤T，按T计算可见／退休，并使用该运行固定的检查跳过标记；不得读取当前活动头来替代T的生命周期。单次判定不覆写、已提交时间单调及封口不可重开共同支持该表示，后续语义改变须重新审阅 |
| 有界页 | 游标包含完整帧键及下一原记录索引，按地图记录顺序读取，不把ObjectId当数组下标。页长1至64，起始索引等于N返回成功末页，超过N拒绝；下一位置和输出计数均检查算术。同一有效游标可重复读取，直到帧键改变 |

成功返回的借用视图只持有只读借用，不允许修改／销毁其运行，也不默认生成可跨tick持有的拥有式全帧快照。分页使用调用者提供的有界输出空间；先核对来源、帧键及页参数，计算count=min(页长,N-起始索引)，再要求输出空间至少容纳count项，所有算术均检查。出错时不改输出或运行，成功只写实际返回前缀并附数量／末页标志，不扫描或清空其余大缓冲。末页count为0时可用空输出空间，页长为0仍拒绝。调用者页缓冲不属于协调池所有权，其容量仍须在测试／工具及后续宿主的成本中单列。

分页请求先拒绝旧RunSource，再核对发布号／时间，最后校验范围／容量；缺少完成帧是明确的成功空状态，不能将旧来源也返回为空。确认事件、重复读、取消推进及仅改变实时Pending状态不会无故更换已有完整帧键；同源重复完成同一无变化T不消耗发布号。新完成截面更新发布号；驱动切换／恢复使完整来源换代，即使T不变也拒绝旧页，来源与帧头共同更新。检查／载入的旧页同样不能跨运行生效。

上述隔离沿用K0-A的组装者身份契约：只要旧输入、事件、任务或脱离借用的帧键／游标仍可能到达，就不复用其RunId。相同RunSource的违规重建不能由本地发布号区分；内核不维护无界的历史身份注册表，也不以MapRevision相等认定来源共享。

发布号只在已算清完整截面后提交，不在查询中递增；耗尽时保留真实已提交前缀、关闭输入并明确失败，不回滚玩法、不复用旧号或假报Frozen／Ready。旧完整帧可作为带当前Pending／Failed上下文的旧截面读取，不能把旧帧内容解释为运行已健康恢复。关闭、取消及最终资源释放不依赖仍可分配发布号。

容量适配与只读视图共用一个玩法实现；不另建“快版”引擎绕开旧边界测试。原有小模型测试可调整读取表达式，但不改变时间、错误、账本、事件及来源的黄金预期来迁就新表示。借用只读及无可变活动运行的编译拒绝回归继续保留。

## 分步工作和取消

创建／载入输入仍按目标有序，拒绝不支持的接受窗口重叠。ObjectId允许任意唯一u32，不能以要求递增、重新编号或哈希碰撞相等来省略查重。拟采用带原记录位置的ID键工作区和自底向上的分步归并：逐记录校验／复制，逐次比较或搬移索引项，再检查相邻ID；只排ID索引，不重排圆圈或改变引用。两份索引工作区均计入运行池，目标总工作为O(N log N)，不调用一次不可取消的全量sort。

查重方式改变不应改变多错输入的既有分类：取原输入中最早无效记录，该记录内按DuplicateObject、UnsortedMap、UnsupportedOverlap的既有优先级选择。可分别记录最早ID重复位置与顺序／重叠错误位置后合并；未完成必要校验之前不能发布成功。空图、0号ID、稀疏／逆序ID、非相邻重复、首末错误及相同数字不同来源分别覆盖。

ID键按(ObjectId,原记录位置)确定总顺序，重复组中最早的第二次出现位置才是该组的错误位置；不能只按排序后的相邻位置报错。例：ID为[0,1,0]、目标为[0,1000000,500000]时，原记录索引2（第三条）同时重复／乱序，选DuplicateObject；ID为[0,1,1]、目标为[1000000,0,2000000]时，先报原记录索引1（第二条）UnsortedMap，不能让后面的重复覆盖它。查重工作区在实际释放后退还，不为本切片新增无用途的长期ID查询索引。

每个准备步骤只处理一个记录、一个有界索引比较／搬移，或一个已准备的固定大小管理迁移；需要的中间键保留到下一步。数组初始化按项计费，不在一次new、Rc／Box包装、activate、Clone或错误格式化中展开N项。运行的时间头、已过对象前沿和自动输入位置保持单调；搜索／跳过仍计费。发布完成截面仅提交已算清的摘要／视图身份，不另扫N条。

### 工作计数与无进展边界

steps不能作为没有隐藏循环的唯一证据。实施须同时给出以下原始计数，测试诊断采用每运行／每任务局部的固定存储，不依赖全局可变计数器、系统时钟或日志：

| 工作类别 | 单位／上界 |
| --- | --- |
| 准备记录读取／复制和运行状态初始化 | 逐项计数；一次相应步骤至多一项，各阶段总项数有明确的常数倍N上界 |
| ID键比较及索引搬移 | 分别计数，一次相应步骤至多一对固定大小键比较或一项搬移；原始位置参与的标量比较不包装全段归并 |
| 运行搜索／检查／自动跳过 | 每次检查一个对象并计费；固定个数时间头选择、至多64项输入／确认管理以及两输入原子接纳的固定成本另列，不扩展为随N增长的循环 |
| 摘要／帧读取 | 摘要无全谱记录遍历；单项读取只取该对象所需的固定记录，页读取不超过实际页长。不在每个发布时刻重建N项投影 |
| 固定管理／分配尝试 | 单列次数及请求字节，不伪造为0对象成本；管理步骤、阶段结束及空输入完成同样消耗声明的有限步骤 |

按上述自底向上归并方案，令L=ceil(log2(max(N,1)))；包含最终重复检查的键比较总数不超过N×(L+1)，索引项搬移不超过2N×(L+1)，初始化／记录处理另按各自声明的线性阶段计数。这是拟采用算法的回归判据，不是本轮实测或CPU判据；替代算法须先写明同等可审阅上界。分配、包装、转为共享存储、错误诊断及释放均审查隐藏复制，不用一次全量收集／转换绕过计数。

旧游标先拒绝且不推进计数；无外部阻塞时，合法step必须完成或消耗步骤并推进固定进度／阶段，不能零步Pending。真实事件／输入背压可以无玩法迁移，但必须给出阻塞原因及可解除条件。Budget=1仍能逐步经过空图、归并轮次结束、初始化和最终发布，不靠一次无预算while扫完多个N项阶段。步数／索引／实际额度溢出走结构化失败及可取消路径；诊断计数若无法有效记录须使计量失效，不能回绕制造低成本。

表示改变可以改变准备／发布所需的步骤数，须记录计量口径差异。跨实现按相同逻辑截面、已接纳集合及控制顺序比较业务结果，不强求“第k次Pending”相同；也不能修改既有来源、时间、错误、账本或事件黄金预期来迁就表示变化。

存储分配作为单列管理操作，先预留完整请求容量及已知存储，不能把分配、清零和填充N项统称一个对象工作单位。安全容器须有可核对的分配请求布局和容量上界；若所选策略无法在分配前界定持有容量，先更换策略，不先分配再补额度。实际容器capacity和已知临时存储不得超过预留；分配器内部开销另列。分配器调用／释放本身没有硬实时保证，外部成本测量须包括，WorkBudget不冒充毫秒上界。保持核心forbid(unsafe_code)及零第三方依赖。

创建／载入全部验证和初始化完成后才有Prepared候选，首次S评估前无Ready；检查仍从Frozen开始，在私有候选中重建Q，完成后显式激活才发布ReadyFrozen／关闭Q／Inspection来源。检查可O(N)但逐项继续，不重放旧输入或补Miss／声音，不借清空旧运行省预算。

cancel及协调器关闭立即撤销资格，不等待剩余对象、不要求普通输入／事件／请求空槽、不申请新代次。保留的任务仍可持有存储并占用池；旧step／activate／Drop不能影响新候选。取消推进保留已提交前缀和准确内部位置，冻结仍有界收尾；恢复不倒退SealThrough，不补发被取消的旧输入，四槽重新武装及Failed门控不变。取消调用与最后所有者Drop分别记录成本，不把“取消成功”当成释放已完成。

## 资源计费与失败原子性

| 资源 | 所属池／计量依据 | 释放条件 |
| --- | --- | --- |
| 规范化圆圈等最终只读来源，查重临时索引不保留 | 预编译池，完整分配请求容量及可计量管理值；同一共享分配只计一次 | 最后一个真实来源所有者释放 |
| 运行状态、账本、检查标记、固定输入／事件／窗口 | 运行池，实际持有容量，不能按当前len或当前可见数折算 | 运行及其真实所有者释放 |
| 校验ID索引、初始化临时值、候选工作区 | 运行池，含同时存在的双缓冲／新旧分配及已知临时峰值 | 对应缓冲实际销毁后归还；仅撤销资格不退额 |
| 协调器、继续位置及核心持有的页管理记录 | 运行池，固定管理值及有界容量；描述符内联字节与其堆存储分别核算，调用者页输出空间另列，不漏计／双计 | 按各自真实生命周期 |

成本估计须接收对象数和相应容量，返回检查算术后的有限值；旧static_storage_bytes／固定costs不能代表万对象完整成本。申请前原子核对两个池及在途旧任务，任一不足不占候选位、不推进请求号、不留下半份预留。复用来源不能再收一份内容费，独立运行账本也不能因此免计。

### 分配清单与可核对的三类记录

在选定容器后，为每类缓冲列出元素类型／size与alignment、容量上界、检查乘加后的请求字节、所属池、分配阶段、同时存活的旧／新缓冲、租约所有者和实际释放点。固定描述符已计入其所属结构时不重复收取；堆载荷和可量化的独立管理分配分别列出。最终来源与临时查重工作区的池归属事先确定，不能仅将字段改名就释放原池额度或漏计保留的索引。

记录中分别保留准入预留、实际已请求／暴露的容量、存活所有者；后两者是前者已覆盖部分，不能将预留与实际容量相加当内存。尚未分配的计划容量仍可占预留，已经cancel的真实缓冲仍占容量。每个池按独立真实预留所有者求和，内容按实际共享分配身份去重；MapRevision是调用者令牌，不能仅因令牌／内容相等就合并两次独立分配，也不能给共享句柄每克隆一次收一份内容费。

任何增长／重分配须先覆盖新旧同时存活的峰值，再申请新块；失败保留旧块，不采用增长后再补收、按len折算或清空记录先退额。可恢复的分配失败、内容校验失败和取消分别标注阶段、池、请求／已用／上限；诊断保留固定大小摘要与原记录位置，不隐式格式化整个来源／运行数组。实际销毁先于相应额度释放，保留的失败任务／Ready任务／已激活任务工作区也遵守同一规则。

清理验证须观察真实缓冲及最后共享所有者的销毁，并与预留账本交叉核对。观察器本身持有的租约／缓冲须单列并按约定释放，不能既用它延长寿命又要求该分配已经归零；关闭后的基线按仍存活的真实所有者解释。分配器内部保留、不可见开销和OS工作集另列，纯核心计费不能替代进程内存。未取得确定布局／容量证明的项保持未准入，不以Unknown从受管预算中免除已知载荷。

8MiB／64KiB不因实现放大而自动上调；默认Reference不能完成声明负载时，保留失败并审阅存储／算法。测试恰好够／少1字节、两池加法及乘法溢出、共享来源最后释放、旧任务延迟Drop，以及保留当前运行时申请新候选的真实峰值。多任务额外容量只能作为单列计费边界用例，不能替代默认Reference轨迹。

所有可恢复的预留／分配／准备错误均返回结构化诊断，当前活动运行、旧完整帧、账本和事件不变；私有候选已持有的存储在实际清理前继续计费。用受控失败点验证每个受管分配边界，不用真实耗尽机器内存测试，也不宣称能够从任意进程级OOM中恢复。已知缓冲生命周期用真实所有者／Drop观察交叉核对，不只验证记账计数器；Rc控制头、分配器内部、编译器临时副本及完整调用栈未量化的部分单列Unknown。

| G1：KT23固定输入黄金脚本 | 新建默认Manual且初始槽释放，由外部回归夹具交接固定脚本；逻辑A第一个槽在T_i按下、T_i+1释放，序号2i+1／2i+2 | 10000次Hit；E(2i+1)=Judgement(i,Hit)，E(2i+2)=SoundIntent(i)，两者时刻T_i；无Miss，末态全退休 |
| A1：实际Automatic驱动 | 独立运行在S完成冻结、选择Automatic并恢复；先由现有生成器记录本来源释放事实，再按相同有限批次准备／封口／推进 | 与G1相同的对象／时刻／结果／事件种类及事件序号；本来源释放事实占输入序号1，脉冲序号为2i+2／2i+3；不能把它改写为G1的原始输入序号 |

G1是K0-A既有“有限批次自动输入”的确定脚本，使用已有Manual提交路径来原样保留黄金输入；它不证明InputDriver::Automatic实现。A1才验证真实自动准备入口，继承K1-5的重新武装及1µs释放前瞻。不同独立运行的RunId、InputEpoch或控制事实不能直接要求全载荷相等；各自完整核对来源，再比较上述明确相同的语义字段。Regression互斥及四槽外部重新武装继续由现有回归覆盖，不冒用Automatic外部提交接口。

G1／A1每批最多32对象、64条按下／释放；最后不足32的批次照实计数。先完成该批交接，再封口至末项释放时刻，推进并显式消费／确认，再交下一批；最终推进至共同终点。不得一次创建20000条输入、保留全曲待消费事件或用无界测试结果列表隐藏容量。受控消费者只按期望游标逐事件核对，至多保留64项，SoundIntent不触发设备。输入去重及确认窗口始终不超过64，Hit所需两事件仍原子预留。

WorkBudget Pending继续同一准确游标；事件背压由明确读取／确认解除，不反复空转；自动准备背压只封口其真实ready_through前缀，不跳到请求目标。没有外部阻塞时，每次Pending须能说明已做工作或下一可用步骤；重复取帧／读事件不生成新迁移。两档工作量比较各自同轨迹的最终账本、事件及完整截面，不将G0与G1成绩比较为相同。
