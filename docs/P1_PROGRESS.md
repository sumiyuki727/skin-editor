# P1 工程与验收记录

2026-10-21。P1-0／1／2 已完成 Windows 范围的工程、模型与事务检查；P1-3 的完整历史控制及 P1-4 草稿尚未实现。本文记录当前事实，阶段计划见 [P1_PLAN.md](P1_PLAN.md)。

## 已交付

- 独立 Rust 1.95.0／2024 edition workspace，仅 domain／application 两个 library 包，application→domain。根锁文件没有第三方依赖，P0 实验不进入产品工作区。
- domain 的非零类型化 ID、SkinProject、不可变 Asset／BlobRef、ElementDocument、嵌套 LayerTree／ComponentTree、显式成员映射、仿射／透明度／几何边界、无损配置记录及输出映射。整体构造校验引用、单父无环、成员唯一、数值有效性和输出冲突。
- application 拥有项目，提供 v2 的身份／状态查询、自有快照及统一 submit(CommandRequest)。资源、文档、图层／组、组件、配置和输出经原子 Command 修改，预校验不获得写权限，不提供可变项目引用或任意整体替换。
- 期望节点＋修订冲突、会话隔离及请求回执去重；成功、NoChange、命令／资源失败的已登记请求均返回原结果，差异载荷拒绝。每次有效事务同步发布一个非零 u64 历史节点及可逆元数据补丁，开放只读旧节点恢复；撤销、检出、分支与短地址仍待 P1-3。
- ResourceStore／BlobLease 端口固定已暂存且经适配器校验的原始资源；候选资源获取失败释放临时租约，同内容共享固定，历史引用保留到会话结束。只有内存存储测试，尚无正式文件适配器或实际摘要核对实现。
- 默认单一无窗口入口：`python tools/check_core.py`；可显式指定现有工具链目录。离线依赖、源码、格式、Clippy、测试及 release 库构建在同一入口完成，不自动安装工具或修改全局设置。
- 仓库安全扫描、实际暂存字节检查和本地提交 hook；按用户授权在通过检查的完整增量后创建本地 Commit，不自动推送。
- Windows／Linux CI 配置，固定 checkout 提交、只读权限、不保留凭据；尚未远程运行，不将配置存在计为 CI 或 Linux 通过。

## Windows 验证

| 检查 | 结果与边界 |
| --- | --- |
| 工具测试 | 21 项：9 项仓库、9 项架构、3 项工具链失败路线；无窗口、设备或网络 |
| 核心行为 | 63 项 Rust 行为测试：11 单元＋30 模型集成＋22 命令集成；包含原模型用例，以及成功、首步／后段失败、零净变化、冲突、去重／载荷冲突、资源失败／临时租约释放、旧节点不变、补丁正反恢复、删除后身份不复用、计数器／容量边界 |
| 公开面 | 6 项编译拒绝：ProjectId 表示、活动项目存储、项目私有集合、只读树节点、不同身份类型及私有候选执行模块；另 1 项可运行文档示例只使用 application 构造并提交事务 |
| 依赖 canary | 独立临时 Cargo 工程实际加入禁止的 UI 包，元数据经同一检查器拒绝；不修改产品清单或锁 |
| 静态与构建 | 格式、Clippy 全目标／feature 且警告视为错误，debug 测试与 release 库构建通过 |
| 来源与隔离 | 当前核心无 UI／GPU／媒体／设备／旧源码依赖，原有 124 份 P0 测量文件保持原字节；新增工具不是旧实验的新成绩 |

本机系统默认 Rust 仍为 1.80.1，验证显式使用已有的独立 1.95.0 二进制目录，Cargo home／输出置于忽略目录。检查器只接受指定版本，缺少已注册工具链时直接失败，不尝试下载；该工具链目录不是产品源码依赖。Windows 链接工具通过已有 MSVC／SDK 发现，仅对子进程配置。

原始运行记录与计量身份写入本地 `artifacts/p1/`；此阶段没有 GUI、真实音频、性能预算或 stable 对照新成绩。245 项旧实验测试没有作为 P1 结果重用。

P1-1 使用标准库 BTreeMap／BTreeSet 和平坦树，关系与派生矩阵成本按节点线性占用，查询副本当前深拷贝元数据，不复制图片字节。10,000 层用例验证可构造／遍历／克隆／释放，不是吞吐／内存预算成绩；完整事务和历史规模成本留在 P1-4。成员内容变换可查询，但像素合成／输出未实现。配置记录按字节与字段范围保留内容，尚无 skin.ini 解析器；BlobRef 的实际字节摘要核对和文件系统导出校验仍待对应适配器。

P1-2 的[命令契约](COMMANDS.md)明确提交顺序、失败回执、预校验限制、资源固定和容量策略。补丁按改变的资源／文档保存，组件／配置／输出在该类别改变时保存前后值；全局准入身份、去重回执与租约均有会话寿命。默认数量限制不是完整内存预算，文档粒度补丁、请求大小及长历史成本仍需 P1-3／4 计量。首轮没有加入第三方依赖、运行时线程、网络、GUI 或媒体读取。

application API 从 1 升为 2：创建会话必须另外提供不复用的历史会话 ID，查询包含会话和活动修订；v1 请求明确拒绝。MODEL_VERSION 仍为 1，尚无项目文件迁移，源调用示例与测试已同步调整。

## 下一步与限制

下一步 P1-3 在现有追加历史上接入撤销／明确重做、检出、有界地址／查询及分支保留；P1-4 接入草稿、取消和规模基线。所有内容写入已同步记录历史，后续控制也不得原地改旧节点或绕过资源／修订规则。当前没有正式桌面编辑器。

新增的玩家资料、统一设置、自动打图、区域描述、外部默认皮肤、实际 stable／Songs 来源与必要媒体读取及全量可皮肤组件覆盖已写入[需求设计](PREVIEW_SETTINGS.md)，尚无这些设置／读取功能实现。本轮没有读取真实谱面或安装目录。Linux 实测仍延期，macOS 待设备；CI 未远程执行，打包、资源授权清单和低延迟游玩均未验收。
