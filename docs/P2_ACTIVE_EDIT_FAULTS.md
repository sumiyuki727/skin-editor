# C4 活动草稿／手势与故障交错

2026-10-29，接续[端点归还保护](P2_ENDPOINT_RETURN.md)。**活动画布拖动／视觉与音频草稿在三种受控故障顺序下通过；C4／P2未整体验收。** 构建、原始判据及日志哈希见[证明](P2_ACTIVE_EDIT_FAULTS_PROOF.json)。零欠载、提交p95≤20 ms、内存／GPU与资源释放仍为硬项，CPU≤15%为优化目标；不提交Git，不推进P3。

## 中断与所有权

此前恢复用窗口覆盖普通退出路径，未取消编辑器持有的草稿，旧手势可随UI一起进入新窗口。现在UI提供故障中断入口：暂停、取消其持有的草稿、清除画布／数值手势，再选取实际音频来源、冻结场景并停止试听。模型取消仍通过application的DraftAction；不是直接改SkinProject、恢复快照或补偿Command。

所有权核对使用会话及DraftId，不能仅凭编号。外部适配器创建的草稿保持原状，旧UI手势清除后也不能在鼠标松开时提交它。重复中断不重复取消或新增节点；数值控件的原按键释放前仍阻止草稿重启或退化为即时命令。

桌面逻辑先处理音频故障、选取取消后的图形来源，再允许GPU接纳准备结果；图形设备失效仍先分发设备状态。故障冻结在推进模拟时间之前生效。音频单独失败时GPU仍可用，须将取消后的实际草稿／基础来源设为期望值，不能只清UI选择而继续接纳旧图形结果。恢复窗口退出和初始化失败清理使用同一中断入口；取消失败保留原所有者并封锁退休。

保留原会话、全部已提交历史内容／关系／短地址／Redo记忆；取消不产生项目节点。Begin／Replace／Cancel本身是有效API请求，回执数量会增加，不能声称它们完全不变；对照仅将这一计数与项目／历史内容分开记录。背景恢复仍使用原生复制锚点，不补跑故障等待期间的时间或输入。

中间失败尝试用真实egui输入和真实GPU／音频资源，随后返回受控AppCreation错误；它尚未进入正常窗口事件循环，不是C5物理鼠标验收。图形为自有Device.destroy，音频为该端点的原生失效信号；均不冒充驱动TDR或实际设备拔插。场景保持冻结、显式试听独立；单个草稿试听的首复制观察另列，不能作为代表性p95。
