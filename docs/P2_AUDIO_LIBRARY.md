# P2-A2：素材独立试听与监听总音量

2026-10-22。接续[音效编辑界面](P2_AUDIO_UI.md)。音频素材现在可以直接试听，不必创建音效组件；监听总音量只影响设备输出，不进入项目、历史或导出配方。完整A2／A3及P3文件输出仍有未完成项。

## 操作与行为

1. 打开顶部“音效编辑”，导入支持的短WAV或添加自制示例，选中素材。
2. 显式启用音频设备，点击“试听原始素材”。界面显示该Asset、完整来源和Pending／Ready／Failed状态。这次显式请求会在准备成功后播放一次；普通组件的后台准备仍不会自动播放。
3. “停止试听”、下一次素材试听或组件试听替换当前素材试听意图。项目来源发生变化时，包括草稿开始／修改／取消、提交或历史导航，保守取消素材试听，不自动重播。只改变监听音量不会取消试听。
4. 场景冻结不阻止显式素材试听，试听不推进背景／场景时间；停止试听不改变场景门控。缺失素材或图片目标明确拒绝，Opaque仍保留原字节并显示Unsupported，不偷偷猜编码或创建组件。
5. 监听总音量范围0–1000，1000为原音量，0为静音；可在设备关闭时调整，重新启用沿用本次会话的值。目前不持久化。单个音效的增益与可见性仍通过Command／草稿编辑。

## 身份、资源与取消

application的AudioEditorPort升级为v2。AuditionAsset只携带AssetId；application解析实际草稿／项目中的Blob与可信元数据，再把只读AssetAudition值交给宿主，不能用调用方声明的路径或临时组件替代。Stop和监听音量不依赖项目同步成功，避免同步错误阻挡终止或静音。模型2、Command5、SkinAudioPort1、FrameDescriptor1及MixConversion1不变。

SoundPlan升级为v2，目标明确区分Component与Library；共享处理仍采用相同的增益、可见性和源PCM语义。项目投影只接收Component，另有**一个**临时Library候选，不登记进项目／导出映射。两个目标即使数字相同也不相等，不保留伪造的AudioComponentId。旧v1内存调用方需将component映射为Component目标；当前无冻结磁盘或AI传输格式，没有文件迁移。

素材与组件共用一个解码worker、一个活动／四个等待任务、32 MiB总PCM／单份4 MiB、16份控制／回执额度及32个Voice。临时素材候选不另建解码器、设备、PCM池或无界队列。相同源和配方可通过弱缓存共用PCM；来源／目标／请求代次仍单独校验。超限显示失败，不关闭有效场景声音。完成播放后最多保留一份当前素材的可复用准备结果；停止、来源切换或关闭释放它，弱缓存不固定样本。

素材试听有一次性意图。停止、目标替换和来源切换先使尚未输出的原生试听副本失效，再由供给所有者取消任务／候选／Voice；迟到结果不能重新启动。取消活动解码或已完成未交接结果，仍需等实际释放后退还配额。回调不访问项目、codec或PCM所有权，清理由控制所有者完成。素材与组件共用显式试听通道，因此切换试听目标会清理该通道；背景及场景通道保持独立。

监听音量以原子值在回调的所有有效通道相加后、饱和之前应用，已排队Copy帧也使用新音量；不重做解码、不复制PCM、不改背景位置。按回调块采样控制值，不能撤回已经交给系统／设备的残余，尚未验证听感残余或声学静音时刻。

## 检查与未完成范围

新增9项确定性测试覆盖无组件的实际WAV试听、完整来源解析、图片拒绝、只读历史、停止／草稿／撤销时旧原生副本清理、迟到解码结果拒绝、共享缓存、任务与Voice超限、取消后实际释放，以及已排队声音的总音量和静音恢复。重复素材试听及不同Asset引用同一原字节均复用当前PCM，无第二次解码或新PCM分配。竞争使用显式结果交接、受控回调和有界回执屏障，不依赖sleep猜测。

原生诊断显式执行`--verify-audio-ui`：先在零音效组件的项目中以50%监听音量试听素材，确认回调提交非零样本且项目／历史不变，再回归组件试听；自有GPU回读包含实际音效窗口。硬件等待只用于观察，不代替上述确定性测试。连续背景诊断仍单独回归。最终检查结果、源码身份与报告见[P2_AUDIO_LIBRARY_PROOF.json](P2_AUDIO_LIBRARY_PROOF.json)。
