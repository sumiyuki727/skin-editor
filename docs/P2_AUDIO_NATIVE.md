# P2-A2：真实WAV、准备线程与原生输出首轮

2026-10-21，Windows x64、Rust 1.95.0。接续[A1资源基础](P2_AUDIO_RESOURCES.md)，本增量接入真实PCM16 WAV、单准备worker和共享预算的原生双通道边界。只在显式`--verify-audio`诊断中组装；正常桌面GUI仍未启用声音或音频导入UI。完整A2尚未退出。

## 实际实现与范围

| 路径 | 已实现行为 |
| --- | --- |
| WAV探测 | 解析RIFF/WAVE、fmt／data块与奇数填充；最多4096个块；拒绝重复关键块、坏长度／对齐／字节率、空／截断数据及不支持的编码。只支持PCM16、44.1／48 kHz、单／双声道，不按扩展名认定编码 |
| 输入与解码 | `BlobStore::stage_wav`只读显式路径，经原有两遍有界读取再探测；`WavDecoder`把signed PCM16除以32768写入已预留的float32源格式缓冲，每1024样本检查取消，报告实际写入数量。原始文件及Blob不被改写 |
| 单worker | `PreparationWorker`只有一个准备线程，空闲阻塞接收，无轮询；工作／结果通道各一个槽。A1队列仍管一个活动及四个待处理项，主控制端才接纳结果／查询项目，不把ProjectSession送进线程 |
| 取消／关闭 | 源变化先取消旧准备，活动预留直到解码／结果实际退出才退还；门闩测试控制真实WAV的迟到结果。关闭先取消控制器，再排空并join线程；不承诺中断不合作的codec或阻塞I/O |
| 监听转换 | 显式启用`MIX_CONVERSION_VERSION 1`，以整数源位置求44.1／48 kHz的线性插值；单声道复制，立体声变单声道取均值。源PCM／元数据及SoundPlan 1不变，转换只用于监听。其他布局／采样率明确失败 |
| 原生边界 | 控制端生成两个未饱和通道的128帧块，经固定Copy队列交给CPAL。回调按各通道代次筛选、合并后饱和、写出F32或I16；不访问项目、不解码、不分配／等待，也不析构最后PCM所有权 |
| 门控与清理 | 冻结只清除场景Voice／事件／未输出副本，显式试听继续；停止试听不动场景。草稿取消／历史切换使两通道旧副本失效，接纳准备／触发／混音前重选实际来源，不依赖UI先刷新 |
| 失效与所有者退出 | 原生错误静音并要求显式重建，不自动恢复；控制所有者丢弃会通过弱安全句柄静音仍在原生队列中的副本。数据回调中只处理Copy值，PCM销毁留在控制端 |

WAV支持是编辑器能力，不是已验证的stable解析规则。ADPCM、float WAV、WAVE_FORMAT_EXTENSIBLE、其他位深、长流、压缩音频和皮肤循环仍未开放；未知音频仍可按Opaque保留原字节。超过单份4 MiB PCM的有效WAV可以保留原始资源，但准备明确拒绝，不截断／遗漏文件。实际保存、透传文件与静音编码仍在P3。

## 依赖、成本与所有权

新增直接依赖仅在infrastructure：CPAL `=0.18.2`（Apache-2.0、默认features关闭），rtrb `=0.4.0`（MIT／Apache-2.0、默认features关闭）。host新增到已有audio的明确边；根domain／application仍无第三方包，UI／preview不获得音频设备权限。桌面锁文件增加12个包，包含其他平台的条件依赖，未引入ASIO等可选后端。依赖检查同步增加反向依赖、版本／feature及源码逃逸的负向回归；没有放宽旧方向。

CPAL提供WASAPI／ALSA／CoreAudio等平台边界，本轮只实测Windows。Linux需要系统ALSA开发库与pkg-config，Linux实测仍暂缓；macOS未测。新增一个准备线程，CPAL另有平台输出线程／系统缓冲；其栈、分配器保留、后端和系统引擎成本不属于PCM配额。产品分发许可／notices仍须按实际安装包核查。

原始字节沿用共享128 MiB，受管PCM总32 MiB／单份4 MiB。原生队列容量2048帧，其中每帧场景／试听各两个float负载，预留32768字节；两个双声道128帧暂存块合计2048字节。队列标签／元数据另计，没有在回调再持有一套原始声源或PCM副本。普通供给目标768帧，128帧量化可能使实际前送稍多；首次播放前显式预填充整个队列，避免把冷启动需求当作稳定期目标。

软件场景帧是已生成的位置，不是设备已消费或权威游戏时间。回调代次确认表示新的回调不再提交旧副本，不能撤回此前交给系统的残余。未测设备消费锚点、残余声持续时间、听感或声学延迟；不把回调计数称为已经听到声音。

## 测试及发现

新增14项infrastructure行为及1项audio行为，另增2项Python边界检查。WAV四种源格式与16种源／输出组合在无设备测试中核对；实际样本范围、立体声均值及非平凡斜坡的重采样有独立参考。原生消费者测试直接调用CPAL使用的同一消费函数，检查通道隔离、饱和顺序、I16量化／饱和、背压、空队列静音、设备故障、控制所有者丢弃及完整资源归还。

真实worker用门闩明确控制解码入口，测试在解码中取消及旧结果晚到；没有sleep猜测竞争。实际application会话覆盖草稿取消后不经UI刷新即清除原生副本、项目／历史不变，以及撤销后旧声音不能进入新来源。硬件诊断的2 ms等待只是供给调度间隔，不能代替这些确定性测试。

首轮原生虽然门控与释放通过，却有14080个空队列帧；第二轮降到448个，均保留原始报告，不能当作稳定输出通过。最终定位到启动回调请求1056帧，超过旧512／1024帧队列；同时128帧供给与常规480帧回调的几何关系需要余量。现使用有预算的2048帧启动预填充、768帧稳定期前送目标，诊断周期等待采用Rust sleep，未修改系统定时器或音频设置。变更联合验证，不声称已经分别量化两种等待方法的独立成本。

完整日志、源码与旧证明摘要见[P2_AUDIO_NATIVE_PROOF.json](P2_AUDIO_NATIVE_PROOF.json)。247项默认工具／行为／文档检查：核心159（Python34、Rust行为118、编译拒绝6、文档1），桌面88（audio29、infrastructure42、preview1、rendering7、UI7、host2）。格式、Clippy全目标、release核心、桌面debug及依赖／源码边界分别检查；原生设备和GPU均只显式启用。

原生03／04及最终检查轮使用Windows默认48 kHz、双声道F32输出；检查场景暂停而试听有非零样本、恢复不补旧事件、A／B真实WAV替换、草稿取消／历史切换后的回调静音确认，以及最终PCM归零。短轮不是长时、欠载预算或低延迟成绩；是否存在启动／持续空帧以各轮JSON报告为准，不能由测试数量替代。

## 剩余A2关口

后续增量已以[独立供给与有限背景参考](P2_AUDIO_SUPPLY.md)推进下列第1／2项。本文247项、旧队列负载及短轮证明保留首轮身份；当前状态以新记录为准。

1. 正式供给脱离GUI帧率：当前诊断控制循环约2 ms，不能把普通GUI的16 ms刷新直接用作输出泵。需有界控制交接及明确暂停／消费锚点，不能把项目搬入回调或让回调释放最后PCM。
2. 持续背景参考时间线及编辑热替换不重置背景的位置验证；本轮仅短音。未关闭完整SA05，也未实现真实歌曲／stable触发。
3. 音频素材库／组件编辑与试听UI、显式错误／旧来源／能力状态；PNG UI保持原样。文件选取到音频登记及用户操作仍待验收。
4. 原生提交延迟、300次修改、32 Voice小负载及最低格式矩阵的更多真实输出覆盖。当前真实端点只测48 kHz双声道F32，I16输出和其他端点未实测；最低源矩阵不能当作全部系统端点通过。
5. A3测标准图形＋音效长时、CPU／工作集／私有提交／GPU／系统引擎、设备重建及20轮生命周期；P3另验真实保存／导出，Linux／macOS保留各自未测状态。

本轮保留已有修改，不暂存、提交或推送Git；不读取用户曲库／认证信息、不录音、不修改客户端或系统音频设置。旧P0与A1证明保留原身份。

## 格式与后端依据

RIFF块与WAVE格式依据[Microsoft RIFF说明](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-)及[WAVEFORMATEX字段](https://learn.microsoft.com/en-us/windows/win32/api/mmeapi/ns-mmeapi-waveformatex)实现受限子集；没有引用旧stable代码。原生API依据[CPAL 0.18.2 DeviceTrait](https://docs.rs/cpal/0.18.2/cpal/traits/trait.DeviceTrait.html)，固定队列依据[rtrb 0.4.0](https://docs.rs/rtrb/0.4.0/rtrb/)，本地锁定源码同时核对。监听插值与门控是本项目显式语义，不归因于上述格式规范或stable。
