# P2-A1：通用原始资源、共享PCM预算与准备准入

2026-10-21，Windows x64，Rust 1.95.0。本增量补齐[候选／双通道控制](P2_AUDIO_RUNTIME.md)后的资源基础：实际原字节存储、分配前配额、可移交且有界的准备工作单元，以及真实application会话中的取消／迟到清理。音频解码使用自制受控fake，没有打开声卡；自有图形回读单独显式运行。没有引入新第三方依赖、线程或stable规则。

后续A2已接入[真实WAV、单worker和显式原生输出](P2_AUDIO_NATIVE.md)。以下230项、资源额度及“未完成”列表保留本轮A1检查身份，不能当作A2仍完全没有解码／原生输出。

## 所有权与数据流

显式输入 → `BlobStore`校验摘要／长度并持有原字节 → `RegisterAsset`经application登记并固定原始租约。图片、声音、Opaque复用同一存储，历史只固定原始字节；运行时PCM、Voice和RGBA不进入项目补丁。草稿／历史的项目写入口及图片与声音独立的规则不变。

声音路径为：application选择完整来源 → `SkinAudioController::admit_builds` → 原始资源及探测元数据核对 → 缓存复用或预留PCM／入队 → 移交唯一活动工作单元 → 探测／解码到预分配缓冲并报告写入样本数 → 原位增益 → 完成时重新查询实际会话来源 → 软件混音边界激活。准备失败只改变派生状态，不回滚有效项目，也不补播等待期间的事件。

`AudioDecoder`只由可信适配器实现，不能用UI声明的元数据冒充探测结果。typed Audio登记仍核对ResourceStore中已验证索引。未知编码可按Opaque保存原字节，不生成可试听的假元数据；实际容器探测／WAV解码器尚未接入。

## 当前额度与释放语义

| 资源 | 已实现的边界与释放方式 |
| --- | --- |
| 原始字节 | 共128 MiB、单份32 MiB、最多4096项。SHA-256＋长度去重，已有相同内容在满池时仍可复用。目录是弱引用，暂存／任务／历史的最后强租约释放才退还字节 |
| 原始输入 | `stage_bytes`接管Vec，不复制负载，按capacity计费。命名文件使用两遍有界读取，第一遍固定16 KiB栈缓冲计算摘要，预留后再分配读取并复核；变短、变长、内容变化或读取失败均不发布部分结果 |
| RGBA | 独立80 MiB额度；解码前预留常驻数据及Vec→Arc转换时并存的副本。历史原字节不再直接拥有RGBA；原字节失效且无人使用的图可清理。仍可达原字节对应的缓存当前不自动驱逐 |
| PCM | 总32 MiB、单份4 MiB，按float32样本计费，先预留后分配。排队预留、候选、绑定、Voice及受管混音输出块共用同一池；Runtime拒绝其他池的声音和输出块 |
| PCM共享 | 分配自身持有配额租约；克隆样本引用只计一次，不隐式写时复制，最后数据释放后才退还。旧一次性Voice可合法持有旧分配，不能在移除绑定时提前退还 |
| PCM缓存 | 最多256个弱配方键，包含原始摘要／长度、源格式／帧数、增益、可见性及处理版本，不含组件／历史身份。就绪内容可跨组件复用，新的激活来源仍单独核对；缓存不永久固定样本 |
| 准备任务 | 一个活动工作单元、四个待处理项；每项明确返回Queued／Cached／AlreadyQueued或错误。每个组件只保留最新待准备候选。队列满Busy、配额不足ResourceLimit，不执行解码 |
| 取消与退出 | 待处理项取消立即释放原始租约及预留；活动取消只置标记，继续占用额度和活动槽直到执行／结果结束或丢弃。关闭清空待处理项及弱缓存，活动工作单元合作停止；孤立工作单元／结果丢弃不会永久锁住活动槽 |

配额统计为**受管负载与预留量**，不是RSS、工作集或私有提交。原字节Vec已在调用方分配的输入、BTree／Arc元数据、PNG／未来codec内部暂存、系统分配器保留、GPU／驱动、原生设备和系统音频引擎成本另计。文件两遍读取的磁盘时间和阻塞取消尚未测量。80 MiB的RGBA常驻与转换副本共同计量，因此单图虽允许64 MiB，转换时仍可能因总额拒绝；不能把单图上限理解为任意当前负载下都能导入。

同时到来的同配方冷缓存未命中目前可以分别预留；没有多订阅者的在途解码合并。若配额因此拒绝，先前结果就绪后可显式重试并复用；不会偷偷超额等待或新增无界队列。PNG原有导入线程及每项结果队列保持原边界，音频候选合并不用于丢弃用户显式导入。

## 确定性验证

新增27项回归：audio的8项PCM测试及infrastructure的19项资源／准备测试。均不使用sleep猜测竞争、真实设备、客户端或个人资源目录；取消发生在明确移交点或解码fake内。真实命名文件测试只创建自制临时PNG，确认成功／损坏失败后源文件字节仍可用，并自动清理自己创建的文件。

| 覆盖 | 已验证行为 |
| --- | --- |
| 原字节复用 | PNG／Opaque同字节共用一份分配；满额重复输入及读取复用；capacity／单份／总额限制，源变化／读取失败无部分登记 |
| 历史与原始释放 | 当前节点删除Asset后旧历史仍固定原始字节；会话退出后释放。取消真实草稿中新登记的资源可释放原始字节，项目／历史保持未修改 |
| 共享PCM上限 | 实际分配8份4 MiB到32 MiB，下一份／单份过大／乘法溢出拒绝；共享／弱引用／Voice结束及受管输出块准确计费并归还 |
| 有界准入 | 一个活动＋四个排队，第六项Busy；PCM不足在解码前拒绝；每个描述都有结果，旧排队候选替换退还，显式重试可跨组件缓存复用 |
| 取消／失败 | 排队取消即释放；活动取消不提前释放；解码过程中取消后即使返回成功也丢弃。失败、短写、丢弃结果、关闭及迟到均释放资源，不缓存失败样本 |
| 完成身份 | 相同本地序号和相同请求的其他队列结果也拒绝；核对工作单元租约身份，不能抢占当前活动槽 |
| 实际会话 | 草稿取消后没有UI刷新仍拒绝完成；准备失败不更改项目／历史；原有完整来源、跨分支、双通道和旧Voice回归保持通过 |

## 下一关口与未完成范围

A1指定的通用资源、受管PCM预算和有界准入已具备确定性证据，路线与模块方向不需变更。音频API对接真实codec时须继续使用同一存储／配额，不另建私有池来绕过限制。MODEL_VERSION 2、Command／Draft API 5、SkinAudioPort 1、SoundPlan 1及FrameDescriptor 1不变；PreparedSound的内存构造必须提供预算，不是磁盘格式变化。

A2仍须接入实际WAV最低矩阵、单worker执行、受限原生控制交接／退休回收、场景与试听真实输出，以及音效编辑UI。现在的工作单元不是已启动的线程，控制器尚未在桌面宿主实例化。软件混音可能销毁最后样本引用，不能直接宣称适合原生实时回调。取消不保证打断阻塞文件读取或不合作的codec。

A3继续测真实图形＋声音标准负载、延迟／欠载、进程与设备成本及20轮生命周期；RGBA独立LRU／按需重解码、持久存储和更完整的缓存策略仍待验证。P3补文件保存、未知音频原字节透传、有效静音／透明文件及失败保护；当前只有内存计划，没有这些文件输出。stable触发／回退规则仍按P4／P5证据逐批实现。Linux实测暂缓，macOS及远程CI未测。

本轮保留已有未提交修改，未自动暂存、提交或推送Git；未操作用户客户端、旧stable源码或系统音频设置。
