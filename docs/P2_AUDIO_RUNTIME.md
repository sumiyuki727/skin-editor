# P2-A1：音效候选、门控与旧声音清理

2026-10-21，Windows，无窗口／无设备。本轮完成用户指定的确定性控制与测试增量，不将软件混音当作原生播放或stable声音兼容通过。[前一轮模型与计划记录](P2_AUDIO_CORE.md)及旧GPU证据保持原身份。

后续[通用资源、共享PCM预算与准备准入](P2_AUDIO_RESOURCES.md)已补齐受管配额及工作单元生命周期。以下203项及限制保留本次控制增量的历史身份，不代表这些后续资源能力仍未实现；真实codec、worker和原生播放仍待验收。

## 已实现的控制路径

`ProjectSession::synchronize_audio`通过application定义的SkinAudioPort v1选择真实活动草稿或已提交项目，交给infrastructure的SkinAudioController；该适配器构建SoundPlan并委托纯audio运行时。全部是只读投影，没有新增项目写入口或项目内的播放状态。当前桌面UI／宿主尚未实例化该控制器；测试使用实际Command／草稿／历史会话驱动它。

来源使用固定大小的会话、节点、活动修订、导航修订、可选草稿ID／修订；BuildRequest另有不复用的序号。导航修订只在成功且有效的历史切换后更新，不因失败、NoChange或缓存回执重放变化。即使两次音频同步之间已经离开并返回同一节点，也不会把旧声音当作当前声音；历史地址格式未变化。

| 行为 | 当前确定性语义 |
| --- | --- |
| 准备／激活 | 同步选择只产生准备描述，不发声；就绪结果必须匹配完整来源、组件、配方及Build序号，在当前软件混音帧边界激活。迟到成功／失败和重复完成均返回Stale并释放输入结果 |
| pending／失败 | 有旧可用声音时明确返回其来源及stale标记；没有时NotReady且不排队，就绪后不补播。失败保留有效项目，只允许显式retry，旧重试序号仍拒绝 |
| 普通提交 | 已开始的一次性Voice捕获原版本，可播完；新触发使用新版本。新版本激活清除对应组件尚未开始的旧排队声音。无关图片修改可复用相同PCM并重新标注就绪来源，不重解码或自动发声 |
| 取消草稿 | application保留取消事实；适配器只查询当前仍被绑定／Voice／事件引用的草稿ID，清理被取消草稿的所有修订、候选、排队与发声实例。不能仅由相邻快照推断取消 |
| 历史切换 | 停止两通道旧皮肤Voice、排队事件，拒绝旧来源准备结果；重新准备目标配方。软件消费位置保持，不把节点切换当作音乐定位 |
| 冻结与试听 | 场景门控关闭并清除场景Voice／排队，独立显式试听仍可混音，场景消费帧不推进。恢复不补发冻结期间事件；停止试听只清理试听通道 |
| 定位与设备fake | seek清理场景范围并保持冻结；旧门控不能恢复。受控设备失效清空两通道、递增设备代次，重建保持未播放；相同格式PCM可保留，旧控制／事件不可复用 |
| 容量与退出 | 固定32个Voice，最多64个排队事件、256个组件绑定；第33个立即Voice拒绝，排队派发时不足容量在MixReport记录丢弃。Voice结束、取消、移除引用或shutdown按生命周期释放PCM引用 |

两个通道共用软件混音帧；场景消费帧只是音频侧的位置／观察值，不是权威游戏时钟。浮点样本按固定Voice槽顺序相加，在输出边界饱和并计数削波，不按声音数量归一化。隐藏音效立即得到无Voice的静音结果，不等待解码；实际静音文件编码仍在P3验收。

## 修复的回归

“草稿发声 → 取消 → 尚未同步音频又提交一次图片编辑 → 同步”的初版实测留下1个旧草稿Voice，预期为0。已先保留失败用例，再改为application中的取消记录与有界引用查询；修复后通过。取消记录不属于SkinProject／历史节点，不记录PCM；数量受会话已接纳的Begin请求及回执容量约束，后续仍纳入正式会话元数据成本测量。已提交草稿不会被误标为取消。

SkinAudioController::accept_prepared在接纳结果前主动重选当前项目来源，取消或历史切换即使没有经过一次UI刷新，也能使旧结果失效。宿主后续必须在命令／历史／草稿状态变化后的控制边界同步，并在输入与软件块生成前处理控制；不能仅在画面刷新时同步。未来原生回调只能消费准备好的值和PCM，不能借用ProjectSession。

## 当前限制与后续关口

- 本轮是单所有者控制模型和软件PCM混音，直接注入已解码的自制样本；没有真实worker并发、WAV解码、重采样、系统设备通知、输出延迟或可听结果。格式不匹配返回明确失败，尚不能关闭最低WAV适配矩阵。
- 软件块生成期间可能销毁最后PCM引用，不承诺原生回调可直接使用。A2须建立有界控制交接、退休回收、回调实时性和真实后端证据。
- 单音处理上限4 MiB；当前没有完整共享32 MiB PCM预算／预解码预留、通用原始Blob存储或派生缓存驱逐。256个绑定是明确的控制描述上限，不能当作整机内存保护。准备描述不等于已实现“一个worker／四个任务”队列。
- A1仍需接好通用资源与有界缓存／任务准入；A2再做真实WAV双通道、热替换、短音输出与UI；A3测组合负载、生命周期和设备，P3补保存／字节透传／有效占位文件。实际stable用途及触发继续按P4／P5证据推进。

模型2、Command5、SoundPlan1、FrameDescriptor1不变，新增独立SkinAudioPort1。唯一新增产品依赖为infrastructure→既有audio，根核心仍只有两个无第三方包；未引入新第三方库、平台要求或运行线程。没有暂存、提交或推送Git。
