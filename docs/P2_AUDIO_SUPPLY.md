# P2-A2：独立音频供给与持续背景参考

2026-10-21，Windows x64、Rust 1.95.0，接续[真实WAV接入](P2_AUDIO_NATIVE.md)。本增量实现不依赖GUI刷新或调用者反复pump的音频供给，验证热替换、暂停恢复及旧声音清理。普通桌面GUI尚未组装声音；完整A2仍开放。

## 实际交接与生命周期

`AudioSupplyClient`只在项目控制端调用application的SkinAudioPort1，取得实际已提交／草稿来源和取消事实，生成最多256个SoundPlan的独立投影。一个`skin-audio-supply`线程拥有Runtime、准备队列、单解码worker和原生producer，每2 ms检查有界控制、接纳准备及补充输出。ProjectSession、UI、文件路径和可变项目引用都不进入线程或原生回调。原有`AudioPlayback`／`--verify-audio`保留作首轮路径回归。

控制请求＋处理＋未读／暂持回执最多16份，以同一RAII额度计数；不能靠清空请求假装已释放PCM。控制满时返回Busy，SkinAudioPort同步沿用其ResourceLimit错误；实际草稿取消／历史同步即使因满队列失败，也先失效两个皮肤通道的原生副本，须重试交接以恢复新的有效声音。终止关闭通过独立原子门及join完成，不需要空闲控制槽。正常UI将使用非阻塞poll；wait_receipt仅供无窗口调用者／诊断，不能拿来阻塞GUI。

在途投影、已选择来源及有序回执携带的保留草稿ID共同参与application取消事实查询，不依赖GUI恰好读取状态。状态采用try_lock发布，观察者不能阻塞供给；发布受阻会保留待更新标记。worker只接纳已验证的只读投影，宿主必须在每次项目编辑／草稿取消／历史控制边界同步，不能等下一画面刷新或把新会话搬进回调。

背景是纯audio的`BackgroundTrack`：不可变共享PCM、格式、生成下一帧及运行门。它独立于皮肤音效组件、项目历史及导出。当前只接同原生输出格式的有限预解码参考，仍受单份4 MiB限制；不支持真实长歌曲流、循环、背景替换或任意seek。测试的暂停回退只供冻结交接使用，未开放时间轴产品功能。

| 控制 | 行为 |
| --- | --- |
| 皮肤A→B普通提交 | 候选激活后新触发使用B，旧一次性Voice可自然结束；背景来源、位置和代次不变 |
| 草稿取消／历史导航 | 两个皮肤通道先失效；旧草稿／分支Voice、事件和迟到结果由完整来源拒绝／清理；不改变背景代次 |
| 场景暂停 | 先使背景及场景Copy副本失效，清除场景声音；显式试听保持独立。回调同时确认背景与场景代次后，用背景提交下一帧回退未用前送，再报告Frozen |
| 恢复／重复恢复 | 从确认锚点继续；不跳过未提交数据，不补墙钟时间或旧事件。重复Running不递增背景代次 |
| 停止试听／关闭／设备故障 | 停试听只失效试听副本；关闭和故障静音所有副本，释放由供给所有者执行；恢复设备仍需后续显式重建 |

Copy帧带两个皮肤通道代次和独立背景代次／源位置。producer使用**已应用控制**的代次，不能把尚未处理的新期望代次贴到旧Runtime样本上。原生消费者仅复制、相加、饱和、计数和原子确认，不分配、等待、解码或析构最后PCM所有权。

背景生成前沿与回调提交锚点分别记录。`background_next`只是本项目向回调输出的源位置；系统缓冲可能仍在播放此前提交的内容。它不是设备消费、声学位置、真实歌曲同步或权威游戏时间，当前Runtime场景帧也没有接入真正玩法。

## 预算与维护成本

没有新增包、feature或第三方依赖，锁文件不变。线程为一个供给所有者、一个准备worker及CPAL平台线程；线程栈、调度、分配器保留、CPAL和系统引擎成本尚未计量，不属于PCM配额。

原始字节仍共用128 MiB；准备仍为一个活动＋四个排队。候选、Voice、背景和原生float负载共用32 MiB PCM总额／单份4 MiB。2048帧队列现在每帧有背景／场景／试听各两个float，负载49152字节；两个双声道128帧暂存块共2048字节。标签及队列元数据另计，不能将49152字节当作实际ring总分配。启动预填2048帧，平时前送目标768帧；这些数值不是整体CPU／内存或低延迟预算成绩。

原生诊断的8秒48 kHz双声道参考占3072000字节；包括短WAV源／派生和队列，三轮受管PCM峰值均3507200字节（约3.345 MiB），最终0。旧路径回归峰值435200字节，相比首轮记录增加16384字节，来自新增背景float队列负载；旧证明中的418816字节不回填。

## 确定性与原生证据

新增10项无窗口测试：audio两项，infrastructure八项。测试直接调用原生使用的同一消费函数、显式回执屏障和受控供给核心；不靠真实设备、GUI、窗口捕获或sleep判断竞争。

- 格式／对齐／有限值、共享源不变及单份超限拒绝；暂停、显式回退和EOF。
- 逐样本核对背景连续性，换增益、历史导航和草稿取消均不重置位置；新激活后的首次触发使用新版本，旧普通提交Voice仍可播完。
- 生成前沿已经超过回调位置时暂停：确认前不得报告Frozen；确认后退回精确样本，冻结中试听可响，恢复从该样本继续。
- 新期望代次已经发布而旧Runtime尚未收到投影时，旧声音仍被拒绝；背景继续。取消后旧排队事件／Voice及旧来源触发不能复活。
- 外部预算池或不匹配背景格式拒绝、额度归还；独立线程无GUI ticks供给，重复恢复不切断背景。
- 回执占满／暂持仍计费，第17份拒绝，满队列关闭可完成；实际application草稿取消不留项目修改或历史节点，也不依赖状态轮询才能取得取消事实。

完整核心159项、桌面98项，共257项默认工具／行为／文档检查通过；格式、Clippy全目标、release核心、桌面debug及依赖／源码边界通过。桌面98＝audio31＋infrastructure50＋preview1＋rendering7＋UI7＋host2；核心159保留Python34／Rust行为118／编译拒绝6／文档1。图形／呈现实现未改，本轮不重开GPU或复用旧图片作为新画面验收。
