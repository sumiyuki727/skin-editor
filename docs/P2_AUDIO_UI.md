# P2-A2：音频素材库与音效编辑界面

本文保留2026-10-21首轮组件试听的检查身份；后续已补[素材独立试听与监听总音量](P2_AUDIO_LIBRARY.md)，下面“先绑定组件”的限制仅描述首轮。

2026-10-21。接续[独立供给](P2_AUDIO_SUPPLY.md)，普通桌面现在可显式启用音频设备，登记短WAV／原始文件、编辑独立音效组件并试听。启动和默认无窗口检查仍不打开音频设备；准备成功不会自动发声。完整A2的延迟／多Voice小负载及后续A3预算仍开放。

## 使用与当前边界

1. 正常启动后点击顶部“音效编辑”，打开独立窗口；图片图层和音效有各自的选择与编辑对象，不建立图片—声音关联。
2. 点击“添加自制 WAV 示例”，或输入显式WAV路径后点击“导入音频”。现有一个导入线程共用PNG／音频原字节存储，四个待处理请求、四个暂存结果；活动草稿期间保留结果租约、延后登记。面板显示待完成／登记数量，失败显示诊断，不添加历史节点。
3. 选中音频素材，填写唯一用途键，点击“创建音效组件”。也可将素材绑定到选中音效；同一素材可复用。用途键是编辑器身份，不猜测stable文件名。删除仍被引用的素材会明确拒绝。
4. 点击“启用音频设备”，等待所选音效显示“就绪”，再点击“显式试听音效”。素材库当前采用**绑定组件后试听**，尚无不创建组件的原始素材试听；试听按钮本身不会创建组件、改项目或增加历史。
5. 拖动增益，松开一次提交；Esc、失焦、窗口尺寸变化或显式取消恢复基础版本。隐藏保留静音占位的输出计划；没有实际文件导出。全局冻结影响场景，显式试听仍可用；停止试听不改变场景门控。
6. 其他编码／不支持的WAV可勾选“仅保留原始字节”后导入为Opaque，绑定与历史仍保留原字节。准备显示Unsupported，显式试听返回NotReady，不偷偷换声音或待准备完成后补播；“重试准备”不播放，也不创建历史节点。

未编辑未知音频的CopyOriginal计划保持有效；本轮没有文件透传／编码或项目保存。音量仅提供单音0–1增益，没有波形、裁切、循环、原始素材直接试听或独立监听总音量。背景仍是前轮诊断中的有限参考，GUI没有真实歌曲、谱面或stable触发。

## 控制与呈现契约

application新增`AUDIO_EDITOR_API_VERSION 1`：AudioEditorPort、动作、准备状态、完整来源、有效旧版本、声音实例计数及错误值。模型2、Command5、SkinAudioPort1和SoundPlan1保持不变，没有磁盘格式变化。control_audio验证实际组件并在试听／控制前同步真实来源；设备与试听控制不进入项目历史。UI不导入audio、CPAL、文件系统或原生句柄，desktop注入并管理具体适配器。

EditorUi的submit、draft及navigation在返回前调用只读同步，涵盖PNG／音频登记、所有图片修改、连续增益、取消和历史跳转，不能只等下一GUI帧。满队列先由已有边界使旧副本失效，项目修改保持成功，并标记待同步重试。每次显式试听再经application同步；候选或Voice来源不同会显示“有效旧版本”及上次实际触发来源。缺少可用版本会明确诊断。

音频供给仍在独立线程，每2 ms补充；原有单准备worker、一个活动／四个排队、共享32 MiB／单份4 MiB PCM及16份控制／回执额度均保留。增加一个无副作用的有界Barrier用于确定性诊断，不是项目Command。准备／控制／声音状态变化需要显示时，GUI约20 ms轮询；稳定冻结且无待处理项时不为音频持续重绘。该轮询不承担PCM供给或音频时钟。

场景目标与已确认状态分开：快速恢复→暂停仍立即向原生边界发布暂停代次，不等待旧GUI回执。Freezing期间的恢复由目标状态在确认后重试，不能把Busy当作已运行；占位模拟和游戏输入在确认前保持冻结。设备故障明确显示，关闭后可显式重新启用；默认端点通知与保持歌曲锚点的设备重建仍未实现。首次打开设备目前在显式控制调用内完成，尚未验证其GUI阻塞成本。

## 验证范围

新增10项无窗口测试：application三项、UI三项、host四项。包括控制前选择来源、禁用不被同步失败锁住、缺失组件不触发；UI操作返回前同步、Busy重试、300次增益草稿一次提交及重复用途键原子失败；真实WAV经同一宿主端口与可控原生消费者，逐样本核对A→B、草稿增益及取消／撤销前下一次UI刷新之外的旧副本清理、快速恢复→暂停和PCM释放。Opaque错误、显式重试不补播、原文件不变及原字节租约另有回归。

这些竞争检查使用有界回执屏障、显式回调与实际准备完成状态，不用sleep猜测竞争，也不读取真实客户端或个人媒体。真实设备和自有GPU回读另由`--verify-audio-ui`显式执行；其等待仅用于硬件观察，不替代确定性测试。它绘制实际音效窗口，在冻结状态显式试听自制WAV，并等待实际回调提交非零样本；不是只检查软件触发回执。试听未改项目／历史，图片像素和GPU租约沿用同一回归。

默认检查共267项：核心162（Python34、Rust行为121、编译拒绝6、文档1），桌面105（audio31、infrastructure50、preview1、rendering7、UI10、host6）；格式、Clippy全目标、核心release／桌面debug及依赖边界通过。原生UI回读使用RTX2060／Vulkan，图像最大单通道误差1/255（容差2），无变化八次请求新增上传0；冻结中组件试听未改项目／历史，首次观察已提交510个非零样本，非整段音效长度。持续背景回归仍使用默认48 kHz双声道F32，183次回调、73248个背景帧，空队列帧及背景位置断点0、PCM峰值3507200字节、关闭后0。原生报告不是听感／设备消费时钟或长时预算成绩；最终editor.png与已目检的布局图逐字节相同。

完整日志、源码／二进制身份及原生结果见[P2_AUDIO_UI_PROOF.json](P2_AUDIO_UI_PROOF.json)。真实鼠标增益、中文用途键输入、投放WAV、设备启停与多屏仍需人工确认；自动界面回读不能冒充人工验收或声学延迟成绩。完整A2仍需软件提交延迟／32 Voice小负载，A3还需图形＋音频长时与整机预算、设备及生命周期。P3另验保存、原字节透传与有效静音文件。
