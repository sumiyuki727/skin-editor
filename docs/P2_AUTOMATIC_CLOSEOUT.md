## 本轮实现

普通 Windows 入口通过 `product_policy::Policy::CURRENT` 组装既有分离声音路径与 MemoryUsage。保留原 2 ms 供给、背景储备、新声音接纳和回调策略；没有改变声音算法、预算或项目写入边界。设备仍按需启用，正常启动不自动打开音频输出。Linux／macOS 保留原适配路线，未将 Windows 专用探测静默应用到其他平台，当前没有跨平台验证结论。

同一个工厂用于本轮标准组合／完整资源循环，显式记录 `production_policy` 与实际配置。历史诊断入口及旧判据仍保留原身份；分析器不能混用两种配置。32 Voice GUI 短测也调用同一个声音工厂。MemoryUsage 不改变呈现模式、图像语义或上传路径；暂存复用没有成为默认。

画布新增可拖动角点缩放和圆形柄旋转，支持普通图层、嵌套图层组、跨元素组件组。控制先在帧坐标中计算，再经父变换的逆映射形成原有 Command；没有额外的项目写入口。整个手势仍由 application 管理草稿，松开一次提交，Esc／焦点或尺寸变化／故障取消，旧松手不能再次提交。旋转柄在组件贴边时保持在画布可点击范围内；这些编辑区域独立于游戏判定与拖动限制。

## 固定自动验证范围

1. 核心与桌面默认／全部 feature 的格式、Clippy、无窗口测试、依赖／源码边界；两次默认 feature release 构建身份一致。
2. 同一构建两轮 300 秒 N：100 图／10 文档／500 层、持续背景、每秒 8 次场景短音、64 次独立试听、300 次修改、20 次切换。仍检查零欠载、双通道提交 p95≤20 ms、帧／编辑延迟、512 MiB 进程及 256／128 MiB GPU、任务／租约释放。
3. 同构建 20 次完整资源打开／关闭，检查各会话真实销毁、在途任务 join、资源实际归零、关闭基线和最终 65 秒趋势。保留进程／驱动的残余分配，不从零租约宣称零保留。
4. 两轮持续背景／32 Voice Q，分别保留原始 CPU 与所有旧谓词；只将明确的播放 CPU15% 谓词列为目标，其余失败不豁免。
5. 两轮空项目与两轮标准资源暂停→关闭的 65 秒稳定段。此轮普通权限只验证实际帧数、输入、冻结、资源和内存／GPU，保留原始 CPU；**不关闭 B05 独立 CPU≤2% 门槛**。
6. 11 种既有窗口／初始化／清理／端点／活动编辑故障顺序，自有默认／MemoryUsage 七帧像素对照及离屏故障回归。

## C3 趋势审查

关闭中位数第1→20轮为203.5938→213.1328 MiB，前后五轮中位数增加0.5742 MiB。全20轮／后10轮斜率为正，后5轮为负，全部原值保留。最终65秒采样跨度64.921秒，私有提交依次为213.1328、213.1016、213.1289、213.1328、213.1563 MiB；净增加24 KiB，不能称严格零增长。相对首次打开前仍保留35.09375 MiB，未归因。

## 采集边缘与保留的失败

首个自动计划完成两轮N与20轮资源循环，但Q因一份收尾GPU未知而停止。加入PID存活边界后的下一组Q仍因一份初始loading未知而停止。两个失败计划及三轮Q原始记录均保留，未重判通过。

最终观测契约与既有N／C3一致：首次已知计数之前连续loading前缀的未知单列；采样前后PID已退出的未知单列；活动中断档仍失败，任一已知生命周期超限仍失败，未知从不记0。确定性测试覆盖启动、退出、活动缺失及已知超限。随后仅以新固定两轮Q完成该观测契约验证，并完成剩余稳定／故障／像素计划；已通过的N／C3不重跑，源码关系和同一二进制由严格接续检查记录。
