# P2-A3：独立背景储备与复制边界时钟

2026-10-23。接续 [Runtime Voice 桥接](P2_RUNTIME_VOICE_BRIDGE.md)，新增 infrastructure::separated_output，将真实 SPSC 背景储备、既有 Voice 交接和 Runtime 外部时钟连接起来。它是可执行、可跨线程检验的候选，**尚未接入 CPAL 或桌面默认路径，没有新的原生零欠载／20 ms／整机预算成绩，P2-A3 仍未验收**。检查身份见 [P2_BACKGROUND_COORDINATION_PROOF.json](P2_BACKGROUND_COORDINATION_PROOF.json)。

## 已连接的路径

BackgroundOwner 独占有限 BackgroundTrack 与生成游标；2048 项 SPSC 环只保存 Copy 背景样本、来源帧及传输代次。VoiceOwner 继续从既有 Runtime 接纳已准备实例，声音实例不进入背景队列。OutputConsumer 合并背景、场景声音与显式试听，最后统一限幅。后台可在接纳声音之前或之后补充储备；已填满的背景不把新短音放到 2048 帧之后。

每次 refill 最多发布 2048 帧，即使消费端同时不断腾出空间也会结束本次所有者工作。受控测试在每次发布后立即消费一帧，验证补充不会追着消费端运行到整个来源 EOF；此处不依赖调度快慢或 sleep。

此边界没有 GUI 帧、项目会话、文件读取或解码。背景采样格式必须与 Runtime 输出格式匹配，覆盖 44.1／48 kHz、单／双声道四种组合；皮肤声音仍可使用 Runtime 既有监听转换。输入是同一共享 PCM 池中的有限参考，不是新增的流式歌曲播放器。没有新增依赖、application 写入口或第二套绑定／候选规则。

持续补充和声音控制由所有者显式执行，适合接入既有独立供给线程；本轮没有修改产品线程启动或将候选接到 GUI。受控测试用独立消费线程及门闩推进，没有依赖 GUI 更新或 sleep。

## 三种位置与控制状态

| 值 | 含义 |
| --- | --- |
| generated_frame | 所有者已写入储备的生成前沿，可以比可听位置更靠前 |
| CopyClock.next_background／next_output | 本传输代次的下一来源帧（从显式恢复基准开始，按实际复制推进）／已写入借用输出缓冲的总输出帧；总输出包含冻结期间的静音或显式试听 |
| 设备消费／声学位置 | 本轮未知；复制到 Rust 缓冲不证明系统设备已经消费或扬声器发声 |

消费端通过固定原子字段发布 CopyClock，单写者序号包围整行，所有字段使用 SeqCst；所有者固定次数读取，遇到半行或变动直接留待下一轮，不等待、不重试读循环。代次与计数 checked，耗尽关闭，不回绕。Runtime 的 synchronize_handoff_clock 只供外部执行：总输出帧不倒退，运行中场景帧不倒退，回退只能在冻结定位状态发生；失败不部分更新两种时钟。

暂停走 Running → Freezing → Frozen。先停止场景输入／实例并发布新背景代次；消费端确认后丢弃旧 Copy 储备，并返回最后实际复制的背景下一帧。所有者收到匹配的新代次确认后才恢复生成位置，重复 pump 不再次回退已经重填的储备。没有确认返回 AwaitingAck，未填足 min(剩余来源, 2048) 帧返回 NotPrimed，显式恢复后才重新接纳场景播放。

复制前发生暂停时，本块尚未复制的背景和场景贡献被抑制，来源位置回到块起点；显式试听继续。复制后才发生暂停时，本块已复制的背景计入确认位置，不能把它当成未输出并重放。两者均不补跑暂停墙钟。OutputReport 的首次声音回执随被抑制的通道清除；关闭抑制两通道及背景。

定位使用来源帧，必须在有限 PCM 范围内。前后定位均先冻结并清掉旧场景声音；新定位可覆盖尚未确认的旧定位，旧确认不得解除新请求的 Freezing。默认停在新位置供检查，重填并显式恢复后才播放。逻辑定位位置与复制锚点分开：冻结回调可能仍报告跳转前的复制锚点，不能覆盖刚定位的新场景位置。

另一受控交错是冻结中的回调晚于恢复完成：它只能推进总输出帧，不能把场景恢复到旧位置。下一次运行回调从已发布的新位置开始，整条路径不依赖 UI 正好刷新。普通素材替换、草稿取消和历史导航不会隐式重置背景代次或游标；生成与复制仍按各自节奏继续，皮肤实例则通过 Runtime 清理。

恢复后若尚未发生一次运行复制就再次暂停，也必须保留显式定位基准。恢复位置与其代次一并发布，消费端记住自己已接纳的恢复代次；即使只观察到后来的冻结，也不会拿跳转前的旧锚点覆盖新位置。直接连发及冻结回调正在执行两种次序均有回归。

这提供有限参考的帧定位及复制边界协调，**没有时间轴 UI、小节／拍定位、真实玩法状态或统计恢复**。外部执行对未来定时触发仍明确报 UnsupportedScheduling；当前已连接的时钟不能当成已经实现定时事件调度。

## 资源与完成确认

构造前先预留背景 Copy 环样本及三个固定暂存平面的共享 PCM 预算，随后才分配。双声道上限为 16 KiB 环样本＋48 KiB 暂存；单声道暂存为 24 KiB，Copy 环仍持有两个样本。来源 PCM 和已准备 Voice 另按共享分配只计一次，沿用总 32 MiB／单份 4 MiB。环中的代次／位置元数据、rtrb／Arc／对象开销额外有界，不冒充已计入 PCM 或整机内存峰值。

环预算由两端共有状态持有，所有者提前退出不会退款仍活着的 Copy 环；消费端暂存也保持租约到实际释放。消费函数只处理预分配数据，不克隆资源句柄、不释放最后 PCM。异常消费端销毁后可由所有者 reclaim_abandoned 回收；正常停止交还独占端点，通过 Runtime 与输出边界身份核对后在所有者释放来源、环、暂存及 Voice。停止凭证仍不证明 OS 流已经静止。

VoiceConsumer 新增内部合成接口，把 Runtime 实例的正常返回放到调用方复制合成缓冲之后，避免正常完成在输出复制前被所有者提前确认。原始候选接口与默认产品路径保持。**真正 CPAL 缓冲、实例撤销快照到实际复制之间、CPAL 闭包析构线程、设备残余与消费锚点仍须下一步验证。** 本轮租约／代码检查没有全局分配器或实时截止时间测量。

## 验证

新增 23 项无设备测试：audio 时钟 1 项，infrastructure 协调 22 项；原有 Voice 交接回归继续通过。线程交错用零容量通道控制，10 秒仅防死锁。最初测试 fixture 试图在相同 Origin 下改变计划，触发正确的 InvalidOrigin 拒绝；修正 fixture 的首次选择流程后重查，失败记录保留。自查补充单次补充工作量限制，以及恢复后立即暂停的基准代次处理与回归后，按最终源码重跑完整检查。

## 原生短轮前的下一步

将此路径接入既有供给控制循环及真实输出缓冲，落实流的开始／停止交还、设备身份与实例复制检查、实际提交观察及回调分配／析构检测，再运行固定短轮对照及 32 Voice。未来定时事件和 UI 定位须明确追加范围，不能借当前立即触发 API 暗中补发。

300 秒若要覆盖持续背景，须另提供受限流式来源或经声明和验证的循环参考；当前有限 PCM 在 EOF 后的静音只证明 EOF 路径，不能据此关闭长时连续背景关口。

零欠载与已就绪立即触发原生提交上界 p95≤20 ms 保持；CPU≤15% 单逻辑核、进程内存≤512 MiB、GPU dedicated≤256 MiB 等预算保持。短轮通过后才能以同版本两轮 300 秒组合、稳定暂停和资源循环检验该方案，不继承旧策略成绩，也不把本轮软件复制称为设备消费或声学停止。
