# P2-A3 标准图片与声音组合验证

2026-10-22。当前 Windows／RTX 2060／Vulkan 的两轮标准静态画布负载通过本文的分项门槛，保留 [机器证明](P2_COMBINED_PROOF.json)。**没有关闭完整 P2 或 A3**：文档切换长帧、稳定空闲、完整资源循环、设备重建及真实玩法仍有后续工作。

## 负载与测量范围

本文及证明保留初轮身份；后续后台化、GPU复用及**最新整体未通过项**见[候选准备记录](P2_FRAME_PREPARATION.md)，不能用本文的旧成绩关闭新版本门槛。

同一 release 二进制、源码、锁文件及 GPU 后端连续重复两轮，报告的原生输出均为48 kHz双声道、period480。每轮在正式 eframe 窗口中使用 EditorUi、NativeHost、统一 Command／草稿和独立 AudioSupplyClient；没有 CPU 像素回读、系统窗口捕获、外部游戏或私人素材。音频控制由诊断入口驱动，不是人工音效 UI 验收。

- 100 个自制 **1024×1024 PNG 文件**经实际文件导入，分布于 10 个文档。每文档 48 个图片实例、2 个嵌套组，共 500 层；活动文档引用 10 张原图，不缩小原始数据。
- 16 个自制 48 kHz 双声道 WAV，0.125／0.5／1／2 秒各 4 个；沿用共享原始字节、32 MiB PCM、单准备 worker／4 个排队和 16 份控制／回执准入。
- 每轮原生回调提交 14,400,000 帧，覆盖 300 秒；每秒 8 次场景触发，共 2400 次。另有每通道 64 次计时探针。组合轮峰值 8 Voice；32 Voice 同帧突发另轮验证，不把二者混成“300 秒持续 32 Voice”。
- 每秒一次，共 300 次草稿替换；每次显式调整图片组透明度与独立音效的增益，两个组件没有绑定或继承关系。整个草稿只提交一个历史节点。前 200 秒内完成 20 次文档切换。
- 使用 1180×800 初始窗口和静态编辑画布；普通输入、控制截止时间和 GPU 回执驱动刷新，撤掉诊断入口额外强制的 60 Hz 重绘。没有宣称 60 fps 游戏场景或 stable 内核的预算。

CPU 为本进程全部线程累计时间除以同阶段墙钟，按一个逻辑核计算。进程及 GPU 内存分别统计，不能相加。PDH 仅匹配本轮自建子进程的 PID，汇总其各适配器 dedicated／shared；缺失计数判未通过，不按零处理。名义等待 100 ms，实际采样间隔 p50／p95／最大为约 109／110／125 ms。采样峰值可能漏掉瞬时分配，Windows 生命周期峰值另报。系统音频引擎、物理设备消费及声学延迟未知。

## 实现变化与边界

原始 PNG 仍由项目／历史固定；RGBA 是可重建派生缓存。常规驻留软目标 64 MiB，包含解码转换暂存的硬预留仍为 80 MiB。只逐出没有 Raster／像素借用者的项；借用中的工作集允许超过软目标，但不能突破硬预留。超限明确失败，原始字节与历史不丢失。当前缺页仍同步重解码，没有 LRU、后台预取或磁盘资源存储。

GpuComposer 只缓存一组不可变原图 buffer，最多 80 MiB；相同 Raster 分配的变换／透明度编辑复用该 buffer，操作与目标纹理仍重新生成。缓存用 BlobRef 和 **Weak Raster 身份**核对，不固定 CPU 像素，也不以指针充当项目／历史身份。上传前检查完整长度、预算并精确预留 CPU 暂存，避免标准 40 MiB 数据因 Vec 扩容多留 24 MiB 容量。换源先解除缓存持有，GPU 在途副本仍由真实回执保留；shutdown 显式清空缓存，并继续跟踪 CPU 绘制数据尚持有的帧。

音频混音按帧提供有界的“具有非零贡献的最高 Voice 序号”，复制到既有环的元数据。原生回调只在通道代次仍有效且样本非零时发布观察值；不增加回调时钟、分配、等待、I/O 或最后 PCM 所有权释放。序号只服务当前输出／Runtime 的观察，不能取代完整来源与代次。独立观察线程将实际 TriggerReceipt 的 Voice 与回调关联，避免把重叠的旧声音误认为新触发；观察上界包含接纳、回执和线程调度，不是精确首样本时间或声学延迟。增加约 34 KiB 固定元数据，浮点 PCM 额度及活动前送 768 帧不变。

UI 自动失焦／尺寸变化取消现在只影响它自己创建的会话＋草稿 ID，保留应用层其他调用者的草稿。UI 自有拖动的 Esc／失焦／resize 回归仍通过；显式取消行为沿用原入口。模型 2、Command 5、Frame 1、SkinAudioPort 1、AudioEditorPort 2、SoundPlan 2 与转换语义 1 均未改变，没有新依赖或文件格式。
