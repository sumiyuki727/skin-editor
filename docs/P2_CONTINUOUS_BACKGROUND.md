# P2-A3：有界持续背景与回调资源审计

2026-10-24。本增量连接 WAV 持续读取、既有供给 worker 和显式候选 GUI，保留独立声音接纳及 2048 帧设备储备。553 项默认检查通过，原生功能／零欠载／20 ms 与资源清理通过；**固定原生计划因两轮 GUI 的 32 Voice CPU 超过 15% 而整体失败**。P2-A3 仍未验收，普通默认路径未晋升。证据见 [P2_CONTINUOUS_BACKGROUND_PROOF.json](P2_CONTINUOUS_BACKGROUND_PROOF.json)。

## 输入与所有权

`infrastructure::BufferedBackground` 消费调用方明确选定的只读 `Read + Seek` 句柄。它不是项目 Asset，也没有项目、历史或文件写入权。正式用户歌曲选择、根目录校验和 Songs 适配仍未接入；本轮只有自制诊断 WAV，不读取用户音乐。

支持普通 RIFF WAV PCM16、44.1／48 kHz、单／双声道；背景必须与候选设备格式一致，本增量不提供背景重采样、压缩解码、自动循环或设备重建。短音仍沿用已有格式转换及一个准备 worker／四个排队单元。元数据检查只使用固定头缓冲并限制 4096 个 chunk；重复 fmt／data、越界、截断、错误帧对齐及未知编码明确拒绝，不按扩展名猜测。

每个输出拥有一个背景读取线程。四个 2048 帧 PCM 块在空闲／读取／就绪／所有者之间循环转移，总共 8192 帧，立体声 65536 字节、单声道 32768 字节。全部先向共享 32 MiB PCM 池预留，再分配；歌曲长度不增加这些存储。读取线程另有固定 8192 字节原始缓冲及独立定额，不把整个外部文件放入皮肤 BlobStore。两个四项块队列、代次／统计元数据和线程栈计入进程成本，不伪装成 PCM 字节。

既有供给线程只复制已就绪样本到原 2048 帧 Copy 环；设备回调仍只访问该环和 32 Voice 交接，不持有文件、读取线程或项目会话。原控制／回执总额仍为 16，背景读取不借短音准备队列创建无界任务。缺少块时所有者停止本轮补充；播放中储备不足仍计真实欠载，不能以补零或重置计数冒充通过。

暂停和定位等待原生冻结确认及所有者回退，再发布完成。随后填足设备储备才允许恢复；尚未填足明确返回 Busy，GUI 保留恢复意图并在就绪后重试。定位回执分别报告请求目标与前一复制锚点，不能把已经重置的生成位置当作新位置已播放。定位为预览控制，不产生项目历史节点，也不恢复已取消的场景声音；显式试听独立。

读取代次在暂停回退／显式定位时改变。正在读取的旧块及已排队的旧块都在交接时核对代次；换皮肤、取消草稿或切换历史只改变皮肤声音来源，不定位背景。退出先发停止，等待实际读取结束并回收块后归还预算。阻塞 I/O 不可由本实现强行打断，关闭耗时没有上界保证；门闩测试确认未退出期间不提前退款。

## 回调资源审计范围

| 路径 | 审计与约束 |
| --- | --- |
| `separated_native::Callback::render` | 只使用预建回调对象、固定统计和首次复制观察队列；TLS 常量 Cell 标记本线程数据回调范围，无项目状态 |
| `OutputConsumer::render_inner` | 已预留的背景／场景／试听暂存平面、固定 Copy 环；每个块最多 2048 帧；闭包最终复制前再次过滤失效代次 |
| `VoiceConsumer::render_committed` | 最多 32 份描述符，固定数组保存游标与取消结果；返回队列满时放入固定 deferred 槽，不析构 Packet；选择性取消只做一次有界重算 |
| `PreparedSound::monitor_frame` | 共用既有只读采样器，不解码、分配或读取文件；格式矩阵的数组金样回归保持 |
| 设备闭包销毁 | 原生宿主保留单槽接收端，闭包交还端点，所有者核对后回收；记录是否发生在数据回调范围内 |

Packet、Voice 两端、背景两端及持续输入的析构进入受管计数。正常复制／32 Voice 结束／取消的计数必须为零，端点交还只能在 render 范围外；负向测试主动在错误范围交还或销毁端点，确认检测器不是恒零。计数不包括全部 Rust 分配器、第三方库或驱动内部；这是受管对象寿命检测与自有调用路径审查，**不是全局分配器拦截或声学测试**。资源租约最终归零仍另验，不能只凭计数判定无泄漏。

## 检查与短轮

最终格式、Clippy、无窗口及依赖／源码边界共 553 项通过（110 Python＋130 核心 Rust＋313 桌面 Rust），新增 4 Python／21 Rust。发布构建通过；没有新增依赖、修改锁文件、供给节奏或原验收门槛。工具链与日志摘要在证明中记录。测试使用受控 reader／门闩及实际状态确认，超时只作失败保护，不用 sleep 猜测竞态。

软件测试覆盖十分钟伪输入的逐帧内容、四块复用与定额、最低格式矩阵、读失败／非法元数据、EOF、前后及重复定位、迟到读丢弃、版本耗尽、超限失败回收；控制侧覆盖定位的两步确认、Busy 第二次定位不会锁死首个回执、未准备恢复、显式试听隔离、历史／热选择连续、非法客户端定位不消耗额度及取消后实际释放。受管回调审计包含正常 32 Voice 退休／取消和主动错误路径的负向检测。

本机 Windows、48 kHz／双声道 F32、480 帧设备周期，同构建固定五进程计划全部完成。所有进程欠载 0，完整请求／GUI 分发到首次原生复制观察的上界 p95≤20 ms；不扣观察余量。

| 轮次 | 场景／试听 p95（ms） | 32 Voice CPU（单逻辑核） | 结果 |
| --- | --- | --- | --- |
| 有限背景 worker 前对照 | 11.1798／11.1815 | 3.7596% | 本轮门槛通过 |
| 持续背景 worker 1 | 12.5393／12.5376 | 7.4618% | 本轮门槛通过 |

| 持续背景 worker 2 | 11.9462／11.9414 | 5.2635% | 本轮门槛通过 |

两轮 worker 在前跳至 120 秒＋7 帧后各连续播放约 20 秒（959520／960000 帧，采样边界不同），再后跳至第 31 帧并恢复，位置连续、未到 EOF。定位保留三秒显式试听；暂停恢复、热替换、草稿取消及历史清理通过。原生使用自制 360 秒 WAV，并未完整播放 360 秒，亦不是两轮标准 300 秒图形组合。

四个持续输入进程 PCM 峰值均为 2435072 字节、退出归零；每个输入原始缓冲峰值 8192 字节、退出归零。GUI 生命周期采样工作集／私有提交最大约 188.051／231.695 MiB，低于 512 MiB；headless worker 最大约 13.586／5.012 MiB。所有九个原生进程（含下面追加的有限背景对照）受管回调析构计数 0、回调范围内端点交还 0、范围外交还 1。没有新的 GPU dedicated／shared 预算或像素测量，不继承旧组合成绩。

五进程计划失败后，未改源码／构建／门槛，另外执行已有固定“有限 worker／有限 GUI／有限 GUI／有限 worker”四进程对照。GUI 的 32 Voice CPU 为 **15.0385%／14.2866%**，第一轮也超限，因此该对照计划同样记整体失败。四轮仍为零欠载、p95≤20 ms、内存／清理通过。有限 worker 的 32 Voice CPU 为 7.5156%／11.0202%；这些约两秒的窗口及 Windows 进程 CPU 时钟粒度不足以将差值归因到某个线程，CPU 为 0 的短阶段也不能理解为没有成本。

两轮持续 GUI 均超限是仍需处理的事实；有限背景也在门槛附近，并不能证明新增读取没有成本或可以豁免预算。下一步先分线程／区段关联读取、供给、32 Voice 混音与 GUI／呈现 CPU，保留这两份失败计划，不能通过更换采样集或扩大阈值追认通过。30 份旧证明保持原始字节；Git 无暂存、提交或推送。
