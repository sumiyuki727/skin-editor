## 实现与计量范围

新增 `tools/measure_cpu_threads.py`，复用既有ETW／QPC区间分析、WAV／背景／GUI诊断和线程查询适配。产品Rust、release二进制、音频供给、GUI帧率和预算不变，无新产品依赖。采集器C仅在tools使用，不随产品分发。

线程身份只在阶段变化时查询，不在每个进程采样时枚举。沿用最多128个累计只读句柄、PID核对和线程创建时间；查询线程描述及可选Win32起始地址，以同次进程的模块区间映射，仅记录模块basename。未发现的短命线程保留为未知，不从CPU总量删除；同TID不同创建时间拒绝关联，不能跨进程或跨轮继承身份。最多24次阶段观察。模块映射优先采用目标阶段，不能被关闭后卸载的模块信息覆盖。

查询依照 [GetThreadDescription](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreaddescription)及动态可选的 [NtQueryInformationThread](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntqueryinformationthread)。线程名不唯一，也不是身份；模块仅表示**启动地址来源，不是正在执行的函数或采样栈**。离线有界读取已冻结产品的PE头（头偏移≤1 MiB），将模块内启动RVA与PE入口RVA核对，避免只凭最早发现线程称作main。

按同一PID／TID和原阶段QPC窗口累计调度区间，线程和须等于进程值，不按机器核心数缩小，不扣除观察器或中断。现有原CPU数值判据完整保留。采集器、区间容量、丢失拒绝与保守重叠语义沿用前轮。

## 普通权限路线与失败记录

预备计划希望只有采集器提升，诊断子进程使用同用户关联的普通令牌。候选严格核对相同用户、非提升状态及Limited类型；不获取其他应用的令牌，不修改用户组、桌面ACL或系统策略。进程创建按 [CreateProcessAsUserW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessasuserw)及 [DuplicateTokenEx](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-duplicatetokenex)的主令牌要求处理，失败不会改称普通对照成功。

本机四次有界尝试均在子进程创建前失败，root PID为0：前两次Secondary Logon路线返回267（工作目录错误），换到系统目录仍失败；直接路线返回1346（令牌级别错误），补主令牌复制后仍为1346。不能据此将原因归为E盘或提升权限本身。全部会话停止成功，没有启动参考负载或产品，没有修改系统权限。各次源码／日志保留；不再重试这些路线。

`--elevated-only` 是**独立、显式的诊断计划**，不是普通对照的自动回退。成功轮的Python runner与产品令牌均核对为Full／elevated；C指定已有的 `winsta0\default`，两种候选启动均先用系统目录，Python进入项目目录，实际产品仍从项目目录启动。普通权限／隔离桌面对照仍未完成，不能从本轮判断其差异。

## 中断范围与下一步

当前调度区间仍含ISR／DPC，没有采其中断事件，不能追溯扣除。[微软cswitch说明](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/cswitch)明确要求启用DPC／interrupt tracing，排除选项才有效；[CPU Analysis](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/cpu-analysis)也将线程与ISR／DPC分别建模。

后续应先验证有界中断事件的schema／QPC时基、嵌套区间并集和对应CPU上的自有运行区间交集，保持原调度总量并列，独立验证前不核减预算。同时改由普通权限runner自行创建测试进程、提升采集器只观测经身份／创建时刻校验的自有进程，避开从提升进程构造普通身份的失败路线。入口线程的应用／框架／提交边界也需单独测量。
