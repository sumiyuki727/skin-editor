# P2 当前声音路径标准长时组合

2026-10-27。接续[C1稳定段](P2_STABLE_WINDOW.md)，按用户要求先收尾P2，P3保持暂缓。旧Combined及旧证明不改写；本轮使用新的显式`--verify-streamed-combined`入口，将同一标准图形fixture接到当前EditorAudio→AudioSupplyClient::spawn_streamed→分离声音／背景储备→NativeExecutor。普通启动路径不晋升，没有修改声音供给策略、设备储备或回调。

## 固定计划与边界

完整核心／桌面检查通过后，以同一份默认feature、release／offline／locked构建运行两轮标准N。窗口1180×800，默认GPU设备策略及原QueueWrite上传，不启用framework-trace、MemoryUsage或暂存复用候选。两轮之间不修改源码、重建或调整门槛；数值硬项失败仍保留并完成预定第二轮，协议／运行失败停止该计划，不自动重试。

每轮真实加载100张自制1024² PNG、10文档／500层和原16种自制WAV，活动文档50层引用10张原图。背景来自自制360秒WAV，沿用四块2048帧PCM及8192字节原始缓冲的读取器；300秒播放不依赖GUI供给。每秒8次场景触发共2400次，另64次显式试听，300次同时修改图层组透明度和音效增益的草稿更新，以及20次文档切换。新声音未就绪、错过125 ms调度护栏或未发布的修改被覆盖均明确失败，不能补发一阵请求伪造连续负载。

修改安排在每秒562.5 ms、切换在1.0625秒起每10秒、试听在31.25 ms起每4秒，与125 ms场景触发错相；这是诊断负载的固定相位，避免故意在同一GUI回调刚提交声音后立刻取消其来源，不属于产品时序规则。所有事件仍由真实GUI回调执行，音效通过原应用端口或既有场景适配器控制。诊断提供受控焦点，实际输入继续计数，不冒充物理点击／IME或OS输入队列延迟验收。

每个请求均保留请求ID、完整来源核对、Voice ID和通道；首次原生有效样本复制由既有1 ms有界观察线程记录，再与精确回执匹配。场景2400及试听64份均纳入各自p95，另外记录p99／最大值及GUI后续匹配时间，不扣观察余量，不用新计数器替代目标Voice。诊断保留上限4096份元数据，不持有PCM；旧短测仍保持原192上限。回调代码未改动。

300次编辑从命令执行前至同修订／草稿／目标的GPU画面发布观察计时，20次切换另列。结束后冻结、将300次草稿一次提交、验证暂停下独立试听及停止静音、恢复背景、再次冻结；随后启动已核实来源的长声音，再执行草稿取消及Undo／Redo，检查旧声音在自然结束前失效、背景不重置及租约释放。最后关闭原生端点和图形worker，丢弃项目会话，检查原始／PCM／RGBA／图形目标／源GPU／暂存实际归零。此单次关闭不替代C3的20轮完整循环。

## 判据与计量

遵守[预算v2](RESOURCE_BUDGET.md)：全生命周期零欠载、无故障／观察溢出，完整请求至原生复制观察p95≤20 ms，编辑发布p95≤50 ms，框架CPU帧p95≤16.7 ms；长帧、p99及最大值另列。进程工作集／私有提交采样峰值各≤512 MiB；GPU PID dedicated≤256 MiB、shared≤128 MiB，Playing／Closed不允许缺失样本，加载期已知超限同样失败，启动未知样本单列而不当作零。受管配额与实际回收门槛不变；OS累计历史峰值与采样峰值分别记录。

CPU≤15%仅保留优化目标。本轮不延长现有240秒提升采集器的会话上限，不新增UAC或把分段CPU窗口冒充完整300秒独立计量；保留未经修正的GetProcessTimes原始Playing值，独立有效性为false、目标是否达成为未知。低原始读数不能宣布优化目标通过，CPU目标缺少有效计量不单独否决本轮其他硬项。帧耗时与原生／GPU／内存判据各自独立。

像素由同一冻结构建的自有GPU直接回读复查，不使用系统窗口捕获。输入、设备消费／声学起音、真实谱面和其他平台不继承本轮结论。以下实际结果仅关闭当前Windows分离声音候选的C2硬项，不等于P2全部完成或普通声音默认已晋升。

## 首个计划失败及修复

初始默认发布`e303d289d9db0e15a4cb4884ec2bc75feac93614fb3733114f3f86eaf1ac6bb0`的第一轮完成300.009362秒、2400场景／64试听、300修改及20切换，累计缺失帧0；但诊断在转入阶段4时，用缓存的阶段3时长检查了新阶段，误触发30秒控制护栏。协议失败后停止该计划，第二轮未开始；`artifacts/p2/current-combined/native/`原样保留。

该轮仅有未完成的partial report：场景／试听p95为12.2863／12.1172 ms，编辑发布p95为11.1547 ms，框架CPU帧p95为3.7337 ms，单帧最大23.3716 ms；采样私有提交508.875 MiB、工作集300.551 MiB，已知GPU dedicated249.816 MiB／shared44.594 MiB。它们不能关闭本轮验收，尤其partial里的初始零值不能作为清理证据，分析器明确拒绝completed=false。

修复仅涉及新的诊断状态机：阶段与进入时刻由同一StageClock维护，每次控制前检查当前阶段的时钟。补齐完整300秒后转阶段、逆序时间／多次控制重置及1秒旧声音清理护栏的三项确定性回归；护栏必须先于“已就绪”分支执行，防止用长声音自然结束冒充取消／历史清理。没有修改声音供给或预算。修复后重新检查、冻结新构建，并启动全新的固定两轮计划；不追认旧失败、不混合构建或选取它的安静窗口。
