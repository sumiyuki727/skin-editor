## 观测与依赖

host默认关闭的`framework-trace`增加可选直接依赖winit `=0.30.13`，默认features关闭、不增加其features；它此前已由eframe传递依赖。锁文件仍为363个package，没有增加或升级package；只是host增加明确直接边。边界检查约束可选性、版本、feature和所属模块，负向回归拒绝默认启用、额外平台features或不可选依赖。

显式诊断通过eframe公开`create_native`和winit的`ApplicationHandler`／`run_app_on_demand`组装，逐项转发new_events、about_to_wait、window／user／device及生命周期回调，不自行泵消息、改变ControlFlow、优先级、计时器或重绘策略。普通产品及feature构建未安装Subscriber时仍走原run_native入口。新旧CPU不能跨入口相减制造收益；本次A／B两侧共用相同新入口。

格式3在原1–18类别后添加19–24回调类别，原容量保持32768个span、4096个pass、128个来源；仍是原约4 MiB有界记录器，无第二套长期缓存。不记录消息指针、原始输入值或文字，不进入音频回调或项目端口。格式1／2仍按各自类别上限读取，不能把缺失的新回调当作0成本。实际平台仅Windows已验证，Linux／macOS实测未完成。

`tools/measure_event_loop_ui.py`固定A／B／B／A、全部相同观测。互斥区间先完整校验结构，再与同一main、同窗QPC调度求交；回调返回到下次进入的间隙另行分组，分组总和须与scope外占用完全一致。它们包括消息派发、等待、原生钩子、观察和未分离ISR／DPC，不直接归为winit或驱动函数。墙钟路径不推算CPU。

## 候选与保留的失败

A为独立的被动状态Label；B将最多五条状态文字合为一条每pass新建的Label，不保存Galley、Response、字体／图集、项目快照或延迟错误／准备状态。监听和编辑控件仍逐帧运行。宽度、字体、Context及来源文字变化有无窗口回归；原生回读中只有预期的文字块间距变化，未发现重叠，预览及七组合成字节完全一致。

实验前已规定：固定组条件有效、无功能／资源／像素失败，且两轮候选均至少比两轮基线低0.5个百分点才考虑采用；这仅是本候选的取舍条件，不替代15%产品门槛或统计置信度。不能只靠减少Label数量、某个父段变低或单个较好窗口采用它。

首次采集器UAC返回1223，参考和产品均未开始，记录在`native/`。随后固定普通权限四轮，第3轮UTC／单调时间偏差85.1 µs超过原50 µs门槛。保留原始第3轮、不重跑它，仅补齐原计划第4轮；整组墙钟比较无效，也没有独立CPU资格。记录补写工具曾读错报告字段，修正路径后完成余轮，失败日志一并保留。

用户明确要求重新触发UAC后，在`native-v2/`重新完成严格参考及完整四轮；不是筛掉上述失败后补成一组。两轮连续参考99.999362%／99.978320%，不同相位／长周期2.466414%–2.578408%，零漏周期，原校验全部通过后准入产品。runner／产品普通权限，仅两次只读采集器提升；无事件／buffer丢失或句柄遗留。
