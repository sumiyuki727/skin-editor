# P2-A3 文档切换与候选准备

2026-10-22。延续[标准组合验证](P2_COMBINED.md)，处理该轮每次切换约 50–58 ms 的交互长帧。旧证明保留原身份；本轮不引用 P0 实现、不增加依赖、不改变模型、Command、Frame 或音频协议。当前仍是静态图层预览与自制音效控制，没有 stable 游戏内核。

后续提交观察与 GPU 成本的分层计量见[归因记录](P2_RESOURCE_ATTRIBUTION.md)；本文两轮成绩和证明保留原身份，不用新的观察追认旧轮通过。

## 归因与实现

先在同步路径增加分段时钟，以相同标准 fixture 的 3 秒控制轮重复两次。记录实际 `Editor::ui` 调用区间及其前后候选轨迹索引，避免把上一帧 eframe CPU 值误贴到当前请求。

| 切换时同一次 GUI 调用／准备，ms | 轮 01 | 轮 02 |
| --- | ---: | ---: |
| Editor::ui 调用 | 49.234 | 49.567 |
| Plan 构造 | 0.015 | 0.018 |
| PNG 派生缓存重建 | 21.842 | 22.050 |
| 原图打包 | 6.674 | 7.071 |
| create_buffer_init 上传准备 | 14.820 | 14.828 |
| 编码与队列提交 | 0.288 | 0.290 |

每轮该调用的索引恰好包含对应文档的新原图准备；这给出直接调用区间证据，但不将短轮外推为上一轮全部 20 个长帧的逐帧归因。上传计时包含 CPU／驱动调用，不是 GPU 执行时间，发布观察也不是物理显示时间。

NativeHost 现在拥有一个 `preview-prepare` 工作线程，同一原生 Device／Queue／GpuComposer 会话复用。GUI 只构造只读 Plan、固定所需原字节及提交一个任务；后台完成 PNG 重建、打包、上传和合成提交，返回私有候选。后台不接收 SkinProject、ProjectSession、UI 或项目写入口。GPU 句柄只在宿主／渲染适配内交接，UI 仍只消费不透明 FrameKey。

一个会话最多一个正在准备或尚未收取结果的任务，没有预取队列。取消立即标记来源失效，但直到收到实际完成才归还准入；每张 PNG 之间检查取消，不能打断单张解码或已经发出的驱动调用。原始字节随任务固定，RGBA 仍共用 64 MiB 软目标／80 MiB 硬预留；没有因后台化另建图像缓存。导入 worker 与音频 worker 各自沿用已有边界。

迟到成功保留原始会话、历史修订、草稿、目标、视口及取消标记；不同内容不能发布。静态占位画面允许时间／场景描述别名，沿用已有静态语义，不能推广为未来动画或玩法场景的重用规则。旧画面继续显示，编辑命中仍核对来源。已经提交 GPU 的取消结果仍交给宿主跟踪到完成，不以逻辑取消冒充资源释放。关闭先取消／接收并加入准备线程，再清理原图缓存；未完成目标保留强租约到 GPU 回执，CPU 待绘数据另持最后读取租约。设备故障与恢复尚未验收。

分段轨迹只由显式组合诊断启用，最多 512 个准备条目及 256 个超过 8 ms 的 GUI 调用，溢出判失败。条目保存完整来源和准备／发布观察；普通编辑器不累积轨迹。渲染每次准备仅携带固定大小 CPU 阶段计时。原生音频回调没有增加计时、分配或等待。组合分析新增最大 CPU 帧 16.7 ms 门槛，保留 p95，不能靠分位数隐藏少量长帧。

发布延迟的起点是当前 `PreviewPort` 请求构造 Plan，不是 Command 接纳；冷重建与复用分别统计，仍不关闭完整 B08。画布和窗口沿用标准 1180×800 的静态编辑负载、正常控制期限与 GPU 唤醒，框架 CPU 帧并非固定 60 Hz 游戏帧。工作集、私有提交、GPU dedicated／shared 分别计量，仍保留 512／256／128 MiB 门槛，未相加或抬高预算。

仅后台化后的两轮 300 秒未通过全部门槛，证据保留在 `artifacts/p2/switch-acceptance/`：CPU 帧最大 6.705／7.251 ms，长帧均为 0，但试听提交 p95 20.968／21.187 ms 超过 20 ms，第二轮 GPU dedicated 约 262.008 MiB 超过 256 MiB。原图内容上传各 21 次，每次换源仍重新分配 buffer；不能把 GUI 改善描述为完整预算通过。第二轮 CPU 计量明显低于第一轮，保留原始样本，不作单因素性能收益归因。

随后尝试带 2 ms 超时的控制接收，原生音频检查出现 60,352 帧欠载，证据保留在 `artifacts/p2/switch-final-acceptance/`，该路线已撤回。没有据此认定所有平台的等待定时行为；具体等待／调度成本未细分。另试 1 ms 休眠／640 帧前送：短轮与 40 次空输出启动通过，但两轮 300 秒中一轮欠载 384 帧，另一轮试听 p95 20.544 ms 超标，记录在 `switch-bounded-acceptance/`，同样不予保留。不能用 640 帧版本的 GPU／长帧成绩掩盖声音失败。

最终产品恢复原有 2 ms 休眠供给、768 帧前送；2048 帧启动预填、480 帧周期下的 960 帧空闲需求／向上取整 1024 帧储备及 192 帧切入保护均未改变。保留有效背景／已调度事件，不能将其当空白丢弃；不对任意回调突发或其他设备保证无欠载。外部 `yield_now` 探针试验于约 219 秒因 484.507 ms 触发迟到中止，1753 次触发／219 次编辑不足标准轮；记录包含 1440 空帧、1056 帧回调及 owner 最大间隔 56.170 ms，见 `switch-reviewed-acceptance/`。不能据此认定观察器、系统调度或驱动中的某一个是原因。该观察方式也已撤回，最终仍用原来的 1 ms 休眠探针，并记录实际最大轮询间隔，不宣称生产延迟改善。

原生边界新增固定 32 条欠载记录（回调序号、请求帧、进入队列量、空帧及前后供给序号），总欠载回调数不截断；超过容量可从总数识别。回调只有固定原子写入，没有时钟、分配、等待或最后 PCM 释放；新增约 1.5 KiB 固定元数据，读取／序列化在控制端。组合轮另记录供给 owner 的最大间隔，帮助区分后续排队／供给问题；这些值不能单独证明系统调度或驱动原因。

GPU 原图缓存容量足够时用同一 buffer 的有序写入替代重复分配，容量不足才重建，容量计量按实际保留大小。原图内容上传与分配分别计数。渲染提交互斥区串行化写入及 compute 提交，队列顺序保护旧计算，输出纹理仍不可变；写入显式 flush，后续编码失败也不遗留未提交的 staging。独立原生对照在首次 compute 未 poll 前连续提交 A→B→A，核对三张输出互不污染及只分配一个 buffer，不能仅用计数证明像素正确。

## 本轮验证

确定性门闩测试覆盖单信用准入、运行中取消不提前释放、迟到成功保持原来源、满结果通道关闭、错误后恢复准入；真实 PNG 验证派生复用、取消及无效输入诊断。来源检查覆盖会话、历史节点／修订、草稿取消／修订、目标和视口。原生回读单独检查像素、冻结刷新、取消、历史／尺寸切换和旧绘制租约，不与性能采样同时运行。

短轮预检中，后台准备时没有超过 8 ms 的 Editor::ui 调用；51 个框架 CPU 帧最大 5.902 ms。文档切换发布约 55.380 ms，期间仍显示旧内容；回调空队列 0，资源计数最终归零。该轮不是 300 秒或全部生命周期证明。
