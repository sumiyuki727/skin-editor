# P2-A3：真实帧标记与独立上传 API

2026-10-26。补齐两种显式宿主诊断，普通产品不安装观察插件、不新增缓冲／缓存层。741项默认检查通过；同一冻结发布构建的两轮真实帧标记、两轮独立上传及原生像素回读通过。上传区段墙钟较短，现有证据不支持新增中间打包层；正常提交／呈现的CPU成本仍需直接分离。P2-A3未验收。[结构化证明](P2_GPU_PATH_PROOF.json)保留本轮记录与48份旧证明身份。

## 真实帧的观测边界

`--verify-gpu-path-gui`沿用原GUI、32 Voice、背景及生命周期脚本，只在32 Voice阶段给当帧新鲜FullOutput前后插入两个不绘图的Callback。每帧固定标量槽，最多512帧；不请求重绘，不返回额外命令缓冲，不替换原网格或纹理更新。声明将丢弃的pass单列计数，缺失／迟到／逆序／重复边界不补值。两轮记录129／128帧，无丢弃、溢出或缺失。

锁定eframe／egui-wgpu 0.37.0公开接口的实际顺序是：框架tessellation后调用App.clear_color；Painter建立encoder、更新纹理及顶点／索引缓冲；所有prepare之后执行finish_prepare；随后获取surface并开始render pass，再按顺序绘图。利用这几个公开边界记录：

| 区段 | 第1／2轮墙钟p50（ms） | 边界限制 |
| --- | --- | --- |
| output hook→clear_color | 0.2750／0.2640 | 包含正式tessellation及集成工作，不是纯Tessellator |
| clear_color→首prepare | 0.0875／0.0855 | 包含encoder建立、纹理更新、实际buffer上传；不能只叫暂存复制 |
| 首prepare→末finish_prepare | 0.0009／0.0009 | 回调prepare／finish工作 |
| 末finish_prepare→首paint | 0.0628／0.0624 | 包含surface配置／获取及render pass建立 |
| 首paint→末paint | 0.0113／0.0083 | 实际绘制编码，含两个标记导致的状态边界 |
| 末paint→完成通知观察 | 15.3275／15.4381 | 包含finish／submit、GPU／队列／poll及调度；不是CPU submit、present或GPU执行时长 |

最后一段p95为15.9592／16.2429 ms。完成通知可等待下一轮poll才被观察，不能将这约一帧的间隔全部归因给GPU、驱动或CPU忙碌。正常Painter的submit和present没有公开成对前后钩子；没有改写第三方源码，也没有拿App.clear_color或完成通知伪造这些边界。

增加两个Callback会改变框架的状态重设与遍历成本，因此是有扰动的定位模式；其墙钟不得从产品CPU扣除或乘帧率追认预算。普通路径的独立CPU另测。

后续[多pass回归](P2_FRAME_DISPATCH.md)确认output_hook执行时Context的内部output已取走并重置，旧标记模式的Context::will_discard过滤不能可靠识别此时输出的丢弃状态；旧两轮全部边界完整核对仍保留，不能扩称任意多pass均验证通过。新入口从当前FullOutput判断丢弃并记录来源；旧辅助过滤修正仍待单独回归，不依赖其discard计数作新归因。后续[官方框架区段](P2_FRAME_DISPATCH.md)已获得实际正常submit／present的包围区段，区别于本页的独立上传和完成通知。

## 独立缓冲的真实上传

`--verify-upload-api-gui`在同一个device／queue上提前建立独立egui-wgpu Renderer，不借用活动renderer的可变引用，也不覆盖正式绘制缓冲。只在第1／33／65／97份新鲜输出运行，每份连续四次，共16次；单列源克隆和tessellation时间，过滤所有原生Callback，不执行预览prepare／paint。实际调用独立Renderer.update_buffers、encoder.finish及queue.submit；提交只包含上传，无绘图或surface呈现。

| API | 第1／2轮p50（ms） | 第1／2轮最大值（ms） |
| --- | --- | --- |
| create_command_encoder | 0.0011／0.0011 | 0.0041／0.0043 |
| update_buffers | 0.0530／0.0575 | 0.2118／0.1435 |
| encoder.finish | 0.0009／0.0011 | 0.0065／0.0063 |
| queue.submit | 0.0471／0.0388 | 0.1377／0.1342 |

首次调用和其余15次分别保留，不能将第一笔容量增长当作每帧成本，或排除它来追认通过。完成回调可能在queue.submit返回前执行，解析只要求完成不早于submit开始，不减去CPU返回时刻制造负GPU耗时。共用queue可能刷新其他待提交工作；独立上传不是原呈现的精确替身，不能据此把正常提交成本判成0.04 ms，也不能据此给write_buffer_with内部取得暂存与复制分别计费。

准入限制为2048个源节点、32层嵌套；tessellation后顶点／索引≤32768／131072、mesh≤2048、视口≤8192²，再调用真实上传API。自有记录固定四份源元数据和16次API计时，不跨帧保留绘制对象／Galley／回调。第三方tessellator的任意输入内部临时分配没有因此获得全量预算保证。

## 所有权、清理与验证

真实帧完成回调只持有预分配标量Trace的Arc，不含项目、PCM、GPU租约或重绘请求；迟到回调写回原固定槽，不能用当前pass槽覆盖新帧。独立Renderer只属于诊断宿主：停止音频／宿主之后，以有界device Wait排空，再移除Renderer，重新poll并记录分配器状态。回调运行期间不等待设备。

两轮分配器记录均为：创建前558160字节，创建后591552字节，关闭后2005952字节；保留块始终12 MiB。这些时点处于不同的应用生命周期，关闭时仍含框架字体、UI缓冲等资源，不能拿总量差值证明探针泄漏或即时回收，更不能充当swapchain／驱动／整机GPU预算。原始分配名和块记录完整保留。

新增五项Rust及四项Python回归，覆盖有界槽、重复／迟到边界、引用释放、原Shape顺序／纹理更新不变、关闭后不再观察，以及缺失计划／完成／释放拒绝。完整默认检查为251 Python＋130核心Rust＋360桌面Rust，格式、Clippy、无窗口测试和模块边界均通过；连续两次发布构建SHA一致。

基线、当前普通路径、当前标记模式的preview.png／editor.png及七组合成pixel_trace.rgba逐字节一致，最大通道差1（原门槛2），没有系统窗口捕获。四轮诊断的原声音／生命周期检查全部通过，零欠载；提交观察p95最高12.5193 ms，单次最大13.4236 ms。PCM2435072→0字节、原始读取8192→0，回调受管释放0，端点回调内交还0／范围外交还1，最多2个正常GPU目标；独立Renderer的缓冲不冒充正常目标计数。
