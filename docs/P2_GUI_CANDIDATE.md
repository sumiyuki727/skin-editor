# P2-A3：候选 GUI 控制与状态观察

2026-10-23。接续[有界 worker 原生短轮](P2_WORKER_NATIVE.md)。普通启动保留原输出；`--candidate-audio` 显式选择候选，音频设备仍由界面按钮启用。音频素材库、组件绑定／增益草稿、显式试听、冻结、取消和历史继续共用原 application 入口、单准备 worker、16 份控制额度、32 Voice 及共享 PCM 预算。图片和声音仍独立，没有新依赖或项目写入口。

## 控制与观察

EditorAudio 管理候选 NativeExecutor 与 AudioSupplyClient；关闭先门控并 join 供给，再销毁原生流、取得准确端点，最后交回所有者并释放 PCM。监听音量是独立 0–1000 原子值，在最终缓冲复制后、发布实例观察前应用，不修改项目或准备缓存。越界拒绝并保留原值。正常 GUI 主动排空有界首次复制记录，避免长时间操作耗尽观察队列。

AudioEditor API 从 2 升到 3，增加只读 AudioOutputObservation：输出格式、回调／欠载计数、背景生成与复制位置、有限来源长度及 PCM 计费。它不含设备、Runtime、项目可变引用或原生句柄；UI 经 application 的呈现值显示。Rust 调用方升级当前常量并处理可选观察；没有新磁盘格式或项目迁移。迟到触发回执保留真实完整来源，界面将与当前来源不符的结果标为旧版本，不能显示为当前来源的新声音。

普通候选 GUI 尚未接歌曲来源，明确显示“背景音频尚未载入；可试听音效”。内部使用已到 EOF 的单帧静音引用，仅计费一帧，不伪造持续背景／歌曲位置。短轮诊断另外注入同预算内的自制 10 秒有限背景，未达到 EOF 才能通过；仍不代表实际谱面／流式音乐已经接入。

新增 GUI 回归先暴露了取消后的观察滞留：旧回执仍报告草稿，而实际声音与 PCM 已经退休，无后续请求时客户端一直保留该记录。现在供给状态与回执带有本客户端单调观察版本；不早于该回执的已发布状态可替代旧记录。如果状态发布因 GUI 查询而竞争失败，保留旧回执和已知状态的并集，不能提前宣布清理。版本耗尽报错关闭，不借用项目修订或历史 ID。回归同时核对实际退休及旧发布不能提前消除保护。

## 验证边界

无窗口测试使用真实单 worker、手动推进的软件端点与控制回执；没有真实设备、窗口捕获或 sleep 竞争猜测。覆盖未载入背景、候选准备状态、运行／冻结和独立试听、停止前门控、草稿取消／历史往返、迟到旧来源标签、最终 PCM 释放、监听音量及观察句柄唯一转移／不固定 PCM。

GUI 短轮另暴露了静态 GPU 候选的发布饥饿：接受准备结果时允许相同材质的时间别名，GPU 完成时却再次比较完整时间来源。运行中的时钟使新图反复无法发布；首轮两秒内约 170 次分配，32 Voice 进程 CPU 达到约 49–54%。修复后，最终发布也通过同一材质边界核对，并赋予当前请求的 FrameKey／时间描述符。会话、项目修订、文档、草稿、尺寸及视口代次仍须一致，已取消候选仍拒绝，GPU 租约与像素不变。新增回归先复现失败，再覆盖 10000 次时间／场景推进及七种不允许的来源替换；原生轨迹另外限制静态热替换阶段的重复分配。

`--verify-candidate-gui` 打开真实 eframe、EditorUi 和 NativeHost，绘制自制示例图片与音效窗口。受控动作从 GUI 回调调用同一 UI／application 控制入口；场景声音由 GUI 内的预览 fixture 事件通过同一适配器触发。**没有模拟物理鼠标点击，也不包含操作系统输入队列到 GUI 分发前的等待。** 音效经真实 WAV 准备后，两通道各触发 64 次，再核对 16＋16 Voice、第 33 个拒绝、热替换、暂停／独立试听、停止后的实际提交非零计数、恢复、草稿取消、撤销／重做和关闭回收。

首个计划使用实际窗口焦点，取消轨迹等了接近三秒，不能证明杀掉了活动草稿声音：UI 可能已经按正常失焦策略取消草稿，之后试听的是提交版本。该计划整体失败并保留，原来的取消布尔值不作为证据。最终 schema 2 诊断明确提供受控 focused 输入，验证试听来源的草稿 ID／修订，再确认显式取消；一秒诊断护栏排除三秒样例自然结束，不是新增产品取消时限。真实失焦及尺寸变化的取消行为仍由既有无设备 UI 测试覆盖，这不证明 Windows 实际授予了焦点。诊断运行中保持 16 ms 刷新请求，空闲／关闭用 50 ms；音频供给和首次复制观察不依赖这些刷新。

计时起点在 GUI 动作分发前，包含 application 同步、控制排队、worker 接纳、混音和实际原生缓冲复制。由独立、有界、仅诊断的观察线程每约 1 ms 读取首次复制元数据并记观察时刻；按请求回执中的精确 Voice ID 与通道匹配。它不接触 PCM、项目、解码或原生流控制，CPU 计入本进程，观察延迟不扣除。原生回调仍不分配、不等锁、不读时钟、不承担资源析构。GUI 下一帧完成匹配的时刻另记，不能把界面晚看到结果混作声音晚提交，也不能把它改写为首次观察时刻。该区分不证明设备消费或声学延迟。

固定同构建计划为 worker 前测、GUI 1、GUI 2、worker 后测。每个进程独立采样 CPU／工作集／私有提交；GUI 短轮包含一个示例图的真实呈现，不是标准图形负载，也不代替 GPU 预算、像素对照或两轮 300 秒组合。原零欠载、提交观察上界 p95≤20 ms、单逻辑核 CPU≤15%、进程内存≤512 MiB 和 PCM≤32 MiB 保持；所有阶段及失败单独保留。

最终检查、原始记录与结果见[本轮证明](P2_GUI_CANDIDATE_PROOF.json)。**本增量不晋升默认，不关闭 P2-A3。** 有界持续背景、回调分配器／析构线程实测、实际歌曲、设备消费／残余、跨设备／平台及重新组合后的 300 秒验收仍待完成；文件导出继续属于 P3。
