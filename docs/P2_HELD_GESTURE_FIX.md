## 原因与修正

锁定的egui 0.37中，`Response::drag_delta()`是本帧位移，不是从按下开始的总位移；`PointerState::total_drag_delta()`才使用当前位置减按下原点。旧代码每帧把本帧增量应用到手势开始时的固定变换，鼠标不动的重绘帧会得到零增量，因而把候选重置为原变换。新增的真实egui输入回归先复现了该错误，不依赖真实设备、窗口捕获或sleep。

现在使用捕获的按下原点与当前位置计算总位移；本帧是否移动只用于跳过重复工作。手势模型继续持有固定父变换／比例／变换基准，所有项目修改仍通过application的草稿与Command，一次松手才提交历史。没有修改导入是否入历史、分支／Undo规则、音频策略、GPU配置或依赖。

额外边界回归证明，只替换为`total_drag_delta()`仍会漏掉“移动与松手在同一帧”的最后一段位移，因为egui已结束drag。最终修正会在松手帧读取最终指针位置，先更新候选再提交；仍可返回最初按下位置并作为无效操作结束。
