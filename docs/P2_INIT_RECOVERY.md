# C4 交接消费后的初始化失败与重试

2026-10-28，继[呈现中设备故障](P2_PRESENT_FAULT.md)后的有界增量。**显式MemoryUsage候选的三个交接消费后失败位置、状态保留和后续重试在当前Windows范围通过；C4及P2仍未整体验收。** 结果、源码／构建身份和日志哈希见[证明](P2_INIT_RECOVERY_PROOF.json)。原声音供给与默认启动策略不变；零欠载、提交p95≤20 ms、内存／GPU及资源释放仍为硬项，CPU≤15%仍为优化目标。

## 原问题与所有权修正

旧路径消费Seed后构造NativeHost、导入worker，再执行音频及观察器初始化；后面的`?`可能直接丢弃已移入局部Editor的ProjectSession。此前App创建拒绝发生在消费交接之前，不能证明这条路径安全。

现在交接先进入desktop内部的单所有者slot。取出交接、构造Editor后，由初始化Attempt继续持有整个原会话；导入、音频和观察器全部就绪才commit给实际窗口。返回错误或取消时先退休本次运行时，再把同一个会话放回slot。没有重新创建ProjectSession、从快照载入项目、复制一份可变项目或提交补偿Command，项目写入仍统一经过application。

Seed的早期构造错误也返回原交接；GPU配方可在构造期间借用，成功或失败后的资源寿命仍由外层原生所有者管理。失败宿主退休时保留其已推进的FrameKey／分配游标，后续重试不能重新解释旧帧。配方不包含旧Device、Queue、Renderer、Texture或egui Context。

失败清理依次关闭观察线程、门控并归还音频端点、关闭导入线程、取消预览准备、销毁该次自有设备并取得真实Destroyed通知、释放旧CPU绘制持有，再将无GPU交接返回slot。worker必须成功join，受管目标实际归零；未成功清理时仍保留整个Editor所有者并标记错误，拒绝再次初始化，不清空计数或提前退还预算。当前测试覆盖正常错误后的成功清理；真实设备长期不响应、原生清理失败等仍须另验。

上述候选的成功窗口创建路径也采用这层保护，观察器成功转移后才发布Editor。它是窗口恢复候选内部的所有权保护，不是项目文件保存／加载接口；普通启动仍未晋升为自动恢复。

## 固定三用例

`python tools/measure_present_fault.py --initialization --binary <冻结release> --build-receipt <构建回执> --out <新绝对artifact目录>`固定执行三组，各启动自己的普通权限进程，不自动重试失败轮次。子入口仍为`--verify-present-fault`，增加下列三个明确的plan，回执和测量由runner协调。

| plan | 真实失败位置 | 资源与保留要求 |
| --- | --- | --- |
| init-consumed | slot交接已取出，原Session已进入实际Editor，Host及导入worker已构造 | 返回原会话，退休本次设备／线程和框架对象；没有准备帧时last_frame_key为0 |
| init-prepared | 已完成一帧，并有一份完成但尚未接纳的准备结果；另持有真实egui CPU绘制数据 | 失败清理时旧绘制确实保有目标，释放后才退休；记录待处理FrameKey，重试拒绝该键 |
| init-audio | 在上述基础上，真实输出已启用、候选WAV就绪且实际产生原生回调，并启动独立观察器 | 保持暂停，关闭观察器和音频，核对欠载／错误／端点归还及PCM租约，保留原背景复制锚点 |

三组都返回受控AppCreation错误，随后检查原会话，再按预先声明的计划开启下一窗口。这是一次失败后的明确重试验证，没有无限自动重建循环。初始化失败发生在实际新Editor构建之后，包含真实GPU／线程／音频工作；不是只在函数入口返回错误。

每组仍有两代完整Editor窗口，采用现有分离声音及持续背景路径，恢复前后场景／显式试听各32次，另包含resize、真实96→120 DPI与最小化恢复。失败App创建未进入正常绘制，因此该次surface、device／queue／texture／buffer注册表严格为空；呈现中销毁的首代仍按[前轮规则](P2_PRESENT_FAULT.md)保留未登记ID原值并退休整个Instance，未把原始非空结果改写为0。

## 项目、历史与旧代次

使用经Command建立的自制图片／WAV和两个不解释兼容语义的Opaque配置分支，先建立历史再开启原生输出。样例有6节点、2个分支编号及1条普通Redo路径记忆；配置分支不改变规范图像。

初始化失败前后对比完整活动快照（含会话、head及修订）、全部节点摘要、父子关系、分支坐标、每个历史节点的项目值，以及历史统计／请求保留数。内部节点地址和分支短地址逐一解析回原节点，失败没有增加项目修改、历史节点或导航操作。历史快照只用于检查，未用于恢复。

两代窗口一致性检查完成后，再通过真实application导航执行普通Redo／Undo，确认返回Undo前记住的第二条分支、保留另一分支，并回到原内容。这个显式导航验证会推进导航修订和回执，但不添加历史节点；它不属于失败回滚，不拿它追认“失败期间完全未变”。

重试窗口拒绝失败尝试的待处理FrameKey；失败设备的通知，以及音频用例中已关闭端点的失效信号，重放后不能使新代失效。首次使用新窗口时仍暂停、Voice为0，背景复制位置为**243840帧**；失败音频回调不推进该锚点，显式恢复后推进至486720帧。初始化耗时不补入游戏时间，不重新从歌曲起点播放。
