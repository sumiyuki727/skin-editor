## 原因与语义

场景决定预览内容，操作工具决定输入用途。切换到原“交互场景”仍保持编辑工具和选择，这是二者独立的预期行为。编辑→交互工具已有清选逻辑，缺陷在于图层／组件面板及程序化选择入口未限制工具状态，可以在清除后重新选中；变换框几何查询也没有独立的模式限制。先前自动测试只检查切换的瞬间，未覆盖后续重选。

本轮不把场景切换改成工具切换，也不增加项目修改或历史规则。顶部使用两行明确标识“预览场景”和“操作工具”，场景名由“交互场景”改为“GUI 占位”，并说明它只切内容。图层面板在交互工具下解释：仍可切换预览元素，图层编辑选择已关闭。

## 实现边界

- 编辑→交互工具沿用本UI草稿的取消与清选；已提交内容、历史和预览目标保留，切回编辑不恢复旧选择。其他适配器的草稿所有权继续隔离。
- 图层、嵌套组和视觉组件行在交互时禁用选中；`select(Some)`／`pick`／`toggle_selection` 同时在公共UI选择路径拒绝接纳。不能仅依赖按钮禁用或下一帧清空。
- 被拒绝的选择请求是无副作用的：不取消已存在的编辑草稿，不切投影目标，也不写项目／历史。交互工具内仍可进行独立音效编辑，不能每帧无条件取消所有UI草稿。
- `selection_geometry` 在交互时不返回控制框，已有缓存也不能显露。画布拾取与变换仍由既有工具门控；游戏 GUI 点击及键盘焦点路线保留。
- 素材入库／添加图层继续经application执行；交互状态下成功添加图片不会自动开启视觉选择。这不改变导入的历史语义，不删除素材或重写层级。
