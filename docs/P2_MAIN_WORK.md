## 普通权限与生命周期

`tools/measure_main_work.py` 必须由未提升的Windows runner运行，接受真实非提升的Default或Limited令牌。它只经UAC启动已编译的自有ETW采集器，不从提升进程构造令牌，不借用其他应用身份，不修改系统策略、桌面ACL、优先级、亲和性或全局计时器。无需产品用户安装C诊断工具。

普通runner保留进程句柄及创建时刻，创建两个新鲜的有界命名事件。采集器核对runner仍存活、PID／创建时刻、相同用户及非提升状态，启动自己的QPC调度会话，准备完成后才放行。采集器只观察已核对runner后续创建的后代；runner自身只作为父身份，不把其已有、起止不完整的线程纳入调度区间。只保留自有后代的调度事件，不保存其他进程名称、路径、SID、调用栈或ETL。

每个测试Python子进程先等待独立准入事件。父进程通过自有Popen句柄核对其令牌、纳入关闭即清理的Job后才释放准入；它再创建实际GUI进程。等待、任务数、事件和线程容量都有上限，失败或取消清理自有进程；提升采集器不创建、恢复或终止目标，仅停止自己的会话。普通runner、子runner、实际GUI及采集端摘要分别核对。四轮均为非提升Limited，实际GPU仍为RTX2060／NVIDIA560.94／Vulkan；不是跨设备或跨平台结论。

第一次完整普通采集因73次线程身份错误被拒绝，原始记录留在 `artifacts/p2/main-boundaries/native/`，不从中提取CPU成绩。长会话暴露了旧采集器把已结束TID在其他进程出现也当成冲突的问题。修正后，已结束线程的映射可退休，其他进程的新生命周期独立登记；外部线程只导致旧映射失效，不登记其身份。活动身份碰撞、同一产品进程内不能可靠区分的TID复用及已登记PID复用仍拒绝。旧调度行保留原PID，不能把新生命周期的调度记到旧产品。新增C原生无权限自检覆盖重复Start／rundown、真实结束、外部复用、新自有生命周期和冲突；每次采集前先运行。

## main 边界与时基

正式宿主新增可选 `--verify-main-work-gui`；日常编辑及 `--verify-streamed-gui` 不记录边界。既有 `--verify-profiled-gui` 保持原用途。新标记不启用音频工作计时，不改声音供给、混音、背景、窗口大小、呈现策略或项目写入口。无新依赖、FFI或第三方框架修改。

边界记录由宿主持有，最多16384行、预分配约384 KiB，不进入音频回调。公开App回调在同一入口线程提供以下互斥区间；以同次PID／TID／PE入口身份和原32 Voice QPC采样窗，对每段求实际调度区间交集。分类和必须等于main调度总量，不能用墙钟相减推算CPU。

| 分类 | 真实边界及限制 |
| --- | --- |
| 应用逻辑 | `App::logic`，包含编辑器调度及该诊断回调的少量记账 |
| 应用UI | `Editor::ui`，包含宿主预览／纹理操作；不是纯控件绘制 |
| 测试控制 | GUI诊断的`step`，与应用UI分开 |
| 框架UI／细分 | `raw_input_hook`之后至`clear_color`之前，排除上述回调；包含egui及少量宿主记账 |
| 呈现＋事件循环 | `clear_color`之后至下次输入钩子；包含wgpu／驱动调用、等待、事件分发等，**不是纯present、GPU执行时间或纯驱动CPU** |

锁定eframe 0.37.0的 `epi_integration.rs` 与 `wgpu_integration.rs` 已核对调用顺序：输入钩子先于logic／UI，根UI结束后细分图元，再调用clear_color和painter。没有公开的精确“present返回”钩子，因此不能把最后一类进一步强行拆成框架与驱动。边界调用密度也不是显示器实际帧率。

为保留Rust的unsafe禁令，宿主只使用标准库SystemTime和Instant。两者精度／实现受平台影响，参见 [Rust SystemTime](https://doc.rust-lang.org/std/time/struct.SystemTime.html) 和 [Windows精确系统时间](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemtimepreciseasfiletime)。runner以QPC前后夹住精确UTC读取，全部配对共同约束一个时钟偏移，包含慢读取，不能挑最快样本。配对宽度或偏移中点跨度>50 µs、UTC与单调记录差异跨度>50 µs、时钟区间无公共偏移、倒退或容量超限均拒绝归因。100 ns读数粒度和额外1 µs观察余量明确单列，不宣称为通用系统保证；不从产品CPU扣除。

后处理初版采用配对中点的宽保守余量，记录在 `analysis-v2.json`。最终改为所有配对区间交集，`analysis-final.json` 保留输入及分析源码哈希；原始采集和拒绝证明不改写。两轮共同偏移区间宽2.7 µs，边界定位观察余量2.35 µs；按边界数累计的分类不确定性上界约0.200／0.666个百分点，UTC／Instant差异跨度3.2／3.8 µs。此改进只收窄分类定位范围，未改变进程CPU值或使参考校验通过。
