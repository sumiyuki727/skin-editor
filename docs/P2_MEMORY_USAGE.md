# P2-A3 MemoryUsage 完整组合验证

2026-10-22，Windows。延续[分配器／提交观察归因](P2_RESOURCE_ATTRIBUTION.md)，将 `MemoryHints::MemoryUsage` 从 3 秒控制扩展到两轮完整标准负载，并单独验证像素和旧资源清理。它仍为显式诊断配置，普通应用默认配置未切换。项目模型、命令、历史、声音供给及合成语义均不变。

后续[提交／冷准备分段](P2_SUBMISSION_STAGES.md)已完成同构建交错控制和新的两轮完整组合；本文件与证明保留339项检查及当时夹界失败的身份，不追认通过。

## 配置与测量边界

eframe 和离屏像素控制共用同一个设备描述符调整函数，只修改 memory hint。保留 NativeOptions 的原 surface 策略，以及设备原有 features／limits；无窗口测试保护这一点。没有改变适配器选择、驱动设置、窗口尺寸、原图大小、派生预算或声音策略。

标准负载沿用 100 个自制 1024² PNG、10 个文档／500 层、16 个自制 WAV、2400 次场景触发、300 次草稿替换一次提交、20 次文档切换及每通道 64 个已就绪声音探针。每轮墙钟及原生提交覆盖 300 秒，使用普通 1180×800 编辑窗口和原有刷新期限。没有回读像素、系统窗口捕获、真实客户端或玩家媒体。

声音仍为活动前送 768 帧、owner 2 ms 休眠、观察侧 1 ms 休眠；没有变更 native callback、供给线程或音效清理代码。继续使用原 20 ms 提交观察上界门槛：夹住 20 ms 的区间不算通过，不用下界或扣除观察余量取代原门槛。该指标不是设备消费或声学延迟。

CPU 单逻辑核平均≤15%；框架 CPU 帧 p95 及最大≤16.7 ms；工作集／私有提交分别≤512 MiB；播放期 GPU dedicated／shared 分别≤256／128 MiB；原始／PCM／RGBA、目标数量和 Voice 上限均沿用已有约束。加载期、播放期、关闭期和 Windows 生命周期峰值分别保留；100 ms 采样可能漏掉瞬时峰值。分配器存活／保留容量不等于 PDH dedicated 驻留，不能相减冒充驱动成本。

验收器按显式 `--memory-usage` 选择完整入口，逐轮严格核对程序报告中的布尔配置；原配置、缺失或非布尔值不能被误记为 MemoryUsage 通过。短轮、完整标准轮和像素对照入口相互独立。

## 像素与生命周期对照

像素检查使用自有 Vulkan 设备／egui 离屏回读，与性能轮顺序执行。每种配置均对照同一 CPU 合成计划、每通道容差 2/255；另保存固定七帧原始 RGBA，跨配置要求字节完全一致，而不是只比较资源计数或两次都落在容差内：

1. 初始隔离组透明度。
2. 整个文档隐藏后的透明占位。
3. 暂停下的变换草稿。
4. 取消草稿后精确恢复。
5. 检出变换分支。
6. 检出透明度分支。
7. 过期尺寸拒绝后发布 257×193 新视口。

六帧为 256²，最后一帧 257×193，共 1,771,268 字节；只在显式像素诊断中暂存，不进入普通编辑器或性能轮。检查器拒绝缺帧、错误策略、像素漂移、不同适配器或清理标记失败。每个原生检查还验证 A→B→A 有序原图写入不污染旧输出，以及 CPU 待绘数据跨 shutdown 持有最后帧，释放后目标与原图缓存归零。性能轮另覆盖旧 Voice／事件、双通道、草稿取消／历史往返和原始／派生租约回收，不用像素进程替代组合生命周期证据。

339 项自动检查通过：核心 56 Python＋130 Rust，桌面 153 Rust；包含格式、Clippy、无窗口行为、依赖／源码边界和构建。新增回归拒绝未实际选中的 MemoryUsage、无效设备策略值、缺帧、跨策略像素漂移及未释放旧帧；设备描述符测试验证 memory hint 不清除原有 features／limits。

最终版本在完整组合之前、之后分别执行原配置／MemoryUsage 对照，共四个独立像素进程；七帧逐字节一致，CPU 参考最大误差均 1/255。四份轨迹 SHA-256 均为 `bee8433fe9c6c6530704fbd6f5ca794e4b900ca16ea5371a14c3f922bceb2270`。每份均为 8 次目标分配／8 次发布、1 次原图上传；A→B→A 隔离、CPU 持帧跨 shutdown 和最终释放均通过。

这是 Plan 请求到发布，仍不是完整 Command→画面 B08。冷发布比前一原配置归因轮约 60 ms 的 p95 更慢；解码、打包和上传准备的 p95 分别为约 46.9–50.6／11.8–12.3／24.6–24.9 ms，前轮约 30.8–31.1／7.9–8.0／8.5 ms。各阶段分位数不能相加成总分位数，上传准备也不是 GPU 执行时间。CPU 代码和素材未变，不能把全部差异直接归给 memory hint；后续需要同源交错 A/B 和阶段证据，决定是否进一步调整上传资源复用。

GUI 仍显示旧的有效图像并拒绝过期来源编辑，后台准备没有形成超过 16.7 ms 的框架 CPU 帧；本轮触发迟到最大约 4.012／4.199 ms。二者不关闭完整 logic／事件循环 B07，也不推翻此前其他轮的长迟到。

结论只关闭当前 Windows／Vulkan 下本次 MemoryUsage 的标准资源预算、像素与组合清理子项；**完整候选／P2-A3／P2仍未通过，普通应用默认配置不变**。下一步优先细分请求、软件队列与原生提交的来源关联，保留原声音供给；复查冷准备的成本差，再推进稳定空闲、完整 20 次资源循环和设备路径。其他平台、真实歌曲／玩法与 P3 文件导出范围不变。

14 份既有 P2 证明、AGENTS.md、两份锁文件及 domain／application／audio／infrastructure／rendering／preview／UI 源码均保持本轮开始时的字节身份。原有工作区变更保留，Git HEAD／索引未变；没有暂存、提交或推送。

## 复现入口

按 README 配置本仓库离线工具链后，完整检查及两轮 MemoryUsage 标准组合：

```text
python tools/check_core.py
python tools/check_desktop.py --run-combined --memory-usage --output artifacts/p2/memory-new
```

已有本次 release 二进制时，可单独复现跨配置像素对照；输出目录必须未存在：

```text
python tools/measure_combined.py --binary desktop/target/release/skin-editor-desktop.exe --output artifacts/p2/memory-pixels-new --pixel-controls
```

原配置完整组合不加 `--memory-usage`。标准轮会播放低幅度自制 WAV；像素对照不打开系统窗口或播放声音。没有新增依赖、GPU 运行时公共端口或项目文件格式。稳定空闲、完整 20 次资源循环、resize／DPI／最小化、设备重建、实际歌曲流／设备消费、真实玩法和其他平台仍须各自验收。
