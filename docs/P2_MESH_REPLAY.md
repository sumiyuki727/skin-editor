# P2-A3：同一新鲜输出的文字／其他网格回放

2026-10-26。同一新鲜输出的文字／其他网格回放完成，纯Tessellator与框架API的逐项等价核对全部通过。全输出Context调用墙钟中位数0.1179–0.1260 ms，已有容量的CPU复制0.0122–0.0159 ms；不包含真实GPU上传。正常路径四轮独立CPU17.8666%–19.3148%仍超15%，其中一轮细分时钟失败，全部保留。**选择继续使用框架现有排版和GPU缓冲容量复用，本轮不新增外置网格缓存或中间打包层；没有CPU优化收益证明，P2-A3未验收。** [结构化证明](P2_MESH_REPLAY_PROOF.json)保留全部结果及47份旧证明摘要。

## 固定方案及归因边界

只在原32 Voice阶段预先指定的第1／33／65／97个output hook运行，每次都使用该次新鲜FullOutput；每份输出执行四轮固定“全部／文字／其他／空／其他／文字／全部”。每轮交替纯Tessellator与Context API先后顺序，以及新分配复制／已有容量复制的先后顺序。记录全部112组结果，不按时长选择画面或重试样本。

- 分组保留Shape::Vec嵌套、各自顺序、裁剪和tessellation后变换；分组只用于回放，不用于替代实际画面，文字与其他组不能重排合并后冒充原绘制。
- 纯Tessellator与Context::tessellate消费同一组形状、像素比例和当前选项。经公开TextureAtlas构造器重建内置圆盘元数据；真实字形／UV仍来自本次原始输出，并非重建或替换字体纹理。每次必须核对全部顶点／索引、纹理ID、裁剪以及回调矩形／Arc身份完全一致，失配即拒绝归因。
- 分开记录两次形状克隆、纯tessellation、Context API调用、CPU新分配并复制、CPU已有容量复制及临时对象释放的原始墙钟。Context API还包括锁、PaintStats等包装；两项分别呈现，不将样本差额或整个框架段直接当作精确包装成本。
- CPU搬运将顶点与局部索引复制进连续的类型化数组，忽略回调数据，保持每个mesh的局部索引；它不调用GPU上传、渲染或回调。不能以此估算queue.write_buffer_with、驱动、编码／提交、等待或事件循环成本。
- 所有回放和等价核对成本计入观察器总墙钟；不从产品CPU扣除，也不将这些短时墙钟乘帧率追认15%通过。实际绘制仍消费原FullOutput，正常输入、布局、草稿／历史和音频同步均执行。

`--verify-mesh-replay-gui`是host私有显式入口；普通应用、旧诊断及文字统计不启用回放。沿用既有GUI音频脚本，不增加项目命令、依赖、feature或缓存服务。纯／API调用会更新Context内的绘制统计；随后正式完整绘制仍走原路径，因此这不是对Context完全无副作用的观测，不作为零诊断扰动证明。

## 资源与失效

只接受受控fixture中的有界源：最多2048个形状节点、512个文字实例、32层嵌套；源中已有顶点／路径点和索引分别受32768／131072上限约束。圆盘元数据的临时CPU图像在分配前检查≤4 MiB；tessellation结果在类型化打包分配前再次检查上述顶点／索引上限。已有容量数组约1.125 MiB（20字节Vertex和4字节索引），数据每次清空后从当前结果重填，全部临时形状、Galley／回调引用和数组在本次hook结束前释放。

这些限制覆盖自有复制与本受控场景准入，不能宣称约束了第三方tessellator对任意复杂形状的内部全部临时分配。进程内存仍按原预算检查；逻辑释放不代表分配器／驱动私有提交立刻下降。

观察器跨pass只保留四份数量／墙钟元数据及112行标量记录，不保存绘制对象、顶点数据、文字或指针地址，不注册纹理、不创建GPU缓冲，也不保留项目／GPU租约。没有外置跨帧网格缓存，因此不以尺寸相同、旧Galley身份或旧TextureId猜测图集失效。

## 当前实现依据

锁定egui 0.37.0的Context::tessellate通过Tessellator生成网格，同时收集PaintStats；epaint公开构造接口支持同选项和圆盘元数据的回放。锁定egui-wgpu 0.37.0的Renderer::update_buffers已按容量复用顶点／索引GPU缓冲，并通过queue.write_buffer_with取得上传暂存区域后分段复制。这支持先测量再选择方案，不能看到CPU数组预留更快就新增一个产品打包层或声称缺少GPU容量复用。

### 选择与下一步

保留当前框架Galley缓存及Renderer的GPU缓冲容量复用，继续从新鲜网格直接进入既有上传路径。本轮不增加文字／整帧网格缓存或额外CPU打包层：前者还需要完整图集失效与绘制状态契约，后者不能省掉实际队列暂存复制，现有容量复用也并未缺失。短时CPU复制较快并不足以证明叠加一个缓存的收益。

下一步优先直接界定Renderer::update_buffers中的暂存取得／复制、编码提交与呈现／事件边界，区分实际队列／驱动成本和剩余框架工作；当前CPU复制数据不能替代这些证据。仍有未归因范围，不据本轮分组结果重选框架、放宽门槛或更改声音供给。

本轮是归因与方案选择，没有新的产品CPU通过、两轮300秒标准组合、稳定空闲、20轮资源循环、GPU总预算、设备／其他平台成绩。旧首帧长卡顿和203次／秒来源保持开放，Linux实测继续暂缓，P3输出及默认晋升未验收。没有Git暂存、提交或推送。
