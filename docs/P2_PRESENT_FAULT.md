# C4 呈现中设备故障：退出、重开与创建失败

2026-10-28，[计划性窗口替换](P2_WINDOW_RECOVERY.md)之后的有界增量。**三组显式MemoryUsage完整窗口对照在当前Windows范围通过；C4及P2仍未整体验收。** 原始结果、源码／构建身份、失败和日志哈希见[证明](P2_PRESENT_FAULT_PROOF.json)。零欠载、提交p95≤20 ms及内存／GPU门槛不变；CPU≤15%仍为优化目标。普通启动默认、声音供给策略和P3范围不变。

## 实际故障边界

使用同进程窗口替换候选，增加三组固定新进程，不自动重试失败：

1. `prepare`：在eframe实际`update_buffers`调用的PaintCallback.prepare中销毁自有Device，此时完整Editor窗口仍在绘制。
2. `paint`：在实际RenderPass的PaintCallback.paint中销毁Device；不是在应用的on_exit里销毁，也没有预先关闭窗口或暂停背景。
3. `rebuild-failure`：准备期故障后退休旧窗口，实际创建新eframe Renderer／surface，在App创建回调返回受控AppCreation错误；核对这些对象释放、原项目交接快照保持，再按已声明计划创建下一窗口。

入口为`tools/measure_present_fault.py`，复用`measure_window_recovery.py`的自有PID、窗口和预算观察。三组分别由`--verify-present-fault <新绝对目录> <prepare|paint|rebuild-failure>`执行，子入口需要runner协调DPI／最小化回执。仅自有Vulkan Device.destroy，不重置系统显卡、不模拟内核TDR或物理拔卡；Windows／RTX 2060结果不能外推到其他驱动或平台。

每组仍运行两代真实Editor的logic／ui、当前分离声音与持续背景，每代32次场景短音及32次显式试听，随后进行resize、软件zoom、实际96→120 DPI与最小化／恢复。故障前恢复背景并保留一个活跃试听Voice，图形任务在本次Editor UI的正常请求结束后才准入，确保故障边界确有尚未接纳的准备结果。另保留一份真实旧CPU绘制数据，验证它仍阻止退休；它不能提交给新Renderer。

## 两个修正

第一组固定三轮均因声音未在退出处理前接到门控而失败，记录保留于`artifacts/p2/present-fault/native-1/`。锁定wgpu-core 30.0.1在Device.destroy后，须等队列排空并由poll分发Destroyed通知；surface可以更早返回Validation。因此设备丢失通知和致命surface状态都进入同一原生失效门控，直接关闭旧音频复制，不等待UI刷新才关门。Lost／Validation停止重配置；其他状态保留原框架策略。故障前的异常、错误类型及通知来源单独计数，不能把任意错误都算作预期故障。

NativeHost现在先poll设备并核对失效，再接纳准备结果，避免通知尚未分发时对旧完成结果建立新绑定。候选故障控制器暂停新的Editor工作，使用非阻塞所有者poll推进实际通知，随后请求关闭窗口。该路径不在原生音频回调中访问项目、解码或释放PCM；通知只持有该端点的失效信号和短状态。回调门控关闭不等于设备已消费完残余声音，声学静音仍未验证。

第二组固定三轮已通过声音门控，但旧Instance的纹理注册表仍有3个ID，严格空表检查失败，记录保留于`native-2/`。继续核对锁定源码：`wgpu-core/src/present.rs`在获取surface纹理之前预留FutureId，错误或没有纹理的路径未assign；`registry.rs`的FutureId没有对应Drop释放。这些ID与登记了纹理对象的槽不同，不能据此推断仍持有3张GPU纹理，也不能把原始非空结果改写成0。

最终对照逐组记录：致命surface获取3次、纹理ID预留3个、用户持有纹理对象0；设备／队列／缓冲及其他全部注册表为空，Renderer已析构、surface为空，worker成功退出、受管目标0。**原始device_resources_empty仍为false。** 只有上述数量精确对应且不存在其他对象时，才允许退休整个旧Instance，随后建立新设备；不回收或复用这些ID。新代正常退出的纹理注册表为0。未知ID、数量不匹配、任何存活对象、Instance未退出或旧绘制租约未释放均继续拒绝。

这属于完整Instance退休的所有权证明，未放宽进程／GPU预算或允许存活资源泄漏。没有修改第三方库、禁用覆盖层或扣减驱动成本。该锁版本细节须在wgpu升级时复核；不能作为其他版本的通用豁免，也不能据此宣布同一个坏Instance可无限次继续运行。
