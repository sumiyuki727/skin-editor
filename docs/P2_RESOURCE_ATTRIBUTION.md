## 提交观察的边界

组合诊断现在为每通道最多 64 个 Voice 保存五个数值：最后一次未提交观察的读取前时刻、第一次已提交观察的读取后时刻、请求到回执耗时、首次轮询时刻，以及请求在播放阶段的位置。原始上界仍保留并用于原验收，不用全局最大轮询间隔减去某个分位数。

原生回调仍不读时钟、不等待、不分配。两次时钟读取都在控制侧，夹住对现有提交原子的读取；下界使用最后阴性读取**之前**的时刻，不能用读取后时刻。若首次读取已经阳性，下界为请求时刻，不能凭回执时刻断言回调此前没有提交。请求回执在 owner 完成本轮 pump 后发送，但不等于该 Voice 已经进入回调。

分别计算逐项下界与上界的最近秩 p95：上界≤20 为确定满足；下界>20 为确定超过；两者夹住 20 为尚不能区分真实提交和观察余量。跨门槛的观察仍使原验收失败。回执后的下界等待单列，只证明控制侧回执之后仍未观察到提交，不将它全部归入软件队列或驱动；这里没有设备消费和声学时间戳。

确定性测试覆盖原子读取跨越真实提交时刻、观察线程迟到、20.0454 ms 夹界仍不能通过，以及确实超过门槛的下界。没有 busy polling、优先级调整或用 sleep 推测测试竞争。

## GPU 的三种不同计量

- PDH 继续按本轮自建进程 PID 汇总 dedicated／shared，新增有界的实例名称、状态和数值，检查是否有重复归属或其他适配器成本。缺失仍为未知，不补零。
- 同一 wgpu Device 在固定阶段提供分配器报告，记录存活分配、内存块保留容量、标签及块内范围；最多 16 次，每次最多 512 个分配／块。超限明确失败，未支持明确诊断。
- 独立空 eframe 窗口控制不创建项目、合成器、PNG 或音频。比较两个物理尺寸和标准素材的 3 秒短轮，另显式比较 `MemoryHints::MemoryUsage`。后者只在诊断入口启用，普通应用与标准 300 秒负载沿用原配置。

分配器报告跨内存类型，不给出 PDH dedicated／shared 的一一映射；保留容量也不是物理驻留。不能将它从 dedicated 中直接相减后声称余数都是驱动。交换链图像经 Vulkan swapchain 获取，不在本次 Device 子分配器报告中；其他驱动、呈现及外部注入成本仍需保留未知范围。实例为零仅表示该次 OS 计数为零，不表示设备不存在。

诊断配置从 `NativeOptions::default().wgpu_options` 派生，仅替换设备 memory hint。单独的 `WgpuConfiguration::default()` 使用不同的呈现策略，不能作为等价对照；对应测试固定这一边界。没有修改第三方代码、开启 unsafe、增加依赖或调整系统覆盖层。

空窗创建时仅约 0.532 MiB 存活分配，就已保留 128＋64 MiB 两块。标准素材并未新增这两块的容量；2 秒处含 40 MiB 原图、约 2.017 MiB 一个合成目标、字体／UI 缓冲及小暂存。关闭合成器后存活约 1.563 MiB，设备仍在，原策略保留容量仍为 192 MiB。这是可追踪的分配器容量保留，不能据此称为图片泄漏；进程退出后的归还与长时间稳定空闲另验。

MemoryUsage 的标准短轮在 2 秒处为 52 MiB，关闭后回到 12 MiB；存活图片大小和合成计划未变。第一轮 147.977 MiB dedicated 峰值发生在加载期，播放期峰值为 113.980 MiB；第二轮播放峰值为 109.918 MiB。既不能把加载暂存峰值遗漏，也不能用一个最高值概括所有阶段。该控制只验证了减小容量保留的方向，未关闭 300 秒、完整生命周期、像素和其他设备的正式配置变更验收。

相同存活分配／保留容量下，大窗口 dedicated 增大；相同窗口的不同进程也存在差异。它支持有呈现面积相关且未被该子分配器覆盖的成本，但不能给交换链图像计数或给驱动／覆盖层逐项定量。上一轮 12.1875 MiB 差值发生在加载初期、随后维持，不能从当前没有逐项驱动回执的报告追溯为某三张纹理。原图只分配一次并不证明整个进程的显存预算通过。
