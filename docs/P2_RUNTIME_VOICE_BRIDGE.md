# P2-A3：既有 Runtime 与 Voice 交接候选

2026-10-23。接续[有界交接候选](P2_VOICE_HANDOFF.md)，连接既有 Runtime 的立即触发实例、候选激活及取消事实，没有另建绑定或准备运行时。**仍未连接背景储备、定时事件时钟、CPAL 或桌面默认路径。P2-A3 未验收。** 检查身份及限制见 [P2_RUNTIME_VOICE_BRIDGE_PROOF.json](P2_RUNTIME_VOICE_BRIDGE_PROOF.json)。

## 职责与执行选择

Runtime 继续核对完整 Origin、准备序号、门控、有效旧版本及声音格式。显式启用单向的 enable_voice_handoff 后，立即触发仍由 Runtime 分配其 32 个实例槽，再导出一次只读 VoiceHandoff。导出携带实例身份、有效来源、PreparedSound 和仅 Runtime 能撤销的租约；消费函数不持有 Runtime、项目会话或绑定表。

启用时有活动实例或排队事件会拒绝切换，不能把已有声音重新从头播放。启用后原软件混音入口明确报 ExecutionMode，未来时间触发报 UnsupportedScheduling，不推进时钟或暗中变成立即触发。mix_frame／scene_frame 在此实验模式中没有设备时钟驱动，VoiceInfo.cursor 仍是所有者状态，**不能当作消费进度**。当前产品默认继续使用原供给与定时路径。

VoiceOwner 的 pump_runtime 在控制侧接纳并回收实例，固定绑定不透明的 Runtime 身份，防止同格式、同预算、同数字 Voice ID 的另一 Runtime 消费旧回执。32 份传输额度包含待交接、活动和已返回阶段；满额时新实例留在 Runtime 中，返回 waiting 数，不提前导出或丢失请求。Runtime 另有其原有的 32 槽上限，历史取消后的旧传输与新等待实例分别有界。

一个边界不能混用原始声音与 Runtime 接纳：尚有原始声音时拒绝绑定 Runtime，绑定后原始 admit 报 RuntimeMode。原始 collect 不消费含 Runtime 租约的回执；通过 pump_runtime 回收并确认，避免丢失 Runtime 槽。finish_runtime 在执行器交还端点后验证双方身份，关闭 Runtime 并释放传输；原始 finish 只供原始模式或已经显式关闭 Runtime 的路径使用。没有新增 application 写入口、第三方依赖或产品启动线程。

## 激活、取消与样本

普通编辑／准备成功只改变 Runtime 的后续事件选择。准备期间可明确使用有效旧版本，准备失败保留其来源，迟到旧请求拒绝激活。已开始的旧实例继续结束，不能在每次素材修订时调用 invalidate_source 切断它。交接层不改写有效来源，也不重复判断草稿取消或普通提交。

Runtime 原有清理路径撤销实例租约：草稿取消只撤销对应来源，历史导航即使节点相同也撤销两通道旧实例，暂停只撤销场景声音，停止试听只撤销试听声音。Runtime 销毁同样撤销仍活动的实例。取消无需下一次 pump／UI 刷新；PCM 额度仍等最后真实租约释放才退还。

正常完成与取消分开。确认正常返回移除 Runtime 实例，但不将刚生成的块误标为取消；返回同时核对数字 ID 与租约身份，旧重试凭证或另一 Runtime 的返回不能结束新实例。失败接纳可以只恢复匹配导出，撤销拒绝句柄后再试，不留下“已导出但无人消费”的实例。

两执行路径共用 PreparedSound 的监控采样函数，保留线性插值、单声道复制、双声道均值与原增益处理。Runtime 负责限制支持的监听转换；桥接覆盖 44.1／48 kHz、单／双声道全部 16 种输入输出组合，原始 admit 仍只接受同格式。没有新增编解码、完整转换 PCM 副本或导出规则。

消费端先检查门控和实例租约，生成后再次检查逐实例撤销。Runtime 短音描述符即使本块已结束，也保留到最终实例检查后才退休；原始模式保持允许并发退休／复用。若中途取消一个实例，按保存的起始游标和原采样／累加顺序有界重算一次，清除该实例首次发声回执；不减去已舍入贡献、不清空同通道其他声音、不分配每 Voice PCM 暂存。随后执行通道代次检查，描述符只移回所有者，消费函数不释放最后 PCM。

这仍是生成函数中的撤销边界。**最后快照后的新取消、函数返回至原生复制之间、完成确认与实际提交点、设备残余均未接入。** 未来适配器须保留设备／通道／实例身份，在实际复制时验证，并把确认放在相应提交边界；不能将 render_split 或回收当作 CPAL 已输出或声学静音。CPAL 闭包析构线程与流静止仍未证明。

## 已执行测试

新增 19 项无设备测试：audio 5 项、infrastructure 14 项。线程交错由零容量通道控制，10 秒超时仅防死锁，没有 sleep 或概率重试。

| 场景 | 验证 |
| --- | --- |
| 激活 | 有效旧实例、准备期间旧版本、失败诊断、重试、迟到拒绝及新版本后续触发，均沿用 Runtime 判断 |
| 精确撤销 | 草稿取消 6 个门闩条件、同节点历史 3 个、暂停／停止试听 6 个；覆盖取队列后、生成后、原始退休阶段，含本块已结束的短音，其他实例／通道保持 |
| 波形 | 16 种转换组合逐样本对照；独立固定值验证插值、声道、结尾与溢出；选择性重算另有“减去旧贡献会改变结果”的浮点反例 |
| 容量与拒绝 | 32 个旧传输未回收时保留 32 个新等待实例，回收后准确接纳；异池、格式、模式、编号耗尽、另一 Runtime、混用原始入口及拒绝后重试均明确处理 |
| 停止 | 待交接、活动、已返回没有下一次消费仍完整关闭；异常消费端销毁回收 Runtime 槽与孤立队列，外来关闭凭证不关闭另一 Runtime |
| 循环 | 新桥接 300 轮 × 32 Voice，共 9600 次。共享一份 8 字节自制 PCM，解除原绑定后每轮弱租约与计费归零；旧 9600 次真实线程交接测试也继续运行 |

新循环 PCM 峰值 8 字节、最终 0，是小 fixture 生命周期证据，不能代表实际 32 Voice／歌曲或整机预算。当前 x64 内嵌测量：所有者 9888 字节、预分配消费状态 12368 字节、Packet 192 字节、两个队列各 32 槽；不含 Arc／rtrb 元数据、分配器取整及系统音频。控制标记在所有者侧创建，有界实例租约与传输引用共享 PCM；消费函数不克隆资源句柄或创建线程。未执行全局分配器检测。

格式、Clippy、依赖／源码边界及无窗口检查沿用核心与桌面脚本，计数见证明。新测试曾有一处组件 ID 的 u64／u128 类型错误，首次桌面 Clippy 指出两处循环写法；均修正后重新检查，失败日志保留于忽略目录 artifacts/p2/runtime-voice-bridge/。25 份旧证明保持原字节，无暂存、提交或推送。
