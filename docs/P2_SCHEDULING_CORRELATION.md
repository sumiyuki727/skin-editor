# P2-A3：供给完成、回调现场与宿主调用关联

2026-10-23。接续[欠载现场记录](P2_UNDERRUN_CONTEXT.md)，补齐旧102.8773 ms回调入口间隔和420.4971 ms宿主触发迟到缺少的关联证据。旧记录没有这些字段，不能追溯还原当时原因；本轮通过新的受控回归和原生样本继续定位。原768帧活动前送、2 ms供给休眠、1 ms观察、125 ms触发迟到拒绝及20 ms提交门槛均保持，没有修改游戏、混音或图片合成语义。

**本增量实现与387项默认检查通过，P2-A3整体仍未通过。** 新现场将音频长等待定位到供给线程休眠前至再次运行的区间，并捕获一次音频仍连续时的宿主迟到；系统／框架内部原因仍未确定。标准首轮300秒出现96帧欠载，第二轮在GPU初始化时失败，另列的一次补测因触发迟到提前失败。失败没有被重跑覆盖，预算及20 ms门槛没有放宽。机器可读结果见[本轮证明](P2_SCHEDULING_CORRELATION_PROOF.json)。

## 新增记录

供给行包含：pass、上轮休眠前时刻、本轮唤醒时刻、pump开始／完成时刻、上轮pump完成、队列前后、实际补充帧、当时已完成回调数。时刻以当前输出的capture origin为零，只在供给线程／控制端取时钟；保留最近四个带精确pass标签的完成行，以及最初32次相邻完成间隔超过20 ms的行，总数不截断。

由此分别观察完成后到休眠的处理、休眠至下次唤醒、控制／准备到pump、pump自身工作。休眠至唤醒包含原2 ms休眠和实际调度，不能直接命名为OS抢占时间；控制段包括准备结果接收，不等于磁盘解码。pass仍在原位置发布，时刻元数据随后发布；读取期间行未完整或槽已覆盖必须显示未知，不能用相邻pass冒名补齐。

以上均为墙钟区间，任意一段内都可能包含未获运行的时间，不能直接当线程CPU消耗。回调侧读取有固定次数上限，部分元数据不会等待写入者完成。

回调遇到超过20 ms的入口间隔或任意欠载时，固定保存前三回调及当前回调，并通过有界读取附上最近四个精确供给完成行。回调只读取已有后端时间戳和固定原子元数据，不取自有时钟、分配、等待或持有PCM。最初32次事件留存，总计与截断明确；缺少完成行不能成为“供给没停”的证据。20 ms是诊断捕获条件，未替换原产品验收门槛。

报告以同一流的控制端clock sample将后端入口戳转换到capture origin的区间，保留调用前后及当前Windows 100 ns网格余量。入口戳不作为完成上界；供给发生在回调执行中时允许转换出的入口年龄跨0，不能强行归成入口前的供给。流销毁后的快照标记quiescent；宿主迟到现场的活动快照另标非静止，二者不混算。

宿主另记录每次逻辑调用的进入、tick返回、完整逻辑返回、请求重绘时刻及delay、最近一次UI子pass起止。下一次进入比该次请求的名义目标晚20 ms以上时保留最初64行；播放中的前八次同时保存供给现场。活动快照在当前tick之后收集，额外记录采集起止，避免采集工作延后当前触发后再被误认成原始迟到。

重绘请求是名义宿主目标，不是OS保证。UI子pass及App逻辑未覆盖GPU呈现、框架事件循环或调度器；“App工作已结束、下一次调用仍晚”只能定位到这些测量之外，不能仅凭用户态时间戳确定具体驱动。现有CPU帧、延迟、欠载及资源门槛保持原算法。

## 验证范围

确定性测试用显式时间值分别构造等待唤醒、控制／准备耗时和生成耗时，验证精确pass关联、时基区间、部分写入拒绝、环形槽覆盖及有界窗口溢出。宿主测试重放420.5 ms名义迟到，区分前次App工作与下一次进入，并验证提前失败也保留行。均不依赖真实设备、GUI或sleep猜测竞争。

默认检查为84项Python、130项核心Rust及173项桌面Rust，共387项；格式、Clippy、无窗口测试、依赖／源码边界和release构建通过。测试只在当前Windows／Rust 1.95实跑，不声称已在其他平台运行。

原生固定计划执行八轮相位扫描、两轮各300秒目标的MemoryUsage＋ReusableStaging组合及前后四个像素进程。首轮完成300秒但欠载失败；第二轮GPU初始化失败。随后只增加一次明确另列的组合补测及两个像素进程，补测仍提前失败；没有继续重跑。报告的normal／partial出口均保存新增调度数据，GPU初始化panic没有生成该报告，保留stderr和进程结果。部分报告不能成为完整通过证据。

最终121个源码／工具／配置文件哈希及release二进制冻结后才执行，性能期间不编译，不注入强制睡眠或供给阻塞。二进制SHA-256为`f8296ca02394de7bb890a6ac8b406bb956a393849bd0c435d87a4adf4ac0e047`。首次检查后的诊断采集位置曾调整，随后重新完整检查／构建，前次日志保留；原生结果全部绑定最终身份。原始日志、逐轮指标、差异及分析位于忽略目录`artifacts/p2/scheduling-correlation/`，20份既有证明保持原字节，未暂存、提交或推送。

没有新增依赖、服务或通用遥测框架；仅修改桌面适配器、诊断宿主及工具。项目写入、候选来源、双通道门控及声音失效语义不变。所有原生成本与时序仍绑定当前Windows默认设备及GPU；Linux按用户要求暂缓，macOS未测。实际歌曲、设备消费／声学延迟、完整UI／设备恢复及P3文件输出不由本轮关闭。

## 独立声音轮已关联的路径

八轮的时基／批次记录均完整，2560个逐Voice探针及每轮全部十个相位桶均有记录。五轮通过，另三轮分别为第一组轮01的场景提交夹界、第三组轮02的欠载、第四组轮02的试听提交夹界。第一组轮01场景精确p95为18.3693–20.1380 ms（原上界20.1374 ms），第四组轮02试听为18.3393–20.3267 ms（原上界20.3263 ms）；两轮均没有长回调间隔或供给完成间隔事件。小幅夹界仍须按原观察区间处理，不能与下面的长停顿混作一因。独立扫描CPU平均约0.595%–1.190%单逻辑核，结束后原始字节／PCM归零；不代替组合预算。

第三组轮02在扫描阶段捕获两次事件，分别缺192／288帧；两次都发生在供给线程长时间未进入下一轮之后。所有时刻来自同一输出捕获原点与带区间的流时钟转换，不再仅比较整轮最大值。

| --- | --- | --- |
| 回调入口间隔 | 67.8901 ms | 35.2565 ms |
| 上轮完成至休眠前 | 0.0007 ms | 0.0007 ms |
| 休眠前至本轮唤醒 | **53.6227 ms** | **33.5652 ms** |

这次延后落在“休眠前到再次运行”段，未落在控制／准备或生成段；原代码仍只请求2 ms休眠，实验没有注入53／33 ms等待。恢复运行时队列已达到原768目标，按原策略不再生成；随后较大的1056帧请求直接超过入口队列。两个回调之间pass 3993曾从空队列生成768帧，pump耗时0.2197 ms，然后才进入第二次长等待。由此确认了当前策略在这个现场的不足边界，但本轮按用户要求不调整前送、休眠或回调缓冲策略。

同一试听Voice 224在回调1039完成，区间98.2038–99.5251 ms，下界确认超过20 ms；请求至pump约64.603 ms、提交至回调入口下界约34.114 ms。控制接纳／生成前和入队后均有实际等待，不是全部由观察器造成。该轮总体p95仍低于20 ms，但欠载非零，整轮不通过。

这些证据只把新的同类路径定位到具体等待段及队列决策。旧102.8773 ms和420.4971 ms记录没有相同字段，不能据此追认；用户态时间戳也没有进一步证明是系统定时器、线程调度、驱动或其他系统停顿。原416帧与224帧旧事件保留各自未知范围。

首轮回调19732入口间隔23.6504 ms，请求960帧、入口队列864帧、缺96帧。入口所见最新pass 67215完成约23.004 ms以前；随后pass 67216的完成行由慢供给记录捕获，恰与同一回调间隔相交：休眠前至唤醒23.1306 ms、控制0.0046 ms、pump 1.0337 ms，完成晚于该回调入口约1.1652–1.1660 ms。这里不能仅看入口前四行或整轮最大间隔；后继完成行把同一事件的补充延后也关联起来。该现场同样未确定OS／驱动内部原因。

第二轮在播放前的`Surface::configure`发生wgpu验证panic：等待GPU空闲后重新配置Surface失败。保存`long/run-02-stderr.log`及失败结果，没有normal／partial报告；它未完成300秒，也不能归为音频入口停顿。后续像素进程能够完成不等于该失败已恢复或修好，B09设备／surface生命周期继续开放。

三组Performance／MemoryUsage像素对照、共六个独立进程，均为同样七帧、1771268字节且逐字节相同；SHA-256为`bee8433fe9c6c6530704fbd6f5ca794e4b900ca16ea5371a14c3f922bceb2270`。CPU参考最大单通道误差1/255（容差2）。它们检查像素／资源交接，不构成失败组合的性能替补。

## 补测捕获的宿主迟到

另列的一次补测在约74秒播放处因546.6752 ms标准触发迟到停止，仅完成589次触发、74次编辑和8次切换。部分报告包含输出关闭后的完整调度快照，不能将未达到最终关闭阶段的`resources_released=false`直接判作泄漏，也不能使用完成专属的播放帧哨兵值声称没有播放；该轮没有完整预算成绩。

这将本次停顿定位到已测App工作之外、下一次逻辑调用之前；尚不能在eframe／winit事件等待、GPU获取／呈现、窗口状态变化和宿主线程调度之间定因。它不是旧420.4971 ms事件的事后还原。首轮另有启动期139.5938 ms名义迟到，其UI约84.1083 ms且越过请求目标；补测的其他启动记录也分别保留，不与播放中的659.8734 ms合并归因。

## 后续关口

下一步优先在原生宿主／框架边缘记录逻辑调用间的重绘唤醒、窗口可见／遮挡状态和GPU获取／呈现边界，继续与供给／回调关联；先用受控测试区分请求名义时刻、框架等待和App工作。供给侧若需进一步归因，须另行取得受限的自有线程调度证据，不能把sleep前后的墙钟差直接命名为驱动或CPU执行成本。保持固定轮数、完整保存提前失败，不通过重复挑选通过轮关闭门槛。

768帧前送、128帧生成块、2048帧队列、2 ms供给休眠、1 ms观察及原门槛继续保持。本轮没有声音策略修复；零欠载、20 ms夹界、宿主迟到及surface初始化失败仍开放。B01／完整B05／B09、设备恢复、实际歌曲／设备消费与声学延迟、P3文件输出及其他平台也没有完成验收。
