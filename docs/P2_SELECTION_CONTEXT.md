# P2 临时联合选择与跨元素变换

2026-10-29，用户确认拖放导入和嵌套组变换正常，但报告建立跨元素组件后出现两个“组件”，并明确这应是基于当前选择的临时操作：共同框未解除时可连续共同编辑，解除框后不保留该临时组件，已有变换保留。

## 旧入口问题

旧按钮“建立包含所有元素的组件”执行一个AddComponent组命令，再为所有尚未登记的文档创建Element成员。组和成员都显示成“组件 N”，没有类型或缩进；一次点击可以出现一组加若干成员。重复点击还可能创建空组。源码能解释这种易混淆表现，但未读取用户当前窗口的内存树，不能断言用户看到的两个条目恰好是哪两个节点，也不将其冒充已复现的重复创建同一节点。

该全量创建入口已移除；已有ComponentTree保留，不删除旧项目、旧分支或组件引用。现有节点分别标为“组件组”和“元素引用”，显示层级。显式图层组仍是项目结构，临时联合选择是另一种编辑器状态，不能复用持久组件节点表示它。

## 行为与生命周期

- 单击图层／已有组件选择一项；Ctrl（macOS用Command）点击追加或移除成员。共同框自动出现，不提供“收集所有元素”的替代按钮。
- 多选最多256项；选项和矩阵只在UI的EditorState持有，不保留资源字节或项目可变引用。规范化通过选中祖先集合和逐项祖先遍历完成，不对每一对选项反复走祖先链。
- 同选组与其后代，只修改最外层有效目标；同选视觉组件与其成员文档内图层时同样去重。其他未被共同祖先覆盖的选项保留。
- 共同框可跨平移、缩放、旋转等多次手势持续存在；Shift保留比例，局部坐标／镜像／剪切语义沿用既有控制器。每个手势单独形成一次原子事务，选择生命周期不等于一个超长项目事务。
- 拖动中Esc只取消当前草稿并保留共同选择，迟到松手不得提交；空闲Esc或画布空白点击解除选择，已经提交的矩阵和历史保持。选择／解除选择不新增历史节点。
- 准备滞后时仍合并指针更新，松手刷新最终位置；失败的Replace不能推进记住的共同框。历史、会话、草稿及投影目标共同限定框的派生缓存，旧状态不成为新项目的几何真值。
- 多选状态不提供含糊的单对象参数或“新建组”操作；添加素材必须先明确单个元素，不能因当前是联合视图而偷偷新建文档。后续[统一输入](EDITOR_INPUT.md)提供经祖先去重的原子多选删除，不删除素材库原始字节。音效组件不参与视觉联合选择。

清除框不是撤销，不删除成员节点或原始资源，也不恢复进入联合编辑前的整个项目。真实撤销／重做继续通过application历史系统执行。

## 坐标、预览与输出

PreviewPort升级至v2，增加只读`Workspace`投影；`Document`和`Components`原含义保持。宿主及UI须处理新目标并核对描述符版本，v1描述符不能启动编辑。Command API、领域模型和未来项目文件格式不因新增投影目标改变。

占位Workspace沿用现有512×512共同编辑坐标，绘制ComponentTree已有成员，随后按稳定文档顺序绘制未关联文档；不会为显示未关联文档创建成员。这个占位布局不是stable游戏场景、mania轨道规则或最终UI布局。文档像素到workspace的矩阵由领域只读查询表达：关联成员为W×M，未关联文档为单位映射。

每次手势先捕获所有有效目标的初始局部矩阵及到共同空间的父映射，对每一项计算`父映射⁻¹ × 共同增量 × 父映射 × 初始局部矩阵`，然后一次Draft Replace提交全部命令。不可逆父映射在Begin前拒绝整个手势，基础命令校验失败由application整体回滚。图层／文档／输出边界及原始资源引用不变；真正修改的是成员的项目矩阵，不能只移动预览纹理。

共同框以首个有效选项的基准方向合并几何，连续编辑和历史恢复后仍能反映旋转；缓存带完整来源标记，不创建通用节点树或跨帧项目副本。预览和未来导出继续消费同一文档合成语义；本轮不实现皮肤文件导出。
