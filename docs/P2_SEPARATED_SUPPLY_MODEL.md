# P2-A3：连续储备与新声音分离的确定性模型

2026-10-23。接续[受控恢复](P2_CONTROLLED_RECOVERY.md)。本轮只建立可执行的小模型，检验“连续背景保留储备，已就绪皮肤短音在消费时混入”能否解除恢复储备对新声音的排队影响。**没有切换产品默认策略，没有接入新的原生回调。** 证明与检查身份见[P2_SEPARATED_SUPPLY_MODEL_PROOF.json](P2_SEPARATED_SUPPLY_MODEL_PROOF.json)。P2-A3仍未验收。

## 模型与边界

实现位于`desktop/audio/src/separated_model.rs`，只通过`cfg(test)`编译；没有新增公共接口、依赖、线程、文件格式或项目写入口。所有步骤由测试显式推进，没有设备、窗口、系统时钟、sleep或竞争概率。使用真实`PcmBudget`、`PcmBuffer`租约及`BackgroundTrack`，邮箱和门控则是顺序协议模型，不能被并发调用。

| 路径 | 小模型的职责 |
| --- | --- |
| 所有者准备 | 校验已解码的48 kHz双声道PCM；预算预留后才分配。准备校验不在已就绪短音的计时接纳路径中 |
| 连续背景 | 独立2048帧Copy环，保存源位置；恢复补充只推进背景生成前沿，不生成新皮肤Voice或改变其起点 |
| 新声音接纳 | 核对完整Origin、设备／内容／通道代次和同一共享PCM池；固定32槽，明确Busy；不等待背景环空位 |
| 消费／混音 | 显式回调步骤读取背景储备及已交接短音的不可变PCM，保留旧Voice游标，两通道相加后统一限幅 |
| 退休 | 固定槽覆盖待交接、活动和已退休状态。所有者同时固定PCM；消费端只移动描述符到对应槽的退休邮箱，所有者核对槽和代次后才释放引用、归还额度 |
| 暂停／取消 | 独立门控更新不消耗Voice额度。场景暂停仍允许新显式试听；取消／历史失效清理两通道旧皮肤声音，背景不重置 |

暂停确认携带背景代次和最后提交的下一源帧。确认前禁止回退／重新填充／恢复；过期和重复确认拒绝。丢弃未提交的背景Copy储备后，所有者从确认锚点重建储备，再允许恢复。恢复更新场景代次，冻结期间取得的旧输入即使迟到也拒绝。该锚点是软件提交位置，不能代表设备已消费或已声学静音。

这是一种待评估的混音位置变化，尚未迁移当前Runtime。正常候选激活时旧版本Voice可结束的既有语义仍须保留；模型中的内容失效专指草稿取消、历史导航和终止等清理边界，不把每次普通素材准备完成都视为全部停止。

## 确定性结果

相位扫描对场景／试听各1204次，共2408次。请求从0到30 ms，每100 μs一步；分别使用正常回调与额外突发，并覆盖同一时刻先接纳／先回调两种顺序。每个所有者步骤故意先填满背景储备，再接纳新请求，覆盖上一轮最不利的AfterRefill顺序。另有独立的接纳后补充、突发中接纳和连续旧Voice逐样本用例。

**时间是假设输入：**所有者每2 ms有一次接纳机会，常规回调间隔10 ms，每次首次生成后保守加1 ms作为提交完成上界。没有实测或证明回调必能在1 ms内完成。突发入口为30／30.148／31.384 ms，原子消费步骤之间可以没有所有者执行；1 ms只是宽松的完成上界余量，不代表回调固定执行1 ms或实际并行重入。扫描使用一个已就绪16帧短音，不冒充32 Voice的原生延迟成绩。

| 检查 | 结果与范围 |
| --- | --- |
| 相位扫描欠载 | 2408次全部0；每次均检查，没有用p95掩盖欠载 |
| 场景／试听提交上界p95 | 均11700 μs，即11.7 ms；从发出请求开始，包含等待接纳和提交完成余量，不扣队列等待 |
| 最大提交上界 | 两通道均12900 μs，即12.9 ms；仅在上述调度假设内 |
| 三次480帧突发 | 2048帧背景储备覆盖1440帧需求，剩608帧；逐样本核对背景及已有Voice，无裁剪有效音频、跳帧或重播 |
| 32槽准入与退休 | 待交接、活动、已退休满额都拒绝第33份；满额仍能停止，退休未回收不能复用槽；32 Voice活动回调480帧核对30720次样本累加 |
| 重复资源循环 | 300轮×32 Voice，共9600次槽复用；身份不复用，每轮只有一份共享短PCM计费，回收后弱引用失效；最终共享额度为0 |
| 相位扫描资源 | 共享PCM峰值147584字节，逐探针退出后均0；其中背景131072、Copy采样负载16384、短音128字节 |
| 固定表结构 | 本机x64模型`size_of`为40688字节，含Copy环和槽元数据；与PCM额度中的Copy负载有重叠，不能相加当作进程成本 |

16个模型测试同时覆盖完整来源字段、迟到代次、草稿取消、跨节点及同节点历史往返、待交接／活动声音失效、暂停前后提交、两通道隔离、冻结输入拒绝、旧确认拒绝、异池／非法PCM拒绝、满额关闭及最后所有权在所有者释放。每次消费步骤前后比较共享PCM用量，完成／取消不能提前退还额度；回调不取得所有者或项目会话引用。

## 必须保留的失败边界

- 旧1024帧储备在三次480帧需求下仍缺416帧；1280帧预混储备后的新声音在10／20／30 ms回调安排下，要到第三次回调才出现，超过20 ms。这是需求算术反例，不追认其他同数字原生事件的原因。
- 新模型单次索取2049帧也明确记1帧欠载；不会把短缺改记成正常静音，也不承诺任意调度停顿下零欠载。
- 所有者直到25 ms才接纳0 ms的请求时，模型提交上界31 ms，明确超过20 ms。储备与混音分离消除了储备排队，尚未解决接纳线程长时间失调度。

因此本轮只接受**在给定服务边界内继续研究该方案**。原生零欠载和提交原上界p95≤20 ms、CPU≤15%单逻辑核、进程内存≤512 MiB、GPU dedicated≤256 MiB等门槛均未改变；虚拟结果不能替代任何一项整机验收。
