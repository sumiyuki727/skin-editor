## 修复边界

- 背景读取器在EOF／全部缓冲借出时改为等待通知；归还缓冲、定位、关闭及版本耗尽终止均唤醒。保留四块PCM、8192字节原始缓冲、版本拒绝和实际释放计费；I/O只在读取线程中发生。
- 分离声音供给仅在完全冻结、背景已准备、没有Voice／准备／定位／回执／旧草稿租约且状态已发布时使用最长50 ms的维护等待。接受控制或关闭立即唤醒；其他状态及原混音路径仍按原2 ms活动节奏供给。待确认冻结、显式试听、后台未准备或异步准备中不得进入该等待。
- 不引入新线程、队列、PCM配额或回调等待；不以GUI刷新唤醒持续供给。50 ms是空闲维护上限，不是新声音排队时间。历史`max_supply_gap_micros`仍记录真实循环间隔，此后可能包含主动空闲；不据此改写旧102.9 ms等事件原因。

确定性测试用原子门闩控制“条件已检查、尚未等待”的窗口，覆盖先通知后等待、EOF定位、版本耗尽、关闭、准备与Voice门控及控制入队。测试门闩本身不能用同线程的channel阻塞接收消耗被测试的park token；超时仅为失败保护，未用sleep猜测竞争。
