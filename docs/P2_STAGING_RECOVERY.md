## 实现和测量边界

新增显式 `--verify-staging-recovery` 寿命入口及 `tools/measure_staging_recovery.py`，复用既有标准组合、音频清理及原门槛。宿主组装函数允许在同一 eframe Device／Queue 上重新创建编辑器；普通入口行为保持。没有新依赖，没有修改 rendering 的暂存实现、audio、解码、供给或原生回调。

每个独立进程按以下顺序执行，源码／锁文件／二进制保持一致：

1. 第一轮资源生命周期运行完整 300 秒标准负载：100 个 1024² 自制 PNG、10 文档／500 层、16 个自制 WAV、2400 次场景触发、300 次草稿替换后一次提交、20 次文档切换、每通道 64 次提交探针。
2. 冻结声音后保留活动项目、准备 PCM、原图、目标和暂存。静置 10 秒，再采样 65 秒。
3. 执行既有双通道隔离、草稿取消及历史往返清理；停止并 join 声音线程、释放原生流，关闭候选线程／GPU 资源，重建空项目并检查全部受管租约。然后销毁整个 Editor，包括导入线程、禁用的 UI 音频适配器及其合成／呈现管线。静置 10 秒，再采样 65 秒。
4. 在同一设备上再创建 19 次完整资源会话。每次重新生成／登记标准资源，准备声音，播放 3 秒（24 次场景触发、3 次草稿修改、1 次文档切换），执行相同清理并关闭；中间关闭观察 2 秒。第 20 次关闭再执行 10＋65 秒稳定观察。

总共是真正的 20 次打开／关闭；300 秒内的 20 次文档切换另外计数，不能代替生命周期。短循环不替代标准 300 秒 CPU、300 次编辑或每通道 64 探针的门槛。全程保留 768 活动前送帧、2 ms owner 休眠和 1 ms 提交观察器；不进行内存修剪、强制回收、像素降级或重置 GPU 设备来获取低峰值。

第一段播放沿用真实 Editor 面板及普通呈现。稳定空闲阶段由寿命脚本保留资源、停止驱动完整面板，用固定状态页等待截止时间；关闭后仅保留 eframe／设备／队列／egui／surface。稳定段的帧数和 CPU 是这个诊断宿主的证据，**不是普通完整 UI 的 B05 验收**。B01 空项目和完整 UI 空闲仍需分别验证。

关闭边界也与[前轮暂存记录](P2_STAGING_REUSE.md)不同：前轮关闭素材后仍保留 Editor／NativeHost；本轮进一步销毁整个编辑器资源会话。不能把二者的私有提交差值称为暂存上传优化收益。

外部观察器每约 100 ms 采样自己启动的进程，分别记录工作集、私有提交和 GPU dedicated／shared。初始 GPU 计数尚未建立时保持未知；播放、关闭及稳定阶段缺值判失败。阶段协议存在采样边界余量，另保留相对阶段首样本 1–64 秒的内部窗口，排除退出尾部，核对有效跨度仍超过 60 秒；该补充不替换原始门槛或回写原样本。性能进程不回读图像，前后跨内存策略像素对照独立运行。

## 复现与开放范围

先运行 `tools/check_core.py`、`tools/check_desktop.py` 并以现有离线工具链构建 release，然后显式执行：

```powershell
python tools/measure_staging_recovery.py --binary desktop/target/release/skin-editor-desktop.exe --output artifacts/p2/new-staging-recovery
```

每轮超过十分钟，共两轮。输出目录必须未存在且位于 artifacts 内；脚本只观察／必要时终止自己创建的子进程，单进程最多 900 秒。全部原始记录在 `artifacts/p2/staging-recovery/`，不纳入 Git。没有读取玩家媒体、旧 stable 源码／资源或使用系统窗口捕获。

普通应用默认、完整 UI 空闲、B01、保留成本归因、触发相位、设备丢失／映射故障注入、实际歌曲与设备消费位置、Linux／macOS、P3 文件透传／静音占位导出仍开放。P2-A3／P2 未标完成；没有暂存、提交或推送 Git。
