# P2-A3：迟到供给的恢复候选

2026-10-23。接续[供给／回调关联](P2_SCHEDULING_CORRELATION.md)，本轮按用户授权调整供给策略，先验证已确认的“队列达到768帧便停止补充、随后1056帧回调缺失”路径。零欠载和原提交上界p95≤20 ms不变；宿主停顿、GPU surface初始化失败单独处理。

**确定性修复与401项默认检查通过，四进程小范围原生正常路径对照通过。** 两轮候选的自然恢复尝试均为0，因此原生恢复分支及完整P2-A3仍未验收，候选没有晋升默认。证明见[P2_SUPPLY_RECOVERY_PROOF.json](P2_SUPPLY_RECOVERY_PROOF.json)。

## 改动与边界

`SupplyPolicy::RecoverLateWake`为显式候选，必须在配置设备period之后、预填／播放之前选择。普通应用及原诊断仍使用`FixedAhead`，本轮没有因短测自动晋升默认，也不把新增内部适配选项加入SkinProject或项目Command。

供给所有者沿用循环原有的Instant。相邻两次进入超过一个已报告设备周期时，下一个活动pump使用一次恢复目标：`max(768, 2×period, 已观察最大回调帧数+128)`，向上对齐128帧并封顶既有2048帧环。设备period和已观察最大值只是规划输入，不能保证未来回调大小；不是stable兼容规则。迟到区间包含控制工作、休眠与调度，不直接命名为OS休眠超时。

正常活动目标仍768帧，生成块128帧；恢复后不永久维持大队列，不回退已经生成／提交的有效声音。目标补充仍受实际空位约束。2 ms所有者休眠和1 ms观察保持，不启用忙等、线程优先级修改或新的平台API。计数单列恢复尝试次数与最大恢复目标，不把目标当作实际新增帧数。

退出空闲时，先完整发布PCM再发布cutover。恢复目标通过保留有界旧空白前缀及追加批次表达；空间不足不提前消耗Voice。仅按明确活动／代次／背景位置裁去废弃空白，有效声音、未来事件与背景位置均受保护。动态前缀guard与cutover串行号使用单写者序列保护成对发布；回调最多尝试三次读取，部分发布时沿用旧状态并推迟裁剪，不等待写者。

回调继续只消费预分配Copy帧、混合及原子门控，不取自有时钟、分配、等待、解码或持有最后PCM所有权。原始128 MiB／共享PCM32 MiB及2048帧环不变，没有新增依赖、线程或文件格式版本，项目修改入口、双通道来源与背景独立性不变。动态目标仅改变生成前沿，暂停仍须按回调确认锚点回退未提交背景。

这个候选只能修复供给线程已经再次运行、仍有机会先于回调补充的路径。回调若先耗尽队列，已有欠载照常累计；任意长停顿、未知大请求及连续突发仍可能超过固定环保护范围。不能把显式静音、旧空白重定时或重置统计当作零欠载。

## 确定性回归

先加入使用同一个原生消费者的测试，再运行旧实现。队列864帧仍高于目标，后续1056帧回调得到缺失样本，回归确实失败，日志保留于`artifacts/p2/supply-recovery/regression-before.log`。修复后用显式Instant偏移和调用顺序重放，不实际sleep或依赖设备竞争。

- 旧策略分别保留192／288帧失败；候选对队列864／768、迟到54／34 ms的两组路径均补足真实样本。
- 正常及恰好一个设备周期不增大目标；恢复只消费一次迟到状态，后续返回768帧目标。
- 空闲退出保留正确前缀；环满时不消耗Voice；最大未知需求封顶2048，配置时序错误拒绝。
- 恢复后场景与试听副本分别失效，背景逐样本连续，PCM额度不增加，最终租约归零。
- 不完整cutover／guard发布只推迟裁剪；回调先于唤醒发生的欠载不能被后续pump抹去。
- 既有背景暂停／确认回退／显式试听／恢复，以及换皮肤、历史导航与草稿取消的逐样本测试，分别以旧策略和确实执行恢复补充的候选运行；不能只测未启用候选的路径。

默认格式、Clippy、核心／桌面测试与依赖边界及release构建均通过：88项Python、130项核心Rust、183项桌面Rust，共401项。新增8项原生边界回归、4项工具回归及2项相位读取回归；已有暂停／历史两项扩展至双策略运行，数量未重复计算。宿主逻辑、窗口或GPU呈现路径不在本轮修改范围。

## 原生结果与诊断修正

首个固定计划只执行到第一个旧策略进程，在相位诊断读到`None`后以`missing achieved reference`提前失败，没有完成的延迟／欠载成绩。原子行读取按设计允许在并发发布时暂不完整；原工具先等待Some再重新读取，或在目标时刻直接读取，均不能保证第二次仍有完整行。该失败属于诊断读取交接，尚无证据把它归于音频供给、宿主停顿或GPU。

修正只在控制端执行最多32次读取，只有Unknown才按原1 ms观察间隔等待，关闭立即退出，耗尽仍失败。取得的是实际后来的快照，后续clock sample及唤醒超时按原算法记录，不能套用旧参考或扣除延迟。回调不等待；受控测试覆盖部分→完整、永久不完整及关闭。原计划失败、旧二进制／源码身份和日志完整保留；修正后完整重查／构建，再以新身份另执行一次固定四进程计划，没有再追加挑选轮。
