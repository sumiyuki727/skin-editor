## 改动及验证范围

只扩展显式 `--verify-main-work-gui` 的宿主诊断。Editor私有持有可选的有界MainWork观察器，正常入口不创建记录缓冲；UI、application及音频回调没有新增依赖或项目写入口。未改图层合成、GPU轮询次数、重绘间隔、音频供给、设备参数、依赖或验收门槛。

诊断格式升级为schema 2，在原五段内拆出控件构建、宿主UI收尾、图形轮询及预览请求。控件段覆盖 `EditorUi::show`，含面板、查询和提交绘制回调，并非纯控件排版。图形轮询段覆盖 `NativeHost::poll`，含worker结果及资源回收，并非纯驱动函数；预览请求段含application只读校验和宿主内第二次poll。其余呈现＋事件循环段仍含框架、等待和事件，不能叫作纯present或驱动CPU。

Python读取器保留schema 1的原解释；新段按同次主线程调度区间交集计费，可回汇到原五段，父段不重复计费。UI调用数仍只计外层入口，不能把返回父段当成新一帧。固定16384行容量、UTC／单调时钟检查、失效拒绝及原误差上限保持；等待不从墙钟推成CPU，也不扣除计量成本。

685项默认检查通过（221 Python＋130核心Rust＋334桌面Rust），含格式、Clippy和模块边界。新增三项Python与一项Rust回归覆盖分段总量守恒、等待不计CPU、旧格式不被新分类重解释及有界顺序记录。随后两次release构建一致，SHA-256为 `cb2d8368460e7c791f1df866891cd50b5b98f34ba0b2a9f46e0234ee25f69d31`；原生计量前后源码及二进制未变。

同构建 `--verify-gpu-memory` 的七组合成字节、预览PNG及整张编辑器PNG与上轮候选逐字节相同，CPU／GPU最大通道误差1（门槛2）。64次时间别名、主编码器租约、暂停草稿刷新、取消／历史恢复、过期视口及关闭清理通过；分配8、发布8、源上传1。没有新增GPU dedicated／shared预算成绩。
