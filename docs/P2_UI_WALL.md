UI提供可选、同步、仅接收 `UiPhase` 枚举的诊断回调，区分场景栏、素材／图层、参数／历史、画布、音效面板、设置／诊断及四处主要项目快照获取。回调不携带项目、输入值、GPU或时钟；宿主只在显式诊断中记录时间。普通 `show` 委托同一路径且不开启观察，无新缓存或项目写入口。没有修改声音供给、重绘间隔、合成、字体配置或依赖。

宿主MainWork升级为诊断格式3，仍最多16384行；读取器分别支持旧格式1／2。分段互斥，可回汇原父段；快照完成返回原面板，不能当作新的UI调用。四处快照包含reconcile、左面板、右面板和画布，不包括所有历史查询或音效面板内部查询；快照析构等其余工作仍归属面板。

新增 `tools/measure_ui_wall.py`，固定两轮普通权限GUI诊断，只分析完整UI调用的单调墙钟区间。保留所有调用、初次长帧、原始进程计数和原检查谓词，不挑选有利窗口。检查记录完整性、原生延迟和生命周期；CPU校验状态固定为未知，不能授权P2验收。工具不构建或启动C采集器，无需ETW权限或额外SDK。该工具成功退出只表示这些诊断完成。

## 两轮墙钟结果

实际runner为普通未提升Default令牌（type 1），产品由该runner直接创建；本机RTX2060／NVIDIA560.94／Vulkan。调用次数354／369，边界9665／10062行，未溢出，UTC／单调时钟差异1500／17600 ns均在原检查范围内。以下覆盖本次诊断的**全部UI调用**，含加载、播放、暂停和关闭流程，不是先前32 Voice窗口的CPU分解。

| 每次UI调用的墙钟p95，ms | 轮1 | 轮2 |
| --- | --- | --- |
| 完整控件构建 | 0.9764 | 0.9108 |
| 场景栏 | 0.2320 | 0.2333 |
| 素材／图层面板 | 0.1034 | 0.0992 |
| 参数／历史面板 | 0.1863 | 0.1889 |
| 画布 | 0.0185 | 0.0184 |
| 音效面板 | 0.5188 | 0.4879 |
| 四处主要快照查询合计 | 0.0245 | 0.0193 |

各段p95不能相加，也不能换算为单核CPU。墙钟包含抢占和系统等待；不从现有CPU失败结果扣除本次耗时。

两轮最大控件墙钟为 **305.3562／154.1281 ms**，均发生在第一次UI调用；其中场景栏占297.9483／146.8941 ms。全部长值保留，不以低p95掩盖。当前只能确认首次调用和区段，尚未区分初始化、排版、字体或系统等待，也未证明它是之前宿主迟到或CPU超限的原因。

本次快照获取墙钟较小，音效面板的常规p95较高，下一步可在无需UAC的条件下细分音效面板内部构建及场景栏首次调用。当前数据不支持优先引入跨帧项目快照缓存；没有因为分段发现较小耗时就修改领域／历史结构。
