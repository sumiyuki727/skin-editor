## 记录边界

相位报告升级为诊断schema 2，不改变项目、Command、音频配方或磁盘格式。原6列欠载行保留，增加最多32次欠载的上下文；每次包含前三次回调及发生欠载的一次回调。总次数与总缺帧不截断，超过窗口明确报告缺失数量并使轨迹完整性检查失败。并发读取未发布完整行返回null，不能作为有效空记录。

上下文每行依次为：回调序号加一（0表示前置空位）、后端提供的入口纳秒戳、请求帧数、入口／结束队列量、缺帧、入口／结束供给pass、重定时丢弃帧数、入口／退出阶段。回调只复制已有元数据，不取自有时钟、分配、等待或持有PCM。记录仅在显式capture下执行；每个输出增加约12 KiB固定元数据，另计于PCM配额之外，实际进程预算仍需验证。

供给pass包括零补充的pump尝试；相同pass只表示没有观察到一次pump完成，不能排除生产者已开始工作。队列变化、回调入口时间间隔、重定时及供给交错分别显示；不把同样的416帧数字或一个时间差直接解释成驱动、系统调度或解码原因。

| 阶段ID | 含义 |
| --- | --- |
| 0 | 未分类；相位报告不允许存在未分类计数 |
| 1 | stream_start：调用play |
| 2 | prepare：同步来源及准备组件 |
| 3 | ready：打开场景及创建观察器 |
| 4 | phase_scan：固定相位探针循环 |
| 5 | collect：收集观察器结果 |
| 6 | stop：停止／清理控制及回执 |
| 7 | close：关闭供给、销毁输出流 |

阶段是诊断标签，不是播放门控。每次回调按入口阶段计入回调数、请求帧数、欠载回调数、缺帧数和重定时帧数；跨阶段行同时保留入口、退出标签。输出流销毁后读取总计和阶段计数，逐列求和必须等于全局累计。schema 1在关闭供给前截取stats；schema 2包含close阶段，两个关闭边界不能混算或追认旧轮通过。阶段统计不依赖进程采样器恰好看见一次很短的阶段。

## 确定性验证

使用产品原生consumer、真实预算及Runtime，在无设备、无sleep条件下重放1024帧空闲储备和三次480帧回调，捕获1024→544→64队列、第三次缺416帧及完整供给pass。回调中用受控写入点切换阶段，验证归入入口阶段且退出标签不同。另验证40次欠载保留最初32行但不丢失总数，释放后PCM归零。Python负向检查拒绝部分行、缺少阶段、累计不一致及身份不符；同样缺416帧的一次1056帧回调与连续耗尽路径分别呈现。旧Voice、双通道及草稿／历史清理沿用全量回归。

## 原生计划与环境范围

固定执行四组共八轮相位扫描，每轮保留20个请求相位、每相位8次、每通道160次；无强制睡眠注入、供给阻塞或重采样挑选。随后尝试两轮300秒MemoryUsage＋ReusableStaging标准组合；第二轮提前失败后只增加一轮明确标识的补测，再完成后置像素对照。源码／二进制冻结，原生性能期间不编译。失败照常保存，不因另一轮通过而覆盖。
