# P2-A3：32 Voice CPU 归因与优化

2026-10-24。本轮沿用零欠载、请求到原生复制观察上界 p95≤20 ms、单逻辑核 CPU≤15%、工作集／私有提交≤512 MiB 的门槛。最终构建的普通固定五进程计划及“仅区段计量”两轮通过；569 项默认检查通过。外部线程采样模式仍有 15.45%／17.43% 超限，诊断扰动与环境波动尚未分清。原[持续背景计划](P2_CONTINUOUS_BACKGROUND.md)及本轮中间超限记录保留，不重写成通过。P2-A3 与普通默认晋升仍未关闭；证据见 [P2_VOICE_CPU_PROOF.json](P2_VOICE_CPU_PROOF.json)。

## 计量边界

外部 Windows 计量器只打开自己创建的子进程及已核对所属 PID 的线程。线程身份使用 OS ID＋创建时间，防止 ID 复用；背景读取、供给、短音解码、WASAPI 输出、GUI 主线程和诊断观察分别列出，未识别线程归入 other。句柄用完即关闭，线程数与累计身份有上限，进程 CPU 仍用原 GetProcessTimes 及原采样窗口，不扣其他线程或观察开销后再验收。

GetThreadTimes 的粒度不足以把约两秒窗口中的 0 解释成没有成本。线程在窗口中退出时明确记录缺失身份和计量缺口，不能用存活线程的零值替代；GUI 进程退出阶段尤其如此。主线程包括 UI、egui 和呈现调用，other 不能直接命名为驱动成本，线程计量不能等同于精确函数 CPU。

另用显式 `--verify-profiled-gui` 对自有回调做固定区段墙钟计量。六列累加值为回调数、总工作 ns、背景取样 ns、声音准备／混音 ns、最终过滤／复制 ns、输出帧数；单写者发布、读者最多三次尝试，拒绝部分快照。区段计量与原生提交时间分开；墙钟含抢占，不能从提交上界或进程 CPU 中扣除。普通候选不读取这些工作时钟，回调没有引入线程计量 API、分配、锁或 I/O。

基线计量指出：背景读取／供给各约 0–0.8% 单核；32 Voice 原生输出线程约 8–9%，GUI 主线程约 6.5–7.3%。输出线程还含 CPAL／系统成本。带区段的基线两轮，声音准备／混音墙钟约占区间的 6.6–7.7%，背景取样约 0.05%，支持优先优化混音。它不是把全部输出线程 CPU 直接归因到混音。

## 实现

`audio::PreparedSound` 提供共享区段累加：匹配采样率／声道时，每块只读取一次不变格式与源切片，保留逐样本零分数插值运算及其零符号；其他最低格式继续调用同一标量采样器。非法目标布局不写入，EOF、地址溢出及最后帧按原规则处理。没有新 PCM 分配、重采样质量改变、裁切或中间限幅。

`infrastructure` 仍拥有 Voice 游标、来源／代次、交接及退休。按槽序把每个 Voice 加到目标平面，各输出采样的 Voice 累加顺序仍为 0…31；块尾判断一次精确完成，块内 EOF 停止，空块不推进。取消重算、最终复制前过滤、原生端点交还和 PCM 所有者规则不变。新增最低 16 格式、浮点位模式／零符号、32 Voice 混合结束位置和空／部分／整块金样，既有跨线程取消／回收回归继续执行。

GUI 只缓存回调数、背景复制／生成帧两行被动文字，最长 100 ms；减少每帧不同数字触发的文本布局。欠载变化、设备格式／计数重置、暂停／冻结变化及 UI 时钟回退立即刷新。音频准备、错误、Voice 状态、应用端口观察、输入／命令与预览绘制仍按原频率更新；精细时间轴和变换参数不使用此缓存。缓存只有固定数量值与文字，不持有项目、PCM、GPU 或历史租约。最终普通两轮 UI 构建均值约 0.50／0.63 ms／帧，阶段仍绘制 129／128 次；其他最终诊断轮约 0.50–0.65 ms／帧。短窗口有波动，未把差值单独归因到缓存，也不把墙钟当作 CPU 扣减项。

## 检查与证据

最终检查共 569 项（117 Python＋130 核心 Rust＋322 桌面 Rust），新增 7 Python／9 Rust。格式、Clippy、无窗口行为、依赖／源码边界与 release 构建通过；没有新增依赖或修改锁文件。整数位置／零符号及块尾金样先在原算法下通过，再实施优化；完整最低转换矩阵、32 Voice 混合结束与选择性取消／原生交还回归继续执行。

一次增量构建在新鲜构建后得到不同二进制摘要，该批虽短计划通过，也未作为最终交付证据。后续固定构建再运行一次 build，摘要不变；以下最终四种配置使用同一摘要、同一源码身份。没有在最终测量期间修改代码、运行构建或检查。

中间三个实现计划均有 CPU 超限，包含 15.04%／15.79%／17.29% 的 32 Voice 窗口和一次约 23.8% 的退出阶段；全部保留。未把某次改动或最终正常退出当作这些事件的完整归因。31 份旧证明保持原始字节；Git 无暂存、提交或推送。

## 尚未覆盖

两轮 300 秒标准图形／持续背景／双通道声音组合、GPU dedicated／shared 预算与像素验证仍需最终候选单独执行。本轮原生 32 Voice fixture 与设备格式一致；不同采样率／声道组合有逐位功能回归，尚无对应 32 Voice 原生 CPU 预算成绩。旧退出阶段 23.8% 的一次超限未得到线程现场归因，不能用之后正常退出追认其原因。真实歌曲入口、设备消费／残余、其他设备／平台、P3 文件输出和全局分配器审计继续按原边界开放。
