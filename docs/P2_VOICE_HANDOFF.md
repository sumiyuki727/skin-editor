# P2-A3：就绪声音的有界并发交接候选

2026-10-23。接续[分离模型](P2_SEPARATED_SUPPLY_MODEL.md)，将其声音交接部分落实为`infrastructure::voice_handoff`候选。它使用真实SPSC队列和受控线程测试，**尚未接入CPAL、背景储备或桌面默认路径**。本轮没有原生延迟、CPU／进程内存／GPU预算成绩，P2-A3仍未验收。检查身份见[P2_VOICE_HANDOFF_PROOF.json](P2_VOICE_HANDOFF_PROOF.json)。

## 已实现的边界

- 构造时预分配两个32项rtrb队列及固定消费状态。32份额度覆盖待交接、发声、待回收三个阶段；已完成但未回收的槽不能提前复用。rtrb沿用锁定的0.4.0，没有新增依赖或线程到产品启动流程。
- 所有者核对完整Origin、同一共享PCM预算、已准备声音格式及通道代次。Token以Weak关联具体边界，防止另一设备会话的同值代次或旧地址复用；VoiceKey只在本边界内有效，不是项目／历史身份。
- 仅接收同输出格式的PreparedSound，复用既有增益／隐藏处理结果，不复制PCM、不解码、不执行重采样。44.1／48 kHz、单／双声道同格式波形与既有Runtime逐样本对照；不匹配明确拒绝。它尚不能替代当前已支持格式转换的播放路径。
- 消费端只移动预分配描述符、读取不可变样本并累加两个未限幅通道；最终背景合并、监听音量及限幅留给输出适配器。单块上限2048帧，非法块在清零、取队列或推进游标前拒绝。
- 场景／试听各30位单调代次及运行／关闭标记共用一个AtomicU64，取消两通道只发布一个原子值；消费步骤有界读取，不等待多字段快照。代次耗尽关闭边界，绝不回绕复用；Voice编号采用checked u64。
- 源失效和普通候选就绪分开：本候选的`invalidate_source`仅供取消／历史清理，不能在每次素材准备完成时调用。绑定选择、候选激活、普通编辑后旧声音可结束等规则仍由既有Runtime／控制器负责，尚未桥接到该候选；不另建一套项目或绑定运行时。

这是实验内Rust接口，没有新的application写入口、序列化协议或UI调用。场景运行开关只是声音门控，真实恢复仍须由上层先确认背景提交锚点并预填充，不能靠它直接恢复整个播放器。

## 取消、所有权与退出

取出队列后检查一次完整门控；生成样本后、返回缓冲前再检查一次。中途失效的通道整块清零，清除其首次发声回执并退休旧实例，另一通道继续。回执附带本边界的通道代次。函数返回后的新失效、原生Copy队列及设备残余尚未接入：未来适配器须绑定设备身份、保留这些代次，并在自己的提交边界再次过滤，不能把本函数的回执当作声学静音或设备已消费。

结束／取消只把Packet移动至返回队列；所有者仍固定同一PCM，收到相同槽和代次后释放两份引用。即使所有者提前退出，消费步骤也把资源留在返回队列，不在函数中释放最后PCM。防御性返回背压有固定延迟退休槽，不以丢弃Packet清理；有效的32份总额度保证正常路径不需要该回退。

`stop`／`finish`须在渲染函数外使用。测试线程在最后一次调用后交还独占端点，所有者即使没有下一次回调，也能回收待交接、活动和已返回实例。消费端被意外丢弃时先关闭门控；所有者通过队列端点消失检测，释放孤立待交接队列和固定引用。实际PCM额度由最后租约析构归还，不提前退款。

这些测试证明的是Rust端点停止／回收协议。**CPAL闭包销毁发生在哪个线程、系统流何时真正静止、失效设备如何交还端点，仍待原生接入验证。** 端点及预分配容器的析构不得放入原生渲染调用；代码检查和PCM计费不等于已运行全局分配器或实时截止时间检测。

## 已执行测试

新增13项无设备测试。跨线程顺序由零容量通道门闩控制，不使用sleep或概率重试；10秒超时只防测试死锁，不参与性能判断。

| 范围 | 结果 |
| --- | --- |
| 确定性交错 | 20种门闩条件：取队列后／返回前，短音已结束／仍活动，分别暂停场景、停止试听、同节点历史导航、取消草稿、所有者退出；旧输出与首次发声回执正确失效 |
| 正常样本语义 | 2采样率×2声道×4增益／隐藏组合，共16组，与既有Runtime输出一致；未引入另一套配方处理 |
| 满额与隔离 | 待交接、活动、待回收状态都拒绝第33份；停止不占额外额度，恢复拒绝冻结输入，另一通道保持有效 |
| 回收时并发复用 | 原回调停在返回检查前，所有者回收并复用同槽；新旧Key不同，新Packet只在下一次消费进入。另覆盖同窗口内历史失效，旧回执不会被新代次冒认 |
| 无后续回调退出 | 待交接／活动／已返回三种状态均交还端点后完整回收；异常端点析构同样清理孤立队列。外来停止凭证原样退回，不释放另一所有者的额度 |
| 资源循环 | 300轮×32 Voice，共9600次交接。共享PCM池总限额及单份限额均设128字节，每轮已完全占满，仍可复用32份句柄；回收后每轮归零，延迟退休为0 |
| 有界错误 | 拒绝异池、格式不符、完整旧来源、外来Token、非法块及关闭后的请求；代次耗尽不部分更新两通道或来源，不产生编号别名 |

本机x64结构测量：所有者内嵌912字节，消费状态预分配12352字节，Packet为192字节，两个队列共64个Packet槽。以上不含rtrb／Arc账本、分配器取整或系统音频缓冲，不是进程内存峰值。PCM循环的128字节是小fixture成本，不能替代32 MiB共享上限或实际歌曲／32 Voice负载的整机预算。

沿用`tools/check_core.py`和`tools/check_desktop.py`运行默认格式、Clippy、依赖／源码边界与无窗口测试；最终计数与日志摘要见证明。初次波形对照测试错误地假定隐藏声音也会创建准备任务，修正测试后重查，失败日志保留。原始记录位于忽略目录`artifacts/p2/voice-handoff/`，旧24份证明保持原字节，没有暂存、提交或推送。

## 下一步

先让既有Runtime输出已接纳的Voice交接数据，连接普通候选激活、草稿／历史的已验证事实及背景储备。需要明确格式转换和共享采样执行位置，保持现有配方与事件语义，不通过每次编辑重建整个边界实现热替换。接入CPAL前验证设备终止的端点交还和实际回调分配／析构，再运行同源短轮、32 Voice及300秒组合。
