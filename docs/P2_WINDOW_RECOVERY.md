# C4 完整窗口的 MemoryUsage 恢复候选

2026-10-28，[离屏策略对照](P2_REBUILD_POLICY.md)之后的有界增量。**完整 Editor／eframe 的同进程窗口关闭、退休和重开用例通过，C4及P2仍未整体验收。** 原始摘要、源码身份和日志哈希见[证明](P2_WINDOW_RECOVERY_PROOF.json)。默认图形策略、普通声音路线及原供给策略未晋升或更改；CPU≤15%仍为优化目标，零欠载、提交p95≤20 ms及内存／GPU硬项保持。

## 恢复方式与所有权

锁定的eframe 0.37接口由框架内部持有Renderer和surface，未提供在一个活动窗口中公开替换整套Device／Renderer的入口。本次使用官方`WgpuSetupExisting`与顺序`run_native`，在同一进程内完整关闭旧窗口后建立新窗口。没有修改第三方框架或新增依赖；**不是呈现中突发设备丢失的原地修复**。

显式诊断入口`--verify-window-recovery`由`tools/measure_window_recovery.py`启动并协调。每代真实调用现有Editor的logic／ui，保留application的ProjectSession、项目历史及编辑器状态。自制图片及音效仍经Command登记，不开放新项目写入口。恢复数据不携带Device、Queue、Texture、Renderer或旧egui Context；新窗口注入新Context，缩略图和字体图集由新宿主／框架重新建立。FrameKey和分配游标保持单调，不能重新把旧键解释为新资源。

原生所有者在交给eframe之前安装自己设备的丢失通知，NativeHost只在首次请求前接受该代的失效门控绑定；已经使用的门控不能替换。关闭阶段先停止新绘制并冻结声音，准备结果仍在槽内时使其失效；在安全的`on_exit`阶段执行真实`Device.destroy()`并等到Destroyed通知。本轮没有在框架仍呈现时破坏设备，因此不把它记作意外驱动复位测试。

每代必须全部满足以下条件，才准入下一个设备：

- 实际Renderer的callback_resources析构见证已触发，旧Instance的surface注册表为空。
- 真实旧egui CPU绘制数据仍持有目标时，交接必须拒绝；丢弃后才允许退休。
- 准备worker和导入worker成功关闭；设备、队列、纹理、缓冲注册表为空，受管目标数为0。
- 旧Context和旧设备所有者退出后再创建新后端；旧图形／音频通知在新代重放不能使新代失效。

Renderer析构、注册表清空和受管租约归零分别检查，不能用一个布尔“已关闭”代替全部所有权证据，也不据此宣称操作系统立即归还驱动提交。

## 窗口与声音计划

固定两代1180×800完整Editor窗口，MemoryUsage通过现有DeviceDescriptor构造接入，保留其特性、limits和QueueWrite上传策略。使用自制单图片、短WAV和受限文件读取的360秒自制背景；不是100张PNG标准负载或真实谱面。

每代先在暂停状态确认新画面和声音就绪，再恢复持续背景，交替发出32次场景声音、32次显式试听。计量从宿主调用前开始，核对请求／来源／通道／Voice回执，由独立观察线程取得该Voice首次原生复制证据，p95使用包含观察余量的上界；GUI稍后合并回执的延迟不替代该边界，也不从读数扣除余量。显式试听经过UI/application控制入口，场景事件从同一GUI回调交给既有client；它不证明真实鼠标输入或stable玩法触发。

暂停确认后依次执行resize到980×700、软件缩放1.25、恢复缩放并请求1180×800、移到另一块显示器、真实最小化和恢复。runner只操作自己普通权限Popen子进程的窗口，逐次核对PID和窗口状态；没有系统窗口捕获、UAC、全局设置修改或用户媒体。两代均实际观察到Windows DPI **96→120**，并由egui的native_pixels_per_point **1→1.25**交叉核对；软件缩放结果单列，不能代替真实DPI。

每代四张图由自有eframe渲染器回读，物理像素尺寸依次为1180×800、980×700、980×700和1841×1240，均与当次视口×像素比例一致，非空且颜色数不少于16。已查看首代初始图及新代DPI／恢复后的图，中文字体与各面板没有可见图集损坏。完整Editor每代实际执行360次UI pass；诊断固定16 ms刷新，不用于C1空闲CPU验收。

窗口变化期间场景保持暂停、背景复制锚点不前进，显式试听仍能独立发声。关闭前特意保留一个活跃试听Voice及一份已完成但尚未接纳的准备结果。图形／音频故障门控清除旧声音和候选，回调外归还端点；重开后Voice数为0且保持暂停，背景精确恢复到前代最终复制位置，再显式继续。本轮前代锚点243360帧，新代恢复也是243360帧，随后正常推进至486240帧；没有用生成前沿或重置到0伪装恢复。仍未测设备消费位置或声学残余缓冲。

## 失败、检查和复现边界

首轮窗口计划保留在`artifacts/p2/window-recovery/pilot/`，因fixture没有实际准入新的在途准备而失败。旧候选占槽时，请求返回Pending不等于新任务已启动；修正为先等待并收取旧实际GPU提交，再请求独立尺寸，并检查准备槽确实占用。没有修改声音供给来规避这次夹具失败，后续成功计划与首轮分别保留。

最终`tools/check_core.py`通过326项Python＋134项Rust（460项）；`tools/check_desktop.py`通过默认404项／all-features412项Rust、格式、Clippy及模块／源码边界。新增5项无窗口Python回归和3项Rust回归覆盖验收范围拒绝、硬项、退休条件、回执／原生操作证据与失败join；真实窗口路径还断言使用后的设备门控不可重绑。首次Clippy拒绝的写法已修正，原日志保留。99份既有docs JSON逐项未变；未暂存、提交或推送Git。

复现工具要求新的artifact目录、普通权限冻结的默认feature release，以及包含当前`source_identity()`、profile、requested_features和两次相同SHA的构建回执：`python tools/measure_window_recovery.py --binary <冻结exe> --build-receipt <构建回执json> --out <新绝对目录>`。它有150秒总上限，子用例每代40秒；只有另一显示器确实改变DPI才报告physical_dpi_exercised。无异DPI显示器时可保留其余结果，不能声明真实DPI通过。关闭／恢复按状态和回执驱动；最小化后的三个100 ms样本仅是已声明的观察段，不用于猜测资源竞态。

本增量关闭的是**计划性完整窗口替换与当前声音路径的联动子项**。以下仍开放：呈现中的意外device lost及失败回退、物理音频端点／默认设备变化、活动编辑手势／草稿与故障交错、C5真实输入和中文IME等人工验收；当前MemoryUsage晋升前还要复核标准规模／冷准备性能及候选集成身份。普通启动仍沿用原错误诊断／重启方式，没有自动重建功能。Linux／macOS、真实stable场景、设备声学同步及文件导出不在本轮证明范围。继续收尾P2，暂不推进P3。
