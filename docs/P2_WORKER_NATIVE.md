# P2-A3：既有有界 worker 与候选原生输出

2026-10-23。接续[分离供给原生短轮](P2_SEPARATED_NATIVE.md)。本轮将候选接入既有 AudioSupplyClient：同一个控制队列、回执、SkinAudioController、真实 WAV 准备和供给循环选择两种具体输出传输。普通 GUI 仍调用原 spawn，候选由 spawn_separated 显式创建；不晋升默认，也不更换采样／声音供给策略。

## 请求、版本与完成边界

请求总额度仍为 16，涵盖排队、执行、等待消费确认及已交付但尚未释放的回执；批量触发最多 32 项，占一个请求额度，Voice 总量仍为 32。准备仍为单 worker、最多 4 个等待任务，PCM 共用原 32 MiB／单份 4 MiB。没有引入另一套请求／候选／历史实现、解码线程池或项目写入口；线程收到的只是脱离项目会话的只读投影和值。

内部 SupplyOutput 只有 Premixed／Separated 两个具体分支。共享控制负责选择、准备、触发、素材独立试听、取消和历史来源；分支只处理补充、冻结和输出边界。两端点启动时装箱以免把大的内联传输状态塞入枚举／线程闭包，不属于回调内分配。OutputMark／OutputFence 移为共用的内部值，未开放给 UI 修改。

候选增加 desired／applied／ack 三组有界原子版本。客户端在入队前发布所需失效，防止旧声音在队列等待期间继续复制；所有者处理相应 Runtime 操作后才更新 applied。消费端在混合前保存 applied，并在复制前与 desired 核对，不能因为中途 applied 已变新就把旧混合块改贴新版本。场景／试听分别失效；背景版本不随图片、声音热激活或历史变化而改变。等待场景操作时先停止背景出队，避免丢弃旧队列后又以旧来源位置读取下一块。

集成回归先捕获了旧声音恢复：仅静音、随后应用新版本，没有撤销仍有效的旧实例，会让它重新发声。现在显式重置在应用新版本前先撤销对应 Runtime 通道；普通热激活的版本未改变，已开始的单次声音仍可自然结束。**草稿取消由 Runtime 按草稿来源选择性撤销，不能把同通道的无关声音全部清掉**；这两种情况分别测试。

入队等待阶段沿用客户端的通道失效语义，可能短暂抑制整个受影响通道；本轮保证无关实例不被删除，不宣称跨控制线程的选择性取消已经做到逐样本无缝。实例归还导致的草稿退休会主动标记状态变化，复制位置也在空闲发布中持续更新，无需另一条用户请求才能刷新这些值。

暂停回执既要等待消费端确认冻结位置，也要等所有者实际重置生成前沿与 Runtime 锚点；单有消费回执不能提早完成。候选 StopAudition 和 Barrier 回执等待相应复制版本的确认，不把 worker 收到请求当成原生完成。该确认仍不是设备消费或声学静音。旧 Voice 的返回、PCM 回收与确认分开：回执／状态还会报告传输里保留的草稿，直到所有者实际收回实例，不能只凭 Runtime 已清空就提前宣布资源退休。

关闭先在客户端发布独立关闭标记，再通知并 join 供给线程；不申请请求额度，不等待另一次消费回调。等待中的请求／回执额度释放；已关闭的核心和输出所有者保留到 NativeExecutor 销毁 OS 流并交还准确端点后，由 finish_separated 核对身份并释放。外来端点拒绝且保留，异常丢弃也不提前退款仍存活的缓冲。控制句柄只持有独立原子元数据，不固定 PCM／背景环。自有原生回调仍不接触 Runtime、项目、解码、锁或等待。

原混合输出的诊断通过 output() 获取，现明确返回 Result；候选拒绝该组旧统计，不能返回一份看似正常的假计数。既有 GUI／诊断调用点均显式处理结果，GUI 没有改为选择候选。新增 copied_background 状态值与 generated_background 分开，不能把生成前沿当成已复制位置。初始非零来源位置在首次回调前也保留。

## 验证方法

新增 15 项 Rust 无设备回归：排队期间的失效与背景连续、冻结确认与独立试听、停止／屏障延迟回执、草稿实际退休、同节点历史来源拒绝、Busy 恢复、满 16 份额度关闭、外来端点、选择性草稿取消、复制中改贴版本拒绝、等待暂停不出队、关闭抑制及句柄不固定 PCM、初始位置、版本耗尽关闭，以及无新控制时持续发布复制位置。关闭用例覆盖连续回调，不能关闭后还出队旧背景、回退来源位置并误报 Protocol。竞争使用门闩；真实 worker 的满额度关闭不依赖 sleep。新增 5 项 Python 结果校验，拒绝 Runtime-only 口径、缺失／重复请求与 Voice、逆序时间、欠载、超过原门槛、错误清理和预算失败。

原生计划固定为：同构建原候选 → worker 候选 → worker 候选 → 原候选。旧候选调用原 --verify-separated-native；新入口 --verify-separated-worker 使用 application 注册两份自制 PCM16 WAV 并创建音效组件，经既有单 worker 真实探测／解码后才测已就绪声音。每轮两个通道各 64 个请求，随后同帧 16＋16 Voice、第 33 个拒绝、热替换、暂停／试听隔离、停止后实际输出缓冲的非零计数不再增加、恢复、草稿取消与历史导航。原始资料只在本次自制 fixture 中，不读取私人音乐或游戏客户端。

**新计时口径**：从 AudioSupplyClient.trigger(session, …) 调用前开始，包含 application 同步查询、请求额度／发送、worker 接纳与供给、CPAL 实际复制和精确回执匹配。保留请求 ID、Voice ID、控制回执耗时、最终匹配时刻、后端时间戳、回调序号和块偏移；目标 Voice 必须由该请求的回执返回，不能用更新的计数代替。1 ms 观察余量全部保留，p95≤20 ms 不扣余量。

这覆盖客户端完整音频请求管线，**没有 GUI 点击／帧排队、冷准备或声学起音的延迟成绩**。原候选仍是 Runtime 直接接纳口径，两个口径分别列出，不相减声称纯排队耗时。32 Voice 短窗口用于同构建成本对照，计数粒度和短采样限制仍保留；不能替代长期图形同载或跨设备结论。

背景仍是共享预算中的同格式 10 秒有限 PCM，幅度小于短音，首声音样本非零。全过程检查未达到背景 EOF；历史切换不能以位置归零掩盖 EOF。草稿取消还核对项目快照／历史节点数未变、旧 Voice 与草稿报告清空、PCM 回落到编辑前基线。完成后停止并核对端点及 PCM 实际归零。结果、身份与失败记录见 [证明](P2_WORKER_NATIVE_PROOF.json)，原始记录位于忽略目录 artifacts/p2/worker-separated/。

## 最终结果与失败保留

最终格式、Clippy、无窗口与边界检查 **515 项通过：101 Python＋130 核心 Rust＋284 桌面 Rust**。新增 15 项 Rust／5 项 Python；最后 147 份源码／配置／工具身份在构建和测量前后不变，28 份旧证明保持原字节。

首个固定计划四个进程完成；两轮 worker 的恢复位置检查均失败，**计划整体保留为失败**。根因是空闲供给未持续发布复制位置。修复并补回归后，一套新计划通过；随后完善实际退休的状态通知，按最后源码重跑全部检查、release 和最终四进程计划。中间通过不能替代最终结果。旧声音恢复、所有者同步前过早确认、关闭后连续回调误报 Protocol 的失败回归及早期编译／Clippy记录也保留。测量时没有并发构建。

最终环境为本机 Windows 10 build 19045，四轮均为 48 kHz／双声道 F32、480 帧周期，无 GUI／GPU；其他设备与 Linux／macOS 未测。
