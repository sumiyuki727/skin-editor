Save／Close接纳标识仅在成功接纳后消费。在版本／会话合法后，先识别同一在途key及原有效载荷，再对新请求检查当前修订、门控及容量；q+1不改变原请求的重复资格。同key不同载荷Conflict；另一保存请求Busy，不排队冻结第二截面。精确重复只返回既有Ticket，关闭门控下也不因此新增保存／捕获或取得关窗许可。结果Ack并实际释放后，旧key返回Stale，不能重新启动保存。用当前槽、下一序号和已消费水位表达，不能累积无限去重表。错误、忙碌和旧请求均不得新增普通命令回执或历史节点。

version 1的用例面固定为：保存状态查询、请求Manual、取消／确认指定SaveTicket、开始／取消指定核对；关闭状态查询、凭CloseAdmissionKey提出关闭、选择Manual／Exit、凭Permit收尾现有草稿、推进关闭协调、明确重试确定失败的自有子保存、取消／确认指定CloseTicket。返回值区分Accepted／Existing、Busy、Stale／Conflict、UnsupportedVersion／Unavailable、Limit及当前状态；实现可按Rust习惯命名，但不得合并掉这些语义。完成事实只能从已注入工作端口进入私有接收路径。核对结果由协调器消费为第5节观察，查询资源实际退出后释放ReconcileSlot，不另要求UI确认；原Unknown是否解除单独判断。

## 3. 捕获截面与完整脏范围

接纳顺序固定为：有效目标／端口与能力已准备→核对版本、会话、来源、草稿和槽位→预留控制、事实确认及捕获预算→同步冻结已提交截面q→发布唯一Ticket／脱离会话的工作。文件选择尚未完成不算接纳。新建工程可在捕获成功时取得永久历史身份，再完成NewUnpublished的Ticket绑定；先前未保存捕获留下的永久映射不等于已发布。首次发布经完整验证后，仅在同一绑定ID／代次内从预备目标token转为对应的已发布文件token，原Ticket仍可确认／去重；真正换文件／重开必须新上下文。application独立记录NewUnsaved／Loaded／Published来源，已发布／已恢复历史不能因内存节点origin仍为None而再调用首次发布，复制转正仍由B另约。开始失败不发布半个任务，不改项目内容、历史或保存事实；为身份准入消耗的候选号不回绕复用，所取得租约须实际归还。

普通手动保存遇活动草稿返回Busy，不自动Commit／Cancel，不把草稿前的内容显示成当前输入已保存。UI尚未提交的文本／IME并不在现有ProjectSession内；A不发出“全部UI输入已处理”的证明。D接线前须把输入处理纳入受验证流程，不能以A捕获成功覆盖未提交文本。

q包括全部节点与分支、父关系／原操作／首写表示、全部admissions（含事务内创建后删除的ID）、全部已登记及历史可达原始资源引用与租约、完整配置原文、活动头／Redo导航及持久元数据。BlobLease只提供BlobRef及字节保管资格，核心不因此取得原字节读取／散列能力；A用测试资源池核对原字节保全，B负责真实读取和校验。未引用素材和不透明音频不能遗漏。worker消费既有捕获流，不为协调新增一份全树状态副本；同步元数据冻结的工作界限如实保留，不宣称本阶段所有工作已经分步或满足响应时间目标。

| 查询维度 | 必须语义 |
| --- | --- |
| 完整内容覆盖 | 以不可变追加历史的完整前缀和资源／admissions范围关联q；前缀末端不是当前head。A→新建B→回A仍有B待保护，不能只比当前头或当前导出 |
| 导航／持久元数据 | 用户有效导航及未来获准的持久元数据变更参与判断；运行选择、预览冻结、试听／监听音量不参与。旧记录、未知扩展和配置原字节保持 |
| 手动／保护／最新文件事实 | 分别保存最新已验证提交与覆盖、最近Manual、最近保护、打开基线和当前活动头；“当前像手动点”不等于“整树已保存” |
| q之后的变化 | q+1节点／资源／导航继续待保护；晚到q的合法回执仍可确认q，不能因当前revision变了便丢弃真实事实，也不能清掉q+1 |
| 未提交草稿 | PendingDraft独立于已提交历史的脏范围；q完成时若已有新草稿，保留草稿及其基础修订，不显示全部输入已保存 |
| 确认与重开基线 | 确认已落盘事实、安装绑定及加载推导Redo不产生内容节点或自致脏循环。打开基线须来自受验证恢复上下文，不能给任意活动工程贴clean标签 |

在交付／poll前取得并保留CaptureSnapshot；现有snapshot()在Complete／abort后不可再取，Snapshot本身也不保留Frozen的全状态遍历。尤其新节点可能没有origin，不能等worker消失后只凭manifest重建完整内容承诺。

CoverageKey只作本地关联；节点数、head、资源数或“相同hash字符串”均不能单独证明全树覆盖。工作端口必须对与Ticket绑定的冻结manifest／原字节范围及持久请求上下文作完整核对，返回有界证明引用和摘要；B负责证明其确实对应完整文件。当前保存状态查询只读维护好的有界事实，不反复capture、复制全树或读文件。来源修订可保守提示需保存；只有受验证的语义等价／NoChange证明才能消除该待核对范围。

保存事实安装采用独立元数据路径，不执行Command、不重放旧操作、不修改旧节点／旧Snapshot。Manual潜在新增标记及ArchiveMetadata候选必须在MayWrite工作交出前实际准备并预留所需capacity，确认时不能再因普通回执／内部配额耗尽而丢掉已提交事实；NoChange和重复确认不追加标记。旧捕获保留其原Arc值，活动会话使用经过核对的新表示；完整保存元数据仍受其自身预算约束，不在控制摘要里复制无限提交列表。候选固定对应q，可能提交后即使取消也保留到事实确定；不得提交后临时按q+1重建或因内部再分配失败丢事实。安装不改变草稿基础ExpectedState、内容／导航修订或未提交输入。

追加标记空间／下一文件代次不足时，若捕获、现有元数据和只读核对仍准入，可采用内部VerifyOnly资格验证既有NoChange；该资格不允许任何持久写入。确认意图仍需新增写入时返回RequiresWriteCapacity／Limit并保留待保护范围；读失败／目标冲突保留原结构化错误及未验证覆盖，不改称容量错误或成功。新目标／缺首次Manual不能借此成功。MayWrite必须具备其可能新增事实的候选容量，不能赌最后会NoChange；这些资格不是新增用户模式，也不证明B已存在该端口。

## 4. 保存状态与所有权

| 状态 | 进入／允许动作 | 退出条件 |
| --- | --- | --- |
| Idle | 无保存任务；可尝试接纳Manual或同CloseTicket最终保存 | 一次原子接纳q，或结构化拒绝后保持Idle |
| DispatchPending | 已接纳q，工作尚未交给端口；协调器拥有捕获和预留量 | 交付后Working；可证明从未交付时取消／失败进入Settled |
| Working | worker消费捕获／准备／写入；查询和取消请求可达。进度不是提交证据 | 完整匹配的确定结果进入Settled；可能提交但结果不明进入Reconciling |
| Reconciling | 保留原Ticket、CommitId、绑定、覆盖承诺和所需租约；禁止该保存槽及目标的新写入 | 受控查询取得第5节的确定观察后才Settled；取消查询、关闭或失效适配器均不能清除此状态 |
| Settled | 保存事实或确定未提交结果已记录；终结结果、Ack资格及资源状态分别保留 | Ack已接受且该任务所有实际消费者／worker资源已释放才Idle；任一未完成则如实WaitingAck／WaitingResources |

捕获分步遍历可能发生在写入工作内部，不能仅凭“仍在捕获”进度声称未开始事务。交付后通道断开、worker丢失、异常或取消，只有端口能证明未提交时才作为确定失败；否则按Unknown处理。Capture Complete、写临时文件、发送取消、清空请求、worker通知完成均不等于磁盘事实或最后Drop。交付后worker退出却没有合格结果，在可能提交时必须进入Unknown，不能丢弃通知后永久停Working。

确定事实被记录后，协调器释放自己不再需要的重型捕获，终结槽仅保留有界值；独立消费者仍持有Snapshot／CapturedNode时保持占用。Ack可先到、实际释放也可先到，两种顺序均不可提前接纳下一保存。Unknown必须保留足够复核上下文，不能为了腾槽删掉；同一槽内的查询拥有独立保留量，不能等待原槽空闲才允许复核。

## 5. 完成封套与真实事实

内容准备和提交事实是两个步骤。端口须在任何可能形成持久提交的边界之前，将唯一PreparedWitness发布到接纳时已预留、寿命独立于worker／完成消息的槽；协调器无需GUI轮询或先行Ack即可保有它。只经私有工作资格关联后才允许提交；VerifyOnly的NoChange证明也须关联同一只读准备结果。见证覆盖完整状态／原字节范围、持久元数据／导航及请求上下文，不能仅用节点数、is_complete或当前存储request_hash替代全部验证；profile的真实算法与文件复核由B冻结。

A的fake以实际捕获状态及自制资源池作独立黄金比对，使用明确测试profile，不宣称真实文件摘要或抗篡改证明。见证只用有界承诺／引用，不新增全树副本；存储scratch另计。发布见证不代表已保存；可能提交而见证缺失／矛盾时保持Unknown／AdapterFault，不猜成功。现有同步write_capture没有这种向外保管通道，属于后续新增协调端口的必要实现。

完成通道由接纳时的工作上下文持有，不能由UI把四字段ArchiveReceipt加一个成功布尔值就制造。注入端口承诺核对同一目标、历史／谱系、固定q、CommitId／expected链、origin、generation、捕获头及完整覆盖，并分别给出Manual／保护事实。私有构造资格只防误接线，不能代替文件验证；A替身通过不构成B端口的证据。

| 观察 | 应用处理 |
| --- | --- |
| Committed | 完整核对后仅确认q；Manual推进手动及保护，Exit仅推进保护；不切当前头，不改既有节点。首次无Manual的显式保存必须有真实Manual事实 |
| Replayed | 只确认同一持久请求已存在的事实；不新增代次／标记、不重复关闭，不将低代次回执覆盖较新事实。相同CommitId但请求上下文不同必须拒绝 |
| NoChange | 本次新CommitId没有提交事实。须证明q完整覆盖，且满足本次意图：Manual还须对应既有Manual点或其已验证打开等价基线；只有保护覆盖不能代替Manual。保留原Manual／保护，不制造新标记 |
| 确定未提交／取消 | 保留已完成编辑、未保护范围和旧文件事实；释放仍按真实所有权，不因返回错误直接退额 |
| OutcomeUnknown | 原任务进入Reconciling，禁止盲换ID重写。不是可Ack丢弃的失败终态 |
| 错会话／旧绑定／旧Ticket | 不改变当前项目事实或关闭状态；只处理该消息自身资源，不能释放当前任务。匹配当前Ticket却缺失／矛盾的提交证据，在可能已提交时保持未决／冲突，不能降格成安全的提交前失败 |

NoChange重点变体：Manual A、保护C、默认打开A且无新工作，允许保持A／C；返回C的四字段回执不是“本次手动保存C”。加载推导的Redo属于打开基线，不能盲用底层same_redo结果或丢掉用户真实导航凑等价。合法无Manual而显式恢复Latest后，第一次手动保存不能以“树已在文件里”为由忽略Manual意图。新空根的显式Manual也不适用无保存关闭例外。

Unknown查询先停止失效写适配器，等待其写连接／执行资格和工作scratch退出；用于核对的原捕获承诺／租约继续保留，不能等待这些被原任务刻意保留的引用全部释放才允许查询。查询使用同目标完整验证的只读事实，既不写入也不激活项目。保存工作取消与核对取消必须分离：每次核对使用独立、初始未取消的token，不能复用已取消的CaptureCancellation，也不能复位旧token。首次核对的控制对象／取消资格在MayWrite交付前准备；后续attempt重新准入失败仍保留Unknown。每次查询绑定原Ticket和attempt；旧attempt结果不得解决新查询。主完成迟到但完整合法时可先确认事实，进行中的查询仍须退出／实际释放；查询取消或旧观察不能抹去该事实，也不能释放新attempt的槽。四类观察固定如下：

1. 找到原CommitId，完整上下文匹配：确认原提交，且不回退更高代次。若同时发现目标后续冲突，保留这项真实提交事实并锁定绑定，不以它放行新写入或关闭。
2. ID不存在，但独立证明原请求满足NoChange：按NoChange规则确认覆盖，保留原Manual／保护。
3. 同目标有效、能证明请求未提交且q未覆盖：记录确定未提交／仍待保护。重试须重新明确接纳；如重捕当前状态，使用新的Ticket，不把q暗换成q+1。
4. 读失败、目标消失／替换、日志待恢复、摘要冲突、验证／查询取消，或仅返回None而缺少充分证据：继续未决／冲突，不重试写入、不退出。

首次发布路径不存在也属于证据不足，除非能排除发布后移动／删除等情形。取消关闭不取消独立保存；取消保存或核对不是“没有提交”的证明。已经确认的提交不能因用户随后取消而被删除或改标为未提交。

## 6. A的最小关闭门控

关闭状态依次为Requested／AwaitChoice→ResolveDraft→SettleExisting→FinalCapture→Protecting或Reconciling→ProtectionSatisfied。后者只表示A层的保护事实条件满足，**不是ReadyToClose、OS关窗许可或项目替换许可**；A没有Quiescing完成／激活授权。完整输入、导入、音频、GPU交接与实际关闭由C／D补齐。失败停在可查询／可取消状态，不能自动强退。

| 关闭意图存活期间的入口 | 决定 |
| --- | --- |
| submit、有效navigate、普通Draft Begin／Replace／Commit、未来持久标签修改、导入登记 | 拒绝BlockedByClose；门控在真实写入口，不能借cached成功回执把旧动作解释为本次关闭收尾。普通拒绝不消耗新命令回执 |
| 关闭前已存在草稿的收尾 | 仅同CloseFinishPermit允许Commit／Cancel；核对实际当前DraftState，再走原子入口。失败保留草稿／旧节点及Permit；只有成功Commit／Cancel（包括NoChange终结）消费收尾资格。失败仍按既有普通回执计费，正确Cancel需合法新RequestId及原保留位；旧Commit回执不证明该草稿已经结束。成功有效Commit至多一个节点；NoChange结束草稿而不造节点 |
| 未提交文本／新配置手势 | A不接纳任意新Command或新Draft绕过门控。未纳入现有草稿的输入需先取消关闭、正常完成后重新提出，或由后续受审阅的D／V1协议收尾；不得宣称现有草稿已具备可视化最后意图守卫 |
| 普通新保存／外部新捕获 | 拒绝；精确既有控制请求只返回原Ticket，不能启动工作；仅本CloseTicket的最终保存可在已结清旧任务并实际释放捕获槽后接纳 |
| 只读查询、正确Draft Cancel、精确Ticket取消／Ack、事实协调和资源回收 | 保持可达，不依赖GUI刷新；控制通道不消耗普通命令回执，正确Draft Cancel仍用既有预留回执规则，普通可用额度耗尽不能吃掉该保留位。预览／试听临时动作不成为项目保存事实，完整停止门控留C |

只读validate／快照查询成功不预留提交资格，也不是关闭收尾许可；所有真实写入口仍重新核对当前门控。为保持既有正确Cancel可达，公共edit_draft的合法Cancel可由application入口匹配当前CloseTicket已持有的Permit，委托同一收尾路径；无需新控制分配，仍需合法普通RequestId及其保留回执。旧Cancel回执不能代替当前草稿已结束的事实或消费新的Permit；无匹配资格不改草稿，其他普通草稿动作仍受门控。

选择在最终保存接纳前固定为Manual或Exit；重复同一选择幂等，改变已固定选择须取消该关闭意图后重新提出。SettleExisting先记录既有保存的确定事实，再经同一精确Ack入口确认、释放不再需要的捕获；application可完成这一步，不等待UI碰巧刷新。Unknown或其他消费者仍在时如实等待。随后在持续门控下取得最终q，包含关闭专属收尾的全部已完成修改；不能拿先前独立保存的旧q直接顶替。重复advance_close只推进已有状态，子保存确定失败后不得自动再提交；明确重试须绑定同CloseTicket和失败子SaveTicket，先完成该子任务Ack／实际释放、重验目标，再用新SaveAdmissionKey／CommitId捕获。Unknown不能重试写入。

CancelClose立即撤销该关闭意图的写门控，并请求取消它自有的子保存；不取消先前独立Manual，也不抹去已经提交的输入或文件事实。SaveSlot的Unknown／实际资源继续独立保留。CloseSlot只在其终结Ack和自身实际资源归还后释放；子保存保留原父身份，即使旧CloseSlot已归还，晚到完成也不能推进新CloseTicket。新保存／关闭仍须受所有未决任务与目标资格约束。

ProtectionSatisfied和EmptyCreationBaselineSatisfied都是非终结状态，ack_close不能将其确认成退出或解除门控；A仅对已Cancelled的CloseTicket接受终结Ack，准入前拒绝没有待Ack任务。保护满足仍保持写门控，直到显式取消A的关闭意图或未来C接管；A不能把“Ack保护结果”实现为直接退出／新建／打开。取消关闭后编辑可恢复，但未决目标仍不能写，未释放的保存槽仍Busy。

全新从未编辑的空根，没有Manual意图时可得到EmptyCreationBaselineSatisfied，不造空保护事实；有效编辑后Undo回空根仍须完整保护分支／资源。新空根首次明确Manual保存必须真正提交；已有相应Manual事实时仍按第5节验证NoChange。需要保护却没有目标／恢复能力时返回NeedsTarget／RecoveryUnavailable、保持工程打开；A不选择临时目录替代B的持久恢复区。

## 7. 固定控制预算与耗尽行为

修订2保持SaveCoord-Control-v1：每活动协调器控制分配上限512KiB，普通区256KiB、不可被普通操作借用的保留区256KiB。每类最多一个SaveSlot、CloseSlot和同SaveTicket的ReconcileSlot；保存／关闭各一个待Ack终结槽，核对仅一个当前结果；无保存排队，无LoadSlot实现。数值沿用草案1为固定槽及故障保留划定的起始契约选择，尚待实现给出静态核算证明；不是已有默认常量、实测需求下限或实际RAM成绩。

| 分区 | 固定容量上限 | 内容 |
| --- | --- | --- |
| 普通：常驻状态／绑定 | 64KiB | 当前来源、最多两个有界目标上下文、序号水位、预算账本；不放路径或全树 |
| 普通：保存槽 | 64KiB | 一个Ticket、当前工作资格／取消状态及所有权句柄 |
| 普通：交接信箱 | 64KiB | 一份工作交接和一份完成，分别最多32KiB容器；不堆积旧结果 |
| 普通：事实摘要／终结值 | 64KiB | 最新／Manual／保护／打开基线及本次终结；不另建无限事件表 |
| 保留：关闭控制 | 64KiB | 一个CloseTicket、选择和现有草稿收尾资格 |
| 保留：Unknown核对 | 64KiB | 一个查询attempt及有界观察；原SaveSlot未归还也能使用 |
| 保留：失败／确认／归还 | 64KiB | 失败终结、取消／Ack及实际所有权归还控制；取消只标记既有槽，不入新队列 |
| 保留：最终保护交接 | 64KiB | 关闭最终保存所需控制空间及保留的首次核对资格；复用同一保存／捕获槽，不能凭有保留字节并发第二次捕获 |

Ticket逐字段值载荷至多1KiB，PreparedWitness值载荷至多4KiB，状态查询至多4KiB，单个工作／完成／查询封套至多16KiB，诊断为有限枚举＋最多四个数值字段、值载荷至多128字节；不放任意String、路径、堆栈或不受限Vec。上述值口径不是新增持久二进制codec；Rust结构体、padding、Arc控制块、容器capacity及持有引用另外按实际受管分配计入对应分区。实现必须给出静态尺寸／capacity计费表与断言，不能只按len收费。须同时核算生产端、信箱、消费端仍存活的副本，以及PreparedWitness、取消句柄、查询结果和迟到封套；出队／转移不是仍存活副本的退额。有限数值诊断不能递归包装不受限错误。

保留区必须预先建立可用的固定槽／控制对象，不能只有数字承诺而在取消／Ack／首次核对时再争抢分配；既有状态查询、取消、确认及终结安装不得临时扩容。分配前预留受约束容器的容量上界，成功后按实际capacity对账；不能先超额分配再检查。唯一共享分配在同一账本只计一次，不同分配／池不能假定共享。清空请求、取消标记或Ack均不归还仍被持有的额度；最终所有者Drop才退额。固定槽容量之外的错误拒绝须能用已有保留位表达，不通过删历史、清普通回执或丢Unknown腾空间。

捕获／原始字节／保存元数据候选不塞进512KiB控制摘要，单列所有权和预算。A回归使用SaveCoord-Fixture-v1的小型负载：Session上限64节点／128普通回执／每请求16命令；捕获上限64节点／256对象准入／8原始资源／原字节总256KiB、元数据1MiB、单状态256KiB、累计逻辑状态16MiB；测试资源池单份上限64KiB。确认用保存元数据候选最多一份、独立逻辑上限1MiB；MayWrite交付前实际准备可容纳本次潜在新增事实的候选。已有ArchiveMetadata.logical_bytes按len及逻辑系数计量，不是实际capacity或堆占用证明，A1须单列候选分配／所有权边界。原共享分配只记一次，候选的新分配另计；捕获和候选同时存活不能互相借用对方限额。捕获限额使用既有逻辑成本，不能与512KiB受管控制容量混加称为实际RAM。最后捕获租约释放只退该租约保留量，历史仍固定原字节时不退真实共享分配；capture_in_flight已清除也不代表SaveSlot的Ack／查询消费者条件已满足。调用者自行复制的脱离协调器POD状态不算该协调器分配，端口实际拥有的队列／副本必须携带预算所有权，不能借此把内部占用转移出账。

该fixture不是产品容量profile，也不改变现有默认常量，更不改变gameplay的Reference／Tiny。各上限不是可同时兑现的笛卡尔积；黄金负载须先逐项证明落在限额内，再测试满额和差一单位拒绝。A只证明协调新分配、端口既有计费和实际租约寿命；既有整个Session的实际堆成本、真实codec／文件／恢复展开、磁盘journal及旧新会话并存由B／C的共同profile补证。不得从A的小型通过外推65536节点或产品性能。

接纳任何工作前同时保留其确定结果、可能的Unknown首次核对和归还资格。正常编辑／普通保存准入不得消耗最后一次保护所需的Save／Close身份和控制量；普通保存序号至少留出本次及一次最终保护，关闭最终任务可使用最后保留值。Save／Close／查询的控制Cancel、Ack、状态查询和已接纳任务完成不再申请普通RequestId或新控制操作ID；Draft Cancel仍走原DraftRequest及保留回执协议，必须使用合法新RequestId，不顺带改成不计费Command；C还需证明宿主请求号分配／预留能支撑它，A不宣称现有UI分配器已具备该保证。查询attempt用原Ticket内独立checked序号，至少预留首次核对；耗尽后保留Unknown，不回绕。

边界测试必须覆盖u64最大值附近和缩小配额。最终保护可能被外部故障阻断；保留量只保证一次有资格的尝试和已接纳任务的清理，不保证无限失败重试。额度／身份已耗尽时拒绝新修改或新任务、保留内存与旧文件、继续允许已有任务正确取消／确认；不通过假重开、清回执或剪枝恢复可写。草稿Commit仍是普通内容修改，额度不足可失败并保持草稿；正确Cancel与已完成历史保护不得一起锁死。
