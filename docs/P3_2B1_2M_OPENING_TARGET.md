# B1-2M 原打开目标的只读观察

宿主通过已有的文件读取器恢复自制工程后，可以对照原打开来源和后来持有的文件观察。这个查询回答三个独立问题：文件名的拼写是否相同，Windows 两次报告的文件标识字段是否相同，以及文件内容与选择的检查点是否仍吻合。即使全部相等，查询仍返回 `InsufficientForSaveReconciliation`。

## 输入、来源和生命周期

`compare_opening_target` 只借用保存游标和文件观察。版本 1 的上下文包含原票、观察号和完整的观察请求。查询在固定预算内核对 Reader、保存序号、目标绑定代次、持久工程／历史范围及根，再从真实捕获取回恢复时封存的私有 Provider。打开请求和保存请求各有自己的序号。原打开的选择必须和本次观察一致，观察必须晚于原打开。旧式恢复、仿造相同公开字段的来源、冻结票据与原来源的绑定不一致（含预期提交或代次已推进）、错误选择或更早的观察得到空事实；错误版本、串票、串 Reader 或串观察返回结构化错误。查询只读取冻结上下文，活动会话的取消与注册代次失效须由所有者另行门控。[应用侧值](../crates/application/src/file_profile.rs) · [查询实现](../desktop/infrastructure/src/project_storage/file_facts/profile/opening.rs)

来源保留原打开请求、观察号、历史根、打开头、文件摘要和原预期提交。本次结果单列名称摘要、卷号和文件索引字段、源文件摘要、预期提交／代次及选中头的比较。观察可以来自更晚的文件代次，比较时原票仍须对应捕获时的预期。公开结果只携带名称和系统标识的比较值。来源不保留路径或文件句柄。

Windows 路径沿用 Reader 的准入上限 1024 个 UTF-16 单元，按传入拼写的 UTF-16LE 单元流式计算带用途前缀的 SHA-256。名称别名可以产生不同摘要。新增 Windows 专用直接依赖 `winapi-util = 0.1.11`，该版本原已在桌面锁文件内。它查询同一受保护文件句柄的卷序列号和 64 位文件索引，禁用默认 feature；查询失败或任一字段为零时保留未知。文件系统可能复用索引，ReFS 上的 64 位索引也不足以证明唯一性。两个瞬时观察之间可以发生替换和回退。[Microsoft 的文件信息说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information)

## 容量与回归

来源的固定开销计入既有 Provider 租约，并保守预留观察工作空间。查询在 Reader 的 512 KiB 分区内预留哈希器、原生信息、临时观察及上下文／结果重叠空间，再读取标识。查询不遍历捕获，不克隆快照；返回的事实只含固定大小值。最后一个 Provider 所有者释放时归还来源额度。[来源保管](../desktop/infrastructure/src/project_storage/file_facts/profile.rs)

| 自制文件场景 | 名称摘要 | 卷号和索引 | 内容摘要 |
| --- | --- | --- | --- |
| 原路径再观察 | 相同 | 相同 | 相同 |
| 另一名称的硬链接 | 不同 | 相同 | 相同 |
| 独立的逐字节副本 | 不同 | 不同 | 相同 |
| 原对象另名保留，同名放入副本 | 相同 | 不同 | 相同 |
| 期间替换后将原对象放回原名 | 相同 | 相同 | 相同 |

回归还覆盖原票与后续代次分离、错误来源／Reader／票据／观察、预取消、容量恰足和差一字节、游标工作计数、实际释放和已安装元数据。上表记录的是受测本地文件系统中具有可用标识的结果。查询不会签发准备见证或保存回执。[物理文件回归](../desktop/infrastructure/src/project_storage/tests/file_facts/profile/opening.rs) · [缺失和仿造来源](../desktop/infrastructure/src/project_storage/tests/file_facts/profile.rs)

## 真实 Exit 的下一道门槛

当前绑定来自实际安装的保存准备端口。生产宿主仍需拥有注册目标、绑定代次及其失效规则，并在注册到关闭决策的必要时段证明物理连续性。后续验收须分别覆盖重新绑定、释放后旧票、跨注册者混用、同名替换后回退及预算耗尽。随后才能在同一次捕获遍历中核对 CurrentProtection、VerifiedOpening 或条件追加，再由有资格的端口报告结果。共同 64 MiB 证明、Unknown 阶段判定和 B2 写入仍是独立门槛。[B 总契约](P3_2B_START_CONTRACT.md)
