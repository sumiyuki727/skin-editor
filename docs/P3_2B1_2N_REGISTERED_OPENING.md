# B1-2N 登记原打开文件与持有区间

宿主现在可以用 `FileTargetRegistry` 登记一次无窗口的工程恢复。恢复候选和登记槽来自同一次完整校验。主文件的原始排他读句柄、祖先目录句柄及原打开观察一起移入槽中，中途没有关闭再打开。普通 `restore_profile` 继续在返回前释放源句柄。[登记实现](../desktop/infrastructure/src/project_storage/file_facts/registration.rs) · [恢复路径](../desktop/infrastructure/src/project_storage/file_facts/profile.rs)

## 登记与重绑

版本 1 的注册者固定使用创建它的 Reader 和控制池，持有一个槽。每个槽状态戳包含私有注册者身份、代次和占用状态。调用方交回上次读到的戳，成功登记后读取新戳。不同注册者即使处于同一代次也不能交换使用。

| 操作 | 成功条件与结果 |
| --- | --- |
| 首次登记 | 空槽戳吻合，新来源经完整校验，发布候选和已占用的新代次。 |
| 换到不同文件 | 旧槽保持占用，直到新候选、文件守卫和预算均已就绪。发布后旧文件解锁，旧来源和票据不能借新槽。 |
| 再登记当前文件或其硬链接 | 受测 Windows 文件系统返回 `Busy`，原登记继续有效。调用方可先显式释放，再登记同一名称，两个持有区间分别计算。 |
| 释放 | 须提供当前占用戳。释放文件和观察后，同代次变为空槽；下次成功登记须推进代次。旧空槽戳不能重放。 |
| 代次耗尽 | 拒绝新增登记。正确释放始终可用，丢弃注册者也会释放文件。 |

恢复、预留、取消或临时副本清理失败时保留原登记；临时副本沿用 Reader 的清理回执及重试入口。已发布的恢复候选／会话独立持有来源与资源租约。Reader 先退出时，注册者仍持有原文件，最后一个使用者退出时各自归还预算。

## 保存捕获能借到什么

`opening_for_capture` 核对当前占用戳、真实游标中的完整原票、取消状态、捕获根、持久工程／历史范围和目标绑定。它从捕获中认证私有 Provider，并将原打开请求、观察身份、打开头和源摘要逐项对回槽。打开请求和保存请求各自保留原序号。仅复制相同公开来源值、传入旧票或传入另一个注册者的戳均无法取得观察。

成功后返回原文件观察的借用。持有该借用时注册者无法释放或重绑，调用方仍可用同一游标继续遍历。它描述的是原打开时的内容以及这段时间内持续持有的原句柄。会话在借出后的取消、外部副本、旁文件状态和将来的写入交接另有判据。B1-2M 中“换走再换回”的反例仍适用于两个独立观察之间的空档。[两次观察的边界](P3_2B1_2M_OPENING_TARGET.md)

## 预算与验收

注册者创建前从 Reader 的 512 KiB 控制池预留固定槽及一次串行操作的工作值。原路径、观察数据、旧 Provider 和新 Provider 各自持有原租约。替换按新旧同时在场的峰值准入。回归用自制的等字节工程先取得所需峰值，再以恰好该上限和少一字节分别验证成功与原槽保留。此结果仅覆盖 Reader 受管开销，完整 SQLite／codec 与共同 64 MiB 仍待证明。

Windows 无窗口回归实际尝试通过硬链接打开写句柄及改名，登记期间收到共享冲突，释放后可改名并读回原字节。其他用例覆盖跨注册者／Reader、同路径释放后再登记、交错的新旧票、仿造来源、真正取消的保存任务、清理失败及最后代次释放。编译负例约束借用中的释放。[回归测试](../desktop/infrastructure/src/project_storage/tests/file_facts/profile/registration.rs)
