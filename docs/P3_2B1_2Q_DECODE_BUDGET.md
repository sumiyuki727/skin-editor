# B1-2Q 完整恢复的解码输入与同时存活的分配

恢复每个历史节点时，解码器现在直接借用块缓存中的原始字节。FileCoord-Small-v1 的查找表和访问标记也改用固定槽。此前在缓存之外还要为该节点复制一整份块载荷和描述符数组；本轮把这两项额外分配降为零。闭包发现、JSON 解码和恢复模型仍有独立成本。全路径的 64 MiB 证明仍待完成。[B 准入契约第 7 节](P3_2B_START_CONTRACT.md) · [前一轮的累计额度](P3_2B1_2P_SESSION_PREFLIGHT.md)

## 本轮可以核算的工作空间

| 所有者与生效区间 | 上界依据 |
| --- | --- |
| 每节点解码器，从闭包获准到该节点解码返回 | 闭包按哈希顺序借出缓存行。最多 128 块时使用 128 槽，129 至 8192 块使用 8192 槽。每槽保存一个可空引用和一个访问标记。64 位平台的最大两组数组合计 72 KiB。计入初始化值与目的地两份、索引视图和具名固定临时值后，编译期上限为 **146 KiB**。节点逐个解码；验证后的项目值转入 RestoreBuilder。 |
| 原文件散列、复制、复验各自的 I/O 调用 | 一个 64 KiB 数组用于分块读取。原文件初次散列、复制、副本散列和原文件复验按顺序执行，各自的缓冲在调用返回时释放。固定数组按两份并存并计入散列状态等临时值，上限 **129 KiB**。工作租约在首次源文件散列前取得。 |
| Rust 侧 SQLite 原始行数／字段长度预检 | 固定 16 项查询计划和消费迭代器、表统计数组及返回值的工作上限 **4 KiB**。编码名在 SQLite 行内借用比较。SQL 引擎、紧接的 schema 校验和目录内容分配另列。 |

上述数字限定各操作的具名 Rust 值。编译期断言把解码索引约束在稍后历史原件图遍历使用的工作份额内，并保留历史元数据另有的工作份额。I/O、原始预检、解码索引及其后的原件图遍历分阶段使用 Reader 已准入的租约。已有观察、来源和候选仍按各自租约并存。FileFactsReader 先在同一 512 KiB 控制池取得工作及结果额度，再绑定源文件；失败释放已取得的额度。SHA、I/O、数据库等依赖内部的临时分配和进程栈高水位仍须另计。[准入和静态断言](../desktop/infrastructure/src/project_storage/file_facts.rs) · [固定解码索引](../desktop/infrastructure/src/project_format/read/index.rs)

累计解码仍对每个节点的独立闭包收费。Small 单状态原始载荷最多 1 MiB，逐节点累计最多 8 MiB；同一块在不同节点再次解码仍计入累计量。已检查的缓存字节仍要经过摘要、引用、未使用块、JSON、模型不变量及规范重编码校验。独立加载与发布复验同样借用缓存块，512 KiB 租约仅适用于 FileFactsReader。公开的独立 bundle 读取允许乱序；一般文件路径仍可按自身限额接纳超过 8192 块的闭包，并使用动态索引。[完整恢复调用点](../desktop/infrastructure/src/project_storage/read.rs) · [共用解码逻辑](../desktop/infrastructure/src/project_format/read.rs)

## 按时间顺序核对同时存活的所有者

下表以登记已有文件、生成可激活候选和保留原打开观察为范围。旧登记或其他观察可以一直存活到新候选通过验证；打开失败时仍由原所有者保管。单行列出的逻辑限额不能直接相加作为堆容量证明。

| 阶段 | 同时存活的主要所有者和释放点 | 尚缺的最坏情况上界 |
| --- | --- | --- |
| 绑定与制作快照 | Reader、此前保留的观察／候选，加上新路径及句柄、工作及结果租约。自有主副本在清理成功前独占磁盘预留；失败时由待清理槽继续持有。原文件句柄可由成功的登记槽长期持有。 | 自有副本限额为 32 MiB。操作系统页缓存、其他卷与 SQLite 临时文件分别核算。 |
| schema 与原始行预检 | 只读副本连接、统计结构和上述所有者。校验时还会创建一份用于比对的内存 SQLite 数据库并查询目录。 | 页缓存配置、字段上限和 SQL 长度限制均不足以推出连接、prepared statement、完整性检查及排序的总工作量。临时文件采用 FILE 模式，独立磁盘额度尚未建立。 |
| 读取块、原件及历史 | Cache 持有块原文、派生行与索引。读取原件时有分块缓冲、BlobStore 原件和租约；同池复用按真实分配身份判断。历史校验还持有逐提交索引、tags／extensions／features 页、当前及前一代列表以及 observer 摘要。 | Cache 中 Map 节点、字符串、Vec capacity、历史页的 JSON DOM 和最新元数据比对副本尚欠逐项证明。文件的行数、原始长度和 metadata 逻辑计数已有限额。 |
| 节点解码与媒体核对 | Cache、原件、节点信息、此前已恢复的项目与本节点共存。发现闭包使用集合和待访问容器；借用索引建好后退出该节点的闭包迭代。解码返回后，文件侧继续核对原件元数据并重编码规范状态。五个主扫描语句（features、blobs、object_ids、commits、manual_marks）分别在扫描结束时释放；已核对的历史统计集合也在节点解码前释放。 | JSON、模型构造、重复引用展开、规范编码结果及 RestoreBuilder 实际容量仍待证明。16 MiB 恢复元数据是逻辑额度。WAV 探测借用原字节；PNG 解码器及其他依赖内部工作量仍待核算。 |
| 保管候选与产生观察 | 完整验证返回 Cache 和 RestoreCandidate。后续构造文件摘要、原件图与来源。Cache 退出后，登记观察、私有来源和候选或活动会话可继续存活；未释放的捕获和其他观察有各自租约。数据库连接在制作观察时关闭。 | 共同准入还需覆盖旧／新所有者重叠、取消与失败后的清理、以及准备候选时的工作量。SQLite 临时增长和资源归还需单独的证明。 |

## 回归与下一门槛

自制项目在两档固定索引上与公开解码入口取得相同项目。反例覆盖错误摘要、重复、缺失、未使用、乱序的内部输入、非法限额，并分别核对 8192 槽的边界和一般文件超过该边界的行为。8193 块样例在 Small 准入时返回块数超限，一般读取则完成可达项目的解码并检出未使用块。另用独占的自制源文件验证，Reader 少一字节时在尝试打开源文件前返回控制额度不足，工作区和临时磁盘回到原状态。既有每节点及跨节点的精确字节边界、全历史恢复和原记录／规范状态区分回归继续执行。[解码回归](../desktop/infrastructure/src/project_format/read/index/tests.rs) · [文件准入回归](../desktop/infrastructure/src/project_storage/tests/file_facts.rs)

下一步优先收紧历史页与最新元数据比对的 DOM 重叠，保留原字段、顺序、编码和各代完整性校验。Cache、codec／恢复模型的容量和独立 SQLite 内存／磁盘额度仍需收口。后续仍按 FileCoord-Small-v1 现有上限取证；生产只读资格和同一张真实 Exit 子票的端到端贯通继续等待共同证明。
