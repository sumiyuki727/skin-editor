# B1-2R 历史元数据页的持有期与末代比对

完整恢复现在只在处理一个提交期间持有该代的标签、扩展声明和特性三个 JSON 列表。校验器直接借用字段，最后一代逐项与数据库表比对。末代比对结果以一个布尔值保留到完整闭包检查之后。进入下一代、恢复历史节点或返回失败时，上一代的列表均已释放。[恢复循环](../desktop/infrastructure/src/project_storage/read.rs) · [元数据校验](../desktop/infrastructure/src/project_storage/read/metadata.rs)

## 校验及拒绝顺序

读取在同一事务内统计实际提交行数，并逐代核对链、代次和节点前缀。每一代仍先验证三个分页索引的形状、页序、长度和引用，再按源行顺序校验元数据。成功后更新该代回执和手动标记，历史摘要观察者才能借用三个列表。观察者按既有域 3 规则排序、取扩展原字节并计算摘要，每代只保留结果。打开较早的手动保存位置仍须验证后续的关闭保护提交。

| 数据 | 每一代的要求 | 最后一代额外核对 |
| --- | --- | --- |
| 标签 | 节点已出现在本代可见的历史前缀中，名称以 `user:` 开头；节点加名称唯一。原始文本按 UTF-8 字节长度校验。各代可有不同标签、值或排列。 | 与 SQL 标签表等长、同序，持久节点、名称、值逐项相等。保留 Unicode 原文、NUL 和换行。 |
| 扩展 | 按名称借用全局扩展的实际字节，核对声明中的 SHA-256 和长度；同代名称唯一。 | 每条声明必须对应有序全局表的同一位置，且声明数量相同。复用刚验证的摘要与长度关系。 |
| 特性 | 三字段及类型完整；每项与全局特性的完整对象匹配，名称加版本唯一。本代须包含四项已知必要特性。历史允许已登记可选特性的子集。 | 三字段、数量和列表顺序与 SQL 特性表一致。 |

节点身份和摘要仍要求固定宽度小写十六进制；长度采用规范 ASCII 十进制。按原顺序报告缺字段、类型、编码、多余字段和业务约束错误。去重只排序原始下标，并找出源顺序中最早重复的行，页内顺序及错误位置均保留。末代顺序或内容不符仍在完整闭包检查后返回 `Invalid("metadata indexes")`。独立加载与只读 Reader 共用该校验。

## 同时存活的容量和释放点

| 对象 | 本轮可核对的界限 |
| --- | --- |
| 从前一代带入下一代的页列表 | **零份**。三个列表均为提交循环的局部变量。原实现逐一替换三个旧列表，读取下一代时旧列表会与新页重叠。 |
| 末代 expected JSON、逐项深复制 | **零份**。标签和扩展声明直接与持久表比对，特性直接与全局行比对；标识及 SHA 十六进制使用固定数组解析，文本字段按引用检查。全局真实扩展字节始终由元数据所有者保管。 |
| Small 的去重和比对工作 | 每次处理一种列表。最多 128 行用 128 个 `u16` 槽，129 至 8192 行用 8192 槽，最大索引数组为 16 KiB。将数组初始化值、目的地、比较键、摘要及固定局部值一并计入，编译期界限为 **34 KiB**。比较键借用原字段，过长的待拒字段不参与长字符串排序。 |
| Reader 工作租约 | 上述 34 KiB 包含在稍后才会使用的历史原件图遍历份额内。历史摘要 collector 的工作数组可以同时存活，其份额独立保留。Reader 先取得原有 512 KiB 池中的工作及结果租约。一般文件读取维持自身限额，大于 8192 行时用借用字符串键的动态集合。 |
| 仍需核算的 JSON | 本代最多保有三类汇总列表；构造时还可能同时持有正在解析的索引、当前页面及增长中的容器。Small 的每类索引在行语义校验前各受 8192 项上限约束，单页最多 256 项。三类合计最多 24576 个汇总项。这里计的是项数；嵌套 DOM、字符串、Map 节点和 Vec 实际容量的字节上界仍待取得。 |

真实数据表、Cache、原件和此前的观察／候选仍可同时存活。此前整路径清单中的恢复模型、编解码器、SQLite 工作内存及临时磁盘仍各自待证。34 KiB 限定具名 Rust 工作值，全路径 64 MiB 的准入及生产只读资格继续以 B 契约为准。[编译期分区检查](../desktop/infrastructure/src/project_storage/file_facts.rs) · [Q 的整路径清单](P3_2B1_2Q_DECODE_BUDGET.md) · [共同预算契约](P3_2B_START_CONTRACT.md)

## 回归与接续

自制两代工程涵盖历史列表逆序仍与独立黄金摘要相同、257 个标签跨页、跨页首末重复，以及从较早 Manual 打开时较新 Exit 顺序错误。普通加载和只读检查共同核对拒绝原因、原文件字节与额度回收。单元回归覆盖 0／1／128／129／256／257／8192／8193 行、多个错误的先后、三类末代顺序、数字表示及文本原样保留。既有四代回执、八个独立域 3 向量和取消后旧观察／候选保管继续适用。[真实文件回归](../desktop/infrastructure/src/project_storage/tests/file_facts/historical_metadata.rs) · [校验边界回归](../desktop/infrastructure/src/project_storage/read/metadata/tests.rs)

下一步可沿 `read_paged` 核算或消除单代内页面解析与汇总容器的重叠，保留乱序历史的摘要和坏末页的拒绝。共同预算仍需覆盖块缓存及恢复模型，SQLite 内存和临时文件须单独证明。生产保存和同一张真实 Exit 子票贯通仍待验收。
