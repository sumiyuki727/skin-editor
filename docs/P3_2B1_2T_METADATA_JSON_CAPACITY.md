# B1-2T 已完成元数据页的数组和文本容量

Small 恢复历史元数据时，在每个 JSON 数组、字符串值和对象键完成解码后移除多余容量。S 的页目录随后接管原页缓冲，逐行校验和域 3 摘要继续借用相同的值。此次为**一代内已完成页的数组槽和文本缓冲**取得 **48 MiB** 的保守上界。[解析器](../desktop/infrastructure/src/project_format/json.rs) · [容量断言](../desktop/infrastructure/src/project_storage/file_facts.rs)

### 从单个 JSON 值推导上界

数组仍通过原 Visitor 逐项解码。完成时若容量大于长度，先转为定长盒装切片，再转回 Vec。文本对 UTF-8 字节使用相同的定长转换。对象键经原有重复检查，在插入前规范容量。所有嵌套值共用一个深度和节点计数器。空数组、空串和空键的报告容量均为零。[Rust 数组转换](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.into_boxed_slice) · [Rust 字符串转换](https://doc.rust-lang.org/std/string/struct.String.html#method.into_boxed_str)

| 单页分项 | 上界依据 |
| --- | --- |
| 全部数组的槽字节 | 设整页实际解码了 N 个 JSON 值。每个数组元素占用一个槽，而且在 DOM 中恰有一个父节点。所有数组长度之和至多 N−1。对规范后的数组，这也是报告的槽容量上界，须乘以目标平台的 `size_of::<Value>()`。 |
| 全部字符串值及对象键的缓冲字节 | 每段文本对应独立的输入区间。未转义 UTF-8 按原字节保留，合法的 JSON 转义和代理对解码后的字节数至多为其输入长度。因此报告容量之和至多为整页原始 JSON 的字节数。 |

Small 每个角色最多 8192 行，每页 256 行。标签、扩展、特性最多同时保管 96 次页出现。同一内容哈希可能反复出现，按每次解码分别计费。每页最多 8192 个 JSON 值及 256 KiB 原始字节。将以上两项按出现次数相加，编译期核对的界限为 `96 × (8191 × size_of::<Value>() + 256 KiB) ≤ 48 MiB`。该界限也涵盖结构合格、稍后业务校验会拒绝的嵌套字段。三个角色都已通过业务校验后，其保留行的字段均为标量，此时所有行数组最多包含 24576 个槽。

### 生存期与准入

解析一张页时，此前完成的页仍在目录中。一个容器收缩时旧分配与新分配可能短暂并存，父容器也可能仍在增长。上面的公式从各容器完成转换后起算。哈希所指块的首次通用校验、索引根解析、在途 Vec 扩容、收缩过渡、serde 暂存、Map 节点和分配器开销均须另行核算。代末、错误和取消继续按现有所有权路径释放。[页目录与移交](P3_2B1_2S_METADATA_PAGES.md)

紧凑解析用于元数据页且按配置的索引项数选路（至多 8192）。48 MiB 还要求 Reader 的 Small 原字节和 JSON 节点限额同时成立。一般宽档、其他分页角色和第一次块校验仍使用原解析路径。512 KiB Reader 控制池覆盖原有具名工作值；上述页堆分项尚未获得共享 64 MiB 的整路径准入。块缓存、恢复模型、其他 codec 分配、SQLite 工作内存和临时磁盘仍待证明，生产保存及同一张 Exit 子票闭环仍待验收。[B 开工契约第 7 节](P3_2B_START_CONTRACT.md)

### 验证与接续

自制样例递归核对每个数组、文本值和键的实际容量，覆盖零长、转义键、代理对、NUL、换行和 8192 节点边界。两种解析模式交叉核对解码结果及多错误首错。分页回归让同一哈希出现两次并追加短末页，直接检查移交后的嵌套容量、页序和宽档读值。原有坏末页优先、历史摘要黄金、旧观察／候选隔离及实际释放回归继续使用相同入口。[解析回归](../desktop/infrastructure/src/project_format/json/compact_page_tests.rs) · [分页回归](../desktop/infrastructure/src/project_storage/tests.rs)
