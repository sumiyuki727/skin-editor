# B1-2U 解析途中数组扩容与收缩的容量

Small 元数据页解析时，单页所有 JSON 数组的缓冲合计最多 **768 KiB**。这个界限覆盖尚未闭合的父数组、已完成的子数组，以及一次扩容或收缩的新旧缓冲同时存在。连同同代此前完成的页和当前页已完成的文本，合并上界为 **48.5 MiB**。两项都按 Rust 可见槽容量核算。[解析器](../desktop/infrastructure/src/project_format/json.rs) · [编译期断言](../desktop/infrastructure/src/project_storage/file_facts.rs)

## 哪些分配可以同时存在

紧凑解析器先按原顺序解码子值。成功后，如果父数组还有空槽就直接放入。若数组已满，设当前长度为 L、剩余 JSON 节点配额为 R，调用 `reserve_exact(min(max(1, L), R + 1))` 申请额外槽位。子值已经消耗了自己的节点配额，因此 R 为零时仍须给它一个槽。只有成功解码的子值才会触发这次申请。一般解析器继续通过原来的 push 路径写入。

这里使用的是仓库锁定的 Rust 1.95.0（提交 `59807616`）。该版本的 `RawVec::grow_exact` 按长度加额外槽数计算目标，并将该目标记为容量；收缩按目标布局发起请求。将来升级工具链时须重新核对这些前提。系统分配器的内部舍入和暂存单独核算。[工具链锁](../rust-toolchain.toml) · [固定版本的容量实现](https://github.com/rust-lang/rust/blob/59807616e1fa2540724bfbac14d7976d7e4a3860/library/alloc/src/raw_vec/mod.rs) · [固定版本的 Vec 接口](https://github.com/rust-lang/rust/blob/59807616e1fa2540724bfbac14d7976d7e4a3860/library/alloc/src/vec/mod.rs)

| 时刻 | 同一数组计入的槽 |
| --- | --- |
| 等待下一个子值 | 空数组尚未分配。写入第一个子值时申请一个槽，此后只在满时扩容，额外槽数至多为 L。因此有 k 个已放入的子值时，开放数组的容量至多为 2k。已经闭合的数组按 T 收紧至 k 个槽。 |
| 父数组扩容 | 非空时旧缓冲有 L 个槽，目标缓冲最多 2L 个槽，按两份同时存在计至多 3L。首次扩容从零到一，计入已经解码的子值。搬移 Value 时子值所拥有的内部缓冲随所有权转移，只计一次。 |
| 数组闭合 | 有 k 个子值时将至多 2k 个槽收紧至 k 个，按旧缓冲与目的缓冲同时存在计至多 3k。闭合后仅精确长度的缓冲随 DOM 保留。 |

一张页的访问器同步递归，一个时刻只有一个数组正在转换。各层已经放入或即将放入的直接子值分别对应唯一的数组元素。它们连同已完成子树中的数组元素，总数至多为 JSON 节点数 N 减一；对象成员会消耗节点而不会增加数组元素。即使后面的子值、页结构或业务字段校验失败，这个关系也成立。故所有当前数组的并存上界为 `3 × (N − 1) × size_of::<Value>()`。失败时正在解析的局部值随错误返回释放，先前已接收的页由本代目录保管至返回或代末。

Small 固定 N≤8192，单页原始字节至多 256 KiB。一代最多出现 96 页；开始解析一页时，最多还有 95 次已完成页出现的缓冲。同一哈希重复出现要分别计费。从 T 的 96 页公式中扣除**一份**已完成页数组额度，再换入本次解析的三份额度，保留当前页已完成字符串值和键的字节份额。计算式为 `96 × ((8192 − 1) × size_of::<Value>() + 256 KiB) + 2 × (8192 − 1) × size_of::<Value>()`。最后的 512 KiB 增量是两份数组槽的保守余量；Reader 的 512 KiB 控制租约另行计费。[T 的已完成页证明](P3_2B1_2T_METADATA_JSON_CAPACITY.md)

## 回归与尚待证明的分配

自制回归逐次检查从空数组到 8191 个子值的实际容量，覆盖最后一次按剩余节点限额扩容。满父数组接收耗尽配额的子数组时，检查父数组只新增一个槽、子数组缓冲地址保持一致。另一组用例让 31 层祖先等待包含 4097 个标量的子数组，交叉核对精确预算、充足预算、少一个节点、较浅深度及缺失结束符。既有跨页、重复页、错误优先级和历史摘要回归继续使用真实读取入口。[定向回归](../desktop/infrastructure/src/project_format/json/compact_page_tests.rs)

下一项宜核算 Map 节点在逐项插入、分裂及错误返回时的分配。解析对象成员值时，待插入的键尚未收紧，它与字符串扩缩容、serde 暂存、索引根和第一次通用块校验都在本次上界之外。块缓存、恢复模型、其他 codec 分配、SQLite 内存及临时磁盘继续列入总账。共享 64 MiB 分配前准入、生产保存及同一张 Exit 子票闭环仍待验收。[B 开工契约第 7 节](P3_2B_START_CONTRACT.md)
