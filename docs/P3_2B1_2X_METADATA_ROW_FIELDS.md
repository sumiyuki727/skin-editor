# B1-2X 检查点元数据的逐页释放

Small 读取器在接收下一页前，释放当前页中无法用于标签、扩展或特性校验的嵌套容器。B1-2W 识别的 32 个不同页同时保有 **74.0625 MiB 嵌套叶节点**的路径已消除。针对固定 FileFacts Small 档和已审计的 64 位布局，检查点元数据页的 Map 节点、数组槽、文本和解码字节缓冲合计上界为 **54,479,952 B，小于 52 MiB**。[页的读取和移交](../desktop/infrastructure/src/project_storage/blocks/metadata_pages.rs) · [容量断言](../desktop/infrastructure/src/project_storage/file_facts.rs)

## 哪些数据要留到校验时

读取器照常检查整个 JSON，验证角色、页字段、行数和引用。成功后才原地处理每一行。行对象保留原来的全部键、字段数及标量值，直接字段中的数组或对象释放后替换为 null。根数组同样替换为 null。上述替换在原有的行槽中完成，原始块字节及哈希继续由缓存持有。

三个角色均要求行是对象，所需字段只接受字符串或布尔值。容器和 null 在相应检查处产生同一错误，缺字段与字段存在但类型错误仍可区分。未知字段仍计入字段数。标签身份、十进制长度、摘要等标量沿用原来的解析顺序。重复项索引读取的字符串保持原样。三份索引仍全部完成结构检查，再按既有次序校验业务内容。通过校验的行与原行相同，末代比较和域 3 摘要继续消费这些值。[业务校验与行投影](../desktop/infrastructure/src/project_storage/read/metadata.rs) · [检查点读取顺序](../desktop/infrastructure/src/project_storage/read.rs)

同一角色内重复哈希仍指向首份所有者，行序及每次出现所需的尾长照常检查。不同角色的页须通过各自角色检查。当前页解析失败时，其已构造部分随错误退出；完成页的嵌套容器在本页移交时已实际析构，保留的顶层对象与行槽在整代结束或返回错误时释放。较宽档案继续保留完整原值。[前一轮页所有权与析构证明](P3_2B1_2W_JSON_MAP_NODES.md)

## 同时存活的请求字节

固定 FileFacts Small 档在加载每一块前检查原块总字节额度 **B = 1 MiB**，三个角色各至多 8192 行。通过验证且实际持有的不同页，其原文总量受同一额度约束。此条件单独来自 FileFacts 配置；仅设置索引上限 8192 的一般读取器可能有更大的原块额度。[Small 配置](../desktop/infrastructure/src/project_storage/file_facts.rs) · [缓存装入检查](../desktop/infrastructure/src/project_storage/read.rs)

已完成页只有行对象自身能保有 Map 节点。一个含 m 个成员的非空行对象在原文中至少占 5m + 1 字节，包括引号、冒号、值、逗号和花括号。各行原文不相交，故不同页实际保留的成员总数 E 至多为 209,715。非空行对象数 R 至多为 24,576。空对象初始不分配节点，投影只改字段值，保留树的成员数。锁定 Rust 的插入树中，根至少含一个成员，其余节点至少含五个。设节点总数为 T，则 E ≥ R + 5(T − R)，得 T ≤ ⌊(E + 4R)/5⌋ ≤ **61,603**。保守地按每节点 728 B 计算。[固定 Rust 的节点布局及分裂](https://github.com/rust-lang/rust/blob/59807616e1fa2540724bfbac14d7976d7e4a3860/library/alloc/src/collections/btree/node.rs)

| 同时计入的分配 | 字节上界 |
| --- | ---: |
| 已完成页的行对象节点 | 44,846,984 |
| 已完成页的行槽及保留文本 | 24,576 × 32 + 1,048,576 |
| 一个尚未移交的页，包括失败页，全部 Map 节点 | 5,963,048 |
| 当前页数组转换、已拥有文本和字节缓冲增长 | 3 × 8,191 × 32 + 256 KiB + 768 KiB |
| **合计** | **54,479,952** |

数组及文本沿用紧凑解析器的容量证明，已完成页只保留各页精确长度的行缓冲。当前页在解析、结构核对及原地释放期间按完整页计费，既有页按上表的完成态计费，覆盖解析失败和析构中的并存情形。[数组扩缩容](P3_2B1_2U_JSON_ARRAY_GROWTH.md) · [文本与解码字节缓冲](P3_2B1_2V_JSON_TEXT_SCRATCH.md)

## 回归与剩余门槛

32 个不同页的自制索引验证了所有 8192 行的位置、标量值及已释放的字段，并在降低深度时确认嵌套输入仍触发原解码错误。旧反例的单页实际对象数仍用于核对 74.0625 MiB 的原下界，跨页回归同时核对重复页共享、短尾拒绝、宽档完整值和原始页的嵌套数组容量。三角色差分回归比较投影前后的精确错误及末代结果；真实临时工程覆盖早期坏标签和较晚坏特性页并存时的首错，既有域 3 黄金与取消／释放回归继续运行。[分页回归](../desktop/infrastructure/src/project_storage/tests.rs) · [差分回归](../desktop/infrastructure/src/project_storage/read/metadata/tests.rs) · [历史元数据回归](../desktop/infrastructure/src/project_storage/tests/file_facts/historical_metadata.rs)

52 MiB 是上表具名分配的静态界限。共同 64 MiB 的分配前预留仍需覆盖索引根、首次通用块解析、浮点转换与错误对象、缓存和恢复模型等同时所有者，SQLite 内存、临时磁盘和系统分配器开销也需分别核对。下一项宜先结合页索引的根解析和块缓存计费，检查它们与上表的重叠。生产保存与同一张 Exit 票的关闭资格仍待验收。[B 开工契约第 7 节](P3_2B_START_CONTRACT.md)
