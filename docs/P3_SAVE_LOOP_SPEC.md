## 2. 范围、所有者与版本

首个产品闭环限定既有Rust文件profile与受验证Windows本地路径：首次手动保存、同目标增量保存、保护关闭、普通Manual打开、显式Latest打开、继续编辑和再次保存。未命名工程退出保护及重开后首次命名保存是完整关闭承诺的必要部分；可分步实现，但未完成前不得声称完整闭环。静态导出、标签编辑、Schema迁移、通用SaveAs、后台周期、设置持久化和K2以后另行验收。

现有版本保持：application API6／模型2，捕获端口2、存储端口1；skin-editor-rust-v1、container2／project1／history2／node record2／state1、恢复报告1。本文的协调值仅为拟议契约；实现时单独版本化，外部签名或文件语义改变须先补版本／旧读取路线，不能靠改应用版本猜格式。本文不修改DDL、旧证明或格式常量。

| 所有者 | 新增责任／禁止越界 |
| --- | --- |
| application | 唯一项目／关闭／加载用例入口，门控写入和导航、冻结捕获、保存事实、候选激活、结构化状态／错误；不读路径、时钟、SQLite、线程或GPU句柄 |
| infrastructure | 已有文件／原字节、随机身份、目标身份和存储验证；worker只接收脱离会话的捕获／候选，不持ProjectSession可变引用 |
| desktop | 注入窄端口，拥有有界worker、文件选择和路径绑定、原生停止／资源回收；不能自行替换项目内部字段或伪造保存事实 |
| UI | 文件动作、状态及明确选择，经application执行；快捷键和按钮共用集中路由，文本／IME优先，重复按键／重复布局不重复提交 |

拟议SaveTicket至少绑定：协调版本、操作ID、HistorySessionId、目标绑定ID及代次、持久history／lineage、捕获ID、CaptureSource（state＋navigation_revision）、全树／资源／持久元数据覆盖标识、CommitId、expected前次提交、SaveOrigin。路径仅保留在本机目标适配器；运行Ticket／epoch不写回工程。绑定不能只比较路径字符串、ProjectId或NodeId；同一路径换文件和重新打开同一工程均形成新绑定上下文。

保存、打开、关闭使用各自有限状态和明确返回值，不引入通用工作流／事件总线。首版每活动工程最多一个保存任务、一个关闭意图及一个加载候选；每类任务仅保留一个待确认终结结果，消费者确认和资源实际释放前不接纳下一任务。取消直接标记其既有槽位，不另占队列；错误用有限枚举／数值字段，不累积无限错误字符串或回执历史。关闭等待已有保存和租约实际退还后才捕获最终截面。第二个手动保存明确Busy，不先显示“已接纳”再换成执行时状态。新打开意图替换旧意图时先取消并等待实际资源归还，不堆积候选。

SaveTicket、CloseTicket、LoadTicket各有独立、checked递增的操作身份及取消资格；关闭意图可以等待既有SaveTicket，但不取得取消该独立手动保存的权利。关闭自己发起的最终保存明确记录父CloseTicket。取消／终结确认针对原Ticket，迟到确认不释放新操作槽；重复请求只能返回当前已知结果或明确Stale／Busy，不另存无限去重表。OutcomeUnknown是该保存槽的未决状态，不是可确认后丢弃上下文的普通失败终态；取消关闭不清除它，目标仍禁止新写入。为同Ticket协调查询和清理预留资源，不能等槽位归还才允许用于归还该槽位的查询。

## 3. 捕获、脏状态和真实回执

手动保存顺序：处理活动手势／配置输入→确定有效目标→同一受控时点接纳请求并冻结已提交截面q→worker写入→核对完成封套和文件事实→application只确认q。文件选择期间尚未接纳保存；选择完成后捕获哪个截面须可解释。草稿Busy时保留草稿，等待用户完成／明确取消后重新接纳，不暗中保存草稿之前的状态并显示完成。普通后台保护不擅自Commit／Cancel草稿；本闭环不开启其周期。

捕获后可继续编辑，q之后新增节点、分支、资源、导航及持久元数据仍待处理；q成功不得换活动头、清空后续脏范围或释放历史引用。捕获失败／取消、输出complete、写完暂存文件、发出请求都不是已保存事实。没有新增内容节点的导航／合法元数据变化也要纳入持久化判定；皮肤预览、选择、音量和缓存不算项目脏状态。

回执核对使用接纳时固定的q及其Ticket；当前会话中已继续编辑到q+1不构成错误来源，不能因当前revision不等于q就丢掉真实保存事实。会话／目标资格和捕获覆盖分别判断，迟到q只确认q。确认已在文件内提交的保存事实、安装新绑定、加载时推导导航及保留永久ID映射，均不自行制造待写内容节点或无休止的“回执→脏状态→再保存”循环；用户实际编辑／导航及未来已支持的持久元数据修改仍按各自修订计入。

至少独立呈现：最新已验证文件提交及其完整覆盖、最近真实手动检查点、最新真实保护检查点、当前打开来源／活动头，以及进行中／失败／结果未知状态。全树是否已落盘与当前内容是否不同于手动位置分开；A→新分支B→回A且B未写入，不能显示全部已保存。默认Manual打开A时可同时显示“较新保护C可恢复”，不能误称当前是C。

| 结果 | 应用事实处理 |
| --- | --- |
| Committed | 核对Ticket、目标、CommitId、代次、来源、捕获头／完整覆盖；Manual推进手动和保护，Exit只推进保护。保存标签来自文件真实记录，不创建内容节点 |
| Replayed | 只确认相同请求既有提交，不新增标签／代次，不把迟到旧回执退回当前绑定或覆盖更高代次；不能重复触发退出 |
| NoChange | 没有本次提交事实，不能要求回执CommitId等于未写入的新请求；结合已验证文件元数据和覆盖证明确认无待写变化。返回的最新保护回执不可冒充Manual回执或改变活动头 |
| 提交前失败／取消 | 不新增保存事实，保留未保护范围、活动工程和可读旧文件；适配器失效后重开校验再用，不能沿用旧缓存写 |
| OutcomeUnknown | 保留CommitId、Ticket、目标和已有证据，暂停该目标写入；完整重开后查询committed(CommitId)。存在且完整匹配才确认；仅查无ID不足以重试，须按下方四类观察区分NoChange、确未提交及不可判定，不能盲目换ID重写 |
| 旧会话／旧绑定完成 | 不影响新会话、UI、关闭决定或手动标签；若旧目标确已提交，保留其文件事实与有限诊断，不删文件“撤销”真实提交 |

重要回归：A为手动、C为较新保护，默认打开A后直接保存／关闭可能得到NoChange及C的回执；此时A仍是手动位置、C仍是保护位置，不新建空提交，不标本次手动保存C。结果未知的查询端口还需提供足够的已验证提交上下文；单独四字段ArchiveReceipt不足以完成Ticket关联，不能从同head推定一致。运行会话／绑定资格由本机Ticket核对，文件侧核对其可持久化部分（CommitId、来源、请求摘要、历史前缀／覆盖等），不要求将运行epoch写进文件。结果未知期间保留足够的捕获承诺与资源所有权用于核对；确认未提交后的重试若重新捕获当前状态，必须是用户明确接纳的新请求，不能把已接纳的q偷偷换成q之后的内容或用新ID盲重写。

关闭采用覆盖证明而非单一头相等：最新已验证文件代次覆盖q的完整节点／资源／持久元数据；q的活动内容和导航则对应已验证的打开基线或本次真实检查点。默认Manual A、较新保护C且无新工作时，A的选择和完整最新树均可恢复，允许NoChange关闭而保留C；不能要求protected.head=A，也不能将“保留C”显示成“本次手动保存C”。NoChange回执本身不证明完整覆盖，目标变化、增加后又撤回的未落盘分支或真实导航变化都须重新核对。

读取器会为“保存时唯一后继、重开时新增分叉”推导Redo偏好；这是加载基线的一部分。底层write.rs的same_redo比较原检查点数组，不能假设它对加载推导后的数组一定返回NoChange。首个协调器须按已验证打开基线识别无用户变化，或在B增量补经回归的等价核对；禁止为凑NoChange丢掉用户实际导航。SL05必须包含这个变体，现有仅验证Exit无变化的用例不能代替手动路径。

未知结果至少区分四种后续观察，均先关闭失效写适配器并核对同一目标身份／提交链：①存在且完整匹配CommitId，确认既有事实；②该ID不存在但有独立证据证明请求本来为NoChange，保留原手动／保护位置；③同目标完整有效且能证明该请求未提交、q仍未被覆盖，保留待保护范围，重新接纳重试；④无法读取、路径消失／被替换、日志待恢复、摘要冲突或验证／查询取消，继续未决／冲突，不能当作③。已有write::existing在NoChange之后核对文件身份失败也可能返回OutcomeUnknown，因此仅committed(id)==None不足以区分②和③。首次发布目标不存在也不是充分反证：还须排除已发布后被外部移动／删除等无法核对情形；不声称能从不存在的文件证明过去没有提交。

协调查询不激活工程、不生成Manual事实、不把运行epoch持久化。现有committed只返回四字段，load还会创建候选并打开读写连接；不能把它们描述为已有轻量只读完整事实端口。B增量须提供受预算和完整验证约束的事实视图，必要时复用验证器但保持无写入／无激活；原件热日志仍按显式副本恢复规则处理。查询失败或缺乏权威观察不降级为成功，未决捕获承诺／租约在真正不再需要前保留。

## 4. 关闭及切换协议

关闭门控用于关窗口、退出程序、新建、打开另一工程和重新打开当前工程。请求进入application后停止普通Command、草稿开始／替换／提交、有效导航、标签修改及旧导入结果的项目登记；查询、正确取消、已有回执协调和资源归还继续可用。唯一写入例外是同一CloseTicket明确授权的当前草稿／配置输入收尾，仍核对原会话、基础修订和草稿身份，经既有原子入口执行并纳入最终捕获；不能借此放行其他新动作。不能只禁用按钮，让快捷键、后台或未来AI继续写入。

1. CloseRequested：记录唯一关闭意图，显示保存／不保存（保留历史）／取消；重复关窗不得另开任务。待决定期间保持门控，取消可恢复当前会话准入。
2. ResolveDraft：未完成手势及输入由用户明确完成或取消；完成经既有Command／草稿入口原子提交。失败或容量不足保持工程打开；已取消草稿不进入退出捕获。没有未完成输入时直接继续。
3. SettleExisting：先处理已接纳保存的实际结果与OutcomeUnknown，关闭不抢断已可能提交事务；停止旧导入接纳并清理在途结果。先消费真实终结事实，再确认并释放该任务持有的捕获／输出／候选；不能一面长期保留CaptureSnapshot作为完成记录，一面等待同一捕获槽空闲。独立消费者仍持有时如实等待，不伪造释放。
4. FinalCapture：在门控下捕获最终已完成内容、全部历史／资源、导航和持久元数据。保存并关闭用Manual；不保存用Exit；已有完整覆盖且无新工作则保持NoChange，不把最新保护C退成默认打开A。
5. Protecting／Reconciling：失败或结果未知不退出；给出重试、取消关闭或经验证的完整新副本路径。尚未实现副本能力时明确不可用，不能提供实际会丢历史的强退选项。
6. Quiescing：按第3节确认最终覆盖或无新工作的打开基线后，撤销旧输入／预览／音频来源资格并等待宿主实际停止、任务结束和必要提交／租约回收；“请求停止”不是资源已释放或设备声学静音。
7. ReadyToClose：按第3节证明最终完整内容／历史已被覆盖，或符合无新工作的已验证打开基线；没有未知写入／可接纳旧结果且清理已确认，才对仍有效的同一CloseTicket授权一次关闭或切换。A／C的NoChange特例不要求最新保护头等于活动头。on_exit仅作最后清理，不承载可失败的首次保存。

取消关闭前后都要确定处理：只撤销该CloseTicket及其自有子任务的资格，不取消此前独立接纳的手动保存；关闭自有保存提交前取消后仍等实际结果，提交后取消仍保留真实保存／保护事实但保持工程打开。输入收尾已经通过Command提交的编辑同样保留，不因取消关闭而自动Undo。已取消CloseTicket的晚到成功不能关闭后来恢复编辑的工程，也不能替新的关闭意图跳过最终捕获。已停止的试听／旧游戏输入不自动重播；恢复编辑准入不复活已撤销来源。用户取消不能释放尚由任务持有的额度，也不能卡在已满普通请求回执表上。

## 5. 重开、身份与旧结果隔离

打开顺序：确定目标和Manual／Latest选择→处理当前工程关闭门控及保护→后台全文件验证为脱离候选→生成新运行会话→准备ID准入与UI／宿主新绑定→旧来源停止／清理确认→application一次激活。目标丢失、损坏、版本不支持、资源不足、取消或旧候选返回均保留旧工程；候选准备不得先清空旧项目、素材或历史。

实际read.rs对metadata.manual=None使用unwrap_or(last)，所以底层Manual成功不等于产品可按手动位置激活。应用协调必须检查经过完整验证的metadata.manual及LoadTicket选择：存在合法Manual才允许普通激活；合法未命名保护且无Manual时返回“需要显式恢复”，用户选择Latest后才继续。若文件声称有手动点但该点／提交链损坏则整体失败，不以Latest回退修补。用于未知保存核对的全文件读取无需选择用户活动头，更不得借此偷偷激活Latest。

LoadTicket固定目标绑定、准备代次、选择和当前CloseTicket；文件对话框、后台结果及最后激活均核对其资格。候选准备完成后又取消、换目标或发现源文件身份／代次变化，不将旧候选接成新的可写目标。新会话、UI绑定和必要呈现准备先在有界候选内完成；发布活动会话是最后一个不可分割切换点，不在其后首次进行可能失败的必需准入。打开失败时，原工程已真实完成的保存事实继续保留；不回滚文件或丢弃原工程来伪装“未发生任何事”。

无论Manual还是Latest，均加载完整最新文件代次、全部分支及所需原始资源；只改变激活头和对应导航。保留永久节点／history／lineage／地址代次／原始操作／摘要及对象首次准入。恢复局部alias仍遵守当前工厂约束，不顺带实现地址重排或分支合并；旧Command不执行，PCM／RGBA／Voice／GPU和工作区选择不从项目恢复。

新建工程的ProjectId经身份源准入，重开保留文件ProjectId；新HistorySessionId在每次激活前产生，拒绝零值／与被替换会话或任何仍存活、在途上下文冲突，生成失败不激活；不采用max(1)把失败值归一化。它由宿主注入，核心不访问随机源；不宣称仅一个非零值就保证新鲜。请求号可在新命名空间重新开始，但旧请求完整来源必须失败。对象ID分配复用application保存的全部admissions，在申请前受验证地跳过已消费ID或由application分配，checked递增和溢出拒绝；不从当前可见对象最大值推断安全。

## 6. 未命名工程与恢复副本

未命名关闭的“不保存”仍须完整Exit保护到独立持久恢复区，不能偷偷选用户目录或放进可清缓存。RecoveryEntry须有版本、稳定工程身份、不含项目私密路径的标识及可验证文件绑定；不伪造Manual检查点。首次无手动位置的恢复必须明确标为“未命名保护状态”，由用户显式恢复，不能将其冒充默认手动打开。

从未产生有效编辑、资源登记或待持久化元数据的全新空根，在没有手动保存意图的关闭／不保存选择下可直接关闭而不造空保护工程或保存标签；这由创建基线及完整历史事实判定。发生过有效编辑后即使Undo回空根，已产生的分支和资源仍必须完整保护，不能按当前画面为空放行。 用户明确选择手动保存空工程时仍须产生有效完整根及真实Manual提交，不能用空根例外忽略其保存意图。

恢复区目标须可重新发现、计量并诊断；写完整自包含文件后才发布可发现记录。索引失败、发布后中断、记录丢失／损坏的定位流程先定约，不让已保护的唯一文件永久不可见。只读取明确恢复根内自己发布的条目；不自动提升、删除未知孤儿或扫用户磁盘。容量满时拒绝新增／保留工程打开，不删除旧项目历史来腾位；具体持久目录与恢复区总配额须在该增量实施前冻结，不能使用临时目录默认值上线。 关闭成功还须同时具备完整文件和可核对的持久发现记录；仅文件发布成功、索引失败不满足可恢复关闭。B开工前必须冻结有界发现协议及自己拥有的恢复标识，覆盖文件先发布而记录尚未可用的中断窗口；不能以扫描任意磁盘或自动提升未知孤儿补足。

已恢复的未命名工程选择正式路径时，需要经验证的新目标复制／绑定及真实Manual提交，保留完整旧历史、原始记录和资源。通用SaveAs的谱系分叉另定约；本路径必须明确恢复副本与新正式目标的身份关系、单活动写者、旧恢复入口仍可核对，以及提交／绑定／索引各失败点的恢复方式。在此能力完成前，允许继续保留恢复文件并报明确未支持，不能清origin、换新根或覆盖已有目标绕开publish_new限制。 转正式目标至少分为复制并校验、真实Manual提交、目标绑定切换、恢复入口状态更新；每步分别记录确定／未知结果。新文件已提交而绑定或索引失败时保留两个有效副本与真实提交事实，不删除新目标假装未保存，也不让两个绑定并行写入。具体谱系关系及恢复区目录／总配额仍是B前置定约，本轮不代用户决定或扩展为通用SaveAs。

普通load遇JournalPresent保留现场；显式recover_copy仍只在Windows受验证本地路径、源适配器关闭且独占冻结成功后操作副本。Busy不强夺锁；未知／损坏日志、不支持WAL、非当前分支损坏均拒绝。RecoveryCleanup保留token／cause，发布后不确定结果先核对完整目标，不删除可能有效的新文件。磁盘满、只读介质及物理断电保证未获实测，不借进程中断测试升级。

只有已通过共同profile准入的当前完整树，才承诺达到其有效节点上限后仍可保存；单独将SessionLimits设为65536不构成这一证明。上限处的新有效修改明确拒绝。普通回执耗尽仍应能完成正确草稿取消（已有保留位）和保存／关闭保护；若继续编辑需要重开新会话，须先完整保护并经过上述新epoch流程，不能在原会话清回执表或自动伪装重启。ID、请求号、修订、文件代次及操作代次溢出均失败封闭，不回绕复用。

接入产品前须证明：准入的新编辑／导航／元数据不会仅因内部固定配额而形成无法保护的已完成历史；需保守计量新增状态、原字节、索引／检查点及完整重开展开，并预留最终保护事务／失败协调空间。该准入由application用已验证预算信息作出，不能在Command里访问文件系统。证明不足时限制可进入闭环的工作负载或提前拒绝新增，不提高常量掩盖缺口；真实OS磁盘耗尽仍按外部失败处理，保留内存和旧文件。

共同准入须同时计入保存期间q之后的新编辑、累计提交／手动标记与导航快照增长、首次发布完整复验、旧会话＋候选＋新会话、未知结果复核以及最终保护保留量。终结值确认后可释放重型捕获，但协调所需的有界来源承诺不能提前丢弃；查询／清理的保留量不得被普通编辑或新加载占尽。相同BlobRef在同一池中共享才计一次；两个独立池或候选模型的重复分配不能假定共享。所有计数／控制操作ID耗尽前也须保留完成当前任务和最后保护的资格，不以回绕或清空去重表继续。持久恢复副本／rollback journal／临时文件的磁盘空间单列；这些逻辑限额均不替代[产品资源预算](RESOURCE_BUDGET.md)的实际内存／响应／释放验证。

字段算术示例：262144项admissions按RestoreBuilder每项128字节已占32MiB，尚未计入任何节点、状态或元数据；因此各默认最大值不能同时兑现为产品容量。此处是源码计费说明，不是新成本测量。B须以共同profile给出接受／拒绝边界及证明；D不得从A的fake端口或单项边界测试推导产品资源达标。

容量、锁、外部更换、格式、校验、清理失败及结果未知使用结构化错误；显示“尚未保护／等待资源／结果待核对”，不自动循环重试或关窗。失败后重试必须重新验证目标，不能覆盖外部较新历史。需要更大容量或新目标时单独审阅，绝不以删枝／压缩既有节点换取保存。
