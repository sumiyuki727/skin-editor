## 设置所有权与入口

下表是后续完整设置／资源用例的目标所有权，不表示当前已有这些application设置端口或持久化；当前仅已接的文本／控制状态以本文件首段和架构为准。

| 数据 | 归属及写入入口 | 保存与历史 |
| --- | --- | --- |
| 玩家展示资料 | 用户偏好中的本地头像引用、用户名及明确支持的展示字段；经 application 的设置用例校验，向 preview 提供只读副本 | 后续由 infrastructure 保存用户设置；不登录、不保存凭据，不进入 SkinProject 或项目历史 |
| 预览运行偏好 | 音频／显示／输入测试设置、自动打图偏好及外部默认皮肤选择；统一由编辑器设置面板调用 application | 独立于 skin.ini；设备 ID／绝对路径不写入共享皮肤项目或导出 |
| 当前预览控制 | 场景、模拟位置、冻结、全屏及会话覆盖；application 编排 preview 控制 | PreviewState；不产生项目历史 |
| 实际谱面资源来源 | 用户指定的本机 stable 安装位置、独立或自定义 Songs 根目录，以及当前选择的谱面引用；由编辑器设置／资源选择用例接入 | 本机设置与预览会话，不进入 SkinProject、skin.ini、项目历史或皮肤导出 |
| 皮肤配置 | SkinConfiguration，包括已经验证的 skin.ini 配置项 | 项目内容，必须经 Command／事务进入历史 |

已采纳的音频方案区分：独立AudioComponent的用途键、素材引用、增益／可见性属于项目，监听总音量属于本机偏好，试听位置／Voice／设备属于运行时。游戏冻结下显式试听与场景门控独立，共用一个输出运行时；准备不自动发声或推进歌曲。模型及Windows音频后端已实现，设置存储未实现，见[音频方案](AUDIO_EDITING_REVIEW.md)。

编辑器提供统一设置入口，预览中不显示原版 stable 设置页。相关的运行能力由平台端口提供；不扫描用户原客户端的账号或设置文件。更改设置不得回写皮肤内容。P1 不预建设置服务或持久化框架，P2/P4 按真实用例增加小型值契约与存储端口。

头像与用户名用于皮肤界面的本地状态，不代表经过认证的账号。缺头像时使用自制占位或明确未配置状态。自定义资料与外部路径默认仅本机保存，诊断／AI 查询默认不暴露私人绝对路径或图片字节，确有需要时通过明确资源引用访问。

## 实际 stable 谱面与必要媒体

用户需要使用已有谱面测试皮肤。预留安装目录和 Songs 目录的独立选择、多个本机来源及重新定位入口；不能假定 Songs 一定在安装目录内，亦不能把开发者的路径固化为默认值。只读发现建议须经用户选用，不依赖读取账号配置、认证信息或整份个人数据库。

资源选择后使用不透明 SourceId、相对谱面标识和内容修订。infrastructure 从明确根目录读取选定的 `.osu` 及该测试能力需要的音乐、背景、音效等关联文件；compatibility 解释有证据的谱面与资源规则，preview 消费解析后的测试投影。故事板／视频等未支持资源需单列诊断，不默默删掉却声称完整测试。音乐与谱面不是皮肤素材库 Asset，默认不复制到皮肤项目或导出包。

读取端口必须校验相对路径、实际解析路径及符号链接／重解析点后的根边界，限制文件数量／大小；超出授权根的引用返回诊断或要求配置独立来源，不自动扩大扫描范围。源文件变化、移除或重定位使旧请求失效；异步结果带源修订，避免把旧音频配到新谱面。播放所需缓存仅放本机忽略目录；不修改原客户端文件，不扫描私人历史、回放、聊天或凭据。

路径、当前选择和来源管理属于本机设置／PreviewState，经 application 专用用例编排；仅显式导入为项目内容的资源才走项目 Command。AI 默认取得来源状态、能力与不透明资源引用，必要文件访问受同样边界约束，不借设置接口获取任意文件系统访问。

P1 本轮只纳入需求和边界，不建立空读取端口或读取真实客户端。P2 预留设置／选择界面，P4 接入受限只读解析与错误测试，P5 用用户选择的真实谱面完成离线测试。自动核心测试继续使用内存和自制 fixture，不依赖用户的 stable 安装。对应 R23。

## 自动打图与输入优先级

自动打图是预览器的输入来源策略，与所选 Auto Mod 分开表达，不通过偷偷添加 Mods 实现。

| 状态 | 默认行为 | 显式覆盖 |
| --- | --- | --- |
| 嵌入编辑器的非全屏预览 | 自动打图，不受 Auto Mod 是否选中影响 | 显式开／关决定有效自动输入；关闭后为手动控制，即使选中 Auto Mod |
| 全屏游玩测试 | 遵从本轮实际 Mods 与手动测试策略 | 单独显示有效输入方式，保留返回编辑器通道；进入／退出全屏不静默更改 Mods |
| 编辑器冻结／故障／未就绪 | 不推进模拟、不生成或接纳游戏输入 | 自动开关不能越过冻结／故障门控 |

preview 只解析并使用一个有效输入驱动，不能同时运行编辑器自动输入和 Mod 的另一套自动输入。嵌入模式的显式开关优先于 Auto Mod；界面保留所选 Mods，并另行显示实际自动／手动控制，不偷偷更改选项。覆盖 Auto Mod 的手动预览属于编辑器增强状态，不能宣称与原客户端该 Mod 的实际游玩等价；兼容截图及判定记录附所选 Mods、覆盖策略和有效驱动。全屏默认策略不覆盖明确的本轮测试设置。

自动控制器归 preview，不属于 UI 模拟鼠标工具或项目 Command；事件带场景／时间代次，定位、切场景、冻结及设备故障作废过期输入。恢复只从当前模拟位置继续，不补跑暂停期间事件。编辑工具与交互工具的路由保持独立，自动打图不抢夺编辑器键鼠或触发设置按钮。

自动播放时间轴支持方向预留见 [定位契约](PREVIEW_TRANSPORT.md)：绝对位置、小节／拍与细调使用同一控制用例，跳转默认冻结以便检查；不能只移动音乐游标。统计来源与实际时间分开，跳转后的 score／ACC／combo 产品模式尚未选定，不将样例或旧统计冒充真实累计值。

## 图像边框与区域

| 描述 | 用途与来源 | 不能替代的内容 |
| --- | --- | --- |
| 变换边框／控制柄 | 元素文档或图层几何经显式坐标变换得到；用于大小、旋转、平移编辑 | 不是游戏判定区或对象可移动范围 |
| 组／组件整体框 | 文档内嵌套组、跨元素组件的后代几何在共同编辑空间内合并；组作为节点整体变换 | 不取消成员文档／输出边界，不自动改变游戏判定位置 |
| 拖动起始区域与允许移动范围 | 已支持场景实例的可拖动位置、允许移动边界及约束；来自预览／已验证兼容规则 | 不能默认由 alpha 包围盒推断，也不意味着能修改游戏控制的位置 |
| GUI 判定区域 | hover／press／click 的形状、状态、层次、坐标空间与实例 ID | 不一定等于可见图片范围；游戏命中对象另有身份与规则 |
| 玩法辅助显示 | 未来 mania 等玩法特有的区域／参考线及状态投影 | 本轮不硬编码列数、轨道布局、判定线或未知默认值 |

preview 返回带 SceneInstanceId、DocumentId 映射、坐标空间、来源及可用性说明的只读区域描述，application 转成编辑器覆盖层查询；UI 只绘制和路由输入。区域显示开关属于 EditorState，不能烘焙到导出图片。可编辑几何仍经项目 Command；预览状态操作走独立控制。扩展按明确玩法的小型值类型增加，不建立通用插件或任意脚本接口。

P2 验证自有占位区域、坐标变换和输入隔离，P4/P5 才据实际证据加入 stable GUI／游戏规则。缺少区域信息返回未支持，不猜测矩形并声称兼容。对应 R17。

## 默认皮肤与来源

预留用户选择外部默认皮肤的设置入口；解析顺序和每个元素的回退规则由 compatibility 的证据决定，不能在 UI 中硬编码通用“文件不存在就随便补图”。结果区分项目提供、外部默认、自制内置、透明、损坏和未支持，并可查询来源。

开发阶段允许用户显式指定本机当前 stable 素材作本地预览对照输入，保持外部只读或置于被忽略的 `local-data/`；不将其作为构建／测试依赖，不从旧源码附带资源取材。用户选择不改变相关资源的授权范围。自动测试继续使用自制／允许分发的 fixture。

发布版不含 stable 原版默认皮肤、头像、字体、声音或用户私人素材。未来自制默认皮肤独立登记作者、来源、分发条件与文件清单，逐元素验收；在其完成前不把诊断占位图说成 stable 默认效果。导出只包含项目资源及明确选择且允许导出的来源，不自动复制整个默认皮肤目录。P7 检查实际分发清单，而不只检查 Git 忽略规则。对应 R18。

## 组件覆盖原则与阶段

所有可由皮肤修改的组件都是最终预览覆盖目标，不能因其原业务被省去而删除其皮肤表现。多人／在线等场景可用本地玩家资料、房间状态、列表和结果数据展示，保留皮肤相关的视觉状态及必要交互，不连接真实网络服务。

不可由皮肤修改的组件按是否支撑编辑、场景导航或离线测试决定保留／简化／省去；原版设置页明确由编辑器设置入口替代。组件清单逐项记录可皮肤能力、必要状态、来源、适用玩法／版本及实现情况。未经证据支持不声称某组件可皮肤或不可皮肤。

P2 建立设置和覆盖层的占位契约，P4 扩展真实场景与默认来源，P5 验证自动／手动输入及全屏，后续 mania 按玩法增量开展。分批实现不缩减最终组件覆盖目标；首轮仍按 [范围基线](p0/PREVIEW_SCOPE.md#首轮范围基线-v1)交付。
