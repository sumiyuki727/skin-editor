## K1剩余工作与收口规则

当前 Query-v1 实现和一致性修订已经完成，不应再把“设计查询批次”或“审阅首次实现”列成下一轮的重复开发。CI 故障复验是本轮质量收尾；之后剩余三个明确工作包：

1. **完整补证工具与审阅。** 按既定规格实现 PC-PREPARE-32／PC-CANCEL-32／PC-DROP-32，使用真实已准备至半程的任务与键；补齐单池／聚合和实际容器准入、cancel-held／Drop 后释放、失败通道及严格完整读取器。保持完整计划 66 条正常流、六类各 16 批次；先回归和独立一致性审阅，不借此扩展 gameplay 功能。
2. **正式新轮与只读复核。** 实现／审阅完成且收到明确测量任务后，冻结完整 CostClosure-v1 二进制，运行 Reference 三轨迹×两预算×两独立进程，共 12 进程，并留存原始样本、诊断扰动、身份和资源回执。可直接进行完整计划的新轮；Query-only 正式测量不是额外强制前置，不能把旧 Query 结果拼入完整轮。
3. **独立 K1 退出决定。** 对照 KT23 的映射和其余适用纯核心条款，检查覆盖及计量有效性后决定是否签收。ReadyForReview 只是具备审阅条件，不能由工具自动变成 K1Accepted、产品性能或 stable 兼容通过。

这三个工作包不是“三轮必定结束”的时间承诺。实际容器上界、必需批次的分辨能力或完整矩阵若不满足，保留 NeedsEvidence，先报告具体缺口并审阅新方案；不自动反复改批次大小、换窗口、增加样本或降低门槛直到出现好看的读数。

**不要求清零所有 Unknown。** 必需的查询／PC 批次及声明家族、映射必须达到各自既定判据；已被充分对应的原单调用仍可 Unknown，短 CPU 窗口和有限采样无法证明的阶段峰值也可按原规格保留。协议 Valid、指标状态、coverage 和 product_verdict 分开；没有发生的采样不能标为有效，合法未知也不能写成零成本。无需新增与 K1 退出条件无关的产品基准来替代这一决定。
