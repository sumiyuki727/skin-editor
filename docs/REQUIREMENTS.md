# 产品需求与验收基线

状态：产品需求设计基线，包含已实现及后续目标；不以整份需求当作实现清单，当前事实见[架构](ARCHITECTURE.md)与[审阅包](review/README.md)。建立日期：2026-10-18；2026-10-20 固定[首轮范围 v1](p0/PREVIEW_SCOPE.md#首轮范围基线-v1)并完成 [P1 准入评审](p0/P0_EXIT_REVIEW.md)，随后补充[预览设置与组件覆盖要求](PREVIEW_SETTINGS.md)。本文记录产品目标与范围；长期约束以 [AGENTS.md](../AGENTS.md) 为准。

## 产品目标

做一款服务于 osu!stable 皮肤制作的跨平台桌面编辑器，缩短“准备素材 → 分层编辑 → 场景验证 → 实际游玩测试 → 导出”的循环。它应能保留可编辑项目、比较不同历史方案，并让 UI 和 AI 使用同一套可靠的编辑能力。

最终目标包含可交互、可暂停且能实时更新素材的必要游戏场景，以及真正的游玩测试。第一阶段只建立可测试的编辑核心和占位场景，不把静态展示作为最终产品目标。

| 概念 | 定义 |
| --- | --- |
| 原始 Asset | 导入素材库的不可变资源内容及元数据，不等于一个图层 |
| 图层实例 | 对原始素材的引用，带独立的变换、可见性与编辑参数 |
| ElementDocument | 一个可编辑皮肤元素文档，包含画布和嵌套图层树 |
| AudioComponent | 独立音效组件，含用途键、一个原始素材引用、增益和可见性；允许共享素材，不属于图片图层或视觉组件树；见[音频方案](AUDIO_EDITING_REVIEW.md) |
| ComponentGroup | 可嵌套并整体变换的跨元素组件组，引用多个文档；各成员仍有独立输出边界 |
| 导出文件 | 文档经合成和兼容性映射得到的派生文件，不是项目源文件 |
| 项目内容 | SkinProject 管理的资源登记、文档、图层／组件关系和 skin.ini 配置 |
| 会话状态 | 历史树、活动节点、选择、场景和工具等编辑期状态；其中只有项目内容变化形成历史节点 |

## 主要工作流

1. 新建或打开项目，将图片放入素材库；音频拟接入同一素材库并按类型筛选。先整理、查看、筛选，不自动创建全部图层或声音绑定。
2. 将素材拖入某个元素文档，多次使用同一素材；每个实例独立编辑，可加入嵌套组。
3. 在预览中用编辑工具选择可编辑对象，显示控制柄和参数；修改通过 Command 提交并立即反映到素材渲染。
4. 切换交互工具操作场景；暂停模拟时间后继续编辑，游戏动画及游戏输入保持冻结。
5. 从历史树返回旧节点并创建新方案，原方案仍可访问、预览和继续编辑。
6. 修改结构化 skin.ini，保存可编辑项目；将指定历史节点合成为 stable 可用的皮肤输出。
7. 在具备对应能力的后端中全屏游玩测试，再回到编辑；使用真实 stable 对支持范围进行对照验证。
8. AI 读取项目、定位对象、提交同样的事务、访问历史和获取预览结果，无需模拟鼠标点击或直接改写项目文件。

## 功能范围

### 项目、素材库与编辑文档

- 项目拥有稳定的对象 ID、文档集合、素材库、配置及文件格式版本；重命名不得改变对象身份。
- 素材导入后由项目管理资源内容，不依赖用户外部原文件一直存在。外部链接、自动监视和跨项目素材库延后。
- 同一个 Asset 可被多图层、多文档引用；内容去重可以共享字节，但元数据身份不以文件名判断。
- 规划独立于本地素材库的在线素材库：远端图片可直接添加到指定图层组，同时下载／登记为本地Asset；完整校验后通过单个事务创建引用，失败不留下部分项目状态。目录／认证／下载状态独立于项目，细节及尚未实现范围见[在线素材库](ONLINE_ASSETS.md)。
- 首个可用版本支持光栅图片图层、嵌套组、排序、显隐、透明度、平移、缩放与旋转。组本身有整体边框与变换，可作为父组的成员；跨文档组件（如 hitcircle＋overlay）也保留独立成员身份，见 [组件模型](COMPONENT_MODEL.md)。画布／组件／场景空间明确，跨输出组效果按可表达能力开放。
- 非破坏编辑首先意味着保留原图并存储参数；完整笔刷、矢量编辑、PSD 往返、复杂滤镜和动画创作时间轴不是首版承诺。歌曲预览定位单独预留；蒙版、裁切和额外混合模式逐项增加。
- 动图／显式PNG序列的后续能力采用导入时识别多帧并保留原字节、帧顺序与精确原时长，编辑时按需解码，导出时按有证据的stable元素规则重采样为帧文件族。原始时序、项目播放配方和派生输出计划分开，兼容预览与导出共用计划；量化／丢帧或未知规则须诊断，不能只取首帧或自动改全局FPS。当前未实现，具体数据与验收见[动画设计](ANIMATION_ASSETS.md)，不等于本轮新增完整动画创作UI。
- 迁移图层到另一组须保持明确的变换语义。默认保持文档空间的几何变换；目标变换不可逆时返回错误，不静默移动图层。新父组的显隐、透明度与合成效果仍然生效，因此不保证迁移后像素完全不变。跨文档复制另立用例，首版不隐式混入组迁移。
- 删除引用中的 Asset 默认拒绝并返回引用列表。显式删除实例后再移除资源可组合为一个事务；历史可达资源仍保留字节。
- “替换素材”须明确区分重新指定某一图层的引用与批量替换共享引用，不原地覆盖不可变资源。
- 文件名冲突、损坏图片、超大尺寸、重复导入及导入失败有结构化结果。大文件解码与缩略图生成不阻塞界面。
- 字体和其他未支持编辑的附件保留原始内容，具体导出支持逐项验证，不能静默丢弃。皮肤音频不再仅以“附件预留”作为最终需求，拟按下面专门的编辑／预览验收交付。

### 皮肤音频素材与实时修改

2026-10-21 [方案v2](AUDIO_EDITING_REVIEW.md)已获审查通过；A1模型／Command／历史和无设备计划已部分实现，实时播放仍未实现。不改变旧P2图形结果，也不把P0歌曲播放视为音效热更新通过。

- 图片与音频共用素材库，但图片文档／视觉组件树和音效组件独立。每个音效组件只引用一个素材，同一素材允许复用；原始Asset、组件配方／用途和实际Voice分开。首轮替换／线性增益／可见性，格式和长流／循环能力按实际范围查询。
- 打击、GUI交互和结算等可皮肤声音均为最终覆盖目标。用途／触发／默认及谱面来源优先级由compatibility按证据提供，P2自有测试槽不冒充stable规则。
- 不建立图片—声音关联；图片变换／透明度／隐藏不影响声音，音效属性不改变图片。未来图层组与音效分开编辑；两类修改仍可组成原子事务，共用引用检查、草稿／取消、失败／NoChange、去重与历史。
- 隐藏子图层／文档内组只去掉该子树贡献；整个图片元素隐藏仍输出有效透明图片，音效组件隐藏仍输出有效静音音频。不能以文件缺失或零字节代替占位。跨元素视觉组未来隐藏逐成员作用于图片，不涉及声音。
- 未编辑的可见音频必须逐字节导出原文件，不因不支持解码／编辑丢失。已编辑但无法处理的音频明确诊断并阻止该次完整导出，不能忽略编辑或跳过文件。导出编码和占位策略按compatibility证据实现。
- 替换音效／增益的候选在明确边界就绪激活，后续触发使用新版，不重置歌曲位置、游戏对象或动画。pending／失败及旧版本来源可查询，迟到结果不能覆盖较新版本；不在解码完成时自动补播事件。
- 冻结时允许编辑和资源更新，游戏声音保持门控；显式素材库试听使用独立位置，不推进游戏时钟。已提交设备残余与冻结确认分开记录，不能把软件静音标志当成即时声学停止。
- 撤销／重做／分支切换还原声音，旧分支或取消草稿的排队声音不能重新出现。历史可达原始字节保留，PCM只作有界派生缓存／发声租约，不随每个节点复制。
- 首轮需验证真实短音效、多Voice、热替换和图形组合负载；软件提交、设备消费和听感延迟分别计量。完整SA01–SA20及已采纳的待测目标见方案，未测不标支持。
- 皮肤声音进入项目；测试谱面的歌曲／自带音效仍是外部只读预览输入，不因播放或选择而自动复制到皮肤项目、Git或导出。

### skin.ini 与皮肤导入导出

- 配置按节、键、原始值及已知类型表达；已知项可结构化编辑，未知项保留并给出诊断。
- 保存原始顺序、注释、未知节和重复条目等必要语法信息；无法无损解释的内容保留原文，不能因解析器“不认识”而消失。
- 2026-11-11确认：适合可视化调节的skin.ini参数均需有对应操作，不限于mania轨道。当前先限定拖拽与缩放：有已验证位置／尺寸语义的配置布局目标，通过手势修改对应参数并更新预览，一次有效手势原子提交一次历史，支持取消、撤销／重做及保存／导出往返。图片变换与配置布局编辑分别选定目标，不通过移动图片冒充配置修改；其他可视化形式后续定约，未知映射明确未支持。当前只有通用配置记录与图片变换基础，尚未实现此能力，范围／准入见[专题规格](SKIN_INI_VISUAL_EDITING.md)；2026-11-14审阅扩展为VL01–VL22，补原文字节及共享参数写回、最后意图提交、同源呈现、P3关闭／重开与规则变化边界，均待实施。
- 导入皮肤须区分可转换为图层的元素、透传附件、未识别文件与错误。首版范围由兼容矩阵限定，不宣称支持全部皮肤。
- 一个 ElementDocument 对应一个可编辑元素；输出映射单独描述目标元素、分辨率或帧变体，不假定永远“一文档等于一个 PNG”。
- 跨元素组件整体变换使用显式坐标映射，并进入各成员的共享合成计划；保留多个输出，不自动压成单一 PNG。不可跨输出表达的隔离透明度／蒙版不能仅在预览假装生效。
- 最小导出覆盖明确的一组静态元素和 skin.ini，输出到独立目录。动画、分辨率变体、回退、声音及打包格式按验证结果扩展。
- 导出基于固定项目节点；缺失引用、无支持的渲染效果、输出路径冲突必须报告，不可生成看似成功的不完整皮肤。
- 项目保存与皮肤导出是不同操作。保存包含原始资源和编辑参数；皮肤导出合成图层，不能替代项目保存。
- 工程文件保存全部已登记内容，含未使用库素材、原始图片／声音／附件、编辑结构／参数、配置／输出及完整历史。历史自动保存也在同一文件内原子增量提交变化状态／节点及新增资源，复用未变化字节，不逐次全量重写；不能只写树壳而等手动保存补资源。自动周期／触发已有[推荐稿](AUTOSAVE_POLICY.md)待审阅，不是已启用参数；具体显示后续定案，默认打开与退出规则按下条执行，个人偏好／本机设置仍独立。
- 2026-11-02确认：选择“不保存”退出时补存已完成编辑的历史，不推进上次手动保存位置；下次普通打开默认激活上次手动保存状态，允许显式打开最新保护状态。两处头／导航与完整历史分开保存，默认打开不能用自动／关闭头覆盖手动状态；补存失败不默默退出，未命名工程和检查点损坏需明确恢复流程，见[约定](DATA_COMPATIBILITY.md#42-不保存退出默认重开与主动恢复)。

### 操作历史树

- 支持撤销、指定后继重做、检出任意节点，以及从旧节点产生新分支。存在多个后继时不得无提示地选择错误分支。
- 不管理分支时，普通Redo沿成功Undo的分叉路径返回原分支；显式检出重置该普通导航上下文，无记忆的多后继仍须选择。保存／曾保存／分支／当前／末端／起始六类系统标签用于后续显示整理，折叠不删除节点或跳过真实Undo步骤，见[契约](HISTORY_PRESENTATION.md)。
- 一个成功事务对应一个节点；拖动过程中的多次更新合并为一次最终提交。失败、取消和无效变更不新增节点。
- 全部已提交节点只增不删，用户／AI／后台都不能删除／清空／裁剪分支、覆盖旧内容或把既有操作压缩合并掉；保存、恢复、另存、迁移／整理也受此约束。标签属于独立可变元数据，可按权限与系统事实规则添加／移除／更新，不改变节点身份、原始操作和内容，不新增内容节点；保存标签仍由真实手动保存驱动。
- 每个节点具有稳定唯一内部 ID；简短分支坐标是会话内便利地址，解析后返回内部 ID，不能代替内部身份。
- 持久节点身份跨重开保持，与每次打开的新运行会话分离；地址有固定长度上限，不逐节点保存完整祖先路径。当前v6实现仍为会话内u64／n≤14、b≤28；未来持久主键与短显示的设计见[数据兼容约定](DATA_COMPATIBILITY.md)，未在本轮改变协议。
- 2026-11-01确认：首版保存捕获时的完整历史树、全部分支、节点状态及可达原始资源；关闭重开恢复已有节点和当前头，不再从新根替代已保存树。保存／导航元数据与运行会话分离。
- 至少允许在两个分支之间往返并继续编辑，互不覆盖。多个节点同时打开并交互编辑属于后续多工作区能力，不能把首版分支切换描述为并发编辑。
- 首版不做分支合并或协同编辑；历史裁剪／覆盖则长期禁止，不提供用户高级开关。历史占用与准入可观测，超预算时诊断／拒绝新增而保留已有节点，不能删旧记录继续编辑；持久化不等于无限容量。未提交草稿仍可取消。
- 场景切换、游戏输入、选择、窗口布局、视图缩放、暂停和全屏不记入项目历史。

### 用户数据与长期兼容

- 已发布的项目／历史格式、偏好和本机设置各有明确兼容与迁移约定；应用大版本升级或内部重构不能成为静默丢数据的理由。磁盘格式独立于内存模型和Command API。
- 项目及所有旧分支的身份、原始字节、未知配置／附件与编辑含义须保留；未知必要能力不能安全理解时禁止覆写，不通过默认降级删除内容。
- 迁移／保存／恢复失败后原版本可用；当前头返回已保存节点但新分支尚未落盘时，仍须提示未保存。设置损坏不能自动以默认值覆盖唯一原件。
- 用户显式偏好与未设置分开；本机设备／路径、工作区和缓存不混入共享项目。具体方案及待冻结部分见[数据兼容约定](DATA_COMPATIBILITY.md)。

### 临时联合选择

- 选中已有图层组／视觉组件，或多选多个成员后自动显示共同变换框；不以全量创建组件按钮为操作前置。
- 共同框在解除选择之前可连续共同编辑，解除后不保留该临时组合，已提交变换保持。拖动中取消只回退本次草稿；框的生命周期不改变每次手势一个事务的历史规则。
- 选择不创建组件节点、移动层级或登记资源；祖先与后代同时选中时不重复变换。跨文档共同映射须明确，独立输出和音效边界不变，见[实现与范围](P2_SELECTION_CONTEXT.md)。

## 预览与实际游玩

“精简 stable 端”目前作为产品目标描述，不能直接等同于已有可嵌入内核。官方 [ppy/osu 的说明](https://github.com/ppy/osu/blob/master/README.md)明确其为 lazer；官方[发布流说明](https://osu.ppy.sh/wiki/en/Client/Release_stream)也区分两类客户端。因此复用 lazer 或 osu!framework 只能成为候选实现途径，不能自动获得 stable 一致性。

| 能力层级 | 目标与验收边界 |
| --- | --- |
| 占位场景（首个编辑闭环） | 使用测试布局和确定性模拟时间验证素材刷新、选择映射及暂停契约；不做判定，不宣称 stable 兼容 |
| 内置兼容场景 | 覆盖已验证的皮肤布局、场景切换、必要 GUI 交互和动画；明确未覆盖行为 |
| 内置实际游玩 | 处理谱面、输入、音频、判定和全屏；暂停后素材仍刷新，恢复时间连续；按玩法逐项验收 |
| 真实 stable 验证 | 对用户安装的客户端导出测试皮肤并对照或游玩；属于验证手段，不替代内置实时编辑与游玩目标 |

用户已明确：本地旧版 stable 源码不是可直接复用的开源代码，且行为可能不同于当前 stable。当前主线因此采用独立兼容实现；该源码只帮助定位研究问题，不裁剪接入，不复制或翻译其中实现，不导入附带二进制/素材。可独立复用的公开组件仍须按自身来源、条件与行为验证。真实 stable 用于对照，不能以旧源码测试替代当前客户端实测。

2026-11-03首批独立内核方案见[架构与K计划](STABLE_KERNEL_PLAN.md)及[交接](HANDOFF_STABLE_KERNEL.md)：首批限定standard／No Mod／受测圆圈子集，明确时间权威、输入、生命周期、编辑器交接与验收；当前只有设计，没有新增玩法功能。未支持对象／语义须诊断并拒绝不满足准入的谱面，不能删掉对象后声称原谱面已测试；此子集不缩减后续完整standard及场景覆盖要求。

具体要求：

- 预览后端能力可查询，包括场景、交互、模拟暂停、热刷新、游玩、全屏与截图；不可用能力应在 UI/AI 中说明原因。
- PreviewState 包含场景、模拟时间、游戏选择、播放及游玩状态；EditorState 单独保存编辑工具、文档与图层选择、视图及面板状态。
- 交互工具路由到游戏；编辑工具路由到编辑器选择和变换。一次输入不能同时触发两类操作。
- 编辑时命中的场景实例要映射回 ElementDocument；同一元素可能被场景绘制多次，编辑共享文档将更新这些实例，不能误导为只修改某个游戏对象。
- 暂停冻结游戏时间、动画、音频进度和游戏输入，场景 GUI 也不接受游戏交互；编辑器控制柄、面板和素材更新继续工作。
- 编辑器的冻结模拟与游戏内暂停菜单分别控制；冻结覆盖必要的场景、音频和动画时间源。日常素材替换保留场景身份及动画相位，不隐式回到首帧。
- 切场景、编辑器缩放等显式预览控制可在暂停时执行，切换后的场景保持暂停；它们不通过游戏输入通道执行。
- 暂停期间的输入不排队；恢复时清除按键边沿和时间累积，避免突发动画、误判或自动触发按钮。
- 全屏测试保留返回编辑器的控制通道；失焦、切显示器和 DPI 变化需验证。独占全屏和操作系统快捷键不是首版必需。
- 外部客户端能否热重载、暂停后刷新和接收控制必须分别实测；不能通过冻结进程或假定注入能力来满足设计。
- 玩家头像、用户名和必要展示资料由用户在编辑器设置中指定，场景使用本地展示数据，不要求登录或查询在线服务；资料不属于皮肤项目。
- stable 运行／显示／输入等测试设置统一放在编辑器设置中；不在预览内重建原版设置页面。skin.ini 仍是经 Command 编辑的项目内容，不能混入用户偏好。
- 用户可独立指定本机 stable 安装／Songs 来源并选用实际谱面，受限只读获取测试需要的谱面与媒体。路径和选择属于本机设置／预览状态，不自动复制到皮肤项目或导出；缺失、越界与源变更按[来源设置](PREVIEW_SETTINGS.md#实际-stable-谱面与必要媒体)诊断。
- 嵌入预览默认自动打图，不论是否选中 Auto Mod；提供显式开／关覆盖。全屏默认遵从实际 Mods 与输入策略，控制方式必须可见。自动输入受冻结／定位／场景代次约束，不补发暂停期间输入。
- 自动播放下预留歌曲时间轴跳转、前后小节／拍吸附及细微偏移，用于冻结检查 mania 等场景；定位需协调音频、对象／动画和旧输入作废。统计准确重建是独立能力，跳转后的分数／ACC／combo 必须标来源，具体展示模式仍待商讨，见 [时间轴设计](PREVIEW_TRANSPORT.md)。
- 除变换框外，预留独立的拖动起始区域／允许移动范围、GUI 判定区域及玩法辅助显示查询。坐标、来源和是否可编辑分别说明；未来 mania 按已验证玩法规则扩展，不在 domain 预置未知游戏几何。
- 可由皮肤修改的组件全部列入最终覆盖清单，包括在线功能界面的可皮肤部分；可用本地数据展示。不可皮肤组件按必要性决定保留；范围分批实现，未覆盖项不能宣称支持。
- 默认皮肤来源可配置为用户本地外部皮肤或未来自制／获授权的内置皮肤。开发用当前 stable 原版素材只经显式本地路径读取，不复制入仓库、测试 fixture 或分发包；发布版不包含原版默认素材。透明、缺失、损坏与不支持不能混为一种回退。

这些设置的所有权、输入优先级和后续验收见 [预览设置设计](PREVIEW_SETTINGS.md)，P1 只保留边界，不提前实现预览功能。

## UI 约束

中央预览是主要工作区，布局暂不定稿。先验证两个可调整的轻量布局草图，依靠普通面板、折叠与分隔条实现。

- 场景切换栏独立于图层和工具面板。
- 交互工具与编辑工具有清晰模式反馈。
- 图层面板、可折叠素材库、选择控制柄与参数面板形成最小编辑闭环。
- 预留暂停与全屏控件，以及历史树和 AI 聊天面板的扩展位置；不提前实现空的复杂聊天系统。
- 首版允许列表或缩进树表示历史，节点与分支可区分；大型可视化历史图、任意窗口停靠、多窗口编辑后续评估。
- AI 项目控制不依赖内嵌聊天面板；面板只是未来客户端之一。
- GPU 画面通过不透明帧身份与桌面呈现桥交接，application 不承载原生纹理。窗口尺寸变化、历史切换、捕获引用及设备故障的回收责任在 P2 落地，见 [呈现契约](PRESENTATION_CONTRACT.md)。

预览器对原版业务功能的保留、简化与省去范围见 [精简功能边界](p0/PREVIEW_SCOPE.md)。场景可由本地测试数据直接进入，不要求完整账号、联网与个人曲库；这种简化不改变已声明的皮肤表现与离线游玩验收目标。

## 结构化控制

- 查询项目、资源、图层、配置、当前修订、历史节点和后端能力，采用稳定 ID 与可分页结果。
- 项目修改复用相同的 Command 与事务；历史检出走同一会话服务；场景切换、暂停、截图走独立预览控制。
- 请求带期望活动节点及会话修订，过期请求明确冲突；支持事务预校验及会话内请求去重，避免 AI 重试造成重复修改。
- 历史查询默认只读；显式检出才切换活动节点。截图携带来源节点、项目修订、场景、时间及渲染修订，避免观察到旧图后继续编辑。
- 初期先建立进程内可序列化契约；外部传输可在本地 IPC、CLI 或 MCP 中选一个，不同时维护多套业务逻辑。

## stable 兼容性的证据基线

官方 [skin.ini 文档](https://osu.ppy.sh/wiki/en/Skinning/skin.ini)与[界面皮肤元素文档](https://osu.ppy.sh/wiki/en/Skinning/Interface)是研究入口，不是所有细节均已验证的声明。规则进入实现前记录：规则 ID、适用元素/版本/玩法、来源链接或提交、客户端版本、输入 fixture、期望结果、实际结果和证据位置。

| 待研究领域 | 当前状态 | 实现前需要的证据 |
| --- | --- | --- |
| 元素文件映射、尺寸、锚点及布局 | 未验证 | 官方条目与固定客户端截图/测量 |
| 分辨率变体和缩放、回退及缺省素材 | 未验证 | 覆盖存在/缺失/冲突的真实客户端样例 |
| 动画命名、帧率、循环和暂停行为 | 未验证 | 按元素验证，不把单个元素规则推广全部元素 |
