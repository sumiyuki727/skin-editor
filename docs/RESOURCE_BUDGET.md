# 产品资源预算 v2

2026-10-27，经用户明确同意生效。取代后续阶段准入对[预算 v1](p0/RESOURCE_BUDGET.md)中 B06 的硬阻塞解释；v1、旧证明、失败结果及其适用版本原样保留，不追认通过。**单逻辑核 CPU≤15% 保留为优化目标，超出它不再单独阻塞后续开发。** 没有新增 20% 或其他替代硬上限，也没有调整声音供给。

## 负载与构建分别记录

| 类别 | 固定范围 | 可支持的结论 |
| --- | --- | --- |
| N：正常标准编辑／播放 | 自制 100 张 1024² RGBA 原图、10 文档／500 层，活动文档 50 层引用 10 原图；300 秒背景播放、每秒 8 次短音触发、300 次参数变更、20 次图形切换；同构建至少两轮 | B02–B04、B06–B09 的标准组合证据；声音不人为填满容量，不能以单 Voice 短测替代 |
| S：32 Voice 压力 | 独立于 N，从静音接纳 32 个同帧短音，验证参考混音及第 33 个 RefuseNew；GUI 压力阶段同时保留持续背景 | 容量、双通道、取消、清理及压力成本；CPU 单列，15% 同时作为观察目标，不新增压力硬上限，不代表正常使用成本 |
| Q：有界发布短测 | 固定两轮既有 streamed GUI 脚本；分别观察 idle、voices_1、voices_32、closed，以及暂停／定位／热替换／草稿／历史 | voices_1 只是轻负载代理，voices_32 是 S 的短轮；不是 N、稳定空闲、20 次完整循环或人工交互验收 |
| D：诊断／归因 | 默认关闭的 framework-trace、逐帧边界、文字／网格回放等按需启用，与普通性能轮分开 | 解释来源；不能扣掉诊断成本、合并不同版本或用诊断成绩宣称默认产品达标 |

默认发布构建使用锁定工具链、`--release --offline --locked`，不启用 host 的 `framework-trace`。Q 仍有受控 GUI 脚本和既有有界首样本观察线程；它使用真实编辑器及原生输出，但不是完全无诊断的人工产品运行。CPU 包含该进程中的观察线程、框架和驱动线程，不作扣减。系统共享音频引擎、外部只读采集器及跟踪扰动另列，不能从产品读数中估算减去。

Q通过既有`--verify-streamed-gui`显式选择分离声音候选；“默认发布构建”指默认编译功能集，不等于普通启动已默认采用该候选。该描述对应2026-10-27预算复审当轮。2026-10-29后续普通Windows组装接入既有分离声音／MemoryUsage，当前复验见[自动收尾](P2_AUTOMATIC_CLOSEOUT.md)；供给参数和帧率需求保持，新结论不追认旧构建。

单逻辑核百分比不除以机器逻辑处理器数。独立调度计量先以连续／周期／不同相位参考交叉校验；原始进程时间计数继续保存，但校验未通过不能独立证明 CPU 目标达成。参考、总量计量、细分归因、原始谓词和阶段结论分别记录；不修改旧脚本的历史判据。

既有`measure_combined.py`等工具的`passed`及退出码仍按其原版本判据解释，不能直接充当v2阶段准入结论。本轮`measure_budget_review.py`只提供Q的v2分类；N的后续复验须显式分别汇总CPU目标与全部硬项，不得仅忽略非零退出码或按名称批量豁免CPU类检查。

## 保持的目标与硬性门槛

| 指标 | v2 处理 |
| --- | --- |
| B06 播放 CPU | 正常 N 的 300 秒 Playing 平均≤15% 单逻辑核是优化目标；S／Q 的各阶段分别报告同一目标是否达到。超目标记录性能欠项，不单独否决 P3 并行开发，也不改称目标已达成 |
| 欠载及健康 | 已声明负载内零缺失帧、无原生故障／协议溢出；失败仍阻塞相应声音路径验收 |
| 已就绪短音提交 | 场景／显式试听分别按完整应用请求至含首个有效样本的原生复制观察上界 p95≤20 ms；报告 p99／最大值，不等于设备消费或声学延迟 |
| B01／B02／B03 | 空项目工作集≤200 MiB；标准工作集／私有提交各≤512 MiB，累计历史峰值另列；Q 全生命周期采样也检查两个 512 MiB 上限 |
| B04 | 当前 Windows 离散 GPU 的 PID dedicated≤256 MiB、shared≤128 MiB；逻辑目标数不能替代 GPU 总量，未测不记零；其他架构另验 |
| B05 | 暂停／关闭稳定 CPU≤2% 单逻辑核及稳定段≤2 帧保持硬门槛；Q 的短 idle／closed 不构成 B05 证明。15% 的调整不豁免空闲忙循环 |
| B07／B08 | CPU 帧 p95≤16.7 ms、已解码编辑→GPU 完成／回读 300 次 p95≤50 ms 保持；p99、最大值及长帧单列 |
| B09／B10 | 20 次完整循环、任务／租约归还、关闭基线趋势及长历史成本保持。不得回收历史可达原字节，不以清空计数器代替实际回收，不设置允许泄漏额度 |

其余负载、失败保护、原始／派生／在途资源预算及退化策略继承 v1。CPU 目标未达、缺少有效计量、内存超限、资源未释放是不同结论；只有 B06 不再单独构成开发顺序阻塞，其他门槛不随之放松。
