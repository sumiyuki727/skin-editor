# 开发路线与质量门槛

状态：2026-10-20 的 [P0 收口评审](p0/P0_EXIT_REVIEW.md)已固定范围、预算与技术决策；截至 2026-10-21，**P1-0／1／2 已完成 Windows 检查，P1-3／4 的完整历史控制与草稿未实施**，见 [P1 进度](P1_PROGRESS.md)。完整产品资源、低延迟游玩及剩余硬件／兼容项仍按对应阶段验收；Linux 实测暂缓，macOS 待设备，不承诺未经验证的发布日期。

## 推进原则

每个阶段交付一个可验证闭环，先解决风险，再扩范围。阶段可以包含多个小迭代；验收、测试、性能记录和文档都属于产物。首轮范围与核心技术已有基线，剩余平台／兼容及生产音频仍需逐阶段验证，不承诺固定工期。

平台范围按用户最新确认：当前继续 Windows 验证，Linux 实测暂缓，macOS 待有设备后验收。保留面向 Windows／Linux／macOS 的平台适配边界，Linux／macOS 实测不阻塞本轮 P0 或后续无窗口核心工作；未测平台始终标记未验证，不能承诺对应发布支持。恢复 Linux 验证时单列发行版、X11／Wayland、音频环境和外部 stable 运行方式，不能把 Windows 结果视为 Linux 结果。

```mermaid
flowchart LR
  P0[P0 可行性与选型] --> P1[P1 无窗口核心]
  P1 --> P2[P2 最小桌面编辑闭环]
  P2 --> P3[P3 保存与静态皮肤导出]
  P3 --> P4[P4 兼容场景与配置]
  P4 --> P5[P5 实际游玩与全屏]
  P5 --> P6[P6 AI 外部接口与历史工作流]
  P6 --> P7[P7 跨平台发布]
```

这表示默认交付顺序，不表示要到 P6 才考虑 AI：可序列化命令与冲突语义从 P1 建立，外部只读适配可在核心稳定后提前；不得借此改变项目写入边界。兼容证据和跨平台检查从 P0 开始，贯穿后续阶段。

## P0：预览可行性、技术选型与范围基线

本阶段进行研究与小型可丢弃原型，不搭建完整产品 UI。

交付：

- 用户已确认非开源旧 stable 源码不能直接复用：只读研究历史行为，主线独立实现，公开组件单独评估；建立旧快照到当前客户端的验证链。
- 首个玩法选 osu!standard／No Mod 离线测试；P2 占位编辑，首个兼容增量为单击对象及光标的 15 个静态文件，完整 standard 后续补齐，见[范围 v1](p0/PREVIEW_SCOPE.md#首轮范围基线-v1)。
- 建立 stable 兼容证据记录和自制测试素材，记录真实客户端版本。没有实测时如实标记未知。
- 独立预览器按 [精简范围](p0/PREVIEW_SCOPE.md)保留必要行为；对照按 [F12 / 文件与日志流程](p0/EVIDENCE_WORKFLOW.md)执行，不依赖系统窗口捕获。
- 按 [技术评估](TECH_STACK.md)实现最多两个同负载原型：中央画布、可折叠资源列表、参数输入、图层合成、模拟暂停及素材更新；验证一种游玩后端的时钟/音频/输入复用路径。
- 当前测量 Windows 的资源成本、交互、输入法、高 DPI、GPU 与构建分发；为 Linux 保留接口与待测清单，实测暂缓；macOS 待具备设备。允许在证据充分时先形成 Windows 候选结论，跨平台支持分别验收，不以未测结果为通过项。选定语言/UI/渲染方案，分别记录实测失败与未测候选；不将未选等同于失败。
- 两个轻量布局草图与具体使用步骤，验证中央预览是否足够清晰，不实现停靠框架。

退出条件：有明确可行的独立兼容预览演进路线、选型记录、支持平台基线、预算测量和首个元素清单。Linux／macOS 按上述延期范围记录，不作为当前 Windows 结论的必需实测条件；其他门槛不因平台延期免除。旧源码可读不代表可以复用，其旧行为不直接作为当前规则；不能以“外部客户端可以打开”关闭实时编辑与游玩路线风险。

此阶段原型可以丢弃，不向产品核心引入占位兼容规则；正式工程和依赖创建属于下一阶段任务。

## P1：无窗口项目核心、命令与历史树

前置：P0 的核心语言、范围及关键边界已确定。P1-0／1／2 已建立独立检查、模型、Command／事务与最小追加历史，按 [P1 实施计划](P1_PLAN.md)继续完整历史控制、分支与草稿；不能以当前追加历史代替整个 P1 验收。

交付：

- 建立 domain / application 等实际模块与依赖规则，提供单一测试入口和最小 CI。UI/预览不参与核心测试。
- 实现稳定 ID、不可变资源引用、文档与嵌套图层／跨元素组件、明确变换空间及结构化配置的最小模型；组本身可整体变换，成员输出边界保留。
- 实现基础命令、事务预校验与提交、结构化错误、修订冲突和会话内请求去重。
- 实现撤销/重做、任意检出、保留分支、固定大小节点身份与有界短地址；只做会话历史，不复制完整祖先路径，见 [寻址约束](HISTORY_ADDRESSING.md)。
- 实现可取消的连续编辑事务与只读查询；历史重放不依赖外部文件。

测试与退出条件：R01–R05、R11、R20 的核心契约，以及 R19 的模型范围通过。覆盖失败回滚、无效变更、资源共享、组循环、迁移变换、跨分支引用、重复请求和过期修订；随机命令序列或属性测试验证树与引用不变量。CLI 测试夹具即可，不先做复杂图形历史界面。

依赖检查必须能发现至少一个人为注入的反向依赖或私有写入入口暴露问题；不能只有“模块名称看起来分开”。README 更新真实工具链、安装与测试命令。

## P2：素材库到占位预览的最小桌面闭环

前置：命令和历史行为稳定，UI 框架已选。

交付：

- 素材导入/缩略图、素材库到文档、图层及嵌套组、控制柄和参数编辑。
- 中央占位场景、独立场景控制、交互/编辑工具、选择映射及暂停控件。
- 非破坏的基础变换与合成，实时刷新和过期任务丢弃。
- 简单历史列表或树，可从旧节点建立新分支并切换。
- 统一设置入口的最小契约，分离本地玩家展示资料、运行偏好和 skin.ini；自有占位场景分别查询变换框、拖动约束和 GUI 判定区，不提前硬编码游戏规则。
- 在 [呈现契约](PRESENTATION_CONTRACT.md)下落地应用控制端口与 egui 原生呈现桥，明确共享 Device／Queue、纹理／TextureId 所有权、resize、历史切换及 GPU 回执／租约退休。自有定位与组整体框先验证契约，不声称真实玩法已支持。
- 按 [实际谱面来源](PREVIEW_SETTINGS.md#实际-stable-谱面与必要媒体)预留本机安装／Songs 来源设置和选择入口；不将真实谱面目录或媒体登记为皮肤项目内容。

测试与退出条件：R01/R02 的视觉部分、R06/R07 的占位版本通过。特别验证“暂停后改图，模拟时间保持、像素变化”和拖动取消；CPU/GPU 合成有基础对照，低分辨率/高 DPI 与中文参数输入可用。静态暂停后没有无意义的持续渲染。

R19 的组／组件选择与变换、R22 的资源交接必须通过自有 fixture 和原生回读；不能仅凭 P0 有直接纹理呈现就关闭正式所有权门槛。候选／活动／退休资源计入同一预算，旧帧输入映射必须核对修订。

不在此阶段实现完整游戏逻辑、真实判定、完整 skin.ini UI、笔刷、窗口停靠或聊天系统。README 明确占位场景能力。

## P3：可恢复项目与可验证静态导出

前置：最小编辑闭环可用，初始兼容输出集合有证据。

交付：

- 冻结首版项目 schema；项目目录、资源自包含、保存/打开、格式校验及迁移入口。
- 保留未知配置和附件，明确哪些可编辑、哪些仅透传、哪些不支持导出。
- 固定节点导出静态图像与配置到独立目录，生成可追溯结果及诊断。
- 使用真实 stable 检查首个输出集合；运行平台和客户端版本单独记录。

测试与退出条件：R08–R10、R13 通过；覆盖保存中断/写入失败、缺失与损坏资源、未知 schema、路径/大小写冲突、导出取消及输出事务。保存失败不能破坏已存项目，导出失败不能冒充完成或覆盖原有成果。

导出 fixture 的像素、配置和文件集合可自动检查；真实 stable 结果另留证据。关闭重开不保留历史，UI 明确告知。先交付皮肤目录，归档格式另行增加。

## P4：已验证的兼容场景与配置体验

前置：P0 已选预览路线；P3 输出可以对照真实客户端。

交付：

- 逐场景加入必要 GUI、布局、配置效果和动画；皮肤回退、变体和声音按证据分批支持。
- 为每批元素记录适用玩法/客户端范围、已知差异与回归素材。
- PreviewCapabilities、场景实例映射、暂停控制与热刷新贯穿真实兼容场景。
- 增强配置编辑反馈，不将未经验证规则散入 UI。
- 所有可皮肤组件进入最终覆盖清单，含在线业务的本地界面状态；接入用户展示资料和外部默认皮肤来源，原版设置页由编辑器设置替代，详见 [预览补充要求](PREVIEW_SETTINGS.md)。
- 接入本机 stable／Songs 来源和选定谱面的必要媒体受限只读读取，覆盖自定义目录、缺失、越界、重解析点及源文件变更；不修改原客户端，不将谱面资源带入皮肤导出（R23）。

测试与退出条件：R06/R07 的兼容版本通过；固定模拟时间与输入脚本可产生可重复截图；和真实 stable 的对照覆盖目标场景。无法解释的差异形成明确问题，不以“接近”标成完全兼容。

P4 不包含完整游玩能力；菜单交互、动画和截图不能代替 P5。每个支持元素的状态可查询，未支持行为在产品中可见。

## P5：实际游玩、音频同步与全屏

前置：所需玩法和素材集合已确认，音频/输入/规则实现路线及平台成本经 P0 验证。

交付：

- 面向已选玩法的谱面加载、离线游玩、输入、音频、基本判定和必要结果反馈。
- 使用用户选择的真实谱面及必要本机媒体完成测试；与自制确定性 fixture 的自动回归分别记录来源和适用范围（R23）。
- 全屏测试及可靠返回编辑，测试期间清晰区分游戏输入与编辑操作。
- 暂停冻结模拟、动画、音频和游戏输入，素材修改仍更新；恢复无时间跳跃或积压输入。
- 真实 stable 对照游玩，记录时间、布局及判定方面的已知差异。外部客户端可作辅助测试，但不替代内置目标。
- 验证非全屏默认自动打图及显式关闭、全屏有效输入方式、与 Auto Mod 的独立性，以及冻结／定位／场景切换后的旧自动输入丢弃。
- 按 [时间轴设计](PREVIEW_TRANSPORT.md)接入绝对／小节／拍定位及细调、音频与对象恢复；score／ACC／combo 跳转策略在本阶段相关 UI／评分实现前讨论定案，统计来源始终可辨。mania 的长按／滚速／判定线投影在其玩法增量补证。

测试与退出条件：R06 的游玩版本和 R12 通过；确定性模拟与录制输入可回放，音频同步、暂停往返、失焦、不同刷新率、全屏退出和长时间游玩有平台实测。没有真实内置游玩时不得标记本阶段完成。

这个阶段具有最高的兼容和时序成本，必要时按玩法和对象类型继续拆分；不能为赶工绕过命令系统或将项目保存塞入游戏内核。

## P6：外部 AI 接口与历史工作流

前置：application 公共契约稳定；截图、历史节点与修订可关联。

交付：

- 选择一个本地传输适配（IPC、CLI 或 MCP），提供 schema、能力发现、示例和版本策略。
- 查询项目/资源/图层/配置与历史，预校验/批量修改，检出分支及获取指定节点预览。
- 明确请求去重、冲突、错误、分页、超时和截图完成状态；不默认开放远程写入。
- 增加历史分支的比较与命名体验；是否增加多工作区和内嵌聊天另立小需求，不与核心接口强绑定。

测试与退出条件：R11 的外部适配通过；同样输入经 UI/application 与 AI 产生等价状态和历史；并发过期请求不覆盖用户编辑，重复请求不重复创建节点，截图来源可核对。外部接口不能导入核心私有模块或直接写项目文件。

## P7：跨平台质量与可分发版本

交付：

- 确认实际支持的系统/CPU/GPU 范围，提供安装包、运行依赖、升级/迁移说明和第三方说明。
- 检查图像解码、缓存、历史树、长时编辑/游玩的资源回收和性能预算。
- 每个实际发布平台分别执行 smoke test：导入 → 编辑 → 分叉 → 保存重开 → 导出 → 场景预览 → 游玩 → 返回。先验收 Windows、Linux；macOS 有实机结果后再纳入发布范围。
- 完整记录当前支持元素/玩法、已知差异和未支持功能，README 的命令在干净环境执行验证。
- 分发资源清单逐项检查来源；不得包含 stable 原版默认素材或用户本地皮肤／头像／音乐，未来自制默认皮肤单独验收。

退出条件：R14 发布版本通过；不存在已知项目损坏、分支丢失、静默丢配置或错误导出的阻断问题。功能不足时发布范围较小的预览版并说明范围，不以此宣称最终产品完成。

## 日常开发流程

1. 选择一个具体用例和验收编号；记录涉及模块、数据变化和未知兼容行为。
2. 对基础行为先定义可验证的输入/输出与失败情况；需要调整公开契约或数据格式时先同步设计。
3. 做最小实现，经 Command 进入项目；避免把一次 UI 便利性改动扩成架构重写。
4. 运行受影响层的测试与静态/依赖检查；涉及图形、平台、文件或时序时增加对应验证，说明未测范围。
5. 复查跨模块方向、资源生命周期、历史和修订、旧格式/未知数据、性能及错误恢复；更新功能状态和运行说明。
6. 交付可审查差异和证据；按用户授权与 AGENTS.md 在完整增量检查通过后自动创建本地 Commit，不自动推送。提交前审查具体暂存内容，保留他人未完成修改。发现需求超出原范围时先完成独立部分，明确新增范围和依赖。

## 检查能力建设顺序

| 引入时机 | 必须同时建立的检查 | 避免的问题 |
| --- | --- | --- |
| P1 首个语言工程 | 格式、静态检查、无窗口测试、依赖规则、Windows／Linux 构建检查；Linux 实机延期，构建缺少环境时如实记录并补齐，macOS 条件独立记录；保留平台边界检查 | 文档边界落不到代码中 |
| P2 图像与 UI | 合成对照、暂停刷新、输入隔离、基本平台 smoke | 游戏冻结连带编辑器冻结、两套合成行为 |
| P3 文件系统 | 保存/导出故障测试、fixture、schema 迁移检查 | 静默丢数据、历史资源提前删除 |
| P4/P5 兼容与游玩 | 证据关联、场景/时间/输入脚本、真实客户端对照 | 将占位行为或 lazer 行为视为 stable 事实 |
| P6 外部 API | schema/契约、去重、冲突、不同入口一致性 | AI 绕过命令或覆盖用户编辑 |
| 每次依赖升级 | 锁定版本、受影响回归、平台/资源成本复查 | 库升级悄悄改变行为或最低系统要求 |

P1-0 已建立当前两个核心包的检查、真实禁止依赖 canary 和私有访问编译拒绝测试；后续模块／行为需同步扩展规则与测试。CI 配置尚未远程运行，不能替代平台实测。P0 契约探针仍是独立历史证据。采用明确验收和自动检查降低维护风险，不能承诺未来永远不会出现违规代码。
