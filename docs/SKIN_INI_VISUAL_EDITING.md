## 1. 目标与当前基础

长期目标是为适合可视化编辑的皮肤配置提供对应操作，不以某一玩法或某一图片为边界。当前增量范围为能用位置／尺寸变化表达的**拖拽与缩放**；其他可视化形式后续分别定约。此范围不收回现有图片编辑能力，也不把颜色、声音、布尔开关或时间参数强行解释成几何。

现有[UI变换](../desktop/ui/src/lib.rs)提交SetLayerTransform／SetComponentTransform；[配置模型](../crates/domain/src/configuration.rs)保留有序原始记录和解释范围，不解析stable布局；[Command](../crates/application/src/contract.rs)有通用配置记录增删改。这些是可复用基础，尚无配置布局目标、逐参数映射、对应控制柄或真实mania布局预览。拖动一张轨道图片不会自动修改轨道配置。

需求对应[R31](REQUIREMENTS.md#验收场景)。当前主线仍为[P3保存闭环](P3_SAVE_LOOP_SPEC.md)，不重测或扩展K1，不改变SyntheticTest纯核心签收、Reference10000／Tiny4及产品NotEvaluated／stable Unknown结论。

## 2. 对象与操作语义

| 编辑目标 | 拖拽 | 缩放 | 持久结果 |
| --- | --- | --- | --- |
| 图片图层／图片组件 | 沿现有图像坐标及变换规则移动 | 沿现有图像变换规则调整 | 图层／组件变换；不顺带改配置 |
| 配置布局目标（待实现） | 根据已验证映射改变位置、偏移或可由边界移动表达的布局量 | 根据已验证映射改变宽度、高度、比例或关联尺寸 | 原子修改对应SkinConfiguration记录；不烘焙进原图 |

配置布局目标可以代表一个元素、某个布局区域或一组由同一配置关系控制的对象，不要求拥有Asset／Layer／Document。mania轨道只是候选例子；本轮不确定其具体键名、默认值、单位或可改范围。图片框、配置控制框、游戏命中对象、GUI判定区域和玩法辅助线保持独立身份，禁止按文件名、透明像素或图片选择猜测配置目标。

首个交互增量一次编辑一个配置布局目标；该目标可以联动多个配置项。跨配置目标联合选择、图片与配置混合共同框另行定约；不支持时明确拒绝，不能只改选中项的一部分。界面须能辨认当前编辑的是图片还是配置布局，命中重叠时采用明确选择规则，不让一次手势同时修改两类内容。

只能沿参数支持的轴操作。只有水平位置的目标不提供虚假的垂直自由度；只支持一个尺度的目标不提供任意二维形变。锚点、轴向、比例关系和关联值的保持策略按每个映射明确规定，不能将全框缩放默认解释为“所有数字一起乘”。旋转不属于本次新增配置手势。

## 3. 覆盖清单与逐项准入

实现前建立版本化覆盖清单，按支持的skin.ini版本、节／选择条件、玩法及场景逐项追踪。最终覆盖所有适合可视化编辑的项；分批实现不删除剩余需求。清单区分“本批可由拖拽／缩放表达”“需要其他可视化形式”“无此几何语义”“尚未知”，未评估项不得记作不适用。

每个拟开放映射至少记录：

| 字段组 | 必须明确的内容 |
| --- | --- |
| 规则身份与证据 | 映射及规则版本、目标客户端／皮肤版本、来源、验证问题、回归样例与客户端证据；Unknown与已验证分开 |
| 定位与上下文 | 精确节实例、选择条件、目标记录／值分量及关联项；玩法、键数等预览选择如何参与解释且不自动变成项目修改 |
| 正向投影 | 配置值到逻辑几何的规则、原点、单位、轴向、锚点、有效范围及场景条件 |
| 反向编辑 | 手势到候选值的确定性规则、量化／舍入、边界处理、保持项、联动项及不可逆／歧义条件 |
| 原文保留 | 缺省值来源、必要时的显式记录插入、重复节／键的生效与写回位置、编码／注释／未知内容保留 |
| 支持状态 | 文档需求、规则已验证、映射已实现、预览／文件往返／客户端已验分别记录；缺失证据或能力给出原因 |

缺省值未经验证、重复项生效规则未知、条件冲突、目标无法唯一定位、场景投影不可用或反向解不唯一时，不开放会写项目的手势。多解只有在已定约且可解释的保持策略使解唯一时才准入。不得猜测键名／默认值、自动修改第一个同名键或在拖拽时顺便清理重复项。

未受手势影响的记录保持原始字节和顺序。编辑已知值只替换被授权的值范围，保留邻接注释、空白、未知字段及换行；无法安全保留时返回诊断。缺失项在有效修改确需显式覆盖时才按已验证规则插入；打开预览、点击、取消和量化后的无变化手势不物化默认项或格式化整个文件。

### 3.1 解析权威与可逆写回

现有ConfigRecord::new只检查解释范围在raw字节内、键／值不重叠等一般条件；Entry／Section标注不证明原文符合skin.ini语法、键已支持或其值生效。映射准入须依据受支持编码、实际原文字节及有版本的解析／生效规则重新核对范围与节上下文；不信任UI传来的“已解析”标记。未知编码、不透明记录、非法已知值及不一致标注原样保管并给出不可编辑原因，不在查询、重开或Begin时隐式修复。

每条映射明确区分三组对象：求值所读的记录／分量及缺省来源、手势获准写入的记录／分量、变化后需重算的布局实例。共享参数可影响多个实例；选中一个实例并不获得独立副本。界面说明联动范围，未选中的依赖项按规则重算，不偷偷写入额外覆盖项来伪造局部编辑。节选择、键数等预览上下文改变只改变解释来源，不自动创建、复制或改写另一节；其生效／回退未知时不选择“最接近”的节。

同一记录的多个值分量先基于同一原文合并为一个候选，冲突或重叠写入拒绝；值长度变化后重新计算该候选记录的解释范围，其他分量／分隔符／注释按原字节保留。跨记录插入、替换的命令顺序须核对基准位置到候选位置的对应关系，不能继续使用已漂移的裸索引。允许插入记录时同时定约节位置、换行／末行无换行及编码策略；无法在写入授权内安全表示就拒绝，不格式化相邻记录。通用原始配置保管能力不因此变成“必须能解析全部配置才允许保存”的全局限制。

数值准入须冻结单位、表示范围、精度、序列分量、舍入（含负数／中点）、量化顺序、越界拒绝或已声明的夹取策略，以及序列化后重新解析／正向投影的等价条件；没有经验证的夹取策略时越界一律拒绝。有限浮点数仍可能无法按原格式精确写回；不使用系统区域设置猜小数／分隔符，不以一次屏幕像素容差掩盖参数漂移。候选写回后重新解释并核对有效值与合法几何；所有关联约束在量化／编码后仍须成立，超限拒绝，不靠第二轮修正补救。

几何无净变化时必须恢复基础记录的原始表示及解释元数据，不能把同值的不同数字拼写重写为规范格式而产生历史。缺省值的零变化同样不插入显式项；已有显式项拖回基础也不删除为缺省。此规则只约束本手势的无操作判定，不改变其他原文编辑的历史语义。零尺寸、负数、控制柄越过锚点和单尺度角柄分别定约；没有可逆规则时禁用对应手势，不强制改成1、自动镜像或偷偷移动锚点。

## 4. 模块与数据流

compatibility按证据提供有限、明确的纯规则及能力；domain继续保存配置与其一般不变量，不引入UI或未知游戏几何。application定义只读布局查询、结构化编辑请求及受控草稿入口，核对来源并负责唯一项目写入。preview只消费配置投影，rendering只合成图片；desktop通过窄适配组装，application不导入预览运行时或原生句柄。不要为此引入通用脚本、插件或共享可变服务。

compatibility目前不是已实现包，application实际只依赖domain。实施前须定约application拥有的窄规则查询／求值端口和结构化结果，由宿主注入有版本的实现；求值只读、无项目可变引用，写入与最终来源检查仍在application。不能在UI里计算任意配置补丁后宣称已走统一映射，也不能未经依赖规则审阅直接增加反向导入。端口／调用封套和手势授权仍待V1冻结，本页不宣布已有API。

数据流为：配置只读截面→经验证的布局投影→控制柄与允许手势→反向求值／整组校验→application草稿→同来源预览→原子提交。几何是派生结果，持久真值仍是配置；UI不能把临时矩形当作另一份配置存储，也不能直接改磁盘skin.ini。

配置目标引用必须携带运行会话、基础头／修订、精确配置选择及布局／规则来源；草稿更新和结果还绑定草稿身份／修订。当前配置记录使用索引，不把裸索引或显示行号当永久目标ID。插入／删除、历史切换、重开或上下文变化后必须重新定位并拒绝旧引用。若实现需要新的稳定标识或格式语义，先完成显式版本／迁移设计，不能暗改现有schema。

来源还覆盖规则／解析器版本、场景实例、模式／键数等布局上下文、参与求值的默认值／外部默认素材来源及其代次。只持有当前节点ID不能识别这些变化；查询页、目标引用、求值结果和帧均绑定同一完整来源。规则升级或本机默认来源改变只失效派生投影及编辑资格，不回写旧节点、不自动物化默认项；工程内容不保存私人路径或运行控制柄。未知／过期／空集合／因分页未列全是不同结果，覆盖表未完成不能显示为“没有可编辑参数”。

屏幕／视口缩放、HiDPI、场景逻辑坐标及图片像素分别表达。鼠标增量通过手势开始时冻结的映射转为逻辑量，从原始基础重算，不能逐帧累乘造成漂移。视口／DPI、场景、模式选择或映射版本改变时取消本次手势并重新查询；首批不做隐式重定基。不可逆变换、非有限数、溢出和越界有结构化诊断。

手势固定布局参考空间及可逆变换，不从正在播放的动画位移、逐帧缩放或旧图像透明范围重新猜参考框。普通刷新及同一稳定参考空间内的动画推进不单独取消手势；时轴跳转、场景代次或布局参考空间变化则失效，不把逐帧序号当作项目修订。若目标没有稳定布局空间，须先有明确的采样／冻结策略，否则该手势暂不开放；不能为了拖拽悄悄暂停或推进游戏时间。每条映射声明影响仅为皮肤派生布局，还是还需要游戏状态／对象重建；后者在相应内核控制契约具备前保持未支持，不能直接挪动命中对象来模拟配置生效。

## 5. 草稿、历史与失败

复用[草稿契约](DRAFTS.md)：Begin固定基础；Replace从基础重建整个候选；Commit一次发布；Cancel恢复基础。一个有效拖拽／缩放只产生一个内容节点，多次更新不追加中间历史。量化后无净变化、拖回原处、失败和取消不产生内容节点，旧分支及原资源保持。既有图片变换不因新配置目标改变语义。

多个相关参数整体校验、整体发布，任何一项失败都不留下半组修改。不能通过暂时跳过校验或依赖下一条命令修复非法中间状态；如既有基础Command无法表达合法原子变化，须先定约一个窄的整组操作及版本，而非开放任意Patch。UI／未来AI使用同一结构化语义，输入、约束失败及受影响项可查询。

被拒绝的Replace保留上一次成功候选并明确显示拒绝，指针松开不得把它自动冒充最后一次手势意图提交；用户须重新产生被接受的更新或取消。预览显示实际接受／量化后的结果，而非只画一个鼠标跟随框。一次输入释放及GUI重复布局不能重复Commit；旧结果或旧释放事件不能提交新目标。

现有DraftState只记录已接受批次：失败不增修订，相同批次也不增修订，旧RequestId还可重放旧结果。因此配置手势须在application的拟议窄用例中另持有手势身份、最后输入意图序号及其接纳／拒绝／结束状态，提交核对最后意图资格，不能仅靠UI禁用按钮或DraftState相等。该用例独占其底层草稿的Replace／Commit入口；普通调用者不能绕过资格直接提交旧候选，合法Cancel与关闭授权收尾保持可达。这是待实现的协调约束，不是宣称现有edit_draft已具备此守卫。

| 时点 | 必须满足的手势与请求规则 |
| --- | --- |
| Begin | 从同来源、完整且可编辑的几何开始；固定目标／基础、指针与手势代次。旧按住状态或旧释放不能建立新手势 |
| 连续更新 | 至多一项在途更新及一个最新待处理意图；下一Replace使用上一项真实结果或重新查询得到的最新DraftState，从基础重建。已接受同批次可不增草稿修订，仍须确认当前意图身份 |
| 指针结束 | 封口最后指针位置，停止接收新移动；等待该最终意图处理完成，再至多提交一次。不能丢掉合并队列最后一次移动，亦不能仅因某个较早更新成功而提交 |
| 更新拒绝／Commit失败 | 拒绝保留可取消草稿；不得以旧成功回执重新获得提交资格。本地预校验失败也须使最后意图资格失效或取消手势，不能只在UI显示错误。已登记失败的修正请求换新RequestId；未知／迟到返回先查原手势状态，不盲目再次Commit |
| Cancel／来源失效 | 先使该手势及待处理／结束意图失效，使用该草稿最新状态完成取消；迟到Begin若曾创建草稿只清理它，不取消后来新草稿。回执／资源容量不足不能阻断合法取消 |
| 结束后重放 | 原回执只表示原执行事实，另查当前状态；不得重开草稿、提交到新目标或把旧按键／指针释放交给游戏。恢复焦点／工具后须新的按下 |

Esc、失焦、切工具、上下文失效和关闭流程依各自门控取消或结束手势。其他写入／导航在活动草稿期间维持Busy，不能偷偷覆盖基础。进入交互工具须清除并禁止配置布局选择，面板和程序化入口同样遵守；编辑输入不交给游戏。冻结时允许配置编辑与素材刷新，游戏时钟／声音／自动输入仍冻结，恢复不补发旧输入。

关闭不能被普通失焦处理先行替用户决定：已进入P3关闭门控时按同一CloseTicket处理“完成／取消当前输入”，仅该授权收尾可越过普通写入禁令；完成仍须最后意图有效，失败则保持工程打开。取消关闭不自动Undo已完成手势，也不恢复已取消的手势或旧输入。普通Esc／失焦／切工具及显式上下文变化默认取消当前未提交手势；若清理仍在途，阻止新手势占用同槽，不能只清空UI选择即宣称取消完成。

一个会话仍只有一个活动草稿；查询分页、单目标关联记录数、批次字节、候选几何和诊断大小须有上限，开工前冻结具体限额。鼠标移动合并为最新意图，不积累无界队列；不能仅因GUI逐帧布局就重复求值或复制配置／历史，实际更新的复制成本仍须准入。预算在分配前预留，取消等实际所有者释放才退还；请求／修订／历史容量耗尽明确拒绝，保留正确取消与P3最终保护所需资格，不裁剪历史。

有界列表不是部分求值许可：分页必须有完整性标识，只有全部必需依赖完成校验才允许该目标写入，不能用第一页、截断实例集合或默认值代替未读取部分。准入须计入原始配置总字节／最大单记录、读写及影响集合、记录复制／命令批次、数值和编码展开、基础＋前次候选＋新候选＋在途帧的聚合存活量。当前[配置命令](../crates/application/src/execute.rs)会复制记录集合，草稿也有候选成本，不能将少量被改字段当作全部实际成本或宣称已有增量实现；限额不相容时拒绝开放该profile，取消后按实际所有者释放退额。

## 6. 预览、保存与导出

同一可交互完整呈现的配置几何、控制柄、只读参数和场景帧须来自同一来源截面；使用逻辑几何及允许轴选择目标，不以图片是否可见或可解码推断配置是否可编辑。无可见图片但有独立已验证布局的目标可提供明确的布局表示；缺少这种表示时返回未就绪。异步保留旧完整帧不等于新配置已显示，具体规则如下。

| 呈现状态 | 显示与写入资格 |
| --- | --- |
| 当前来源Ready | 完整帧、几何和目标查询同源才可开始新手势；按键、重复布局或拾取结果不能跨来源复用 |
| 新候选Pending／Failed，旧完整帧保留 | 整包保留旧帧及其旧只读说明、标明来源和过期状态，不叠加新可写控制柄。新候选数值只能在明确标注来源／未显示状态的独立状态区展示，不冒充旧画面对应值 |
| 原手势仍有效且等待呈现 | 可以按Begin冻结的映射处理后续意图，不从旧帧重新拾取／取几何；最后意图完成几何、编码和整组校验后才具备提交资格。像素帧完成不是纯命令提交的前置，提交成功后仍须如实显示呈现Pending／Failed |
| 取消、提交、换头或上下文失效 | 旧草稿／旧页／在途帧资格失效；已提交结果重新按新已提交来源查询，不能因内容碰巧相同把旧草稿帧改贴为当前帧。旧资源按真实租约释放，迟到失败也不能覆盖新Ready状态 |

布局求值／编码失败属于输入拒绝，不能当作仅显示失败继续提交；单纯呈现失败不抹去已成功提交的历史或真实保存事实。设备／视口等变化若使手势来源失效，按第5节取消仍未提交的手势。规则、配置和场景的来源检查属于逻辑协调，不把GPU句柄或窗口回执塞进核心Command。首批不得以配置布局刷新直接改变谱面对象、模拟时间、判定统计或输入驱动；需要这些行为的映射另守第4节准入。

允许按完整版本／配方核验复用不可变合成缓存，但新呈现仍建立自己的来源与资源租约；像素相同不使旧FrameKey、旧拾取页或旧手势资格重新有效。不能为失效处理无条件清空仍被旧完整帧或在途提交持有的资源，也不要求为了新来源重复分配同一共享缓存。

手动保存按[P3闭环](P3_SAVE_LOOP_SPEC.md)先处理活动手势，再接纳并捕获完整已提交截面；草稿Busy时保留草稿，不暗存草稿前状态并报告成功。保存回执只确认捕获截面，不将保存期间的新编辑标为落盘。配置修改进入完整历史、所有分支及真实保存／关闭／重开；新运行会话不恢复旧手势、请求或预览结果。

两类NoChange不得混用：手势无净变化只表示不新增内容节点，不证明其他分支／导航已落盘；存储NoChange依据P3完整覆盖及既有文件事实，不是本次新Manual提交。A手动→配置分支B→回A仍须保存B；捕获q后继续修改成q+1，q成功仅确认q。保存失败或OutcomeUnknown不回滚已提交的配置编辑、不推进虚假保存标记，关闭保护／查询按P3继续；“不保存”关闭仍保护所有已完成修改，普通重开Manual与显式Latest保留各自激活语义。

重开须恢复所有节点中的raw记录、顺序和解释元数据，再在新运行来源下重建布局能力；旧选择、手势、短期目标与帧缓存不持久化。配置映射缺失／规则不支持与工程结构、摘要、必需资源损坏分开：前者允许按已有codec保管完整工程并显示该目标不可编辑，不能删掉不支持记录／分支或改写为当前规则；后者仍按P3整体拒绝，不降级为局部加载。保存／重开不依赖原机器的外部默认皮肤仍存在；缺失只影响相应预览能力，不能自动导入替代素材。原始状态不随规则升级重编码，必要格式演进遵循独立版本／迁移契约。

皮肤导出读取指定已提交节点的配置和图片计划，修改参数须真实出现在对应skin.ini输出中；不能只改变编辑器画面或用移动导出图片代替配置变更。保留无关／未知记录，失败不留下看似完整的输出。重读导出配置的有效值与预览接受值一致；真实客户端对照另行记录，不把Synthetic样例或F12静态截图当成全部动态规则验证。

配置和图片输出须捕获同一已提交节点／资源来源，不能一半取草稿、一半取当前头或旧缓存；导出声明其解析／映射及目标版本，活动工程继续编辑不改变该输出截面。语义未支持的内容按明确透传／拒绝规则诊断，不以“已无损写出原文”宣称兼容验证成功。外部默认素材和本机设置不自动成为导出依赖或发布资源。
