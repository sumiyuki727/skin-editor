| 值 | K1约束与失败行为 |
| --- | --- |
| 内容时间 | 有符号i64微秒，允许负预备时间；时间比较及区间端点显式，偏移计算检查溢出；不使用饱和截断掩盖错误 |
| 运行身份 | 独立、非零的128位RunId，由组装者注入，在其管理的旧输入／任务／事件及脱离借用的帧键／游标仍可能到达期间不复用；纯内核不读取随机源、不借用项目／节点ID，不维护无界历史身份注册表 |

| 合成坐标 | 本批仅用[-1024,1024]内的整数测试坐标及正整数半径，半径≤1024；差值／距离平方至少以i64计算并校验，不静默夹紧。其单位是SyntheticTest测试单位，不宣称stable像素／CS精度；非整数兼容坐标的表示与转换须另行明确 |

运行开始边界与最后完成截面分开；尚无完成截面用显式空值。构造先完整验证输入／配置／端点和容量，再发布运行候选；失败不发布部分候选。完整校验可以按下述准备预算分步执行，不意味着一次阻塞扫描或在校验前发布半成品。

### 输入批次和按住态

每批总条目数（包括重试）不超过所用配置的输入总容量，超大批次先拒绝。对有界窗口中的相同事件身份，核对完整、规范化的固定大小载荷：来源、时间、序号、逻辑动作／物理槽、边沿及按下坐标；指纹只能加速查找，不能以哈希相等代替载荷相等。窗口外旧序号按过期拒绝，不以重新执行找回旧结果。

整批先基于接纳前的窗口／序号状态校验并预留新增条目容量，再一起更新新输入队列、最高已接纳序号及窗口；混合新条目与重试时，重试不重复占队列，批内先处理的条目不能把后面的重试挤出校验窗口。任何新条目无法接纳或发现冲突时不留下部分新增、部分窗口或序号推进；拒绝原因按下述错误表表达。

批内相同身份的相同载荷只计一次新增，不同载荷使整批冲突；同一InputEpoch的新条目按入口序号核对，不能重新接纳低于或等于已关闭最高序号的未知旧条目。允许序号缺口，但不能稍后以“以前没有接纳过”为理由回填旧序号。只有新接纳条目推进窗口，重试不刷新年龄或挤走其他记录。

入口捕获／门控状态与内核已经消费到的按住态分开。一次接纳不得提前用将来的释放覆盖较早击打的消费状态，也不能因内核尚未消费已排队的释放，就把后续真实新按下误判为重复。消费按(MapTime, sequence)顺序执行，击打携带捕获时坐标。若Hit所需事件容量不足，输入作用、对象状态、账本和事件作为同次迁移保留待提交，不能先消耗逻辑上升沿再丢掉Hit。

失焦、驱动切换及恢复门控清理旧逻辑按住态，但不把物理上仍按着的键重新解释为新击打。每个槽保留有界的待释放／重新接纳状态；只有当前来源可信的释放或入口状态同步才能重新武装。旧InputEpoch的迟到释放不能替新来源完成重新武装；未知物理状态保持门控关闭，不猜测已释放。这里只规定纯控制／输入事实，不把IME或平台对象引入gameplay。

K1-2复核落实的资格边界：对当前源的新按下，先核对此槽是否已经具备接纳资格，再核对其游戏时间及整批待消费容量；未武装按下返回非故障RearmRequired，不能因此取消其他有效输入。已经具备资格的输入仍按C1拒绝封口内的新事件，可信的带时间Release也不能绕过时间校验；超大原始批次仍按原有有界要求先拒绝。由定时Release首次重新武装时，按下的捕获序号须晚于该释放，游戏时间不得早于释放，允许同刻较高序号；不能在接纳端借未来释放提前授权较早击打。该资格不依赖回执缓存是否仍保留原Release，不因重试或已经武装后的其他事实而放宽；关闭／恢复换代清理旧资格。此为合成输入资格修正，不是新增stable时序规则。

一次基本步骤至多检查一个输入／对象／事件，或提交一次已经算清的不可分割迁移；搜寻候选和扫描工作也消耗预算，不能把遍历全谱包装成“一步”。确定总顺序及继续位置须覆盖搜寻中间进度，迁移提交前仍按C2预留全部事件。Tiny的一个工作单位能够提交一次S01 Hit迁移，其两个事件槽独立于工作单位；不能把工作量1误解为只许发布一个事件。

源内容与运行池按受管分配的请求容量及可计量管理存储预留，不能用集合长度冒充所持容量；具体布局及共享计费由K1验证。分配器内部开销等不可直接计量部分单列未知，不假称这些额度覆盖全部原生堆，也不把Rust布局当持久格式。它们不代表进程工作集、原生堆或GPU预算通过，产品仍继承既有[预算](RESOURCE_BUDGET.md)。K3每玩法事件的声音子请求上限、在途供给容量和迟到阈值保持待定，不能由本表推导声学保证。

准备候选只在全部验证／初始化完成且来源仍有效后原子激活。分配前预留预算，不将全量初始化、排序或复制藏在一次“准备一步”中；必要的处理须可分段或对超出已支持输入的情况明确拒绝。取消使候选失效，不等待整个数组处理完才接纳取消；保留当前运行，候选持有的分配／共享租约等实际释放后归还。K1采用调用者驱动的纯分步操作，不因此新增线程或通用任务引擎。

准备继续值与运行推进继续值是不同种类；候选核对基准来源、操作类别、目标和请求代次，运行推进核对自己的运行／传输／输入及请求代次。二者的完成进度不得互用；相同数字的旧请求不因此有效。最新候选可以与被取消但尚未实际释放的旧分配短暂并存，但只有一个有效候选位，所有在途分配仍受同一预算约束。

## 推进请求与取消

### 初始与检查截面

从头运行显式给出开始边界S，S不得晚于首个对象的最早可见边界；空对象集合不以整数哨兵求最小值。推进不得请求S之前的目标。S处的输入在首封口之前可以接纳；完成截面初始仍为空，第一次SealThrough(S)及有界评估完成后才形成包含S的完整截面。没有完成初始评估时不得返回Ready帧／ReadyFrozen或伪造“已经推进至S”。合法负S与正S使用同一规则。

检查定位采用独立候选和新TransportEpoch，起点为目标Q。初始评估直接求Q处的检查状态，不从旧运行重放输入或为过去对象补Miss／声音；已过接受区间的对象退出可判定集合，结果标为检查跳过／Unavailable，不写成Hit或Miss。若保留其检查用视觉投影，必须带Inspection来源，不能冒充自然判定后的表现。Q处仍在接受区间内的对象保持未判定，未来对象保持未来状态。

检查候选完成后才共同发布Q处的ReadyFrozen、关闭的Q截面及Inspection统计来源；新账本只记后续真实处理的合成事件，旧账本不填充成当前累计成绩。仅检查时计数为空不等于从头成绩为0或ACC为100%。恢复只接纳Q之后的新输入，自动驱动也不补发目标≤Q的旧击打；Q之后仍在窗口内的新按下可正常命中。这只规定SyntheticTest检查行为，不选定产品HUD默认方案。

### 正常继续与冻结

请求目标不早于已经提交的工作位置；同刻中途Pending时，即使最后完整截面仍较早，也不能用新目标退回已提交迁移之前。相同来源／目标／继续位置的继续不会重做前缀；旧游标、不同运行或过期请求代次拒绝。

取消推进使该请求的外部继续令牌过期，保留已提交的运行前缀及内部下一工作位置。随后新请求可以从该位置继续至不倒退的目标，不得因外部令牌更新而重放事件。取消未激活的定位候选则丢弃候选，不覆盖当前运行。关闭／失效入口可在输入、事件及普通控制容量耗尽时执行，不能分配失败后锁死取消。

冻结若遇同刻部分迁移已提交，先进入Freezing、关闭新输入，不把此前完整截面当成已经回滚的位置。对选定边界的既有有效工作有界收尾后才发布Frozen；无法收尾则保持明确Pending／失败，不假报成功。冻结后的恢复不重放旧输入／声音；K3音频回执及冻结锚点仍须独立接线验证。

冻结边界F不得早于最后已提交的工作位置，且必须受有效封口保护。关闭新入口与撤销已接纳前缀的内部消费资格是不同操作：正常冻结保留MapTime≤F前缀的结算资格，不能因更新普通入口InputEpoch将它们一并判为过期；内部结算不会重新开放旧来源的新请求。F之后尚未消费的旧输入明确作废，恢复不补发；诊断及统计区间不得把这些取消项当成已测试的未来区段。

结算资格来自内核持有的已接纳记录，不由外部请求中的布尔标记或调用者自称授予；不能为了兼容旧队列而允许程序化入口伪造“已接纳”绕过来源／封口校验。

K1-2实际控制为request_freeze／settle_freeze／resume：前者允许先关闭再等待有效封口，只声明Freezing；后者仍须核对封口才能做结算和发布Frozen。InputEpoch在成功恢复时检查递增，不在关闭时强行分配；四槽按未知状态门控。独立ReleaseObservation没有MapTime，只提供当前来源释放事实，与游戏输入共用序号及完整种类／载荷回执；它不向已封口的游戏前缀倒插释放，不修改消费按住态。普通带时间Release仍按C1与原子批次规则处理。具体签名、错误与声音意图取消水位见[K1-2审阅](K1_2_FREEZE_REVIEW.md)，不是原生时钟／捕获／设备契约已接通。

### 错误与观察结果

以下是结构化结果分类，不是已有枚举。先核对完整来源，再处理已知重试／过期序号，之后才对新输入核对载荷、门控、时间和容量；不能让旧请求触发新运行的LateInput或清空新按住态。

| 情况 | 必须结果与当前运行处理 |
| --- | --- |
| 旧运行／旧代次／旧候选／过期推进继续值，以及旧作用域确认 | 拒绝旧请求；不改新运行的账本、游标、额度或有效性 |
| 当前源窗口内原样重试／已退休确认重放 | 返回已接纳／已退休的观察事实，无第二次执行或资源退还；窗口外旧序号只过期拒绝 |
| 当前源未发行或越出可确认范围的确认 | 明确拒绝，不跳过缺口、不提前退额度，也不使有效运行失效；与同源已退休确认重放区别处理 |
| 正常门控关闭时的新按下 | 拒绝接纳，不伪造击打；可信的当前源释放观察可仅用于重新武装，不回放成旧游戏输入 |
| 越过封口的推进、倒退目标、零工作量等调用参数错误 | 拒绝本次调用且不提交前缀，不把它当作已经完成或可倒插的输入；原有效继续状态仍可取消 |
| 构造／准备候选损坏、超限或算术溢出 | 不激活候选，不覆盖当前运行；释放候选自身持有的资源，不虚构完成结果 |
| 当前源新输入发生载荷冲突、结构错误、LateInput或输入容量不足 | 整批无新增接纳；关闭入口并进入有界故障清理，统计标为不完整，既有已提交前缀不回滚。尚未提交输入须明确取消，不默默当作已消费；不得恢复后冒充准确的连续测试 |
| 工作预算耗尽／临时事件背压 | Pending带原因及准确继续位置；不是输入丢失，不因此改写既有判定或把统计标成完整目标 |
| 推进中出现不可恢复的计算／协议故障 | 保留此前已提交前缀，无半次迁移；Failed／清理中投影明确无效，不冒充完整Frozen截面。之后只能按显式新运行／检查重建恢复有效测试来源 |

Ready帧／完整统计只声明已完成截面；若查询已提交但尚未完成同刻工作的账本前缀，必须同时带Pending／Failed、工作位置及有效区间，不能与较早Ready帧拼成新的完整T结果。不要求为此复制整份运行器或保存无界快照。

## S01–S04 操作与预期

本页所有用例都是规格，后续实现按以下定义编写fixture；本轮不执行KT。S01常量及Hit／Miss语义以[主方案](STABLE_KERNEL_PLAN.md#k0-准入要求)为准；下面仅展开操作、配置及观察，不另定义stable规则。

每个独立用例使用全新RunId，TransportEpoch=1、InputEpoch=1、规则版本1、固定合成修订令牌，输入槽初始释放。除专门驱动／物理聚合用例外，默认手动来源、逻辑动作A的第一个槽、中心坐标；两路动作分别使用A／B的第一个槽。E1／E2等表示该运行／传输代次的事件序号，不是全局整数身份。每次击打均按所声明的物理顺序产生有效新按下，释放也有独立输入序号。

除故意测试未收齐／迟到的步骤外，每个要求Complete的目标都先交接其范围内的有效输入，再在同一来源上封口至该目标；后续表中的“推进至”沿用此约定。测试辅助函数不得在输入尚未交接时自动宣称封口，也不能通过直接改运行时钟绕过C1。

### S01 正例和生命周期

单圆圈ObjectId=0，运行开始边界为799999µs，完成截面初始为空。使用Reference-v1或Tiny-v1，先封口并推进到799999；后续若预算不足，按同一来源继续，直到Complete，读取事件不自动确认或发声。

| 步骤／独立运行 | 操作 | 必须观察 |
| --- | --- | --- |
| 初始与出现 | 推进至799999，再至800000，无击打 | 前者Future、后者VisibleUnjudged，账本／事件均空；读取不推进时间 |
| 尚未评估起点 | 构造S01后不推进，读取完成状态／投影；再以小预算评估S | 完成截面为空、无Ready；完成S评估后才声明799999，不假设构造即已推进 |
| Hit运行 | 先接纳1000000时刻中心按下，再SealThrough(1000000)并推进至该时刻 | 账本仅[0:Hit]；E1=Judgement(0,Hit)，E2=SoundIntent(0)，顺序固定，二者属于同次迁移 |
| Hit后观察 | 重复推进至同一时刻、反复读取；再推进至1299999、1300000 | 不新增判定／事件；1299999仍为ResolvedVisual，1300000退休，账本保持[0:Hit] |
| Miss运行 | 不接纳输入，先推进至1100000，再至1100001 | 前者尚未判定；后者账本仅[0:Miss]，仅E1=Judgement(0,Miss)，无SoundIntent |
| Miss后观察 | 推进至1300000，再至更晚有效目标 | 已退休，账本及事件身份保持，无第二次Miss |
| 统计来源 | 读取上述两个运行的统计 | 只能报告对应合成判定及运行来源，不生成stable score／ACC／combo或客户端验证标记 |

### S02 拒绝与精确边界

边界用例各自重开S01运行；所有需要完成的目标都先封口。窗口外／错位置按下不产生判定，随后无其他有效击打推进到1100001时才得到一次Miss。以下预期不使用浮点容差，也不依赖显示帧率。

| 用例 | 输入／配置 | 必须观察 |
| --- | --- | --- |
| 时间下界 | 分别在899999、900000中心按下 | 前者本次无判定，最终Miss；后者Hit |
| 时间上界 | 分别在1100000、1100001中心按下 | 前者Hit；后者不命中并产生一次Miss，不出现Hit与Miss双结果 |
| 空间边界 | 1000000时刻分别在(9,0)、(10,0)、(11,0)按下 | 前两者Hit，后者本次无判定、最终Miss；负方向对应边界也单独验证 |
| 区间／溢出 | 下界大于上界；将对象目标置于i64端点附近使所需偏移溢出；坐标／半径超出声明值域 | 构造明确拒绝，无部分候选；不得夹紧、回绕或把负预备时间一概拒绝 |
| 身份与规则 | 重复ObjectId、零运行身份／代次／规则版本或缺少SyntheticTest标识 | 构造拒绝；两个不同ObjectId同点同刻的身份仍分别保留，不按坐标去重。其执行顺序须有单独合成profile，不能宣称兼容布局已开放 |
| 无进展配置 | 事件总容量1，或零工作量，或容量／内存不足以容纳一个最大迁移 | 构造／调用前明确拒绝，不永久Pending；S01 Hit需要的最小事件容量为2 |
| 倒退目标 | 完成到1000000后请求999999 | 拒绝，不改既有账本／事件／完成前缀；更早位置只能走独立检查定位候选 |
| 输入批次 | Tiny中提交五个新输入；或一批内有无法接纳的无效条目 | 整批拒绝，无部分新增输入；运行按明确错误／门控结果处理，不冒充准确测试继续 |
| 物理槽聚合 | 同一逻辑动作的两个物理槽依次按下，释放第一个，再释放第二个 | 第一次按下产生一个逻辑上升沿；第二槽按下不多击打；中间仍按住，最后才释放。单槽重复按下也无第二上升沿 |
| 起点与负时间 | 首次封口前请求S-1；另以合法负S构造／评估合成对象 | S-1请求拒绝且完成截面仍空；合法负S可完成，不因符号拒绝或使用S-1整数哨兵 |
| 混合批次原子拒绝 | Tiny先接纳一条合法输入且保留窗口；再提交含其原样重试、一条合法新输入及一条载荷冲突的批次 | 全批无新增入队／窗口／最高序号提交，旧条目仍仅一次；按故障表诊断，不把哈希相等当相同载荷 |
| 批内重复与缺口 | 独立运行首次在同批重复同一新事件；另测相同身份不同载荷；再在已接纳序号3后提交从未接纳的序号2 | 第一种只新增一次，第二种全批冲突无新增；第三种过期拒绝，不回填旧序号，不借重试刷新窗口年龄 |
| 候选分步取消 | Tiny按准备工作量1进行多对象校验／初始化，在完成前取消；另使最后一条对象无效 | 取消不必等剩余数组，旧候选不激活；后者拒绝完整候选，当前运行保留，实际持有分配释放后才退额度 |

### S03 输入封口和控制交错

T固定为1000000µs，使用Tiny-v1，按下默认在中心且为有效新按下。除明确的不同控制顺序外，同一接纳集合必须跨分段得到同一账本及事件序列。

| 用例 | 交接／控制顺序 | 必须观察 |
| --- | --- | --- |
| 同刻分批 | 两路动作分别在T按下，序号1／2；均先接纳，再SealThrough(T)，一次推进或按工作量1反复继续 | 只判定一次Hit，E1／E2与S01一致；第二个已接纳输入可以晚消费，不能误报LateInput |
| 已封口新输入 | 已完成S01 Hit至T，再交接另一路动作新的T时刻按下；另测T-1 | 均LateInput，旧账本／事件不变；严格运行冻结、统计不完整；不与原物理槽的重复按下混同 |
| 尚未封口前缀 | 封口仅到T，输入在T+1，先请求推进至T+1，再封口T+1 | 首次不得越过T，给出未收齐原因且不改前缀；有效封口后该独立运行得到一次Hit及E1／E2，不与等于T的迟到情况混同 |
| 捕获／入队交错 | 受控入口先捕获T输入、暂不交接，另一操作尝试封口T | 不能成功宣布收齐；待交接按同一入口顺序完成后才封口。无需依赖真实线程时间或sleep |
| 重试与冲突 | 完成Hit后原样重试序号1；再用同身份但不同坐标／动作载荷重试 | 原样重试不重复执行，也不因时间≤T误报新迟到；窗口内冲突明确诊断，旧账本／事件不变 |
| 窗口外重试 | 新运行，在900001至900005交替按下／释放，按下位置(11,0)，序号1至5；逐次封口推进后重放序号1 | Tiny窗口仅4条，旧序号过期拒绝，不重放也不无限保留；此时尚无判定／事件 |
| 输入先于冻结 | T按下先接纳，随后同刻冻结关闭入口、封口并完成T的有效前缀 | Frozen前完成一次Hit；不得丢失此前输入。SoundIntent只形成合成事件，冻结阻止后续旧声音交接 |
| 冻结先于输入 | 同刻冻结先关闭入口，之后尝试交接T按下 | 新按下被门控拒绝，不纳入接纳集合；Frozen时账本为空。恢复不补发此按下；两种真实控制顺序允许不同结果 |
| 来源与恢复 | 旧RunId／旧InputEpoch输入到达新运行；暂停后换代恢复再重放旧输入 | 拒绝旧作用域且不改新运行；InputEpoch变化不重开已关闭前缀，也不制造新的按下边沿 |
| 重新武装 | 按住A后关闭门控并换InputEpoch，保持物理按住而尝试新按下；随后投递旧代次释放，再投递当前来源可信释放，最后再次按下 | 前两次不能制造击打或清除新来源隔离；可信释放重新武装后才接受新上升沿。用故障／失焦／驱动切换分别覆盖，不依赖GUI正好刷新 |
| 自动／手动互斥 | 三个独立运行各只启用手动、自动、回归之一；有效驱动先交接T中心按下，再封口并推进；同时尝试其他驱动来源 | 各有效轨迹均为一次Hit及E1／E2，其他来源被门控拒绝；合成自动输入不绕过C1在封口后倒插。冻结停止生成，恢复不补发旧T输入，也不修改No Mod／Auto Mod状态 |

### S04 小预算和事件确认

本节单对象用例T=1000000µs，冻结边界F=T，多事件迁移沿用S01的Hit两事件。为制造临时背压，另定义合成双圆圈：原始ObjectId=0目标0，ObjectId=1目标1000000，中心均(0,0)，开始边界-200001；S01可见／接受端点相对各自目标平移，偏移计算检查溢出。两者接受窗口互不重叠，执行只针对唯一时间合格对象；不是stable堆叠／notelock规则。

| 用例 | 操作 | 必须观察 |
| --- | --- | --- |
| 差一个空槽 | 双圆圈Tiny运行不击打对象0，推进至100001，保留其E1=Judgement(0,Miss)未确认；再接纳对象1在1000000的中心按下，封口并推进 | 只有1个空槽，Hit需要2个；Pending明确背压，不生成半份Hit／SoundIntent，账本仍仅[0:Miss]，不能发布已完成1000000的Ready投影 |
| 排空后继续 | 明确确认E1，使用有效来源和继续位置完成同一目标 | 账本[0:Miss,1:Hit]；新E2=Judgement(1,Hit)、E3=SoundIntent(1)同时出现；不能因提前处理按住态而丢掉此次击打 |
| 不同预算 | 同一双圆圈输入／控制顺序，分别以Reference大预算及Tiny工作量1执行；按声明策略确认事件避免永久背压 | 最终账本与累计发行事件键／载荷序列相同；允许Pending次数不同，不伪造已经完成的目标 |
| 读取和乱序确认 | 反复读取E2／E3，先确认E3再确认E2 | 读取无副作用；E3先到时连续退休前缀仍为E1，不能提前释放缺口前记录；E2到后才退休至E3 |
| 重复／无效确认 | 重复确认已退休E1／E2／E3；确认尚未发行的E4或旧运行／传输代次的同数字序号 | 不重复释放额度、不推进新来源的游标、不产生声音；未来键及旧来源明确拒绝，不跳过缺口 |
| 同刻取消继续 | 独立S01 Tiny运行，先接纳T时刻两路按下并封口；工作量1继续到首次Hit已提交而第二输入未消费，取消本次推进，再分别持旧令牌和新请求继续至T | 旧令牌拒绝，既有Hit及E1／E2不回滚；新请求只处理剩余工作，最终一次Hit及原E1／E2。目标不得退回最后已提交工作之前 |
| 满容量停止 | 独立S01 Tiny运行，T时刻依次交接A按下／释放、B按下／释放共4条并封口；小预算到首次Hit发行E1／E2但剩余3条未消费时，再交接T+1时刻A按下填满输入，随后请求冻结T，对事件给出明确消费／取消结果 | 两队列均满仍能关闭入口并进入明确Freezing／Pending；有界完成T的前缀后才Frozen，未纳入该截面的旧T+1输入明确作废、恢复不补发。清理不需普通槽，不假报回滚或释放尚持有资源 |
| 旧定位候选 | 当前运行已判定后，请求Q_A=900000的检查候选，未完成即取消；新请求Q_B=1000000。旧A及继续值在B完成前／后分别返回 | 即使两候选面向相同下一个TransportEpoch，也按请求代次拒绝A；仅B完成后激活。B不复制旧判定，取消不写项目／历史，预算等实际释放后归还 |
| 检查窗口内／后 | 独立S01来源分别检查至Q=1000000和Q=1100001，完成后保持冻结 | Q处截面关闭，账本／事件为空且来源Inspection；前者对象未判定，后者判定Unavailable／检查跳过，不生成Miss或SoundIntent |
| 检查负值与端点 | 独立S01来源分别检查至Q=-1、i64最小值、1100000和1300000 | 均先完成候选评估才ReadyFrozen；负Q对象Future且无Q-1哨兵溢出，窗末仍未判定，退休边界不可判；账本／事件均空且来源Inspection |
| 检查后恢复 | Q=1000000检查完成后，不补发Q输入；在新来源重新武装后交接Q+1中心按下，再封口推进 | 只在1000001产生新Hit及该传输代次E1／E2；无Q时刻补播，旧代次同数字确认不影响新事件 |

### KT23 固定规模负载

Reference-v1的规模用例明确为10000个自制圆圈：原始ObjectId=i，i从0至9999，目标时间为i×1000000µs，中心(0,0)，沿用S01相对可见／接受偏移及半径；从头起点-200001，初始输入全部释放，无输入基线运行不交接击打。所有端点以检查算术生成，各对象接受窗口互不重叠。这里给出生成式定义，不创建谱面或fixture文件。

准备阶段按256或1的独立工作量继续，完成之前不发布半份运行。随后封口并推进至9999300000µs（最后对象退休边界），在预算耗尽时继续，在事件背压时由受控消费者读取并明确确认，直到Complete。预期账本恰有10000次Miss，每对象一次；仅发行10000个Judgement(Miss)，事件序号1至10000，目标事件时刻为i×1000000+100001，无SoundIntent，末态全部退休。事件队列及确认窗口在任何时刻不超过64，不为整曲事件新建无界临时列表。

另开全新运行，复用同一不可变合成谱面，执行有限批次自动输入轨迹：对象i在其目标时间由逻辑A第一个槽按下、1µs后释放，输入序号分别为2i+1／2i+2。每批至多32个对象、64条输入，按C1先交接再封口至该批最后释放时刻；推进至该目标，明确消费／确认该批事件后才送下一批，最后再推进至9999300000。预期恰有10000次Hit，发行20000个事件：E(2i+1)=Judgement(i,Hit)、E(2i+2)=SoundIntent(i)，二者时刻均为i×1000000；无Miss且末态全部退休。SoundIntent仅交给受控合成消费者，不触发真实音频。

这两条轨迹分开记录，均使用Reference容量，分别以推进工作量256和1比较同轨迹最终结果；不能给Tiny-v1越过4对象上限，也不能比较有输入／无输入轨迹要求它们同分。两条都不一次展开全部输入或事件；队列上限64、确认窗口及受管分配保持，旧请求／取消和输入槽重新武装另按S02–S04验证。

另在校验／推进／检查重建中途取消并投递旧完成／继续值；分别观察当前已提交前缀或当前活动运行保持、取消候选不激活，以及资源实际释放。准备与推进均记录工作量、检查／复制对象数量、受管分配及取消完成成本；空闲时取帧不应重复扫描／复制这10000条。真实耗时由外部有界测量入口记录时基和扰动，不能让纯内核读取系统时钟，也不能凭工作计数或此轻量负载宣布产品CPU／内存预算通过。
