# 皮肤音频编辑与实时预览：采纳方案

2026-10-27资源准入补充：按用户批准的[预算v2](RESOURCE_BUDGET.md)，正常标准组合与32 Voice压力分别记录，15%单核CPU保留为优化目标、不再单独阻塞后续开发；SA10容量、零欠载、提交p95≤20 ms及原内存／资源清理门槛不变。默认发布与诊断构建分别留证，SA17文件行为可按[P3并行边界](P2_STAGE_GATE.md)先行实现，不代表SA清单或P2整体已完成。

2026-10-22，方案v2不变。用户已确认图片／音效独立、未编辑音频无损保留、子图层隐藏只移除子树、整个元素隐藏输出有效占位，以及一音效一素材且可复用。A1／A2已有[真实WAV与原生输出](P2_AUDIO_NATIVE.md)、[独立供给／有限背景](P2_AUDIO_SUPPLY.md)、[音频素材库／组件试听UI](P2_AUDIO_UI.md)及[原始素材独立试听／监听总音量](P2_AUDIO_LIBRARY.md)。人工UI、实际歌曲流、设备消费锚点／延迟、组合预算及文件输出仍待对应阶段验收。

## 已采纳的方向

保留 Rust、egui／eframe、wgpu 和模块化单体。application 独占项目写入，UI／AI 共用命令、草稿和历史。图片与声音共用 AssetLibrary 及原始 Blob 租约，各自拥有编辑对象和派生缓存；未来 UI 分开编辑，不建立图片—声音关联表。

当前模型已含 Audio／Opaque、独立 AudioComponent 和类型化图片／声音输出源；桌面实际导入仍只有 PNG，没有正式音频后端。P0 的[流式输出](p0/STREAM_OUTPUT.md)、[压缩取消](p0/MP3_CANCELLATION.md)和[设备变化](p0/AUDIO_ADAPTATION.md)仅是局部证据，不成为产品依赖，不替代音效热更新验收。

## 首个音频增量的范围

P2 先交付显式导入短音频、共享素材与独立音效组件、替换引用、线性增益／可见性、独立试听、草稿／历史与自有触发场景。最低可播放矩阵为自制 WAV PCM16、单／双声道、44.1／48 kHz；实际设备转换须验证，矩阵内仅返回“不匹配”不能算通过。格式与循环／长流能力单独查询，不把扩展名当作编码证明。

首轮增益为0–1，默认1，不覆盖原文件。监听总音量属于本机偏好，场景事件音量属于运行时；只有组件配方影响导出。波形后续可派生，裁切、淡变、音高及多轨编排暂不实现，不提前引入空效果框架。

不支持解码的音频允许明确以原样保留能力导入／恢复，不冒充可试听。超限长音频、未接入编码、循环切换返回明确能力诊断；不静默截断或擅自登记为可播放。皮肤音效属于项目；用户测试谱面的音乐／自带音效是外部预览来源，不自动导入或导出。P2 用途键／事件是自有fixture，stable用途、来源优先级和触发仍须当前客户端证据。

## 数据模型与不变量

```mermaid
flowchart LR
  Library[AssetLibrary: 不可变 Asset] --> Sound[独立 AudioComponent: 用途键 + AssetId + 增益 + 可见性]
  Library --> Image[ElementDocument: 嵌套 LayerTree]
  Sound --> Plan[共享 SoundPlan]
  Plan --> Preview[后续试听 / 场景声音]
  Plan --> Export[固定节点的输出计划]
```

| 对象 | 内容与约束 |
| --- | --- |
| 音频 Asset | AssetId／BlobRef；已核验的采样率、声道、帧数为 AudioMetadata。无法探测／解码的原始文件保持 Opaque，不猜测时长或丢失未知字节。编码能力仍由适配器探测 |
| AudioComponent | 独立 AudioComponentId，一个用途键、一个 Audio／Opaque Asset、增益和可见性；多个组件可复用同一素材，各自独立编辑 |
| SoundSlotKey | 有界字符串、项目内唯一，不是文件路径，不从文件名推断。stable用途映射属于 compatibility |
| 视觉组件 | ComponentTree只组织图片文档，无音频成员或关系表；声音不贡献包围框、不继承图片变换／透明度／可见性 |
| SoundPlan | 从固定只读项目生成，含源摘要、元数据、组件配方和处理语义版本；预览准备与导出共用单音处理，监听总音量不进入文件 |
| OutputMapping | Image(DocumentId)／Audio(AudioComponentId)，共用OutputId／OutputPath与全局大小写／文件目录冲突检查 |
| Voice | 临时实例、捕获的声音版本、起始混音帧、播放位置与PCM租约；不进入项目或历史 |

- 所有登记／删除、替换、增益／可见性和输出映射均通过 Command；图片与声音可组成一个原子事务，但不持久关联。载荷不携带文件句柄、回调或设备对象。
- Asset／Blob不可原地覆盖；PCM、波形和设备对象不进入项目或历史。历史仍可达的原始字节保持租约，PCM按活动／候选／发声／导出任务固定并可重建驱逐。
- typed Audio登记必须通过 ResourceStore 的只读已验证元数据索引核对，不只相信UI／AI。即使同Blob已按Opaque固定，新typed别名仍需核验；缺失或不匹配拒绝发布。pin／命令执行不读文件或解码。
- 仍被音效引用的Asset、仍被输出引用的音效组件默认拒绝删除；可以显式解除引用后在同一事务删除。删除视觉组件不影响声音。
- 连续增益使用既有可取消草稿，松开一次提交；取消／失败／无效操作不留下修改或节点。试听／场景触发／设备控制不进入项目历史。
- 图片整体变换不改变声音，声音增益不改变图片。未来批量调音量须是明确音频操作，不能借图片组透明度。

### 隐藏与无损输出

隐藏子图层／文档内图层组只移除该子树贡献，其他层照常合成；隐藏整个 ElementDocument 保留画布和输出映射，生成有效透明图片。隐藏音效组件保留映射并要求有效静音音频。空可见图层树也正常合成透明画布。跨元素视觉组未来的隐藏操作逐成员作用于图片，不涉及声音。

缺失、隐藏和不支持处理是三种状态。不能删除文件或写零字节文件来代表隐藏；隐藏占位的编码、合法扩展名、时长和stable解析范围需有证据的导出策略。本轮只有EncodeSilence计划，没有编码器或磁盘导出，不将计划测试当作stable已接纳静音文件。

未经编辑的可见音频（增益1）按原始Blob逐字节透传，即使无法解码，也保留容器、编码和未知字节。隐藏再恢复至默认配方仍可透传。修改增益的已知音频使用共享PCM配方；不支持的编辑必须诊断并阻止该次完整导出，不能跳过文件、忽略编辑或擅自换格式。P3补文件往返、复制／编码失败保留原文件、固定节点导出和哈希对照。

现有application的ResourceStore／BlobLease端口足以表达跨媒体原始字节生命周期。A1资源增量已将Images中的原始PNG移入通用BlobStore，音频／Opaque可以复用同一原字节与128 MiB额度；RGBA、PCM与原始租约分开。PCM已实现共享32 MiB预算、分配前预留、弱缓存复用及一个活动／四个排队工作单元；控制器实际会话测试覆盖取消及迟到释放。真实音频导入UI／codec、worker执行、原生输出及RGBA独立LRU仍未实现，不能把配额测试当作整机预算实测，详见[资源记录](P2_AUDIO_RESOURCES.md)。

## 模块责任与实际依赖调整

| 模块 | 新增职责／边界 |
| --- | --- |
| domain | 音频 Asset 元数据、独立 AudioComponent、用途键、引用与数值不变量；不解码、不访问设备 |
| application | 新 Command／补丁／资源固定／草稿／查询；定义窄音频导入与预览控制端口，选定已提交或草稿来源；不在命令执行中播放声音 |
| audio（新增逻辑模块） | 纯 SoundPlan、增益等已支持 DSP、固定声音实例表和混音；可对已解码 PCM 无设备执行，使用同一处理语义生成导出样本；不读文件、不 import UI／application |
| preview | 场景事件调度、模拟／歌曲位置和冻结门控，向音频运行时提供带时间代次的触发；不定义 stable 文件查找规则 |
| compatibility | 经过当前客户端验证的声音槽、名称／格式、来源优先级、回退及事件映射；未知规则保留诊断 |
| infrastructure | 通用原始字节存储，图片／音频独立缓存、探测／解码／必要转换、后台任务、输出设备与保存／编码；平台回调不反向进入项目会话 |
| ui／automation | 仅 application 查询与控制；显示有效版本／pending／错误和试听状态，不直接调用设备或修改模型 |
| host | 组装一个音频设备运行时，连接预览与编辑器试听，协调生命周期；不持有另一套项目模型 |

建议代码依赖：`audio → domain`；需要声音能力时 `preview → audio`；`infrastructure → application / audio`；host 组装这些实现。UI 仍只依赖 application，application 仍只依赖 domain；rendering 不因音频而依赖设备或 audio。audio 先是 `desktop/` 中一个小库，根纯核心工作区不扩成含编解码／平台依赖的工程。

真正引入时，同步扩展两个检查器的显式包集合／依赖规则与负向测试；不得为通过检查而允许 UI→audio、application→设备或引用 P0。正式编解码与平台后端依赖在 A2 前单独评估，不在本轮选择或引入新包；已有100 ms轮询的 P0 输出不自动满足短音效延迟目标。

## 实时更新、试听与暂停

### 版本与激活

声音内容来源包含历史会话／节点／活动修订、可选草稿 token、AudioComponentId、源内容／配方版本。异步请求另外持有 BuildId；场景、Transport、设备和试听会话使用各自有界代次，不把它们拼成越来越长的历史地址。

缓存键使用源摘要、配方、处理语义版本及实际混音格式／转换策略；不只使用文件名，也不因无关图片编辑就重解码相同声音。复用结果时仍须签发与当前来源一致的就绪描述。设备重建代次不代表内容改变；相同格式的已验证 PCM 可复用，旧控制／事件不得复用。

1. 项目／草稿修改先按 Command 规则成功发布，再产生只读音频候选。准备失败不会回滚有效项目，项目历史与播放失败分别诊断。
2. 候选就绪后再次核对完整来源，以明确的 `effective_from_mix_frame` 激活用途绑定；准备过程不重置歌曲、对象、动画或分数，也不自动发声。
3. pending／失败期间可以保留上次可用声音，但状态、实际触发回执和 UI 必须标出旧来源；没有旧资源则返回 NotReady，不偷偷用别的音效。等待期间不积压事件，候选就绪不补播。
4. 已开始的一次性 Voice 捕获不可变版本，可按原版本播完；激活边界后的新触发用新版。尚未开始的旧排队事件按代次失效或重新解析；已经提交到设备的样本不能假装撤回。
5. 取消草稿清除该草稿候选、排队事件及正在试听／发声的草稿实例，恢复基础版本；普通提交可让已开始的旧实例播完，但不能把旧实例来源改写成新节点。历史检出默认停止旧皮肤声音与旧试听，恢复目标节点声音，外部歌曲位置保持。
6. 长流／循环切换不沿用“旧 Voice 播完”的策略。P2 能力返回未支持；在对应场景实现时定义切换位置、循环相位及淡变策略，再补测后开放。

### 游戏声音与素材库试听

同一个输出设备／混音器中设置两个固定用途通道：场景通道和编辑器试听通道，不建立通用音频路由图或第二套播放器。

- 场景通道的音乐／音效由 Simulation／Transport 控制；冻结关闭事件、作废旧排队声音并确认停止锚点。恢复不补播被跳过的声音，定位也清除旧 Voice／事件。
- 素材库试听只有用户或获授权 AI 的显式请求才开始，使用独立试听位置；游戏冻结时仍能试听，但不能推进歌曲／游戏时钟。编辑器试听总音量独立，不能烘焙到导出。
- 修改资源只准备新版本；用户需要重新试听时显式触发。P2 不默认自动循环或在解码完成时播放，避免连续增益草稿重启成大量声音。
- Scene 冻结不能不加区分地 Reset 整个共享设备而截断独立试听。进入 Freezing 时立即拒绝游戏输入／新声音，确认场景静音及位置锚点后才报告 Frozen；预提交残余样本、确认耗时和位置误差单列，不能把软件标志当作立即声学静音。
- 音效内容更新不改变外部歌曲；全局冻结／seek／输出故障才使用相应 Transport 协调。设备故障可使两通道都不可用，重建后保持未播放，等待显式继续或试听，拒绝旧代次控制。

监听边界建议：单个音效配方先采用线性增益；多 Voice 在明确顺序下浮点相加，设备输出边界饱和并统计削波，不按声音数量自动归一化。正式导出使用相同单音配方；实时混音饱和与监听总音量不属于单个文件的处理。格式转换与量化策略应有版本和容差。

| SA16 | 音频＋标准图形同版本长时、暂停稳定空闲和20轮打开／关闭满足预算；无非注入欠载、错版本或无说明丢音，池／任务最终归还 | A3；普通测量与诊断回读分轮 |
| SA17 | 保存／重开含独立音效组件与配方；固定节点导出不中途换版本，导出样本与同配方预览一致，监听总音量不进入文件；图像与声音输出间也拒绝大小写及文件／目录冲突 | P3；缺失、迁移、全局输出冲突及失败后原文件可用 |
| SA18 | 每批真实打击／GUI／结算／循环声音的文件解析、来源优先级、触发和回退均有当前stable证据，发布不含未授权原版声音 | P4/P5；文件／配置身份、受控步骤与用户听感分别记录 |
| SA19 | 不支持解码的未编辑音频逐字节保留；处理失败不能静默遗漏或忽略编辑 | A1输出计划＋P3文件往返／导出失败注入 |
| SA20 | 子图层隐藏只移除该子树贡献；整个图片／音效隐藏仍输出有效透明／静音文件，与缺失区分 | A1像素／计划＋P3真实占位编码＋当前stable对照 |

SA18 的 F12 只能证明画面／测试场景，不能证明声音。自有 PCM 对照可以证明样本与调度，原生提交／设备时钟可以证明相应管线阶段；听感与声学延迟需单列，不相互替代。首轮只用自制低幅度信号，不读取个人曲库或录制系统声音。

SA05的背景使用独立于SkinProject的自制连续参考流，实际核对原生消费锚点与模拟位置。它用于证明编辑皮肤声音不会重启背景播放，不因此声明已经支持真实谱面音乐、皮肤长声或循环素材。

## 接口、迁移与审查重点

2026-10-22增量采用AudioEditorPort2／SoundPlan2，为素材独立试听加入明确Library目标和只读来源值，不改变本方案v2的产品范围。项目投影仍只接受Component；素材不创建临时组件，任务／PCM／Voice使用同一额度。模型2／Command5不变，尚无磁盘格式。详见[增量决策](P2_AUDIO_LIBRARY.md)。

本轮已升级 MODEL_VERSION 1→2、application API 4→5，明确新增集合／Command／历史补丁及类型。现有FrameDescriptor v1与短历史地址不改成音频协议；新增的音频预览值契约单独以v1开始，区分项目写请求与Prepare／Audition／Stop／Status等只读派生控制。FrameDescriptor v1与历史短地址未变。

已有项目没有冻结的磁盘schema。本轮的显式内存v1升级保留Opaque、未知配置、图片输出ID／路径和可见文档，音效集合为空；未知版本和伪装成v1的新内容拒绝，已补回归。P3另冻结磁盘格式，不把这个转换当作文件迁移完成。

P3皮肤导入不能只登记当前能解码或已识别用途的声音：未经处理的音频必须保留原始Blob及原输出映射。未知用途使用有界内部标识保留，不由支持列表过滤掉；未被采用的素材库候选与已导入皮肤中应保留的文件要区分。命名、大小写、冲突、缺失原字节及磁盘失败均返回明确诊断，不能以“导出成功”掩盖漏文件。

2026-10-22：[A3标准组合记录](P2_COMBINED.md)已用同一最终二进制完成两轮100原图／10文档／500层＋WAV的300秒验证。双通道短音提交观察p95≤20 ms、回调空队列0、既定进程／GPU采样预算及逻辑资源归还通过；没有更改上述目标。文档切换长帧、稳定空闲／20轮循环、设备与消费锚点、人工UI及真实歌曲／导出仍开放，不将本轮静态画布与声音控制等同全部SA验收。

同日后续[候选准备与最终未通过项](P2_FRAME_PREPARATION.md)已把常规PNG／上传准备移出GUI。最终生产声音仍为原有768帧／2 ms；等待唤醒和640帧试验出现欠载，均撤回。最终两轮300秒欠载0且资源归还，但第一轮试听提交观察p95为20.0454 ms，第二轮GPU dedicated约262.004 MiB；SA提交／组合及B04不关闭，也不通过舍入或抬高门槛改判。原生回调仅新增固定有界欠载元数据，仍无时钟／分配／等待，原始声音与导出语义不变。
