# application 草稿与一次提交

2026-10-21，P1-4 已实现，application API v4。当前为无窗口 Rust 值接口；Esc 由未来 UI 映射为 Cancel，尚无桌面拖动或键盘绑定。

## 所有权与接口

ProjectSession 同时拥有已提交项目和至多一个私有 Draft。`edit_draft(DraftRequest)` 接受带版本、HistorySessionId、RequestId 的四类操作；载荷只能是已定义 Command 或身份，不能传入项目、闭包或任意补丁。

| 操作 | 输入与结果 |
| --- | --- |
| Begin | 核对 expected head／revision，分配会话内不复用的非零 u64 DraftId；返回基础状态和草稿 revision 0 |
| Replace | 必须匹配完整 DraftState；相对开始时的已提交基础重新执行整批 Command，替换候选，不累计上一次拖动命令 |
| Commit | 核对草稿身份／修订及基础活动状态；使用普通事务的私有发布路径，一次发布一个内容节点并结束草稿 |
| Cancel | 核对草稿身份／修订，丢弃候选与临时租约，结束草稿；不修改项目、活动修订或历史 |

DraftState 包含 id、revision 和 base { head, revision }。每次接受不同命令批次时草稿 revision 加一；完全相同批次不增加。不同批次即使候选内容相同，也推进草稿 revision，防止旧调用覆盖最新交互意图。无净内容变化的 Commit 返回普通 CommandResult::NoChange，不发布候选 ID、不增加内容修订或节点。

`draft_info(session)` 返回最新可选 DraftInfo／has_changes；`draft_snapshot(session, expected)` 返回标有基础节点与草稿修订的自有只读投影。普通 snapshot、历史查询和 validate 仍基于已提交内容。调用方可修改返回的副本，无法取得内部可变引用。预览未来根据草稿身份／修订区分临时内容，保存／导出默认仍取已提交节点。

## 隔离、失败与重试

活动草稿期间，新 submit、Undo／Redo／Checkout 及第二个 Begin 返回 Busy，包含活动 DraftId。只读查询不阻塞；既有回执重放仍返回原结果，不触发写入。Busy 是可重试状态，不登记回执；取消后可使用原请求重试。validate 仅预检已提交内容，不保证草稿期间能提交。

Begin 使用期望活动修订；Replace／Commit／Cancel 使用期望 DraftState。旧身份、旧草稿修订和基础修订冲突明确拒绝，不能自行合并或改变基础。单一 owner 的 Busy 正常情况下阻止基础变动；内部故障测试仍验证基础意外改变时 Commit 拒绝，Cancel 仍可释放草稿。

Replace 使用与普通命令相同的私有候选执行和领域校验，每条基础命令之后检查不变量。后段命令、资源固定或修订溢出失败时，保留上一个成功候选及草稿修订；失败的部分候选不发布。UI 应展示错误并明确重试或取消，不能将失败更新标成已接受。Commit 失败保留草稿供修正／取消，不产生部分项目或节点。

草稿与命令／历史请求共享 RequestId 命名空间和有界回执表。相同已登记请求返回原成功／拒绝结果；即使草稿已结束或已有新草稿，也不重复创建、提交或取消。不同载荷／不同请求类型复用同 ID 拒绝。返回的是原执行回执，最新活动状态需另查。

版本、会话、批次数量、Busy 和回执准入拒绝不登记新回执。其他已登记失败和 NoChange 保留；修正后使用新 RequestId。为保证取消可用，Begin 至少需要 3 个空回执位；活动草稿的更新／提交／无效取消至少需要 2 个，最后 1 个只允许身份修订正确的 Cancel 使用。因此达到保护线时可能拒绝 Commit，调用方可取消再开启新会话；不驱逐回执或偷删历史。该策略是会话数量保护，后续基于真实交互量评估回执预算，不能假装无限会话。

## 资源与发布

Replace 在候选全部通过模型校验后固定新增 BlobRef，复用已提交或上一成功草稿仍需的租约。新租约任意一步失败，释放本轮临时租约；成功替换后释放候选已不再需要的临时租约。Cancel 释放全部草稿临时租约；回执只保留命令元数据，不保留这些字节租约。

Commit 将需要的临时租约转入会话历史保留，不重复读取／解码／pin；当前分支删除资源仍不能释放旧节点需要的字节。暂存字节与摘要校验继续属于 ResourceStore 适配器的前置工作，本阶段只有内存测试存储。

提交前完成所有可失败检查和资源准备，再一起发布项目、节点、修订、准入身份与租约；有效草稿无论更新多少次都只有一个内容节点。原候选已经按相同规则校验，基础状态必须一致，发布不重执行外部操作。旧节点后的草稿提交追加分支，原后代不删。

## 验证与边界

13 项公开草稿集成用例覆盖 300 次替换／一次提交、撤销重做、取消／身份不保留、空与零净变化、后段失败、Busy／读查询、活动与草稿修订冲突、作用域／版本、跨接口去重、容量取消保留位、临时租约替换／取消／转正、资源失败与分叉。内部单元覆盖草稿计数器、基础意外变动及发布失败后恢复／重试。

资源成本使用独立 release 工具测量，见[核心成本基线](CORE_COST_BASELINE.md)。本接口没有运行时线程、计时器、设备或窗口依赖；项目保存、真实素材导入、像素预览和 AI 传输由后续阶段接入。
