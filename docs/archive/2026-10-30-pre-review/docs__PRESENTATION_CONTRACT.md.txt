# 预览控制与 GPU 呈现交接

## 临时联合选择与PreviewPort v2（2026-10-29）

[选择控制](P2_SELECTION_CONTEXT.md)新增只读Workspace目标以展示未关联文档，UI不再通过AddComponent来准备联合预览。Document及Components目标保持原语义，v1描述符不能启动新编辑，Command和项目模型版本不变。目标是FrameSource身份的一部分，不能把旧Document或Components的GPU完成别名为新的Workspace。

UI只保存有界选择、基准矩阵及带会话／修订／草稿／目标的几何缓存；实际修改仍是application拥有的原子草稿。一次Replace准备全部有效成员，失败不推进框并取消该次UI草稿；原草稿被其他入口替换时，旧指针及松手不得提交新所有者的内容。清除共同框释放临时选择，不删除项目成员、不撤销已提交命令；图形租约和声音来源仍按各自既有回执清理。

## 连续变换的候选准入（2026-10-29）

[变换控制](P2_TRANSFORM_CONTROLS.md)在同一活动手势内合并尚未接纳的指针位置／Shift状态，当前来源已发布为可呈现帧后才继续替换草稿，避免持续取消在途准备。松手立即计算最终位置并只提交一次；Esc、目标失效和故障清理不等待呈现就绪。这里合并的是编辑器输入，不能接纳旧草稿／历史／视口结果，也不能让旧帧冒充当前来源。当前无新输入也可在候选发布后处理最后位置；暂停游戏时仍允许此编辑循环。可呈现回执不代表物理屏幕已经显示。

变换控制框来自所选节点局部矩形的四角映射，允许旋转／镜像／剪切；它与canonical图层合成、导出画布、游戏判定区和音效身份分开。UI只查询项目和提交application草稿；没有GPU资源所有权、旁路写入或新的可变模型缓存。

## 活动草稿与故障交错（2026-10-29）

[中断契约](P2_ACTIVE_EDIT_FAULTS.md)只取消本UI持有的会话／DraftId，清除原手势并保持暂停；外部草稿继续存在，旧指针松开不能提交它。音频来源按实际会话重新选择，旧声音与控制不能因恢复重放。音频单独失败时，在下一次GPU准备接纳前选择取消后的来源；目标失效则清除期望来源及旧可呈现帧，取消在途工作但不提前退还额度。

普通桌面逻辑、恢复窗口退出和初始化失败清理共用中断入口；模拟时间冻结在故障处理之后、推进之前。取消仍通过application，失败保留原所有者并阻止退休；取消成功不创建历史节点。真实Begin／Replace／Cancel会增加回执，不能用忽略项目／节点／地址差异的宽松比较追认通过；受控活动草稿对照只单列retained_requests，其余状态保持严格一致。物理输入与真实驱动／设备异常仍另验。


## 音频归还结果与资源准入（2026-10-29）

[端点受控验证](P2_ENDPOINT_RETURN.md)细分音频关闭结果：Pending保留原接收句柄及供给所有者，可再次检查真实返回；Disconnected、重复接纳或finish身份／清理错误保持Terminal。返回端点不等于完成资源释放，必须由原所有者finish；不被接纳的端点也须保留。待清理时禁止新音频工作与新后端，UI保持冻结／错误，不能以关闭／启用、清空标志或复制项目绕过。

实际迟到返回并成功finish后，才允许继续GPU／任务清理，随后仍需Renderer、surface及整个Instance退休的独立回执。重试保持同一项目／历史和背景复制锚点，显式恢复后再播放；真实CPAL／驱动异常与永久失败后的恢复另验。旧章节中笼统的“音频关闭失败Terminal”以本节按真实结果的细分为准，原JSON证据不重判。


## 清理失败与继续清理（2026-10-29）

[清理恢复候选](P2_CLEANUP_RECOVERY.md)保留失败尝试的完整清理上下文及原会话。Pending表示通知、worker或外部绘制引用仍未实际退出；不得丢弃所有者、提前退还仍占用的额度或启动下一设备。可明确继续清理并重新核对资源；join失败、音频关闭失败或非预期设备通知是Terminal，不因重复调用变成成功。

运行时成功清理只产生保留原会话及已推进游标的GPU无关Seed；Renderer／surface／注册表及整个Instance退休是另一个准入门槛。仅完成前者仍拒绝创建新后端。失败时先暂停并关闭图形／声音门控，清理完成后仍按复制锚点保持暂停，显式恢复后才继续播放；项目和历史不靠快照重建或补偿Command恢复。真实驱动／端点错误的范围仍须分别实测。


2026-10-20设计基线；2026-10-21 P2-1及后续分范围实现见下文。最新[交接消费后初始化保护](P2_INIT_RECOVERY.md)补齐Editor、预览准备及音频观察器初始化错误后的状态保留和重试；完整退出条件仍未全部满足，尤其真实驱动丢失、原生清理失败、活动编辑交错及正式默认集成。

## 初始化消费交接后的候选契约（2026-10-28）

项目交接取出后由初始化Attempt持有整个原会话，直到观察器和运行时就绪才commit给窗口。任何前置错误须返回原Seed；已有Editor后的错误须实际退休该次资源后返回无GPU交接。清理未完成或失败时保留原Editor及项目所有权并阻止再次初始化，不能为显示“可重试”提前释放预算或重建一份可变项目。

失败尝试使用新Context，其FrameKey和分配游标即使未显示也可能被准备请求观察；正常退休后把推进的游标带到重试中，不能倒退。原设备、端点信号与旧待处理FrameKey不得影响新代。音频仍保持暂停并核对同一来源的最终复制锚点；运行时重建和瞬时UI状态不进入项目历史。项目／全部历史值／地址的对照只用于验证，不能成为绕过Command的项目恢复通道。

三组真实App创建错误及资源范围见[验证](P2_INIT_RECOVERY.md)。此处是候选的错误回退契约，不承诺真实TDR、OOM、进程终止或GPU析构中panic安全；纯所有权层unwind回归与真实原生清理分别记录。

## 呈现中故障的当前候选契约（2026-10-28）

DeviceLost通知可能晚于surface失败；致命Lost／Validation须立即关闭同代图形与声音门控并跳过重配置。准备结果只在设备poll完成且失效检查通过后接纳；收到失效后不创建旧设备绑定，不等待永远不会到达的绘制回执。回调只更新该代短状态、关闭音频复制并唤醒宿主，不访问项目。候选控制器使用非阻塞所有者poll等待实际通知后关闭窗口，不能将GUI刷新当作持续音频供给。

受控destroy的窗口仍遵守真实Renderer析构、surface退出、任务成功join、旧CPU绘制租约释放和受管目标0；新窗口拒绝旧FrameKey和旧通知。锁定wgpu-core的失败获取可能留下未登记纹理ID，必须保持原始非空报告，逐项证明其与失败获取精确对应、纹理用户对象0且其他注册表为空，再退休整个Instance。未知对象或数量不匹配继续阻塞，不能将此规则用于坏Instance的继续运行；预算与最终原始／派生资源归还门槛不变。

显式三组验证及计量边界见[记录](P2_PRESENT_FAULT.md)。普通启动尚无自动恢复，真实TDR／Unknown丢失、OOM、项目交接已消费后的初始化失败、活动草稿／手势交错及物理音频变化仍开放；下方保留计划性关闭基线，不能把其空表条件或旧退出顺序误当成所有故障形态。

## 完整窗口计划性恢复契约（2026-10-28基线）

eframe持有窗口Renderer与surface，NativeHost持有离屏目标，两者必须分别退休。显式MemoryUsage窗口用例通过原生所有者创建设备、安装自己的一次性丢失通知，再使用官方WgpuSetupExisting注入框架；不能覆盖框架已经安装的通知或向application／UI暴露设备。NativeHost的门控只允许在首次请求前绑定，恢复后即使FrameKey游标已经很大也仍是新设备寿命；不能靠FrameKey是否为1判断能否绑定。

恢复交接中的RebuildSeed只保存资源来源、上传策略与单调身份游标，不携带旧Context／Device／Queue／Renderer／Texture。新窗口提供新Context，重建缩略图及框架纹理。ProjectSession和编辑器状态保持在内存，项目快照不可变；这不是文件保存或绕过Command的项目恢复入口。现有诊断顺序是停止绘制与声音、在安全on_exit中destroy、实际退休后顺序run_native重开；普通启动仍只诊断错误并要求重启。

准入同时要求真实Renderer析构、旧Instance surface为空、旧CPU绘制目标引用释放、准备／导入任务成功退出、设备／队列／纹理／缓冲注册表为空。先保留旧FullOutput验证交接拒绝，再丢弃并核对0目标，不能直接清空计数或借用固定帧延时。独立音频门控清除旧Voice／未输出副本，保持暂停并从最终复制锚点恢复背景；旧图形／声音信号重放不影响新代。

已验证两代完整Editor的resize、软件zoom、实际96→120 DPI、最小化／恢复及自有渲染器回读像素尺寸。规范皮肤输出跨Context逐字节一致；跨DPI的整个GUI不要求逐字节一致。此结果不包括仍在呈现时的意外device lost、原地替换Renderer、活动草稿／输入交错或物理音频变化；它们仍是C4／C5待验范围，不由下文历史基线自动推断通过。

## P2-1 实际交接（2026-10-21基线）

控制端口是 application 的 PreviewPort v1，只借用已提交或指定草稿的项目；Command v4 不变。FrameDescriptor 含历史会话、节点／修订、草稿 token、目标、尺寸、视口代次、场景及模拟时间，不携带 GPU 对象。当前只有单设备宿主，没有设备重建代次或通用捕获任务 API；`--verify-gpu` 是显式诊断入口。

实际呈现选择 egui-wgpu PaintCallback：UI 只向自己定义的 Presenter 传 FrameKey／Rect，NativeHost 在回调中绑定同一设备生成的离屏图。预览画面没有注册为 egui TextureId；缩略图才使用 egui 自有 TextureHandle。下文的 native texture 注册规则保留作为另一条受约束的设计路径，不表示现在两套方案并用。

活动帧描述、一个候选及退休目标均由宿主所有。2026-10-25 的[呈现交接更新](P2_GUI_BASE_COST.md)将Frame元数据保留为宿主独有值；待提交egui CPU绘制数据通过Arc固定不可变NativeTarget，完成回执也只持有目标。prepare直接向egui提供的主CommandEncoder登记 `on_submitted_work_done`，返回空的附加缓冲列表；不再为回执创建空command buffer。升级wgpu／egui时须重新核对契约并运行晚交接回归。只有CPU绘制数据和实际提交完成回调均释放后，退休目标才可回收；weak观察表不保有资源。合成上传另有完成回调租约。[原生对照](P2_GUI_BASE_NATIVE.md)验证了像素和所有权，但未证明CPU收益。

候选 GPU 完成后核对完整来源，尺寸／历史过期则丢弃；旧画面保留时 UI 拒绝用其坐标开始新编辑。最多八份不同目标（≤1024² RGBA，约32 MiB），达到上限合并最新请求并背压。相同静态材质的时间／场景描述可生成新来源 FrameKey 并共享不可变目标，不能用此省略实际材质修订。关闭等待自身有限 GPU 工作；普通编辑不回读、不每帧等待空闲，稳定暂停仅在 pending 时安排轮询。

原生验证覆盖：组透明度及 CPU／GPU 对照、冻结草稿、取消精确恢复、旧分支、快速尺寸过期、重复请求无上传、egui prepare 后尚未提交时切换目标，以及回执和绘制数据结束后的退休数量。证据见 [P2 记录](P2_PROGRESS.md)。device lost 目前诊断并要求重启；窗口实际最小化／DPI 变化、真正捕获租约、标准规模上传和总内存预算仍待实现／验证，不能据此关闭整个 R22。

## 控制通道与呈现通道

application 定义小型 PreviewPort／RenderPort，由桌面组装的适配器实现并委托给 preview／rendering；application 不导入其运行时或 GPU 实现。预览端口覆盖只读投影更新、场景／时钟控制、状态查询及捕获请求，渲染端口覆盖文档合成／导出任务。端口使用有版本的值、请求 ID、状态与错误，不包含 egui／wgpu 类型、UI 控件或可变项目引用。只在 P2/P3 的实际用例需要时落地这些端口，不现在创建空实现或公共服务容器。

UI／AI 通过 application 获取 `FrameDescriptor`：不透明 FrameKey、源节点／项目修订、可选草稿修订、场景／时间代次、视口／设备代次、尺寸、状态和诊断。它是来源与可用性描述，不携带原生纹理或把每帧像素搬到 CPU。

FrameKey 标识一份有明确来源的内容帧，原生 RenderTargetKey 标识资源槽及分配代次，二者不同。并非每个动画帧都要新建 GPU 纹理；可复用完成退休的槽。连续帧的同队列有序使用／缓冲策略在 P2 实测后落地，不能仅因 TextureId 相同就丢弃内容版本与最后使用回执。

桌面 UI 将 FrameKey 和布局尺寸交给 UI 自己定义的窄呈现端口，由 desktop 的 egui 呈现桥完成 native texture 注册及绘制。UI 可保存不透明展示标识，不能操作 Device、Queue、TextureView 或渲染器可变引用；egui::TextureId 只留在原生呈现边界，不进入 application、项目、历史或 AI 协议。这个端口只负责画面展示，不提供项目查询／写入捷径。

AI／无窗口捕获使用独立的捕获任务，在请求修订就绪后由渲染适配器直接回读，返回带来源的图像产物。它不要求存在 egui 注册或可见桌面窗口，正常屏幕呈现不执行该回读。

## 所有权与具体责任

NativeRenderHost 是 desktop 组装的运行时部件，不是新增领域模块或插件框架。使用 eframe 时复用该窗口的 Device／Queue；图层合成器、场景绘制适配器和 egui 呈现桥使用同一 GPU 上下文，不能各自再创建一套设备。多窗口／不同 GPU 属于后续能力，不静默共享跨设备句柄。

| 对象／操作 | 唯一责任方 |
| --- | --- |
| 窗口 surface、GPU 上下文及设备代次 | desktop／eframe 原生宿主；向实际渲染适配器注入上下文，不向 application 注入 GPU 对象 |
| 图层源资源、合成缓存与中间图像 | rendering 的 GPU 适配实现，按共享合成计划生成；不负责场景逻辑 |
| 最终预览离屏纹理与 FrameKey 注册表 | NativeRenderHost 内的场景绘制适配器创建、持有和退休；preview 提供只读场景／绘制状态 |
| egui::TextureId、绑定与展示引用 | egui 呈现桥注册／注销；每个视口绑定一个明确的帧来源 |
| 尺寸、DPI、最小化变化 | UI 上报布局；宿主解析物理像素与视口代次，渲染适配器重建目标；UI 不自行分配纹理 |
| 历史检出／草稿／seek | application 提交新来源；渲染宿主生成候选帧，旧帧按展示引用与提交回执退休 |

注册 egui 纹理并不转移我们对原生纹理的所有权。核对本机固定 egui-wgpu 0.37.0 的 `renderer.rs:790–903`：native 注册保存的是绑定并设置 `texture: None`；`free_texture` 会移除登记，只有拥有其内部纹理时才调用 destroy。因此释放 TextureId 与释放我们的离屏纹理必须分别管理。公开 API 亦见 [Renderer](https://docs.rs/egui-wgpu/latest/egui_wgpu/struct.Renderer.html)（本次查阅显示 0.37.0；升级时按锁版本重新核对）。

本机固定 API／源码身份见 [只读核对记录](research/graphics-presentation-20261020.json)；它不构成产品依赖或新增资源测量。

## 发布、替换与回收

1. 收到请求后分配代次，后台结果在上传前核对来源。候选纹理保持私有，不覆盖仍在显示的纹理。
2. 记录合成／场景命令并提交，取得完成回执；候选完成后再次核对来源，才在 egui 帧边界注册／发布为可显示。已失效的候选进入退休，不因为 GPU 完成就覆盖新画面。
3. 切换后停止生成对旧 TextureId 的新绘制，旧帧进入 Retiring。注销登记、释放原生引用和池复用分别等待各自条件，不能只在替换变量后立即 destroy。
4. 旧 ID 不再被任何待提交的 egui 绘制数据使用，最后一次 GPU 读取已完成，且捕获／其他展示租约已结束后，宿主才注销绑定、释放或复用原生资源。每份资源有唯一回收责任方，不依靠 UI 和 preview 分别猜测 Drop 时机。

GPU 完成不等于物理显示完成，也不等于 OS 已立即回收驱动提交。wgpu 的 [Queue::on_submitted_work_done](https://docs.rs/wgpu/30.0.1/wgpu/struct.Queue.html#method.on_submitted_work_done)需要事件循环中的提交／poll 推进；回调只更新短状态并唤醒处理，不在里面改项目或做重操作。稳定暂停时仍须完成有限的退休工作，完成后停止无意义的持续重绘／轮询；不能为等待退休而阻塞 UI 到 GPU 空闲。

P2 先采用代次隔离的候选／活动／退休资源，并限制候选数量和退休字节；不能无限积累旧纹理。达到限额时合并请求／背压，维持旧画面并明确 pending。没有证据前不复用已发布 TextureId 指向新来源，亦不把固定帧数或延迟两帧当作 GPU 完成证明。未来原地更新或池复用须新增相应提交依赖和来源测试。

## 尺寸、历史、故障与颜色

- 视口 resize／DPI 变化产生新尺寸请求，短时保留并缩放显示旧帧，标明旧视口来源；零尺寸／最小化不创建无效目标。快速 resize 只保留最新请求，按预算控制旧资源退休。
- 历史检出、取消草稿和时间轴跳转独立增加对应来源代次。旧帧暂留时，其实例映射只能关联旧来源；命中／编辑请求要核对当前修订，不把旧画面坐标直接用于新节点。
- device lost 使全部旧设备 FrameKey／TextureId 失效，呈现桥先停止引用；失败的捕获返回诊断，不能等待永远不会到达的旧回执。上下文清理后显式重建，旧设备结果不得进入新设备帧。
- 原生展示纹理需匹配 egui 的格式、alpha 和采样要求。固定版本的 native 注册要求 Rgba8Unorm；展示转换单独处理并做像素对照，不能因此修改导出合成语义、重复预乘或重复色彩转换。

## P2 退出门槛

正式集成必须覆盖：反复 resize／DPI／最小化，冻结下刷新，快速历史／草稿／场景／seek 交错，GPU 与 egui 提交前后旧帧晚到，关闭与 device lost，捕获租约和资源上限。测试核对无悬空 ID、双重回收、旧帧冒充新来源和持续增长；像素／alpha 对照与资源预算单列。fake 提交／租约测试无窗口运行，原生测试用自有回读，不依赖系统窗口捕获。

上面退出门槛适用于 P2 整体；本轮只完成“P2-1 实际交接”列出的范围，不改 P0 的测量结论。

2026-10-22 的[候选准备增量](P2_FRAME_PREPARATION.md)将 PNG 重建、像素打包、GPU 上传与合成提交移入 NativeHost 所有的单 worker，UI／application 不持有其可变引用。工作线程不登记 egui 纹理，不读取项目会话；只回交私有 GPU 候选及完整来源。取消仍占准入直到实际完成，已提交结果须由宿主收取并跟踪 GPU 回执。关闭先终结准备工作，未完成目标与 CPU 绘制租约分开跟踪；设备故障／恢复门槛保持开放。

## 编辑器GUI字体与派生绘制

本节仅涉及编辑器GUI文字；皮肤自身的位图字体、数字素材和玩法输出仍通过项目渲染计划处理。GUI字体生命周期不属于项目修订或历史身份，不能用相同FrameKey或SkinProject修订证明文字图集未变。

- 目前每次UI pass通过框架正常接口取得新鲜排版，框架负责自身字体缓存失效。场景冻结也必须执行编辑器控件、布局、输入／焦点／IME、拖动取消及最新项目／音频状态同步；绘制复用不得缓存Response或跳过这些处理。
- 相同Galley身份仅说明共享排版内容，不授权复用整张TextShape。位置、裁剪、颜色／透明度、下划线、角度、层变换、顺序及当前布局须按本次绘制处理，旧几何不能成为命中测试真值。
- 字体定义、提供者、字形栅格化器、缺字策略、DPI和字体选项，以及自动图集清空／重建均属于失效范围。图集尺寸、纹理ID或一次完整／局部纹理更新不能替代完整图集代次。尺寸不变时旧UV仍可能失效，见[字体契约回归](P2_TEXT_WORK.md)。
- 当前未建立外置跨帧文字网格缓存。未来引入前须先有可靠的Context／图集失效契约、完整绘制状态匹配和资源上限；GPU缓冲释放仍按所属框架／设备提交生命周期处理，不能将TextureId或Galley Arc当作GPU租约。

宿主的显式文字统计只保留有界相邻输出弱身份、数量和自身墙钟，不提供字体或项目写入口；关闭清理及只读FullOutput有回归覆盖。统计不代表采用了外置缓存，也不能替代像素、逐帧交互或性能验收。

[同输出CPU回放](P2_MESH_REPLAY.md)仅使用当前pass的新鲜形状、像素比例、选项和经等价核对的圆盘元数据；不得把临时CPU图像当作字体纹理来源，或把CPU连续数组复制当作实际GPU上传。回放输出不替代原FullOutput，回调只比较／转交身份，不执行其准备或绘制。通过Context API回放会更新框架统计，必须单列观察扰动，不能据此跳过正常绘制或从CPU预算扣减；该机制不授权跨帧复用。

[真实帧标记](P2_GPU_PATH.md)利用公开的prepare／finish_prepare／paint及提交完成回调观察原绘制；它改变回调遍历和状态重设，须单列诊断扰动并验证像素。不把绘制后至完成通知的墙钟叫作GPU执行或CPU呈现时间。独立上传探针拥有自己的Renderer／缓冲，只用当前mesh，过滤原生回调，不修改活动Renderer；待完成后由宿主排空并释放。正常submit／present尚无成对公开观测钩子，不能用独立上传提交或旧TextureId补造该边界。

正常API的进一步观测通过默认关闭的`framework-trace`读取框架既有profiling区段，不增加渲染回调、额外提交或跨模块GPU所有权。acquire／finish／submit／present的CPU墙钟和同线程调度交集与GPU完成／设备消费分开；包含它们的事件分发／整帧区段是父区段，不能与子区段相加重复计费。诊断Subscriber只在宿主线程作用域内存在，记录有界标量及事件类别；其同步、时钟和特性编译成本不得从产品预算扣除。
