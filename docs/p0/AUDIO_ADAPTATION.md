# 源格式不匹配与默认音频设备变化

日期：2026-10-20。状态：Windows 两组共十六轮格式／策略验证及一次真实模拟耳机失效后的暂停重建通过，P0 整体仍在进行。独立、默认不运行的 P0 实验，不是正式音频后端或 stable 行为规则。

## 路线与边界

解码输出与五块 PCM 池保留源采样率、声道数和源帧身份，不按端点格式重解释样本。Windows 可选入口将单／双声道 float32 源格式提交到 WASAPI shared，以 `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY` 请求系统引擎转换；原严格匹配入口保留。平台转换不进入媒体库、Transport 或项目 Command。其他平台未来实现同样的小型输出契约，分别选择并验证转换后端，不假定 Windows 引擎能跨平台复用。

此选择依据微软的[共享转换标志说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/audclnt-streamflags-xxx-constants)与[流初始化接口](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-initialize)，本项目没有自写通用重采样器。转换后的引擎音质、相位和内部缓冲尚未回采，接受源包正确不等于转换后逐样本一致；不录音，也不把平台转换当作导出音频语义。

设备时钟仍按 `IAudioClock` 的实际频率换算微秒；队列、padding 和提交前沿使用客户端源格式帧，混音格式单独记录。暂停停止并重置自有流，保存逻辑位置，清空原生未读尾部并作废软件队列／在途旧块；恢复从源采样点向下取整，至多一源帧量化，不重放暂停期间的时间或输入。源率与混音率不同不允许改变歌曲播放速度。

转换入口当前限定源 8–192 kHz、单／双声道，实际可用格式还须初始化成功。原生缓冲超过四块队列容量时明确拒绝，不能永久等待无法达到的预备阈值。多声道源、独占模式、动态变速及精确声学延迟不在本轮范围。

默认输出按 `eMultimedia` 选择。可选入口约每 250 ms 比较不落盘的端点内部身份，并在暂停时调用原生 client 健康检查；paused 工作线程的 100 ms 等待会使检查间隔约为 300 ms，调度和原生调用没有硬期限。默认端点变化／不可用或原生失效进入 Faulted，立即关闭游戏输入，再释放旧流；不修改系统默认设备、采样格式、音量或服务。故障发布与可能较慢的释放分开，原生调用阻塞／最终 join 上界仍未知。正式后端可用设备通知替代轮询，按平台资源与维护成本重新验收。

恢复遵循微软[释放旧接口、重新选择默认端点并初始化](https://learn.microsoft.com/en-us/windows/win32/coreaudio/recovering-from-an-invalid-device-error)的方向，但产品意图保持显式：故障冻结 → 请求新代次 → 重查混音格式并重开 → 确认暂停锚点 → 用户显式播放。失败保持故障，不循环重试；新流不会因旧控制、早到的播放意图或 held 按键启动。端点 ID 仅在原生线程比较并按 [GetId 的内存规则](https://learn.microsoft.com/en-us/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-immdevice-getid)释放，不写设备名称或标识。

没有新增 Cargo 包、锁版本、平台绑定 feature 或线程。原生调用仍隔离在 `p0-wasapi/src/platform.rs`，egui 主包禁止 unsafe；Output 三方法与正式模块边界保持不变。格式诊断字段为实验内追加值，不是产品文件格式。

## 验证协议

- 自制 120 秒 PCM16 WAV：48 kHz 双声道严格匹配／转换对照，44.1 kHz 单声道、32／96 kHz 双声道、48 kHz 单声道转换；另将同一 44.1 kHz 单声道源编码为 MP3／Ogg。不读取私人音乐或客户端素材。
- 所有源先完整线性解码，并以独立 WAV 转换或固定私有 FFmpeg 参考核对全部样本和长度；四个定位片段与完整解码对照。无裁切或未比较尾部。参考与编码器不加载到原生播放进程。
- 每轮先连续消费至少八秒，然后跨暂停故意扣留一个旧解码块，确认晚到结果被拒绝；显式定位到 1234567 µs，冻结位置下检查不提交 PCM／不接受游戏输入。
- 自动轮受控退休自有原生流，检查故障冻结、新代次重建、恢复就绪前的播放及旧代次控制均无效，随后显式恢复和新按键才生效。它不冒充物理拔出或系统错误。
- 每个原生接受包按源位置、声道、增益、哈希和探针独立核对；所有队列代次、暂停未读尾部和旧完成事件逐条验证。关闭后五块全归还，不能有队列、在途块、欠载、解码失败或轨迹溢出。
- 每个格式／策略重复两轮。第一组严格对照及 44.1 kHz 单声道转换各有 65 秒暂停与关闭观察；其余为三秒短观察，不声明稳定空闲预算。

只采样本次子进程的 CPU／工作集／私有提交，不读取页面内容。Playing 阶段与转换／控制、稳定暂停、关闭分别汇总，丢弃阶段不一致的样本及每阶段首秒。累计历史峰值截至最后有效采样，包含已发生的诊断和记录成本，可能漏掉进程退出前的瞬时序列化峰值。ClosedIdle 已释放原生流并加入解码线程，但诊断 Input 句柄仍持有归还后的池和记录；池归还不等于进程分配全部释放，不作为空进程基线或长期无泄漏证明。

系统音频引擎可能在 `audiodg` 进程承担转换成本，本次自有进程指标不包含该共享服务成本，不能据此宣称转换的系统总成本为零或完成总体预算。无 GUI／图形负载，本批不替代前轮组合成本。

第一项仅检查／构建。准备需要已记录身份的私有离线 FFmpeg，目录须未存在；已有则复用。`--skip-checks` 仅用于正确 feature 已验证的构建。原生步骤会播放增益 0.002 的低幅度自制音调，不改系统设置。Windows x64 已有适配，Linux 实测延期、macOS 待设备。

人工设备变化另用 `--manual` 单独启动，按聊天中的阶段提示拔出当前默认 USB 音频设备、接回并确认；程序通过独立 `recover` 与 `play` 标记等待显式操作。未收到真实设备错误／默认变化的普通模拟耳机插拔只能记为未观察到端点变化，不能判物理恢复通过。不需要 F12 或窗口捕获。

## 本机模拟耳机插拔

用户确认使用 3.5 mm 模拟耳机，轮次 `audio-adaptation-13b11a65`。用户拔出并回复“已拔出，但没听到声音”，接回后回复“已接回”；本轮未写入 `no_change` 标记，也未在设备等待阶段受控退休流。原生 `GetPosition` 实际返回 **0x88890004／AUDCLNT_E_DEVICE_INVALIDATED**，因此本机这次插拔确实产生了设备失效，不能将其泛化为所有模拟耳机都会如此。

故障冻结位置 **19984567 µs**，重建后暂停位置仍为 **19984567 µs**，旧代次观察和控制未启动新流。收到接回确认才写入 `recover`，确认新暂停锚点后才写入独立 `play`；显式恢复后模拟继续推进，最后再次暂停。各代次客户端均为 44.1 kHz 单声道，实际混音均为 48 kHz 双声道；这次不是混音格式变化实测，也没有证明默认端点轮询检出了新 ID。

程序侧全轨迹核对通过，欠载／解码失败／轨迹溢出为 0，刻意扣留的旧块被拒绝，关闭后五块 PCM 全部归还。本轮没有可听确认或声学连续性结论；未覆盖 USB 拔出、暂停时真实拔出、无默认设备或接回失败的硬件情形，这些失败／暂停路径目前由 fake stream 回归覆盖。

## 结果

### 正确性与稳定性

同一压缩 feature 二进制、**124** 份固定源码／锁／便携 fixture／工具，两组各八种格式／策略共 **16** 轮全部通过。矩阵 **11517** 个原生接受包逐包核对；加上短轮及上述人工轮共 **14155** 包，欠载、解码失败、轨迹溢出均为 **0**，每轮五块归还，无排队或在途块。暂停跨代次的旧块被拒绝，定位、故障冻结、暂停重建、早到／旧代次控制拒绝及 fresh press 恢复均通过。

首次连续播放的设备时间与墙钟分开核对，首尾观测跨度超过 7.5 秒，设备／墙钟比为 **0.99858–1.00099**。在本次观测粒度下未见按混音率误算源速率；这不是声学时钟或端到端延迟测量。实际混音均为 **48 kHz 双声道**，因此包含单声道上混、升／降采样，但不包含真实双声道下混到单声道或多声道端点的验证。

七份 120 秒源完整解码与独立参考同长，WAV 最大差 **0**，MP3 **8.35e-7**，Ogg **1.49e-7**，全部在 `1e-5` 内；定位片段与完整线性解码一致，没有裁切或补尾。严格匹配入口以 44.1 kHz 单声道源连接本机混音时仍明确失败，未被新入口悄悄放宽；越界输出及已有目录写入均拒绝，原文件哈希不变。
