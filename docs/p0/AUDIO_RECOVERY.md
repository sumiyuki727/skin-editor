# 静音输出流重建与平台端口

2026-10-19，P0 Windows 实验新增纯值音频端口和显式流重建。Linux 实测按用户要求暂缓，macOS 待有设备；保留适配位置，不创建未经验证的 Linux／macOS 后端。此处验证自有静音流的受控关闭与实际重开，不代表物理拔出恢复、可听内容恢复或正式音频选型。

## 端口与寿命

`experiments/p0-egui/src/audio_output.rs` 的 `Output` 只有读取快照、提交暂停意图、请求新代次三个方法。载荷为代次、请求／样本序号、微秒位置、暂停／故障值和结构化控制错误；没有设备指针、UI、项目引用、文件或系统时钟。`None` 表示设备尚未就绪，不能用墙钟填补模拟进度。纯 Transport 与端口接受静态边界检查；Python 回归故意注入原生／UI／I/O／墙钟依赖，确认检查能拒绝。

Windows 组装模块 `windows_audio.rs` 将可选适配器快照映射为这些值；原生格式与 HRESULT 诊断留在适配侧。UI 视图只借用 Transport，既有文档命令／历史与设备生命周期分离。图像与 GPU、文件、窗口输入也继续留在各自适配边界，本轮没有把 WASAPI 当作通用平台接口。

一个既有设备线程顺序拥有输出流，控制通道仍限 8 项：

```text
设备错误／显式退休 → 发布 Faulted → 释放旧流 → 等待显式恢复请求
                                       ↓
新代次 → 打开新流 → 暂停确认／锚点 → 等待显式播放 → 读取新流位置
```

故障先发布，再执行可能较慢的释放，编辑器可先关闭游戏输入。释放和重开都在专用线程执行；旧流释放结束才开新流，没有第二个音频线程或并存流。实际原生调用若阻塞，恢复会等待；主线程不等待重建完成，但最终退出的 join 上界仍未知。无窗口回归用阻塞 Drop 的 fake stream 验证故障通知先到、恢复能排队，不能由此声称驱动调用已可中断。

失败时保留故障状态与冻结位置，不自动重试或自动播放。重复／旧代次控制不会触发新流，队列已满／关闭返回结构化错误。适配器旧 `request` 仅用于初始代次的既有实验，新端口使用带代次的 `request_in`。

## 时钟和输入

故障冻结最后一次有效模拟位置 `F`。显式恢复分配新代次，重置该代次的请求／样本门控；新流首次有效暂停位置为 `P0`。随后：

```text
simulation_us = F + (device_position_us - P0)
```

恢复就绪前的播放意图保持暂停，不抢先增加请求号。新流首次有效回执必须暂停；之后显式播放才推进位置。检查设备倒退、暂停漂移及加减法溢出；拒绝旧代次的正常回执和故障，即使其序号或位置更大。流代次不等于文档／GPU 请求号，也不进入项目编辑历史。

故障与恢复不清空 held 按键。故障、打开、暂停时游戏按下被丢弃，编辑输入继续工作；恢复后已有按下／repeat 不重放，释放再按下才接纳。没有补跑恢复等待期间的墙钟或输入。

这里设备只输出静音；尚无真实 PCM 内容、seek／重排音频队列。逻辑位置连续不证明真实音乐已在同一位置恢复，正式游玩仍须实现并验证内容定位、缓冲与延迟。

## 原生验证

```text
python tools/check_p0_recovery.py --fixture artifacts/p0/gpu-fixture --repetitions 3
```

入口先运行无窗口检查和 feature 构建，再顺序打开自有 Vulkan 窗口和默认 shared 静音输出。`invalidate` 只关闭本进程自己的流，不更改默认端点、音量或系统设置；它不伪造驱动 HRESULT。每轮：

1. 播放约 350 ms，接纳一次 Z，显式退休当前流并观察 Faulted。
2. 故障中完成 30 次拖动更新并一次提交；模拟位置及游戏输入不变。
3. 新代次实际重开，观察至少三个新鲜暂停样本，再显式播放。旧流故障回执被拒绝；held／repeat 无效，释放再按下只接纳一次。
4. 播放后再退休／重开一次；至少三个新鲜暂停样本后显式播放，最后暂停。最终仍需至少三个新鲜暂停读数。

四个 1024² 检查点分别为故障基线、故障中提交后、第一次重建暂停、第二次重建暂停。CPU／GPU 和 GPU 显示适配容差 2／255；故障中提交须改变 PNG，后三个状态的 CPU、GPU、显示三类 PNG 各自逐字节一致。阻塞像素参考仅在故障或暂停下执行，不作为帧／延迟预算。

最终三轮证据见 [windows-audio-recovery.json](windows-audio-recovery.json)。每轮两次重建的首个逻辑位置均等于之前冻结点，旧代次拒绝两次，游戏按下总数 2，节点数从 1 到 2；最大通道差 1／255，无超差像素。源码、锁文件、测量脚本、输入与图片哈希冻结在各输出目录。先前六次为逐步补充保护及故障通知顺序之前的预备运行，单独保留，不混入最终统计。

## 测试和剩余门槛

共 119 项无窗口测试：原生候选 60、契约 10、Python 45、可选平台适配器 4。新覆盖包括恢复成功／失败重试、非零设备起点、旧流故障、过早播放、溢出、释放先于重开，以及故障通知不被阻塞释放拖延。真实设备错误／失败开流使用 fake stream；实际开流和重建另由上述原生实验验证。

默认／feature 格式、Clippy 和 release 构建通过。既有共享时钟／后台文档切换入口及旧单文档内部时钟入口各回归一次，通过，目录分别为 `switch-audio-201a4ec2`、`transport-826feac1`；其结果／证据哈希也登记在本轮汇总。没有重复执行与本次音频改动无关的完整 60 秒 GPU 预算测试，已有结果保留原身份。

本轮不验证物理拔出／默认设备自动切换、设备通知、可听输出、声学延迟、物理输入、IME、全屏、驱动阻塞退出上界、完整资源预算或 stable 玩法／兼容规则。当前客户端兼容案例仍为 0；无需 F12，不访问旧源码或客户端素材。没有新增第三方依赖、unsafe 或正式产品模块。
