# 流式音频与标准图形组合长时观察

日期：2026-10-19。此实验将后台 WAV 解码、固定 PCM 块池、WASAPI、设备时钟驱动的纯 Transport，以及标准 PNG 后台读取／GPU 合成放在同一进程。它是 P0 候选验证，不是 stable 内核、实际游玩或最终产品预算。

后续同源 WAV／MP3／Ogg 的两组各五分钟对照见[压缩组合续篇](COMPRESSED_COMBINED_SOAK.md)。本页保留当时的 WAV 结果、测试数和证据，不与新轮次混计。

## 方法与边界

- 标准图形 fixture：100 张 1024² 原图、10 个文档、500 层；活动文档引用 10 张原图、合成 50 层，保留隔离组。使用既有每帧最多两张／8 MiB 的后台上传和一次性 pipeline 预热。没有加入正式素材库、缩略图面板、项目持久化或完整历史。
- 自制十分钟规范头 PCM16 WAV，48 kHz／双声道，文件按需读取；要求当前端点匹配 48 kHz 双声道 float32，不匹配即失败，每轮设备实际消费至少 300 秒。输出增益 0.002，不改系统音量／设备。周期波形只用于独立核对和测量，不代表真实压缩音乐、冷盘或复杂混音。
- 播放期间每个编辑帧经既有 `Owner` 值命令更新可取消草稿，通过同一合成计划刷新 GPU；前 200 秒每十秒切换一次，合计 20 次，保留 10 个文档编辑状态。文档请求不重开音频或复位模拟时间。
- 暂停确认后做两次 CPU／GPU／显示目标直接回读，证明暂停下命令编辑改变像素，最大通道容差 2。昂贵的验证与写 PNG 归到独立 Diagnostic 阶段；正常播放没有 CPU 像素回读或截图。
- 暂停稳定十秒后观察 65 秒；然后关闭活动文档、设备和解码线程，待后台工作结束并稳定十秒，再观察 65 秒。空闲阶段按截止时间唤醒，不逐帧画图；输出后端仍维持原有暂停轮询。关闭后保留框架／设备／pipeline 会话，不等同于全新空项目或进程退出。

诊断没有无限增长的内存列表：PCM 仍为五块／160 KiB、最多四块排队；8192 事件的生产记录约每秒取出并增量写 JSONL，缓冲复用，溢出标志不会被清除。帧时间最多 40000 条、音频观察最多 700 条、文档切换 20 次，超过容量即失败。逐包记录的生成、取出及文件写入成本计入进程资源；新回归覆盖超过原事件容量的完整消费和不可掩盖的溢出。

Python 以有界周期参考缓存逐包独立检查所有已接受包的双声道 float32、增益、FNV、峰值、非零数、源帧连续性与探针，并核对暂停未消费尾部、代次作废和关闭池归还。欠载指标是适配器报告的软件队列／提交前沿故障，不是录音或驱动内部／声学中断检测。没有刻意引入饥饿；受控欠载与恢复见[短轮流式实验](STREAM_OUTPUT.md)。

## 计量口径

使用 release、Windows Vulkan／MemoryUsage 候选，在隐藏的自有原生渲染窗口正常提交 GPU 工作，不捕获系统窗口。外部采样器只读取自己启动的进程及对应 PID 的 GPU 内存计数，每 200 ms 采样；记录工作集、私有提交、进程历史峰值、累计 CPU、GPU dedicated／shared。CPU 为累计内核＋用户时间差除墙钟，单位为一个逻辑核的百分比，不能与整机归一化 CPU 混用；GPU 内存不是利用率。

工作集、私有提交和 GPU dedicated／shared 是不同计量口径，不能简单相加作为总物理占用；它们也不等于原图、PCM 或缓存的逻辑容量。最终产品预算仍须纳入完整 UI、素材库、命令／历史及真实游玩成本。

阶段文件在前后读取一致时才接纳样本；播放和稳定空闲排除首次观察阶段后一秒，空闲有效跨度必须至少 60 秒。退出前先标记 Done，避免退出／序列化计入稳定空闲。记录峰值是稀疏采样观察值；历史峰值计数另列，含诊断成本，不能代替各阶段峰值归因。

核对现有预算：常规编辑工作集 ≤512 MiB；暂停／关闭稳定 CPU ≤单逻辑核 2%；框架编辑 CPU 帧 p95 ≤16.7 ms。私有提交与 GPU 内存单列，没有据此新增或放宽阈值。帧间隔用于报告实际节拍，不将 CPU 帧时间当作 60 Hz 保证；文档切换到接受的 host 延迟也不是物理输入、显示扫描或编辑到屏幕延迟。诊断像素验证不能替代 300 次显示延迟测试。

旧 80 MiB 原图纹理槽预算属于另一个缓存实验；本组合器使用自己的合成缓冲，没有启用该槽池，不能沿用其总进程或 GPU 峰值结论。

20 次切换的阶段序列与前后稳定观察用于识别持续增长迹象，不宣称能排除任意时长／系统压力下的泄漏。全量素材库缩略图、完整产品 UI／命令历史、压缩格式、重采样、设备变化、真实输入及真实游玩仍需后续验证。

## 复现

```text
python tools/check_p0_combined_soak.py
python tools/check_p0_combined_soak.py --run-native --fixture artifacts/p0/standard-fixture-9f325f13 --smoke --repetitions 1
python tools/check_p0_combined_soak.py --run-native --fixture artifacts/p0/standard-fixture-9f325f13 --repetitions 2
```

第一项执行媒体 feature 的边界、格式、Clippy、无窗口测试及 release 构建。PNG fixture 必须是仓库内已经生成并逐文件验过哈希的标准数据集；短轮仅播放三秒／切换两次，不评定预算。长轮顺序执行，每轮约八分钟。可以用 `--audio-fixture` 复用同一自制 WAV；`--skip-checks` 仅用于已经独立完成检查的二进制，源码及二进制身份仍冻结验证。

每轮将原生结果、全部逐包轨迹、阶段和进程采样、环境、源码／锁／二进制／fixture 哈希与日志写到全新 `artifacts/p0/combined-soak-*`。失败也保存计量，不能删除失败后只展示通过轮。拒绝覆盖既有目录与输出越界；不读旧源码、客户端资源或私人曲库，不录音，无需 F12。Linux 实测延期、macOS 待设备，不能将 Windows 结果推广到未测平台。

## 结果

本机为 Windows 10 x64、Ryzen 7 4800H／16 逻辑核、约 15.87 GiB 可见物理内存、RTX 2060／NVIDIA 560.94，Vulkan。结果仅适用于此环境与上述负载。

`combined-soak-ffd559cc` 与 `combined-soak-a2e984c3` 使用相同源码、二进制及 fixture，两轮全部行为／证据验证与本次九项预算检查通过。每轮 30003 个接受包／14405760 帧全部核对，欠载、解码失败和轨迹溢出均为 0，关闭后五块全归还、无在途或排队块。每轮完成 20 次切换、接纳 21 个文档；暂停下两次像素证明通过且图像不同，GPU／显示最大通道误差均为 1。
