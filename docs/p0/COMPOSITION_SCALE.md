# 标准规模合成与资源记录

这是 P0 合成实验的规模扩展，沿用[合成语义 v1](COMPOSITION.md)，未接入正式项目、预览器或旧 stable。2026-10-19 在 Windows／RTX 2060／Vulkan 上顺序运行两次独立进程，原始结果、源码快照及 PNG 哈希见 [windows-composition-scale.json](windows-composition-scale.json)。

## 输入与方法

使用现有自制标准 fixture：100 张 1024×1024 straight RGBA8 PNG、10 个文档、500 个图层。每个文档引用 10 张原图，含 50 个图层和 10 个嵌套组，生成 70 条只读操作；输出画布 1024×1024。只解码当前文档的 10 张原图，共 40 MiB，不把全项目 400 MiB 像素一次上传。

保留清单中的组结构和几何；本实验按合成语义 v1 隔离组并应用一次透明度，**没有使用旧 standard-load 的透明度平铺结果**。因此输入文件相同，颜色语义与旧加载实验不同，不能将其输出直接判为同一画面。CPU 与 GPU 在同一语义下逐像素比较，每通道预定容差仍为 2／255。

每次遍历全部 10 个文档：重新读取 PNG，CPU 参考合成一次，建立 GPU 常驻计划，首次回读比较并保存两张 PNG，再执行 30 次复用计划的派发与回读。每进程共 300 次温热派发；这些是相同计划的重复执行，**不是 300 次实际拖动或参数编辑**。所有重复输出须与本进程该文档的首次 GPU 输出完全相同。

GPU 适配层从单次入口中分离，保持 CPU 模块不依赖图形、UI 或文件系统。源像素、操作、输出和回读缓冲复用；没有新增第三方包或线程。显式 SMALL／STANDARD 预算分别控制旧小图与本轮 1024 边长、40 MiB 活跃源字节；它们是实验上限，不是产品格式限制。深度仍最多 8，节点及素材引用表最多 128，非法输入在 GPU 分配前失败。

## 两次结果

| 指标 | 第一次 | 第二次 |
| --- | ---: | ---: |
| CPU／GPU 比较像素数 | 10485760 | 10485760 |
| 最大通道差／超容差像素 | 1／255；0 | 1／255；0 |
| GPU 温热合成 p95 | 5.530 ms | 5.513 ms |
| 温热提交、等待与回读 p95 | 8.555 ms | 8.342 ms |
| 温热提交、等待与回读最大值 | 9.413 ms | 16.383 ms |
| 显式常驻缓冲 | 48.004 MiB | 48.004 MiB |
| 进程工作集采样峰值 | 191.3 MiB | 170.7 MiB |
| 进程私有提交采样峰值 | 374.9 MiB | 329.7 MiB |
| OS 生命周期提交峰值 | 374.9 MiB | 333.7 MiB |
| GPU Dedicated 采样峰值 | 97.0 MiB | 97.0 MiB |

CPU 每个文档约 1.5 秒，仅适合当前正确性参考，不能称为实时 CPU 路线。GPU 结果支持继续评估 compute 方案；尚未测量持续修改操作缓冲、异步取消、编辑器呈现和整个游戏场景的组合成本。

GPU 时间戳仅在设备支持 TIMESTAMP_QUERY 时启用，包围 compute pass，按队列返回的时间单位换算；不支持时保留 null。这个时间不含 PNG 解码、源上传、排队、回读及 PNG 保存。host 墙钟另列，不拿完成回调时间替代 GPU 时间。

常驻缓冲合计 50336176 字节：40 MiB 源、4 MiB 输出、4 MiB 回读、4480 字节操作、16 字节参数、32 字节时间戳解析／回读。组使用着色器线程内部栈，没有单独申请离屏组纹理；栈、寄存器与潜在溢出到私有内存的成本由驱动决定，尚未归因。这个数不包括源上传暂存、查询对象元数据、驱动或 CPU 原图，不能替代总内存。

Windows 采样每约 100 ms，只读取此脚本启动的 PID；样本包括 CPU 参考、PNG 保存及 GPU 等待。它不是完整 GUI、60 秒暂停或关闭后资源预算测试，不与既有 80 MiB 纹理池成绩作因果比较。

## 复核

```text
python tools/p0_workload.py artifacts/p0/composition-fixture
python tools/check_p0_composition.py --fixture artifacts/p0/composition-fixture
```

新 fixture 路径必须不存在，也可复用已生成的标准 fixture。入口先校验清单全部文件哈希，执行无窗口测试和九组小图 GPU 回归，再顺序测量两次标准规模。每次新建结果目录，保存源快照、输入身份、图像哈希及进程样本，并检查已有输出不会被覆盖。`--repetitions 1` 可用于单次复核，不冒充重复验证。

当前只在 Windows Vulkan 实测。蒙版、效果、色彩配置文件、几何覆盖率抗锯齿、mipmap／缩小时的质量策略、stable 色彩兼容、跨平台和真实编辑延迟仍开放。
