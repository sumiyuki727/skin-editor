# P0 压缩音频解码与原生输出

日期：2026-10-19。独立实验，默认关闭。只验证自制 MP3／Ogg Vorbis 与原有 WAV 基线，不是正式播放器、格式兼容承诺或 stable 声音规则。Windows 结果和未解决差异分别记录；Linux 实测延期，macOS 未测。

本文保留首轮实现和计量快照。**2026-10-20 续篇已用独立 libsndfile 与相同音频包的分页控制归因短 Ogg 差异，并为 Vorbis 接入准确定位**，见[尾部归因与定位](VORBIS_TAIL_AND_SEEK.md)。下文前缀重读限制及 216 项测试／旧性能数值属于首轮；MP3 仍保留前缀路径，旧产物不改写。

## 入口与依赖

```text
python tools/check_p0_compressed.py
python tools/check_p0_compressed.py --run-benchmark --run-native --repetitions 2 --fixture artifacts/p0/compressed-fixture-v2
```

第一项执行无窗口检查和构建，不打开输出设备。第二项复用本机已生成的自制 fixture，顺序执行离线读取与 Windows 原生播放，会播放很低幅度的合成音调，无 GUI、GPU、录音或系统窗口捕获。资源测量期间不并行编译或运行其他实验。

复现数据生成需另备 FFmpeg，当前已验证的准备与生成命令：

```text
python -m pip install --disable-pip-version-check --no-deps --retries 0 --timeout 30 --index-url https://pypi.org/simple --target .p0-tools/encoder imageio-ffmpeg==0.6.0
python tools/p0_compressed_fixture.py artifacts/p0/compressed-fixture-v2
```

生成入口拒绝已有目录；重复时换用新的 `artifacts/p0` 子目录。私有工具仅用于编码和独立参考解码，测试及实验播放器不调用 FFmpeg。便携 Rust 回归的压缩文件与参考样本在 `experiments/p0-media/tests/fixtures`，不依赖工具下载、真实设备或个人目录。

`p0-media/compressed` 仅增加 `mp3`／`ogg`／`vorbis`；`p0-egui/compressed-proof` 显式组合已有媒体 feature 和该能力。默认 GUI 不编译媒体库，原有 `media-proof` 仍只启用 WAV／PCM。锁文件只增加 Symphonia 0.6.1 的四个包：`symphonia-bundle-mp3`、`symphonia-codec-vorbis`、`symphonia-common`、`symphonia-format-ogg`，不升级既有版本，不启用 ID3、SIMD 或新平台 API feature。

Symphonia 为 MPL-2.0，属于 Rust 依赖的维护与分发清单；此处没有修改其源码。工具安装包 `imageio-ffmpeg 0.6.0` 的 Python 包与内附 FFmpeg 可执行文件许可不能混为一谈：本机 FFmpeg 7.1 的构建明确启用 GPL／version3，**不纳入产品分发**。可执行文件 SHA-256 为 `2ce797a0f88d7f067180338fb227f7b1928ea727bd9a4d7a1d022f7c52af71a3`。正式选型和打包时重查实际启用的依赖、许可及平台成本，不从本实验自动继承后端。

## 数据与正确性协议

- 输入为独立生成的 48 kHz 双声道 PCM16，持续 0.37／3／180 秒；MP3 使用 libmp3lame 192 kbps、Xing，关闭 ID3；Ogg 使用 libvorbis q4。原始 WAV、编码参数、压缩文件和 FFmpeg 原生浮点参考均登记哈希。
- 逐样本比较解码与独立参考，绝对容差 `1e-5`；报告样本数、最大差异、RMSE 和未比较尾部。长度不同单列未解决问题，不裁切后称通过。
- 在完整线性读取后，向半程、11 帧、末尾前 9 帧和 EOF 定位，再读取并逐字节对照本解码器的线性结果。跨实现比较使用浮点容差；同一实现的定位和传输要求精确一致。
- 原生播放使用同一五块 PCM 池、四块排队和单解码线程，设备仍为 48 kHz 双声道 float32。每轮先连续消费至少 30 秒，再暂停、定位到 90 秒和 0.5 秒，并显式恢复。定位计量包含请求到软件队列预备好至少 4800 帧的时间，不只报告控制确认。
- 原生接受包核对源位置、代次、全部样本哈希、增益、非零数量及探针；参考来自已经过独立解码比较的线性 PCM。四段暂停各至少 650 ms，多次新鲜快照必须保持位置不变且不提交新 PCM；暂停下游戏输入拒绝。关闭先释放设备，再加入解码线程，五块全部归还。

错误路径包括畸形／超限文件、截断后清空并失效、无效请求不改变状态；本轮还修复了完整读取后定位的累计帧数边界错误，并加入 EOF 后双向定位回归。既有受控欠载与恢复由 WAV 专项覆盖；本轮正常播放的零欠载不等同于压缩格式下的全部故障恢复。

## 资源边界与限制

媒体库只收 `Read + Seek`，没有路径、设备、线程、墙钟、UI 或项目写入权。WAV 仍委托原来的严格读取器。压缩输入要求单音轨、已知总帧数、1–2 声道、8–192 kHz、至多 600 秒／128 MiB；这些是实验防护上限，**不是 stable 规则**。

源缓冲 64 KiB，压缩包 PCM 缓存 64 KiB，调用方最多 4096 帧；最大压缩包 256 KiB／8192 帧，单实例至多解码 120000 个包（含定位重读）。后台池的逻辑 payload 为 160 KiB。解码器内部表、容器索引、线程栈、原生设备、分配器与有界诊断另计，不用缓存大小代替总进程内存。

为优先确认样本与代次正确性，压缩定位使用解码并丢弃前缀：前进从当前位置推进，后退从零重读，耗时随目标位置增长。180 秒文件的定位数据不代表任意长音乐的快速随机定位；后续索引／预滚优化必须保留相同样本回归。未实现重采样、混音、设备格式转换、VBR／标签／链式 Ogg 的完整覆盖及实际游玩。超出 `[-1,1]` 或非有限 PCM 明确失败；有损解码可能出现超幅，尚未确定正式限幅策略，不能声称任意正常音乐可播放。

Windows 进程峰值取包含启动的历史工作集／私有提交；采样值与历史峰值分别归档。离线 `decode_ms` 包含 float32 序列化和写文件；读取采用温热本地文件，不是冷盘基准。CPU 是本进程观测区间的累计核秒，不是整个系统的开销。本轮没有图形组合负载，不与此前 GPU 长时实验相减或视作完整预算。

## 首轮短 Ogg 尾部差异（后续已归因）

0.37 秒输入为 17760 帧。Symphonia 输出 17760，FFmpeg 原生 Vorbis 输出 17632，差 128 帧；公共前缀样本在容差内。另以 FFmpeg 的 libvorbis 解码器重查仍为 17632，但它共享 FFmpeg 解复用路径，不能据此断言哪一端错误。3 秒和 180 秒输入帧数一致。

首轮保留两端原始输出，不裁切或补静音，当时没有将短 Ogg 纳入全量解码通过项。后续已核对独立解复用／解码、granule 及分页边界，完整样本通过 libsndfile 参考；差异归因与适用范围见续篇。当前 stable 尚未进行本批音频对照，自有解码结果不等于 stable 解码语义。

## 结果与来源

同一组 115 份源码／锁／便携 fixture／工具身份，两次重复共 16 轮离线读取和 6 轮原生输出。离线 14 轮长度与样本比较通过；两轮短 Ogg 保留上述尾部冲突。3 秒／180 秒 MP3 的最大样本差异约 `9.54e-7`，Ogg 约 `1.49e-7`，均低于 `1e-5` 容差。

180 秒离线读取结果（两次范围，峰值为完整进程）：

| 编码 | 工作集峰值 MiB | 私有提交峰值 MiB | 解码＋序列化／写盘 ms | 半程定位 ms | 靠近末尾定位 ms |
| --- | --- | --- | --- | --- | --- |
| WAV | 3.566–3.570 | 0.863–0.867 | 115.8–124.6 | 0.062–0.074 | 0.027–0.045 |
| MP3 | 4.051–4.063 | 1.227–1.262 | 290.5–448.1 | 98.7–118.8 | 194.6–242.3 |
| Ogg Vorbis | 5.551–5.566 | 2.898 | 218.9–260.8 | 71.6–87.5 | 143.3–167.9 |

| 编码 | 工作集峰值 MiB | 私有提交峰值 MiB | 进程 CPU 核秒 | 整轮平均 CPU，占一逻辑核 | 定位 90 秒至预备好 ms |
| --- | --- | --- | --- | --- | --- |
| WAV | 21.375–22.652 | 14.730–17.801 | 0.031–0.047 | 0.089–0.134% | 32.6–33.0 |
| MP3 | 20.602–23.297 | 15.094–18.652 | 0.281–0.344 | 0.799–0.977% | 130.7–131.8 |
| Ogg Vorbis | 20.094–23.340 | 14.496–18.750 | 0.297–0.313 | 0.847–0.889% | 110.3–121.0 |

六轮报告欠载、解码失败和轨迹溢出均为 0；共 **12316** 个原生接受包全部核对，24 段暂停均至少 650 ms，新代次暂停提交为 0，关闭后各五块全归还。上述 CPU 包含暂停、定位与诊断，不是单独播放区间的稳态 CPU；低量计数受 Windows 时间粒度影响。原生峰值包含线程、设备、轨迹和最终 JSON 序列化，不按编码差额直接归因给解码器，也不是图形组合预算。

原生 MP3／Ogg 向后定位到 0.5 秒的预备等待约 76–110 ms；控制确认不足以说明准备完成，既有 worker 取消／前缀重读成本亦可能参与，尚未细分。应先改进索引和取消交接，再制定正式随机定位预算。没有为了降低观测延迟而跳过首尾样本或旧块校验。

本轮无窗口共 **216** 项通过：GUI 74、WASAPI 22、媒体 17、契约 10、Python 93；默认、WAV 和压缩 feature 的格式、Clippy、测试、release 构建通过。两个控制台的输出越界、覆盖、输入越界及多余参数共八项在握手／设备初始化前拒绝，原输出哈希保持不变。可执行文件大小约 0.971 MiB（离线）／1.172 MiB（原生）；这只是本轮静态链接实验产物，不是产品安装体积。

完整身份和数据见 [windows-compressed-audio.json](windows-compressed-audio.json)；原始产物在 `artifacts/p0/compressed-*`，每轮单独冻结源码、锁文件、fixture 与工具，并保存可执行文件和哈希。首个 fixture 因参考命名碰撞失败、最初六个探索读取在 EOF 后定位触发累计帧数错误，均保留原产物且不计成绩；修正并补回归后使用全新最终轮次。另六个修正后探索读取不纳入性能范围。
