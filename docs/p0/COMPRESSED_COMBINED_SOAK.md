# 压缩音频与标准图形的长时组合验证

日期：2026-10-20。沿用 [WAV 组合协议](COMBINED_SOAK.md)，增加同源 WAV／MP3／Ogg Vorbis 对照。状态：六轮组件级长时验证及 54 项既有预算检查通过，P0 整体仍在进行。它是默认关闭的 P0 候选实验，不是 stable 内核、完整产品或实际游玩验收。

## 固定负载与证据

- 图形：100 张 1024² 原图、10 文档、500 图层；活动文档引用 10 张原图并合成 50 层。每帧最多上传两张／8 MiB，pipeline 预热后开始播放。播放中持续提交可取消的值命令草稿，前 200 秒每十秒切换一次，共 20 次。
- 音频：同一自制 600 秒、48 kHz 双声道 PCM16 源；WAV 直接使用源，MP3 为 libmp3lame 192 kbit/s／Xing、Ogg 为 libvorbis q4。设备接收同采样率／声道 float32，增益 0.002，不自动重采样或修改系统音量。它们不是私人音乐或客户端素材。
- 三种格式使用同一个启用 `compressed-proof` 的二进制，解码仍在单 worker 中，经五块／160 KiB PCM 池传给原生输出。文档切换不重开音频、不复位设备时钟。
- 每轮实际连续消费至少 300 秒，暂停后直接回读两次自有 CPU／GPU／显示目标，证明同一模拟时间下编辑改变像素；然后暂停稳定十秒并观察 65 秒，关闭活动资源、稳定十秒后再观察 65 秒。正常路径不做 CPU 像素回读，不捕获系统窗口。
- 顺序重复两组 WAV→MP3→Ogg，共六轮；另有原 WAV 入口及三种格式的短轮验证。短轮不评定长时预算。

编码、独立参考与完整线性解码先于组合测试完成，不与资源采样并行。WAV 参考由标准库按 PCM16→float32 转换；压缩文件先完整对照固定 FFmpeg 7.1 的独立参考，要求帧数相同、全部样本在 `1e-5` 内。原生逐包哈希参考使用已通过独立校验的完整 P0 线性结果，避免将不同解码器的小数差异误记为输出错误。

准备和校验已经预热文件系统缓存，本组不是冷盘测试。

每个原生接受包按源位置、双声道样本、增益、哈希和非零数核对；参考按需读取，完整 PCM 不进入被测进程。600 秒参考上限与文件大小在设备启动前检查；`soak.json` 绑定源、完整解码证明及媒体源码身份，不接受缺失尾部、被改写源或旧解码器的未复核参考。

私有 FFmpeg 仅离线生成 fixture／参考，许可与身份沿用[压缩首轮记录](COMPRESSED_AUDIO.md)，不进入产品、核心测试、原生进程或构建依赖。没有新增 Cargo 包、平台 API、unsafe 或生产线程；仅扩展组合入口的诊断字段和 Python 证据工具。原 WAV 工具仍构建 `media-proof`；新工具明确检查 `compressed-proof`，防止 feature 不匹配的二进制被误计为压缩测试。

## 计量与预算

沿用既有门槛，不根据结果调整：播放及正常流程采样工作集 ≤512 MiB；暂停／关闭稳定 CPU ≤一个逻辑核的 2%，有效观察跨度各至少 60 秒；编辑框架 CPU 帧 p95 ≤16.7 ms；暂停／关闭不连续重画。每轮九项预算检查，缺失、失败或非布尔预算字段不能计为通过。GPU 计量缺失时保留不完整状态。

播放 CPU、私有提交、GPU dedicated／shared、框架回调间隔、切换延迟及 30 秒分窗趋势均单列。播放 CPU 目前没有独立数值上限，私有提交／GPU 也尚未定正式上限；不能把它们描述为通过了不存在的预算，不能将这些口径相加。CPU 帧时间不等于物理输入到显示延迟，接受包检查不等于声学中断检测。

采样每 200 ms 一次，只读取本次启动进程及对应 PID 的 GPU 计数；阶段切换前后不一致的样本丢弃，播放／稳定空闲排除观察到新阶段的首秒。诊断像素校验与正常绘制分别计量；历史峰值包含初始化、诊断和关闭序列化。关闭后保留图形设备、pipeline 和框架会话，不等于空项目或进程全部释放。

所有源码、锁、便携 fixture、工具和二进制在六轮之间保持不变，每轮保存快照及原始轨迹／采样，失败结果同样保留。参考校验在被测进程结束后进行，不与下一轮播放并行。重复运行使用新目录，不覆盖历史。

## 可复现入口

```text
python tools/check_p0_compressed_soak.py
python tools/check_p0_compressed_soak.py --skip-checks --prepare-audio artifacts/p0/compressed-soak-audio-v1
python tools/check_p0_compressed_soak.py --skip-checks --run-native --smoke --repetitions 1 --fixture artifacts/p0/standard-fixture-9f325f13 --audio-fixture artifacts/p0/compressed-soak-audio-v1
python tools/check_p0_compressed_soak.py --skip-checks --run-native --repetitions 2 --fixture artifacts/p0/standard-fixture-9f325f13 --audio-fixture artifacts/p0/compressed-soak-audio-v1
```

首项检查并构建，不打开设备。准备音频需要已有的私有编码工具，输出必须尚未存在；600 秒源和全部参考约占 GiB 级磁盘空间，不是播放内存成本。图形 fixture 必须已生成并逐文件验证，亦可按 `tools/p0_workload.py` 创建新标准集。

原生入口仅在 Windows 验证，使用 Vulkan 和默认 WASAPI 输出；不适配不匹配端点，不替用户切设备。`--skip-checks` 只用于已验证的正确 feature 构建。Linux 实测暂缓，macOS 待设备；本轮无需 F12，不访问旧 stable 源码或私人曲库。

## 结果

准备阶段已完成：三种格式各 **28800000** 帧／**57600000** 声道样本完整对照，帧数全部一致，没有裁切、补齐或未比较尾部。最大绝对差分别为 WAV **0**、MP3 **9.54e-7**、Ogg **1.49e-7**，均在 `1e-5` 内。

原 WAV 入口及新压缩构建的 WAV／MP3／Ogg 短轮已通过；短轮不评定长时预算。无窗口 **236** 项通过（压缩 GUI 77、WASAPI 23、压缩媒体 22、契约 10、Python 104），相关格式、Clippy 与 release 构建通过；新增七项证据工具测试。

全部 **180010** 个接受包／**86434560** 帧按参考完整核对；包大小可变，不能按固定包数推算时长。共完成 **120** 次文档切换、**108145** 次草稿更新及 **246** 个实验命令节点。欠载、解码失败、轨迹溢出和报告的 GPU 错误均为 **0**；每轮关闭后五块 PCM 全部归还，无在途或排队块。暂停编辑的十二次直接像素检查全部通过。

每轮九项既有预算检查全部通过。暂停／关闭稳定段各有 **63.61–63.89 秒**有效采样，暂停 CPU 为 **0–0.0246%**，关闭 CPU 计数均未增加；十二段空闲各只绘制一帧。计数未增加受系统时间粒度限制，不表示物理零功耗。

正常阶段 GPU dedicated 峰值 **167.855–171.105 MiB**，shared **54.281–56.484 MiB**；包括初始化、像素诊断和退出序列化的历史工作集峰值 **268.113–270.820 MiB**、历史私有提交峰值 **388.652–395.578 MiB**。它们与表中正常采样峰值口径不同，不能相加或相减作为净成本。私有提交／GPU 尚无正式数值上限。

前 200 秒有文档加载和切换，提交占用会上下波动。最后三个 30 秒窗口的末次私有提交为 **295.24–298.07 MiB**，各轮三点跨度均小于 **0.06 MiB**；关闭末次工作集 **168.56–177.05 MiB**，私有提交 **196.20–200.38 MiB**。本批未观察到持续增长，但六段五分钟测试不能证明无长期泄漏，也不能精确拆分驱动、覆盖层和堆保留。

### 保留的长帧与适用范围

框架回调间隔 p95 为 **17.133–17.155 ms**，最大 **25.668–86.999 ms**。两轮 MP3 分别有 **3／2** 个框架 CPU 帧超过 16.7 ms；第二轮有一个 **64.761 ms** CPU 帧及十个超过 33.3 ms 的回调间隔。软件音频队列没有同时报告欠载，但尚无隔离诊断可将停顿归因于解码、驱动或系统调度。p95 门槛通过不表示所有帧达标，也不表示严格 60 Hz 或可听无中断；若后续交互或预算要求消除这些长帧，应单独诊断，不能改写本轮原始结果。

三种格式的 CPU／工作集处于相近范围，这一顺序重复不足以证明格式间的小差异有因果关系。播放 CPU 上限、私有提交／GPU 上限、物理输入／显示／声学延迟均未验收。真实音乐／标签、非零起点／链式流、冷盘和系统压力、重采样／声道转换／设备变化仍开放；正式历史和实际游玩成本留待对应产品阶段验证，不把未实现功能纳入本次通过范围。

本次固定 **121** 份源码／锁／便携 fixture／工具及同一压缩二进制，六轮快照全部复核；相对上一轮只有五份入口／证据工具源码变化，未改变 worker、解码、队列或合成行为。机器记录包含完整源身份、每轮原始结果／轨迹哈希、30 秒分窗、编译 feature 和预算：[windows-compressed-combined-soak.json](windows-compressed-combined-soak.json)。复现编排及原始结果留在忽略的 `artifacts/p0`，正式记录不依赖该目录构建或运行。
