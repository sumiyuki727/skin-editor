# 连续编辑、GPU 合成与界面呈现

2026-10-19，P0 的可取消拖动已连接到[标准合成](COMPOSITION_SCALE.md)的同一只读计划与 GPU 执行器。两次普通呈现和两次逐次回读运行通过，使用相同 exe 和 fixture；来源、结果哈希及原始目录见 [windows-edit-composition.json](windows-edit-composition.json)。这仍是实验，没有建立正式项目核心或 stable 内核。

## 范围与数据流

取现有 100 原图／10 文档 fixture 的文档 0：1024² 画布、10 张原图、50 层、10 个隔离组。选定首个叶实例，连续移动 300 次，支持草稿、取消和单次提交。此次没有把全部 500 层同时放进一个文档，也没有验证缩放／旋转控制柄、任意图层选择或异步文档切换。

```text
egui 输入 → 命令会话拥有者 → 只读位置投影 → 只读合成计划
                                      ↓
                              操作缓冲更新 → GPU 合成
                                                ↓
                                    GPU 显示适配 → egui 纹理
```

UI 不持有可变项目／草稿引用；合成器只消费位置值和不可变 fixture。文档位移经父矩阵逆变换转换到实例局部空间，保留父组旋转、缩放与其他实例；新增无窗口像素测试覆盖这一点。取消不回写已发布节点，松开只形成一个节点。

源素材以共享不可变 `Arc<[Image]>` 保持存活。更新计划必须绑定同一素材集合、相同画布和操作数量，否则在写 GPU 前失败；不能将不同源像素误套到旧 GPU 缓存。这里的内存身份仅用于此 GPU 派生计划的绑定校验，不是项目、图层或历史节点 ID。

原图只在建立 GPU 计划时上传 40 MiB。每个位置变化只上传 70×64＝4480 字节操作；初始、首个草稿、取消及第二次手势的 300 次移动共 303 次更新，合计 1357440 字节。提交位置未变化时不重新合成。GPU 显示纹理直接注册给 egui，普通呈现不经过 CPU 像素回读或 CPU 纹理重传。

导出参考结果仍为 straight RGBA8／sRGB。独立显示适配在 GPU 上将其按 linear-light 合成到固定编辑器背景 `[18,22,30]`，输出不透明 Rgba8Unorm 供 egui 使用，避免误用 straight alpha 或重复 premultiply；不修改导出缓冲。四个关键状态同时验证 CPU／GPU 导出像素及显示纹理对 CPU 显示参考，每通道容差均为 2／255。

## 结果

Windows／RTX 2060／Vulkan，MemoryUsage，1100×720 自有隐藏窗口，AutoNoVsync；两种运行各重复两次。输入为合成 egui RawInput，经过与手动模式相同的控件及命令路径。

| 指标 | 普通 1 | 回读 1 | 普通 2 | 回读 2 |
| --- | ---: | ---: | ---: | ---: |
| 连续变换数量 | 300 | 300 | 300 | 300 |
| 控件／计划／提交 host p95 | 0.562 ms | 0.313 ms | 0.575 ms | 0.276 ms |
| 输入进入控件至界面回读 p95 | 未测 | 9.377 ms | 未测 | 9.724 ms |
| 界面回读最大值 | 未测 | 12.108 ms | 未测 | 11.446 ms |
| CPU／GPU 导出最大通道差 | 1／255 | 1／255 | 1／255 | 1／255 |
| 显示纹理最大通道差 | 1／255 | 1／255 | 1／255 | 1／255 |
| 私有提交采样峰值 | 264.2 MiB | 260.4 MiB | 258.6 MiB | 260.2 MiB |
| GPU Dedicated 采样峰值 | 88.1 MiB | 88.1 MiB | 122.8 MiB | 88.1 MiB |

四组关键画面均验证：草稿变化；Esc 后中央画布逐字节恢复；第二次手势提交变化；模拟时钟始终为 0，游戏输入始终为 0；历史节点数量为 1、1、1、2。逐次回读组另有 300 次界面回读，只保存第 1／100／200／300 次图片，其余只保留耗时。

host 耗时包围控件处理、计划编译、操作写入及提交，不含完整 eframe 帧的后续工作或 GPU 执行，不能称为完整帧时间。回读耗时从合成事件进入 input hook 到自有渲染截图回调，不是物理鼠标至显示器延迟。两类运行分进程；不能把回读组 host 时间更短解读为回读优化。

显式常驻缓冲约 48.004 MiB，显示纹理另 4 MiB；四个关键状态的诊断还临时申请 4 MiB 显示回读缓冲。普通路径保留但不使用合成回读缓冲。驱动、组线程栈、上传暂存、窗口资源及 CPU 像素不包含在上述显式预算中。约 100 ms 的自有 PID 采样包含 CPU 参考和 PNG 保存，未完成 60 秒暂停／关闭观察，不作为整个应用资源预算成绩，也不与旧纹理池试验作因果比较。

## 复核与限制

```text
python tools/check_p0_edit_composition.py --fixture artifacts/p0/gpu-fixture
experiments/p0-egui/target/release/interaction-proof.exe --interactive --fixture artifacts/p0/gpu-fixture
```

fixture 须已由 `p0_workload.py` 生成；自动入口先校验全部文件哈希，运行无窗口检查和九组小图 GPU 回归，再顺序执行四组新进程。保存源码快照、输入身份、原始耗时及 PNG 哈希，拒绝目录越界和覆盖已有证据。手动模式尚未人工验收。

首轮出现 WGSL 保留标识符导致编译失败，已修正并保留日志。另一轮严格比较 UI 坐标时发现 f32 屏幕运算约 0.000004 文档像素的差异；坐标断言显式采用 0.0001 像素容差，增加异常／超差／非有限值回归。没有修改素材、像素判定或 RGBA 容差。

当前只有单队列有序提交，没有异步合成 worker；取消后的新投影在队列中排在旧草稿之后。关键状态回读验证了最后结果，没有宣称能抢占已提交的物理工作。初次 PNG 加载仍同步，既有后台加载器尚未连接到此闭环。真实输入、IME、DPI、全屏、音频联动、低延迟游玩、跨平台和 stable 兼容仍待验证。

后续进展：[TRANSPORT.md](TRANSPORT.md)新增了同进程真实静音输出时钟／模拟／输入的联动证据，以及后台加载接入的像素和组语义审查。本文四轮性能与回读结果保持原始范围，不混入后续的阻塞 CPU 参考检查。
