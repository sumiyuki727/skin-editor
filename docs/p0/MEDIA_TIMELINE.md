# 音频文件与最小对象时间线

P0 独立原型把“读取真实音频文件、解码、设备消费位置、对象时间线”接在一起。它不实现 stable 判定、皮肤规则或实际游玩；当前只接受自制的短 WAV 和受限 v14 单击对象 fixture。Linux 实测暂缓，macOS 待设备，纯逻辑测试无需窗口或音频设备。

此记录保留短文件原型及原始证据；后续[有界按需解码](STREAMING_AUDIO.md)单独验证长 WAV，不回写本批设备结果或宣称流式输出已接入。

## 模块与数据流

```text
自制文件 → 组装入口受限读取 → p0-media 解码／解析
                          ├→ 不可变 float32 样本 → WASAPI 自有线程
                          └→ 只读对象／时间线          ↓
                             ↑                  设备位置快照
                             └────纯 Transport 的已确认内容位置
```

`p0-media::audio` 从有界字节解码，不打开文件、不接触 GUI、原生设备或项目。`chart` 不依赖解码器、墙钟或平台；节点身份按 fixture 内对象顺序分配，重复时间仍是不同对象。二者不是正式 domain、compatibility 或项目文件格式。

原生组装入口读取明确指定的自制目录，拒绝资源逃逸及越界／重复输出。它先完整解码并验证，再打开设备；当前没有 UI 窗口或后台文档加载器，不宣称已实现异步音乐加载。解码失败不发布部分 PCM。输出适配器只接收采样率、声道、不可变样本和显式增益，不依赖解码库、文件名或谱面。

现有 `Output` 仍为快照、暂停意图、显式代次／内容起点替换三个方法。文件播放与旧的生成音调／静音共用设备线程、8 项控制队列、格式校验和提交确认；新流仍暂停，显式播放后才提交。设备消费位置决定模拟时间，提交前沿不充当播放头；读取、解码、平台输出和时间线各有单向边界，无新通用播放器或插件框架。

## 范围与来源

公开 [.osu 格式说明](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format))和[官方 wiki 原文](https://github.com/ppy/osu-wiki/blob/master/wiki/Client/File_formats/osu_(file_format)/en.md)在 2026-10-19 核对：版本行、General、相对音频名、Mode、AudioLeadIn，以及对象位置／音频起点毫秒时间／类型位与单击对象字段。实现只使用这些格式事实，未读旧 stable 源码，不从 lazer 实现移植行为。公开规范和自制文件成功解析不等于当前 stable 兼容验收，客户端案例仍为 0。

当前子集：

- 明确的 `osu file format v14`、`Mode: 0`、同目录单个音频文件名；AudioLeadIn 仅为 0。
- 至多 64 KiB 文本、1024 个对象、6 秒对象时间。只接受普通单击对象与默认 hitsample，保留重复时间的不同 ID。
- 不支持的配置、section、对象、声音字段与版本返回带行号／种类的错误，不静默丢弃。该只读 fixture 解析器不是通用 `.osu` 导入器，不保存或改写输入。
- 场景窗口显式取对象时间前 150 ms、后 100 ms，仅用于 fixture 状态求值，不是 stable AR、命中窗口或消失动画规则。

普通位置推进只接纳单调的已确认内容时间；事件跨越仅发出一次，暂停时相同位置反复求值不发出新事件。显式定位在设备新代次暂停确认后才更新：向前定位跳过旧事件，向后定位重新求值后续事件，没有分数、命中或历史节点。输入仍由 Transport 门控，暂停／held／repeat 不重放。

## 解码依赖与资源边界

独立 `p0-media` 锁定 [Symphonia 0.6.1](https://docs.rs/crate/symphonia/0.6.1)（MPL-2.0，公开 Rust 解码库），关闭默认功能，仅启用 `wav`／`pcm`。未启用 MP3、Vorbis、AAC、SIMD／FFT 等额外功能，不把上游支持列表当作本项目已经验收的格式。库要求 Rust 1.85，本实验沿用私有 1.95；未决定正式技术栈。GUI 通过默认关闭的 `media-proof` feature 引用它，默认 GUI 构建不编译解码器，WASAPI 包依赖仍只有既有 Windows bindings。

相对上一轮 GUI 锁新增九个第三方包：Symphonia 主包、core、metadata、format-riff、codec-pcm 均为 0.6.1，以及 `extended 0.1.0`、`lazy_static 1.5.1`、`num-complex 0.4.6`、`regex-lite 0.1.9`；没有升级或删除既有版本。纯包自己的锁还包含已在 GUI 锁中的基础库。新代码继续禁止 unsafe；原生缓冲操作仍只在既有平台文件，没有新增平台 API feature。

编码输入上限 8 MiB，最终解码 float32 payload 上限 16 MiB，单／双声道、8–192 kHz、最长 6 秒。校验 RIFF 总长度、完整帧数、稳定格式与有限归一化样本，禁用无关元数据／附图预算。上限是输入和结果 payload，解码器暂存、Vec 容量、转为 Arc 时的临时复制及分配器保留另计，不是总提交预算。本轮不声称处理任意恶意音频的内存／CPU 上界。

输出必须与设备采样率／声道完全匹配，不做重采样或隐式混音。增益明确为 0.04，样本峰值受诊断预算限制；保留左右声道差异，EOF 以零填充，不循环。提交成功才推进源帧游标；失败可重试，设备重建仍使用同一已验证样本集合和新内容起点。长音频、流式解码／缓存、重采样及压缩格式路线仍开放，不能把短 WAV 整段解码作为最终播放器设计。

## 入口与验证

```text
python tools/check_p0_media.py
python tools/check_p0_media.py --run-native --repetitions 3
```

第一项检查新包的格式、Clippy、无窗口测试、依赖边界及可选 GUI feature 构建。第二项额外生成新的 `artifacts/p0/media-fixture-*`，顺序运行三轮原生程序，短暂播放低幅度自制文件；不改默认设备／系统音量、不录音、不读客户端资源，也不需要 F12。Linux／macOS 仅保留可适配边界，未宣称构建或实机通过。

fixture 含三秒 48 kHz 双声道 PCM16 WAV、Unicode 音频文件名和 6 个单击对象（250、500、500、900、1400、2100 ms）。左右声道使用不同频率／幅度，便于发现声道复制错误。编码字节 576044，解码 payload 1152000 字节，均与 GUI／GPU 标准负载分开。

每轮播放到约 600 ms → 暂停 350 ms → 定位到 1100 ms → 播放到约 1600 ms／暂停 → 向后定位到 100 ms → 播放到约 600 ms／暂停。三个内容代次的事件集合分别为 `[1,2,3]`、`[5]`、`[1,2,3]`；两个 500 ms 对象保持独立。定位暂停确认之前不改时间线，新流在显式恢复前提交帧数为 0。

Python 以标准库 WAV 读取和独立 float32 增益计算，逐个核对原生包首／末的全声道 FNV 哈希、峰值、非零样本及前八帧探针，分别检查提交游标、设备位置和内容起点。原生暂停期间也比较完整对象状态、不变的提交帧数及新鲜设备样本；输出、fixture、源码、锁文件、二进制与环境身份一同保存。错误时不因内部成功标记而放行。

该批无窗口检查涵盖 6 项媒体、11 项适配器、71 项 GUI（含可选文件读取）、10 项契约和 58 项 Python 测试，共 156 项。新增测试覆盖损坏／截断／超限输入、声道和归一化、重复对象身份、Unsupported、暂停／重定位、文件 PCM EOF／增益／失败提交、依赖方向、完整本地依赖归档及证据拒绝。原生重复结果登记在 [windows-media-timeline.json](windows-media-timeline.json)，以实际记录为准。

## 本轮结果

首次三轮 `media-999fef4d`、`media-4f5d0d28`、`media-7348d644` 使用相同 exe、源码及 fixture 身份，全部通过；补充原生文件读取的无窗口回归后，`media-8897c34f` 用另一明确标识的构建再通过一次，不把它混入首批同构建重复。扩展共用归档清单后，`media-8867f257` 以后一 exe 和新的工具身份复核通过。每轮三个暂停区间均各有 3 个新鲜设备样本，设备位置跨度与提交帧数跨度均为 **0**；向前／向后定位分别确认在 **1100000／100000 µs**，新流提交 **0** 帧。三代次事件集合均符合预期，接纳脚本输入 **2** 次。

五轮字节到已验证媒体 Clip 的解码墙钟分别为 **1.457／1.379／1.387／1.435／1.455 ms**。这是内存中的短 WAV 解码计量，包括解码库初始化与 Clip 构造，不含读盘、输出适配器再次样本校验或打开设备，不当作端到端加载、待机或资源预算。编码与解码文件内容及所有原生包的独立参考核对通过。

默认、`device-audio` 和 `media-proof` 的格式、Clippy、测试及 release 构建通过。初次生成 PCM／静音恢复回归均通过，但共用归档清单漏列新增的可选本地媒体包；补齐并加入无设备回归后，以 `pcm-f31ce58c`、`recovery-2ce2beaf` 重新验证并完整归档，两轮均通过，四个 CPU／GPU／显示对照仍通过。早先记录保留且单列归档限制，不改写原始证据。未重复与本次文件／输出变更无关的完整 GPU 性能预算流程。

## 尚未关闭的门槛

本原型无图形窗口、图层编辑或判定，不将已有 GPU 原型成绩拼接为本轮端到端表现。设备接受文件 PCM 不代表本轮已做听感或声学延迟验证；脚本输入不代表物理键到声音同步。组合资源预算、压缩格式／流式与重采样、真实设备切换、最小实际玩法及后端最终选择继续开放。完整游玩仍按 P5 交付。
