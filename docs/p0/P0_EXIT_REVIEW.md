# P0 收口评审与 P1 准入

日期：2026-10-20，评审基线 v1。**范围与工程决策已收口，允许进入 P1 无窗口核心；P1 尚未开始。** 本轮只整理决策、证据和门槛，不创建正式工程，也不宣布完整产品、全部 stable 兼容或跨平台验收通过。

本文保留 P0 准入时的评审状态；此后 P1-0 已启动并完成 Windows 工程检查，当前事实见 [P1 进度](../P1_PROGRESS.md)。原有未完成的兼容、资源与平台门槛不因此变为通过。

## 决定与依据

P0 的退出产物是可行路线、首轮范围、技术与平台基线、预算及剩余风险。现有实验足以支持独立 Rust 核心，并已验证 GPU 合成、暂停刷新、桌面输入、后台音频和设备代次的组件路线。完整功能仍按 P1–P7 实现、集成和验收；这些门槛有明确的后续阻断位置，不以原型结果替代。

| 准入项 | 本次结论 | 可审查依据 |
| --- | --- | --- |
| G01 来源隔离 | 满足。旧 stable 仅研究；独立实现，不作为构建／测试／运行依赖 | [研究边界](REPORT.md)、[架构 D11](../ARCHITECTURE.md#当前决策记录) |
| G02 首轮范围 | 满足。首玩法选 osu!standard；P2 占位编辑，首个兼容增量选单击对象及光标的 15 个静态文件 | [范围 v1](PREVIEW_SCOPE.md#首轮范围基线-v1)；没有将单击对象宣称为完整 standard |
| G03 核心及宿主方向 | 满足。P1 采用 Rust 1.95.0／2024 edition；P2 以 egui／eframe＋wgpu 为集成基线 | [技术决策](../TECH_STACK.md#本次选型结论)；UI、GPU、平台音频不进入 P1 核心依赖 |
| G04 平台范围 | 满足。Windows x64 先行；Linux 实测延期、macOS 待设备；纯核心无平台 API | [平台基线](../TECH_STACK.md#平台与依赖基线)；只声明已测参考机，不虚构最低 GPU／系统要求 |
| G05 资源路线与预算 | 满足准入。已有固定负载数据；保留旧门槛，新增工程预算明确为待测 | [资源预算](RESOURCE_BUDGET.md)；P1 不需要未实现的 GUI／游玩先通过产品预算 |
| G06 核心契约及维护规则 | 满足准备条件。模块、Command、原子事务、历史分叉和不可变资源约束明确 | [架构](../ARCHITECTURE.md)、[P1 启动增量](../P1_PLAN.md)；正式检查须先于功能代码建立 |
| G07 验证与风险交接 | 满足。每项未测／缺陷均关联阶段门槛，没有用测试数换算完成率 | 下表及 [245 项最近检查](AUDIO_ADAPTATION.md#检查与证据)；正式核心尚无实现或测试成绩 |

P1 的准入不要求先实现 P3 保存、P4 全部皮肤表现或 P5 实际游玩。P1 仅允许建立无窗口项目核心、命令、事务、会话历史及查询；不引入 UI、GPU、解码器、设备对象、旧实验包或旧源码。若启动时无法建立独立检查入口、单向依赖或可用工具链，停在启动增量修复，不能继续叠加功能。

## 本轮工作边界

本轮重读并核对既有机器记录、源码身份及已锁定依赖元数据，新增的预算只作工程决策，不回填旧记录为通过。未运行新的 GUI／GPU／音频轮，也不把上轮 245 项说成本轮新测。P0 原始实验和历史报告保留原身份，当前决策以本文及资源／范围基线为准。[决策与证据索引 v1](p0-exit-review.json)记录所引用材料的哈希、准入范围及未完成门槛；它是本次评审快照，不是新增性能成绩，后续评审须记录变更依据。

进入 P1 时按 [实施顺序](../P1_PLAN.md)从启动增量开始；本轮未创建正式工程、安装依赖、修改系统设置或提交／推送 Git。
