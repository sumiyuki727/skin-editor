# 精简预览器的功能边界

建立日期：2026-10-18；首轮范围 v1 定稿：2026-10-20，同日补充[设置、输入、区域及最终组件覆盖](../PREVIEW_SETTINGS.md)。用户已确认原版客户端包含大量非必要业务功能，预览器应围绕皮肤编辑与离线测试进行简化。本文约束的是独立实现的预览器，不是修改或裁剪非开源旧客户端，也不改变外部原版 stable 的安装。范围定稿不表示产品功能已经实现，准入结论见 [P0 收口评审](P0_EXIT_REVIEW.md)。

## 首轮范围基线 v1

首个玩法选 **osu!standard、No Mod 的本地离线测试**，依据是现有自制单击对象 fixture、当前客户端对照及图形／音频路线。其他玩法及额外 Mods 后续另立范围；完整 standard 支持不能只交付单击对象。

| 增量 | 确定范围 | 验收与限制 |
| --- | --- | --- |
| P1 无窗口核心 | 素材、分层文档、配置值、Command、事务、会话历史和只读契约 | 不含游戏规则、GPU 或设备；后端只接收只读项目投影 |
| P2 首个编辑预览 | 单一自有测试场景，素材库→图层／嵌套组→变换→草稿／取消／提交→暂停下像素刷新→历史往返 | 占位场景；独立场景栏、Edit／Interact、普通折叠面板与控制柄；布局不锁定，不做停靠系统 |
| P3/P4 首个兼容增量 | standard 固定单击对象场景＋光标，共 15 个静态 PNG 文件；直接进入本地测试状态 | C01–C04、C09/C10 对应行为有证据和回归后才标支持；不含完整判定／游玩、序列动画或所有配置组合 |
| P4/P5 需要的场景 | 本地菜单、选歌、游玩、游戏暂停、结算；最小导航与明确注入的本地状态 | 逐场景增加必要 GUI 状态、动画和声音；不做账号、网络或完整曲库 |
| P5 首个可游玩玩法 | standard 的单击对象、滑条、spinner、必要 HUD、声音、输入、判定、结果反馈、全屏与返回编辑 | 谱面子集须声明；只有小型单击测试时标为子集，不称完整 standard。不得借“精简”删去这些能力 |

首批 15 个文件：`hitcircle.png`、`hitcircleoverlay.png`、`approachcircle.png`、`default-0.png` 至 `default-9.png`、`cursor.png`、`cursortrail.png`。文件是导出映射，ElementDocument／Asset／Layer／SceneInstance 各有独立 ID；数字前缀、分辨率变体和序列不是列表的隐含承诺。名称以[官方 standard 元素说明](https://osu.ppy.sh/wiki/en/Skinning/osu%21)及[界面光标条目](https://osu.ppy.sh/wiki/en/Skinning/Interface#cursor)为研究依据（2026-10-20 查阅），布局、着色、缩放、时序、叠加和查找规则另附验证。

首个兼容对照先固定为当前证据条件：b20260924.1／Stable、1920×1080 全屏、Windows 100%、No Mod；这不是编辑器窗口尺寸限制或全部分辨率支持声明。初始场景可注入一个或多个单击对象、数字及光标位置，固定模拟时间便于重复比较；真实对象生命周期在 P5 验收。

配置先提供节／键／原值的无损模型与编辑，含 Name／Author／Version 元数据的原值；P1 不解释 Version 的默认行为。首个兼容增量使用明确的 fixture 配置组合，未验证的 combo 色、数字前缀／间距、叠加开关及其他项保存原文并标未支持，不能伪装为已应用。自定义配置语义先补 C09/C10；序列动画在 C05/C06 后扩展，声音规则在 C11 后扩展。

缺失、存在且全透明、解码失败和未支持必须区分。缺失 overlay 在当前客户端使用默认素材已有定性证据，但产品不能提取该素材；自制／明确授权的兼容默认资源尚未验收。首批内置支持声明先限定已提供素材的组合；无可用默认资源时返回明确的未支持诊断，不能把诊断占位图描述为 stable 默认效果。P3 保存未知附件和原值，导出支持集以外内容须明确透传或报错，不静默丢失。

编辑器冻结覆盖模拟、动画、音频进度和游戏输入，继续允许选择、变换、场景控制和刷新；普通游戏暂停菜单是单独状态。素材修改保留场景实例、模拟时间与已定义的动画相位；帧集合改变按已验证规则重新求值。P2 占位闭环先验证契约，真实兼容／游玩分层复验。

## 判断原则

所有可由皮肤修改的组件均保留在最终覆盖目标中，按证据和阶段逐批实现；即使对应在线业务省去，也提供本地状态预览其皮肤表现。不可由皮肤修改的组件才按是否影响必要 GUI 状态或离线测试取舍。只是原版产品流程所需的服务可以省去，不能用“精简”省掉难以实现但已承诺的实时编辑、动画、声音或实际游玩。

需要兼容的是已声明范围内的皮肤显示、声音与玩法表现。编辑器自身可以增强操作流程，例如直接切场景、注入测试状态、冻结全部模拟、暂停时改图；不必复刻原版完整启动链、在线服务或皮肤重载方式。

## 保留、简化与省去

| 能力 | 处理方式 | 保留到什么程度 |
| --- | --- | --- |
| 皮肤元素、skin.ini 与素材来源 | 保留并逐项验证 | 文件选择、回退、缩放、原点、着色、叠加、动画与声音等可观察结果；未知规则明确标记 |
| 场景显示与必要 GUI 交互 | 保留 | 已支持元素的布局、hover/pressed/disabled 等状态和必要导航；不以静态截图代替全部交互 |
| 游戏模拟与编辑器状态 | 保留并分离 | 模拟时间、音频、游戏输入、场景实例独立于选择与工具；冻结下素材仍刷新 |
| 离线游玩测试 | 保留，按范围递增 | 谱面、对象生命周期、输入、必要判定、声音、结果反馈、全屏及返回编辑；不因省掉排行榜而省掉可测试判定 |
| 谱面选择 | 简化 | 首先使用文件/目录选择和小型自制测试集；需要预览选歌素材时提供对应场景，不建立完整个人曲库管理系统 |
| 菜单、选歌、暂停与结算场景 | 简化业务流程 | 保留目标皮肤元素及其状态，可用固定/可注入数据生成场景；不要求先登录、刷出成绩或完成在线流程才能预览 |
| 配置界面 | 统一到编辑器 | 原版设置页不在预览显示；玩家展示资料、运行偏好和默认来源由编辑器设置管理，skin.ini 仍为独立项目内容 |
| Mods、玩法和特殊状态 | 分批明确支持 | 初始 standard/普通离线测试；影响皮肤表现的额外状态逐项登记，不能宣称全部支持 |
| 回放/自动输入 | 保留编辑与测试能力 | 非全屏默认自动打图且可关闭，独立于 Auto Mod；全屏有效输入方式明确。可重复输入用于回归，回放社交、在线分享和录像产品延后 |
| 音乐播放器 | 简化 | 必要播放/暂停/定位、时钟同步和测试素材；不重做完整 jukebox 或媒体管理 |
| 成绩与个人档案 | 简化 | 用户设置头像／用户名及场景展示数据；会话内测试统计和结果保留，不建立长期玩家成绩数据库、PP 系统或排行榜上传 |
| 登录、账号、好友、聊天、Bancho、联机、观战 | 省去在线业务，保留可皮肤界面 | 核心预览和测试不得依赖账号或网络；可皮肤组件及必要状态用本地测试数据呈现 |
| 商店、捐赠、下载、社区浏览、在线推荐 | 省去 | 皮肤编辑不依赖这些服务；产品自身更新机制将来另行设计 |
| 原版自动更新器、安装器、遥测、在线反作弊与成绩可信链 | 不移植 | 独立编辑器有自身分发与诊断需求；离线测试不参与在线成绩或公平性认证 |
| 谱面编辑器、storyboard 编辑器、完整绘画软件 | 不作为产品模块 | 读取必要测试输入，不承担另一套创作工具 |

省去在线系统不等于可以拿掉其界面中被用户皮肤覆盖的元素。可皮肤组件进入最终覆盖清单，目标场景清单决定分批实现顺序；使用本地状态呈现并明确与真实服务的边界。图像变换边框、拖动范围、GUI 判定区和未来 mania 辅助显示按独立区域接口设计，不合并为一个图片矩形。

## 最小演进切片

| 切片 | 最小闭环 | 对应阶段与限制 |
| --- | --- | --- |
| S0 | 自定义测试图 → 模拟冻结 → 改材质 → 新像素、原时间 → 导出自有渲染结果 | P0/P2 契约实验；无 stable 规则、真实声音或游玩声明 |
| S1 | standard 单击对象、光标、数字与 overlay；可注入固定场景与相关配置 | P3/P4 首批静态及动画兼容验证；不算完整游玩 |
| S2 | 本地小型谱面 → 必要对象/声音/输入 → 实际离线游玩 → 暂停改图 → 返回编辑 | P5；滑条、spinner 等对象类型按支持声明验收，不以单击对象代替整个玩法 |
| S3 | 补齐目标菜单、选歌、暂停、结算及配置状态 | P4/P5 增量；使用精简导航和本地测试状态 |
| S4 | 其他玩法、额外 Mods、声音/动画变体及罕见布局 | 根据已确认需求与兼容证据扩展；不提前承诺范围 |

S2 所需能力的可行性仍在 P0 研究，不推迟到 P5 才发现音频/输入宿主不可用。P0 的自有 GUI 原型只验证 S0 和桌面框架，不能据此宣布 S1–S4 完成。

## 简化对模块设计的影响

- preview 接收本地场景参数、只读素材和测试输入，不自行登录、下载、保存项目或建立原版全局服务。
- 场景可通过有限的状态参数进入目标状态，例如选中、悬停、暂停菜单或结算；参数须有明确类型，不暴露任意改写游戏内存或脚本接口。
- 皮肤内容更新走素材修订；不依靠重启游戏、重建个人数据库或切回菜单才能刷新。
- 应用依赖采用实际需要的功能集合；游戏框架若必须启动在线/全局宿主才能使用，计入选型成本，不能因为语言相同就默认接入。
- UI 控件、AI 控制和自动化测试共用 application 的公开入口；外部客户端仅用于对照，不进入生产依赖。
- 默认皮肤来源可由用户设置；本地开发对照素材不纳入仓库或测试依赖。导出只包含生成与明确允许透传的资源；发布包不包含 stable 原版默认素材、字体或声音，未来内置皮肤单独自制／授权验收。

## 兼容证据与增强流程分开

官方[快捷键文档](https://osu.ppy.sh/wiki/en/Client/Keyboard_shortcuts)描述了本地 F12 截图，并说明游玩/结算时发起皮肤重载会延后到返回选歌。2026-10-20 的 [C03/C08 首轮](STABLE_C03_C08_RESULTS.md)已观察到菜单刷新与普通暂停后直接返选歌的光标变化；活动游玩中发起请求、结算与完整重载机制仍未实测。

编辑器要求暂停后立即更新素材，属于明确的工作流增强。对此验证自有渲染器的时间、修订和像素，而不是要求外部 stable 必须提供相同接口；外部客户端依然用于验证载入相同素材后显示的结果。

每增加一个复杂系统，先记录它对应的皮肤/游玩用例、模块与资源成本；没有实际用例时省去。每个已支持元素仍需对应可观察结果的测试，不能用简化业务流程掩盖显示差异。
