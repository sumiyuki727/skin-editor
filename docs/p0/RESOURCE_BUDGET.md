# 资源预算与验收口径 v1

决策日期：2026-10-20。**保留既有门槛，补齐后续产品工程预算；新增数值尚未经过正式产品验证。** 本文是后续测量基线，不修改旧实验结果或运行参数，不是系统最低硬件要求。

## 负载和统计边界

- 标准编辑负载：100 张 1024² RGBA 原图、10 文档／500 层；活动文档 50 层引用 10 原图，包含嵌套组。按需解码，原始字节、CPU 像素、GPU 资源和派生结果分别计量。
- 组合负载：300 秒设备实际消费，前 200 秒完成 20 次后台文档切换，持续草稿更新；不同格式顺序重复。冻结后像素检查归 Diagnostic，普通路径不做 CPU 像素回读。
- 长历史负载：上述项目元数据＋10000 小事务，含至少两条保留分支、跨分支资源及检出；P1 先测基线，不预设其耗时成绩。
- 大项目压力仍保留 1000 资源／5000 层／10000 小事务，在 P1 先建立核心元数据基线，P3 接入实际资源后复验；不能用标准负载成绩宣称大项目已通过。
- 稳定空闲：停止操作／等待后台结束后稳定十秒，再采样 65 秒，有效跨度至少 60 秒；空项目、暂停保留活动资源、关闭资源保留宿主、进程退出分别记录。
- 本进程及应用自建辅助进程计入应用预算；系统共享服务（例如 `audiodg`）、驱动、外部 stable 单列。GPU dedicated／shared、工作集和私有提交不能相加为“总内存”。不测到的数据标未知。
- 多进程工作集可能重复计算共享页，须保留逐进程值并说明聚合口径，不能把简单求和当作实际物理驻留。
- 依赖、feature、GPU 后端、负载、源码及二进制需同版本；快照之间不合并峰值。采样峰值、OS 累计历史峰值、GPU 回执和页面实际回收分别表述，记录采样间隔与可能漏掉的瞬时峰值。

## 内部限额与退化策略

每帧最多两张／8 MiB 原图写入是已试验的调度起点，CPU／GPU 分配、清零、原图暂存及回执仍单列；它不等于总瞬时上传／分配上限。预览使用单解码 worker、有背压的候选交接和旧结果拒绝；是否增加并行度以正式负载测量决定。

早期 80 MiB GPU 纹理池只在旧纹理路径有对照，后续隔离组合成持有的是另一套源／中间缓冲；不将 80 MiB 硬编码为所有后端总预算。正式缓存需分别记录已解码图、缩略图、活动／候选资源及中间结果的逻辑字节上限，再验证实际进程和 GPU 成本。

P2 的[呈现交接](../PRESENTATION_CONTRACT.md)将最终场景纹理、egui 绑定、候选／活动／退休资源和捕获租约纳入计量；注销 TextureId 不等于原生资源已回收。快速 resize／历史切换／seek 需要有界背压，不通过提前销毁仍在使用的纹理取得低峰值。[历史寻址](../HISTORY_ADDRESSING.md)只限制地址元数据，仍须分别测补丁、索引、快照和资源字节。

内存压力下可逐出可重建缓存、取消过期候选及延迟后台任务。历史可达原始字节不能回收；不得删除分支、静默缩小原图、改变 alpha／采样或降低导出质量。预算超出产生诊断或结构化 ResourceLimit，不把 OS 波动计数直接当作允许部分修改项目的条件。

P1 只建立核心元数据／历史基线，不加载 GUI、GPU 或真实音频。P2/P3 添加组件后再做完整预算；系统音频引擎、真实输入／显示／声学延迟在 P5 测量与定案，不能用本进程数字代替系统成本。
