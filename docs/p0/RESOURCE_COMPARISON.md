# 资源释放与无回读对照

2026-10-18。结构化记录：[windows-resource-comparison.json](windows-resource-comparison.json)。本轮解决了空列表关闭时的多余动画绘制，验证了共享像素上传和较低 GPU 保留容量的可行配置。**加载瞬时私有提交仍高，P0 与技术选型仍未完成。**

此页保留同步加载的历史对照；后续有界后台加载、取消与上传限额验证见[后台加载记录](ASYNC_LOADING.md)，不将两批脚本混成同一组因果比较。

## 结果

同一 release 可执行文件、同一 100 PNG/10 文档/500 图层数据集，在同一台 Windows / RTX 2060 / Vulkan / NVIDIA 560.94 上顺序执行三组。每组 300 次变换、20 轮文档遍历、60 秒暂停和关闭资源后 60 秒静止观察；CPU/GPU 原图缓存仍各 128 MiB，没有降低负载或放宽预算。机器详情与基础负载见 [首轮记录](STANDARD_LOAD.md)。

无回读两组只改变 wgpu 的 `MemoryHints`。本机 MemoryUsage 的 GPU Dedicated 峰值约降低 40%，关闭后 GPU Dedicated 与私有提交也降低；框架帧耗时仍在初始 16.7 ms 目标内。**工作集峰值没有随之下降，加载私有提交峰值也没有得到充分解决**，不能概括成所有内存都降低。

省内存两组只改变是否请求 GPU 回读。回读组单帧 p95 没有显著增加，但每次操作带来更多绘制，总 CPU 开销明显增加；不能只看单帧耗时认定回读没有成本。实际编辑间隔均值约 17.1 ms，约 58.4 次/秒，仍须与目标 60 Hz 区分。无回读的常规编辑成本现已有独立基线。

三组都通过当前可测的工作集、CPU 帧耗时、暂停/关闭后静止和资源引用检查。无回读组的像素验证、回读延迟及其样本检查为 null，**没有被判为通过**。回读组 300 次变换的图像区域确实改变；冻结 PNG 前后像素不同，模拟时钟均为 **9248 ms**，图片已直接查看。

## 修改与归因

**关闭时的绘制请求来自滚动条淡出。** 原生诊断的重绘原因指向 egui 的 ScrollArea 动画；无窗口复现中，清空内容后仍有 13 个早期动画请求，后续会静止。首轮的“三秒内 366 帧”是时间窗口总计数，不能据此认定整个三秒都在持续工作。本轮空列表直接显示静态占位，不创建已无内容可滚动的 ScrollArea，并给两列表明确的 UI ID；不全局关闭编辑器动画。回归用例先失败，修复后通过。原生测量另保留按 100 ms 聚合的帧数和重绘来源。

**上传不再深复制解码图。** GPU 上传队列直接共享 CPU 缓存中的不可变 `Arc<ColorImage>`；无窗口测试检查上传的像素对象与解码对象具有相同身份。队列所持引用仍属于存活内存，不能因缓存淘汰就当作已经释放；本轮用弱引用跟踪解码图，用 renderer 查询跟踪本实验创建的纹理，收尾后均为零。原始 PNG 的 201 个输入文件哈希保持不变。

**较高的 GPU 保留容量有分配策略的贡献。** wgpu 原生分配报告将 allocated 与 reserved 分开。本轮无回读两组关闭后的存活分配同为 1.68 MiB，而保留容量为 256/72 MiB；这解释了部分保留量，不是额外的活跃皮肤纹理。只使用公开的 MemoryUsage 提示，没有修改上游源码、手工指定堆块大小、裁减缓存、强制整理进程工作集或重建 GPU 设备。部分后端可能忽略此提示，不能推广为跨平台结论。

回读组关闭后还存在 `egui_screen_capture_texture` 等框架资源；比无回读组多约 3.2 MiB 存活分配，不能把框架为下一次回读保留的资源列为“自有素材泄漏”。同样，自有原图/纹理释放为零只证明本次跟踪范围，没有证明整个驱动或所有框架资源均不存在泄漏。

## 口径与边界

- 分配器事件发生在当前帧提交前。Cycle 刚清空时仍可能看到旧纹理；释放结论取关闭后 2 秒收尾结束的 Closed，以及 60 秒后的 Done，不把排队释放判作泄漏。
- 进程工作集、私有提交、GPU Dedicated/Shared、wgpu allocated/reserved 是不同口径，可能有重叠。100 ms 目标间隔采样不保证捕获所有瞬时峰值；进程原始样本完整保留，编辑耗时目前保留统计与计数。
- 单核 CPU 使用进程 CPU 时间差除以墙钟。0.00% 表示本次计量精度下的差值，不表示绝对无开销。CPU 帧值来自框架上一帧报告，有阶段边界样本；不是独立 GPU 执行时间戳，也不代表物理输入到显示延迟。
- 三组各运行一次，不是统计意义的多轮性能排名。对照使用同一适配器、exe、Rust 源码和测量脚本身份，并共同校验数据集；旧首轮成绩不混入本轮的因果比较。
- 本轮仍是受限 PNG 绘制，没有隔离组/特效/正式导出、命令与历史、后台解码、真实输入/音频/游玩、IME、高 DPI、macOS/Linux 或当前 stable 行为验证。

原始目录为 `compare-performance-none-203fb034`、`compare-memory-none-52114d57`、`compare-memory-readback-273dd512`，共用 `comparison-fixture-998e86f1`，均位于 `artifacts/p0`。完整比较记录为 `comparison-998e86f1.json`，原始样本和图片不提交；摘要保留各目录、输入、输出、exe、Rust 源码及测量脚本的 SHA-256。旧记录与中止诊断均保留。
