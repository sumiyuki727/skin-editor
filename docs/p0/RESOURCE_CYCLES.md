# 文档与流式音频资源的重复打开／关闭

日期：2026-10-19。本轮延续[五分钟组合验证](COMBINED_SOAK.md)，补齐“重复切换”与“完整关闭活动资源”的区别。它只验证 P0 文档、解码器和原生流的所有权，不是正式项目保存／加载或实际游玩。

## 方法

Windows release、Vulkan／MemoryUsage、自有隐藏渲染窗口；沿用 100 张 1024² PNG、10 文档／500 层的标准 fixture，活动文档 50 层，原始像素与隔离组合成不变。每轮顺序访问一个文档，20 轮让十个文档各打开两次。仍用自制十分钟 PCM16 WAV／48 kHz 双声道／增益 0.002，要求当前默认端点匹配 float32 格式；没有压缩、混音或重采样。

每轮依次：

1. 重新创建五块 PCM 池、一个后台解码线程和原生 WASAPI 流；通过只读后台文档请求加载并上传图像。收到文档可用与设备暂停确认后显式播放，记录打开到准备就绪的 host 时间。
2. 设备实际消费至少六秒，并通过既有值命令更新至少 300 次可取消草稿；每个 UI 帧最多更新一次，结束时提交。该最低数量用于保证编辑负载，性能下降时不能靠少做编辑完成测量。
3. 暂停并至少等待一秒，比较前后新鲜的设备序号、停止位置和原生提交数。第一轮和末轮额外在暂停下编辑并直接核对 CPU／GPU／显示目标，最大通道容差 2；归到独立 Diagnostic，不在正常编辑路径回读。
4. 先释放原生流，再关闭并加入解码线程；归档完整 PCM 轨迹，检查所有五块归还、无在途／排队、欠载／解码失败／溢出均为 0。之后销毁本轮队列／轨迹缓冲，关闭活动合成文档并等待后台空闲。
5. 等待四秒，给先前观察到的延迟回收留出时间；再观察四秒，保存本轮关闭基线。后续才创建下一轮资源，禁止新旧会话重叠。

图形设备、pipeline、窗口、只读文档加载线程和实验组装继续存在，按会话复用。每轮的图像、合成计划、音频线程、原生流与 PCM 池有独立寿命；操作草稿拥有者也重新创建，不模拟正式项目历史的保存／恢复。不能把此处的“关闭”描述为渲染器卸载、全新空项目、GPU 驱动全部归零或进程退出。

最后一轮的短基线结束后再观察 65 秒，按现有 ≤2% 单逻辑核 CPU 门槛检查稳定空闲。每轮四秒基线只用来观察内存趋势，不冒充 60 秒空闲预算。

## 计量与证据

复用现有进程／GPU PID 计量，每 200 ms 采样工作集、私有提交、累计 CPU、GPU dedicated／shared；历史峰值单列，GPU 内存不是利用率，各口径不可简单相加。阶段身份包含轮次、名称和单调步号，前后读取一致才接受样本，避免重复名称和写入边界污染分段。

每轮关闭基线排除首次观察后的 0.5 秒，要求有效跨度至少 2.5 秒；最终空闲排除一秒，要求至少 60 秒。播放 CPU 按每轮独立区间累加 CPU／墙钟差，不能将中间暂停和关闭时间算进播放的平均值。最后退出先标记 Done，将归档和进程退出排除在稳定空闲之外。

20 个基线分别记录内存末值、首尾差、前五／后五中位数差和线性斜率。趋势没有新增任意的“允许泄漏”阈值：有增长时须说明幅度、是否趋稳及未知归因，不能仅因低于 512 MiB 就判定不存在泄漏。工作集门槛仍是正常负载 ≤512 MiB，框架 CPU 帧 p95 ≤16.7 ms；私有提交／GPU 正式数值上限未定。

每轮独立 JSONL，逐包复用独立周期 WAV 参考，核对样本、哈希、增益、源帧连续性、暂停尾部和作废顺序。队列固定五块／160 KiB，事件缓冲固定 8192；实验最多 20 轮、200 个阶段、20000 条帧记录，超容量失败。每轮关闭后不保留 PCM 或原图副本，只保存有界的统计值。诊断与文件归档成本均按实际进程计量，不从实测数字扣除。

采样、原始结果、每轮轨迹、环境、fixture 哈希和测前冻结的源码均保存到全新 `artifacts/p0/resource-cycles-*`；失败同样归档。测后核对源码和二进制未变，再保存二进制副本。拒绝覆盖和输出越界，不读旧 stable 源码、客户端资源或私人音乐，不录音或捕获系统窗口，无需 F12。

## 复现

```text
python tools/check_p0_resource_cycles.py
python tools/check_p0_resource_cycles.py --run-native --fixture artifacts/p0/standard-fixture-9f325f13 --smoke --repetitions 1
python tools/check_p0_resource_cycles.py --run-native --fixture artifacts/p0/standard-fixture-9f325f13 --repetitions 2
```

第一项执行媒体 feature 的边界、格式、Clippy、无窗口测试与 release 构建。标准 PNG fixture 须已生成且逐文件哈希通过；可通过 `python tools/p0_workload.py artifacts/p0/my-standard-fixture` 另行创建，然后传入对应路径。短轮只做两次、一秒播放及较短基线，不评定预算。完整每个进程 20 轮，约六分钟，顺序重复避免互相干扰；输出低幅度自制声音，不改系统音量。

`--audio-fixture` 可复用已有自制周期 WAV，`--skip-checks` 只用于已独立检查的 release。所有测量限于 Windows，本轮不为 Linux／macOS 创建假后端或认定其平台支持。

## 结果

本机沿用 Windows 10 x64、Ryzen 7 4800H／16 逻辑核、RTX 2060／NVIDIA 560.94。`resource-cycles-3da954d5` 和 `resource-cycles-971ee335` 的全部行为、逐包证据与本次六项预算检查通过，源码、二进制与 fixture 相同。两组各 20 次打开／关闭、7204／7197 次草稿更新，12065／12067 个原生接受包全部核对；所有轮次关闭后五块全归还，报告欠载、解码失败和轨迹溢出均为 0。每组首末轮像素核对通过，最大通道误差不超过 1。

实验保留逐轮 JSON、阶段、上传统计及有界帧时间，这些也计入内存；缓存、分配器和驱动保留尚未精确拆分，不将全部小幅增长直接归给其中一种。关闭后图形会话仍保留，不能与五分钟实验的切换峰值直接相减来宣称优化收益。

机器记录见 [windows-resource-cycles.json](windows-resource-cycles.json)，每组 `source-snapshot` 保存二进制及 104 份源码／锁／工具；测后核对两组和当前文件一致。输出越界、覆盖既有结果、输入源越界三项均在 GPU／设备启动前拒绝，已有证据未变。短轮 `resource-cycles-0ff560ce` 的两轮流程通过，不用于预算。二进制 SHA-256 为 `693c6b3c4252e58e9e53ae08cefe17e95f1f8c8d16cec7ed060c6f70571e3b12`。

本轮无窗口 **205** 项：GUI 默认 70、可选媒体读取／worker 4、WASAPI 22、媒体 12、契约 10、Python 87。新增 11 项证据／计量回归覆盖轮次复用、未归还块、故障和溢出、暂停新鲜度、首末像素证明、分离区间 CPU、趋势统计、未知 GPU 计数及不足观察时长。默认／音频／媒体 feature 的格式、Clippy、测试与 release 构建通过；没有新增依赖、平台 feature 或正式项目模块，没有改写既有长时播放入口，unsafe 范围不变，未提交或推送 Git。

20 轮组件资源回收的行为验证已完成，未见整份原图／PCM 随每轮关闭持续遗留的证据，但小幅私有提交保留尚未精确归因，不能关闭长期泄漏结论。两组均通过本负载下 512 MiB 工作集、2% 最终空闲 CPU 和 16.7 ms CPU 帧 p95 门槛；实际帧间隔仍有长帧，不代表严格 60 Hz 或物理显示延迟达标。私有提交／GPU 数值上限、完整产品预算、压缩音乐、重采样、设备变化、真实游玩与首批 stable 兼容对照继续开放。Linux 实测延期、macOS 待设备；无需 F12，未读旧源码／客户端资源，stable 兼容案例仍为 0。
