## C03：存在、透明与缺失分别拍摄

1. 将包目录里的 `P0 First Batch Transparent.osk` 和 `P0 First Batch Missing.osk` 分别拖到**已经打开的 stable 窗口**。Baseline 和谱面已安装，不必重复导入；不要依赖可能指向其他客户端的双击关联。
2. 在皮肤设置中选择 **P0 First Batch Baseline**。从头开始同一张 `Static Circles`，看到第一个圆圈（约两秒处，左上区域、数字 1）后按 F12。鼠标放在远离圆圈的空白处，不击打、不暂停。记为 **C03-Baseline**。
3. 返回选歌，在设置选择 **P0 First Batch Transparent**，从头开始同一谱面，在同一第一个圆圈处拍一张，记为 **C03-Transparent**。
4. 对 **P0 First Batch Missing** 重复一次，记为 **C03-Missing**。
5. 错过第一个对象可重试，不用其他位置的对象代替。截图时刻不必达到相同毫秒，记录可见差异即可；外圈收缩和淡入会随时间改变，不单凭其大小差异判断 overlay 的回退。

这三张验证的是同一底图对应的 overlay 存在方式。不要手动删除游戏内文件来制造 Missing，也不要预先认定透明等同于缺失。本轮不覆盖损坏文件、扩展名冲突或所有回退来源。

## C08：先确认复制目标和 A／B

1. 重新选择 **P0 First Batch Baseline**，在游戏设置的皮肤部分打开当前皮肤文件夹，记下资源管理器中实际路径。确认它属于本包 Baseline；不直接猜目录名，避免导入时重名产生不同目录。
2. A 是 `skins/baseline` 的 **cursor.png、hitcircleoverlay.png**，均为粉红环；B 是 `refresh-B` 的同名两图，均为绿色环。每次只复制这两个文件到**游戏当前 Baseline 目录**，允许替换这两个测试文件。不要复制 skin.ini，也不要覆盖其他皮肤。
3. 开始每个独立轮次前，都先复制 A 的两图、返回菜单按 `Ctrl+Alt+Shift+S`，松开全部按键，确认粉红光标已经恢复。如果没有恢复，停止这一轮并反馈，不继续叠加变量。

源目录不可作为粘贴目标；它们是恢复用原图。可先并排打开源目录和游戏目标目录，再回游戏，减少全屏切换操作。

## C08-M：菜单刷新（两张核心图片）

1. 保持 Baseline 的 A 状态，在主菜单将鼠标放在空白处，按 F12，记为 **C08-Menu-A**。
2. Alt+Tab 到资源管理器，将 B 的两图复制到已确认的游戏 Baseline 目录。
3. 回到主菜单，**先不要按刷新键**。记录光标是否已经变绿；若已变化，额外拍图并说明“复制后／快捷键前已变”，不能将它归因于尚未按下的快捷键。
4. 按 **Ctrl+Alt+Shift+S**，松开全部按键，等约一秒，将光标置于与之前相近的空白位置，按 F12，记为 **C08-Menu-After**。即使没有变化也拍图，说明是否出现提示、失败或延迟。
5. 按 A／B 准备步骤恢复 A，菜单刷新并确认粉红光标恢复，再开始下一轮。

这是观察步骤：B 文件本身是绿色，不预先保证这一客户端在任何状态下都会立即使用它。

## C08-P：普通游玩暂停与返回选歌（两张核心图片）

1. 确认 A 已恢复。开始 `Static Circles`，第一个圆圈出现时按 **Esc**，确认普通暂停菜单已打开。此时不要点继续。
2. Alt+Tab 到资源管理器复制 B 两图到同一游戏目标目录，再切回游戏，**保持暂停**。先不按刷新键，记录光标是否已变化；若已变，额外留图并注明。
3. 在暂停菜单按 **Ctrl+Alt+Shift+S**，松开全部按键，再按 F12，记为 **C08-Pause-After**。记录光标是否变绿；若圆圈被暂停界面遮挡，只报告能看见的部分。
4. 点继续，观察一小段游玩时光标／圆圈是否发生变化；可文字记录，必要时额外 F12。不要为了这一轮开 Auto／No Fail 等 Mods，也不测试命中和声音。
5. 再按 Esc，通过暂停菜单返回选歌。**不要再次按刷新快捷键**，等待约一秒后 F12，记为 **C08-SongSelect-After**。记录是否直到返回选歌才变化。失败导致返回的情况也照实记录，不能写成主动返回。
6. 复制 A 两图回游戏目录，在菜单刷新并确认恢复；最后选择回自己原来的皮肤和设置。恢复 A 可文字确认，无需固定再加一张图片。

官方说明 `Ctrl+Alt+Shift+S` 用于刷新皮肤，并指出游玩／结算时的请求在回到选歌后执行；因此“暂停时未立即变化，返回选歌才变化”也是有效结果，不能当作操作失败。**普通暂停是否遵循该时机仍以这次观察为准。** 此轮也不代表编辑器特有的冻结模拟能力。[官方快捷键说明](https://osu.ppy.sh/wiki/en/Client/Keyboard_shortcuts)，2026-10-20 核对。

## C08-G：活动游玩中请求刷新（可选，单独一轮）

本轮与在暂停菜单发出请求不同；未操作可直接写“未测”，不影响先交回前七张。

1. 再次恢复 A、菜单刷新并确认粉红光标。开始同一谱面，先普通暂停，仅用于 Alt+Tab 复制 B，**此时不按刷新键**。
2. 回到暂停界面，点继续；确认当前确实在游玩，没有暂停菜单。先观察是否已经变绿，必要时 F12，记录“恢复后、快捷键前”的状态。
3. 在**活动游玩中**按刷新组合键，松开所有按键再 F12，标记 **C08-Playing-After**。若组合键没有赶在失败／结算前按下，记未完成并重试，不混为活动游玩结果。
4. 返回选歌时不再按刷新键，观察并记录是否延后生效；可 F12。最后恢复 A 并菜单刷新。Alt+Tab 的失焦暂停、恢复时变化和手动快捷键效果分别记录。
