# Windows 标准规模 PNG 负载记录

日期：2026-10-18。结果：[结构化证据](windows-standard-result.json)。此项完成了本批 PNG/资源基线测量，**不代表 P0 通过或技术栈已选定**。

这是首轮历史基线，原始数字与缺口保留。后续已完成[资源释放与无回读对照](RESOURCE_COMPARISON.md)，补充关闭后 60 秒观察、空列表回归修复和分配策略验证；当前结论以两份记录的适用范围分别理解，不能混合轮次数字。

## 输入、实现与测量

独立原生实验使用 Rust 1.95、eframe/egui 0.37.0、wgpu 30.0.1、image 0.25.10 的 release 构建，未新增第三方依赖。参考机器为 Windows 10 19045 x64、Ryzen 7 4800H、16 逻辑核、系统报告物理内存总量约 15.87 GiB、RTX 2060 / NVIDIA 560.94 / Vulkan。仅验证这一台 Windows 机器。

输入由自有脚本生成：100 张 1024×1024 RGBA PNG、100 张 64×64 缩略图、10 文档、500 图层；当前文档 50 层，引用 10 张原图。两层嵌套组传递平移、等比缩放与透明度，按顺序 source-over；图案有不对称色块、透明和半透明像素。文件目录含中文/日文。201 个输入文件逐一记录 SHA-256，外加库存清单；测试后校验输入未被改变。fixture 不是 stable 皮肤，也未使用旧源码或游戏资源。

元数据阶段读取原图尺寸，首次只解码 10 张当前引用的原图与 12 张可见缩略图。CPU 解码缓存、GPU 原图纹理缓存分别限 128 MiB；共享引用不重复解码。冻结替换另使用 4 MiB 视图覆盖纹理，12 张缩略图 payload 共 192 KiB，不能塞进原图缓存数字中隐去。原始 PNG、解码像素、视图覆盖和回读文件分离。

测试窗口请求可见，1100×720 逻辑点，AutoNoVsync，脚本目标 60 Hz。egui 的可见性接口在此平台返回未知，记录为未知，不冒充已验证的窗口可见/隐藏状态。所有画面验证来自自有 GPU 渲染目标，无系统窗口捕获，无外部客户端输入。渲染 PNG 实际为 1100×720 像素；这没有验证其他 DPI。

进程指标以约 100 ms 目标间隔采样，共 877 个样本，实际间隔含采样成本。工作集与私有提交使用 GetProcessMemoryInfo，CPU 用 GetProcessTimes 的差值除以墙钟，归一为一个逻辑核；GPU 使用 PDH 的本进程 Dedicated/Shared Usage，跨适配器实例求和。实验本身单进程；Python 测量工具不是产品运行时，不计入应用工作集。不同指标可能重叠，不能把 CPU/GPU 数字相加当物理内存总量。

## 实测结果

| 项目 | 本次结果 | 解释 |
| --- | --- | --- |
| 空场景工作集采样峰值 | 151.3 MiB | 3 秒启动观察，低于初始 200 MiB 目标；不是长时间待机验证 |
| 常规编辑阶段工作集峰值 | 263.1 MiB | 已解码素材的参数变化，不包含首次加载 |
| 整个负载/切换阶段工作集采样峰值 | 396.7 MiB | 低于初始 512 MiB 目标；100 ms 采样不保证捕获瞬时峰值 |
| CPU/GPU 原图缓存 payload 峰值 | 各 128 MiB | 仅是受管理缓存，不是进程或显卡总占用 |
| 私有提交采样峰值 | 943.0 MiB | 明显高于工作集；不等于全部物理驻留，仍属于资源成本 |
| GPU Dedicated / Shared 采样峰值 | 539.9 / 89.1 MiB | OS 计量，含缓存之外的资源；未设定/放宽新的 GPU 通过阈值 |
| 编辑阶段框架 CPU 帧耗时 p95 | 1.081 ms | 低于 16.7 ms 目标；不是独立 GPU 执行耗时 |
| 编辑到 GPU 回读完成 p95 | 6.979 ms，300 样本 | 低于 50 ms 目标；含 GPU/复制/回调，不代表物理输入到显示 |
| 脚本编辑间隔 | 均值 17.132 ms，约 58.4 次/秒 | 目标 60 Hz；真实间隔 p95 17.639 ms，不能声称精确 60 FPS |
| 单张原图解码 p95 | 5.398 ms，2010 次 | 文件/解码/预乘转换；不含上传与导出 |
| 文档加载 CPU 耗时 p95 | 64.572 ms，201 次 | 当前文档的解码/缓存/上传排队；同步操作，不符合连续编辑帧预算 |
| 首次元数据与文档准备 | 约 901 ms | 文件刚生成，OS 文件缓存可能已热；不是冷盘导入速度 |
| 暂停观察 | 60.001 秒，544 个进程样本 | CPU 样本跨度约 59.922 秒，单核 CPU 差值为 0.00%；不解释为绝对零开销 |
| 暂停期间 UI 帧 | 1 帧 | 用于进入 Idle 状态的必要显示更新；随后无连续重绘 |
| 资源循环 | 20 轮，每轮遍历 10 文档并清空原图缓存 | 共 200 次切换，GPU 计量进入平台后保持约 539.9 MiB；不能据此宣称不存在泄漏 |

每次变换都对动画标记以外的固定图像区域检查像素变化。冻结后另解码一张真实 PNG 作为视图覆盖，前后完整画布不同，模拟时钟均为 **10044 ms**。PNG 已直接查看；它们证明自有加载/绘制路径，不证明 stable 兼容性。

原始证据位于 `artifacts/p0/standard-9f325f13`，数据集位于 `artifacts/p0/standard-fixture-9f325f13`。原始逐样本记录留在忽略目录，结构化摘要保留目录、exe/源文件/锁文件、输入库存和输出图片的哈希。各初始预算按原口径逐项记录，没有为测量结果放宽工作集、帧耗时、延迟或 CPU 阈值。

## 暂不关闭的问题

- GPU 回读为每次参数变化带来额外帧：编辑阶段共有 1496 次 UI 帧，约 5 帧/次。预热已按约 60 帧/秒调度；不能把带回读仪表的资源/帧数直接当作正常可见编辑器的 60 FPS 成本。独立 GPU 时间戳和无回读对照仍待补。
- 私有提交和 GPU 保留量较高。最后几轮私有提交波动约 870–914 MiB，没有本次可见的线性增长；清空资源后工作集约 224.6 MiB、私有提交约 709.8 MiB、Dedicated 约 283.9 MiB，均未完全返回初始值。驱动池、上传/回读缓冲、分配器与实际泄漏尚未归因，不自动判无泄漏。
- 关闭资源后的 3 秒阶段记录到 366 次 UI 绘制（含状态切换帧），单核 CPU 约 4.35%。该阶段未通过“正常空闲”的额外认定，需继续查调度/布局触发原因；暂停静止阶段的 60 秒结果独立成立。
- 当前按需加载同步执行，文档切换 CPU p95 约 65 ms；正式交互前必须验证有界后台解码、取消、修订身份与陈旧结果拒收，不能把阻塞加载推广成产品实现。
- 没有隔离组、蒙版、特效、旋转、正式导出像素语义、Command/历史、真实输入、音频/游玩、IME、高 DPI、macOS/Linux 或 stable 行为对照。产品性能与选型门槛继续开放。

首轮诊断记录 `standard-700060fe` 已标记中止，不能用于预算：隐藏参数被上游首帧显示行为覆盖，调度曾被 UI 帧推迟，初版 PDH 格式标志也未正确读取 GPU 数值。后续 `standard-2cb51994` 完成了 PNG/内存路径验证；它的可见性布尔统计把未知混为 false、零重绘检查包含进入 Idle 的必要帧，现已更正。原始文件保留，最终成绩只使用上面标明身份的复测，不合并不同轮次数字。
