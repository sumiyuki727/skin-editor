# 后台解码与原生流式输出

日期：2026-10-19。Windows x64 的独立 P0 原型已完成三轮同版本验证，覆盖十秒连续设备播放、暂停／定位丢弃旧块，以及受控解码饥饿后的故障与显式恢复。没有 GUI／GPU、stable 游戏逻辑、物理输入或声学测量；Linux 实测暂缓，macOS 待设备，正式音频后端未定案。

## 边界与所有权

```text
实验源工厂 → 单解码线程 → p0-media::stream
                           ↓ 代次、源帧、PCM
                 固定五块池／最多四块排队
                           ↓
WASAPI 专用线程：准备 → 原生提交 → 确认消费
                           ↓
                 设备观察 → 纯 Transport
```

`streaming_decode` 只在默认关闭的 `media-proof` 中组装已有库。文件打开、头部验证、定位和解码在后台线程执行；代次变化时重开同一不可变源。源工厂属于实验内部组装，不是 Command／AI 载荷。`p0-wasapi::buffered` 仅交换配置、PCM 值及统计，不依赖解码器、文件、UI 或项目；生产端不能消费或激活队列，单一接收端持有该能力。原有 Output 三方法和项目写入边界不变，音频队列不进入历史。

池固定 **5 × 4096 帧**，双声道 float32 共 **160 KiB**；最多四块排队，一块可在解码或诊断屏障中。块消费／作废后归还，不逐包分配 PCM。媒体库另有 32 KiB 解码缓存和 64 KiB 源缓冲，本机 4800 帧设备缓冲对应 37.5 KiB 暂存；解码器内部、原生引擎及诊断记录另计。

无需求时用条件变量等待，I/O／解码不在队列锁内。队列保留短互斥区，不宣称无锁或严格实时。原生线程取得指针后不等待解码／空位，完整初始化并配对释放，`ReleaseBuffer` 成功后才消费队列；失败提交可以重新准备。准备令牌绑定代次，即使回到相同源帧也拒绝旧令牌。unsafe 仍只在原平台文件，无新依赖、锁升级或 Windows API feature。

## 暂停、定位和欠载

流式暂停执行 Stop → 读取停止位置 → Reset，保留逻辑时钟偏移并换新块代次。Reset 清掉端点未消费数据、将原生时钟归零，逻辑位置保持停止点；依据 Microsoft 的 [Stop](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-stop)／[Reset](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-reset) 接口。旧静音、生成 PCM 和短 Clip 入口保留原暂停语义。

暂停清掉软件排队块，迟到解码结果按旧代次丢弃；允许预备有限新块，但不原生提交或推进游戏时间。恢复先等预备量，再确认 Playing；等待期间游戏输入关闭，较新暂停可取消待启动播放。定位／恢复替换设备代次，旧流释放后才开新流，新流保持暂停并等待显式播放。

本轮欠载采用明确故障：消费超过有效提交前沿，或端点无排队数据且不能准备完整下一包时，报告 `Streamed PCM queue underrun`、关闭流、使旧块失效，冻结最后确认时间并拒绝游戏输入。不做中途静音补齐或墙钟补跑；可能仍有不足一包的残余数据。这不是驱动 HRESULT 或声学中断测量，EOF 零尾部也与欠载分开，不循环文件。

恢复使用最后确认位置，可能重播检测／发布／停止之间尚未确认的小段，未保证样本级无缝恢复。微秒起点向下取整到源帧，单次量化不足一帧；均为实验策略，不是 stable 规则。阻塞 I/O 不能强制中断，代次取消只保证返回后不发布旧结果，退出的系统／驱动阻塞上界未验证。

## 复现与证据

```text
python tools/check_p0_stream_output.py
python tools/check_p0_stream_output.py --run-native --repetitions 3
```

第一项检查组装边界及可选 GUI／适配器的格式、Clippy、无窗口测试和 release 构建。第二项生成三十秒自制规范头 PCM16 WAV，顺序运行三轮，会播放低幅度音频，不改系统音量或默认设备。格式范围沿用[有界 WAV 实验](STREAMING_AUDIO.md)，没有压缩格式或重采样。

每轮：十秒连续播放 → 扣留已解码结果并暂停 → 释放／验证旧结果作废 → 普通恢复 → 向前到 20 秒并播放 → 在 25 秒处扣留结果并退回 0.5 秒 → 释放旧结果并恢复 → 阻塞解码至欠载 → 故障冻结 → 显式重建、暂停确认、播放 → 最终暂停／关闭。`DiagnosticGate` 仅在解码与发布之间受控阻塞，不伪造驱动返回值。

每个原生接受包记录代次、源帧、包长、FNV、峰值、非零样本数和探针；Python 独立从 WAV 计算 float32 增益，逐包核对所有声道，同时检查连续性、重置顺序、旧块身份、消费时钟、暂停与回收。诊断上限为 8192 事件、4096 观察，溢出使验收失败。原始结果、源码／锁／二进制／fixture 哈希、环境和进程采样归档；逃逸及覆盖既有结果均拒绝。不捕获窗口、不录音、不读旧源码／客户端资源或私人曲库，无需 F12。

## 本机结果

`stream-output-4fe05f47`、`stream-output-720f24b6`、`stream-output-1ab1ddec` 使用相同源码、二进制与 fixture，全部通过。明细见 [windows-stream-output.json](windows-stream-output.json)。

| 观察 | 三轮结果 |
| --- | --- |
| 正常连续段消费位置 | 10.010000／10.000395／10.001104 秒，报告欠载均为 0 |
| 受控欠载 | 每轮恰好 1 次，恢复前时间／游戏输入冻结 |
| 迟到旧块 | 每轮拒绝 3 块，来自暂停、定位和故障前 |
| 四个暂停区间 | 每段至少 350 ms、3 个新鲜观察，位置不变、新代次提交 0 帧 |
| 关闭与回收 | 5 块全归还，无在途／排队块，解码失败与记录溢出均为 0 |
| 软件／原生累计丢弃帧 | 软件 107008／107488／107488；原生 18720／17760／19200 |
| 脚本游戏输入 | 每轮接受 3 次，暂停、held／repeat 及故障输入均拒绝 |

采样观察到的进程历史提交峰值 **13.168–13.477 MiB**，工作集峰值 **18.750–19.129 MiB**，累计 CPU **0.046875–0.078125 秒**。包含诊断记录成本，退出前的短暂 JSON 分配可能未被最后一次采样覆盖，不作为总峰值上界、PCM 池或图形组合预算。计量分辨率与轮询调度仍有限，十秒片段不代表任意长音乐／系统压力下的实时保证。

本轮无窗口 **185** 项：GUI 默认 70、可选文件读取 1、解码 worker 3、适配器 20、媒体 12、契约 10、Python 69。默认／音频／媒体 feature 分别检查；旧短 Clip 原生路径另回归一次并单列原始结果。压缩格式、重采样、长时／慢磁盘／图形压力、设备变化、声学与物理输入仍开放；P0 总预算、客户端对照、范围和选型未关闭。
