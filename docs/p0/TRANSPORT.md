# 输出时钟、模拟和编辑输入的同进程验证

2026-10-19，Windows x64 原生实验完成三轮联动验证：真实 WASAPI 静音输出驱动模拟时间，暂停期间仍可通过命令会话连续编辑 50 层文档并直接呈现 GPU 合成结果。结构化结果见 [windows-transport.json](windows-transport.json)，前置的独立设备诊断见 [AUDIO_DEVICE.md](AUDIO_DEVICE.md)。这是 P0 能力原型，尚未实现 stable 规则或实际游玩。

## 边界与数据流

```text
编辑器暂停／恢复控制 → 带递增请求号的设备控制 → 单个 WASAPI 工作线程
                                        ↓ 只读设备确认／流位置
                          纯 Transport 状态机 → 模拟时间及游戏输入门控

编辑器拖动 → 私有命令会话 → 只读草稿投影 → 共享合成计划 → GPU → egui 纹理
```

设备和编辑器状态不属于项目或编辑历史。暂停／恢复请求发出后立即进入 Pending 并关闭游戏输入，只有匹配当前请求、序号更新的设备确认才改变运行状态。旧确认不能重新打开输入；模拟时间直接采用流位置，不使用 host 墙钟补偿。控件刷新、素材更新与设备轮询独立。

游戏按键还受交互工具、焦点和编辑控件占用限制。Z/X 的按下、释放和 repeat 经同一门控；暂停、Pending 或编辑期间的按下仍更新 held 状态，但不积压或重放，恢复后须释放再重新按下。设备错误、倒退、暂停漂移和错误状态确认进入 Faulted 并关闭游戏输入，不悄悄切换为墙钟；编辑会话仍可工作。故障重建和设备切换尚未实现。

新增可选 `p0-wasapi` 仅向实验提供安全的值接口，COM 接口和原生指针全部留在其 `platform.rs` 与专用 MTA 线程；UI／纯状态机仍禁止 unsafe。它只直接引用已锁定树中的 `windows 0.62.2`（MIT／Apache-2.0），未引入新第三方包版本。默认 `device-audio` feature 关闭；默认构建和所有单元测试均不打开设备。平台成本与审查边界见[适配器说明](../../experiments/p0-wasapi/README.md)。这不改变产品技术栈或引入跨语言产品核心。

微软的 [Stop 契约](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-stop)说明停止会冻结流时钟，Start 从当前位置继续；[GetPosition 契约](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition)说明位置须结合频率换算，S_FALSE 表示读数精度不足。本实验保留原始 HRESULT，仅接纳 S_OK；这属于平台依据，不是 stable 兼容规则。

## 脚本与结果

复用全部哈希已校验的 100 原图／10 文档 fixture，仅载入第 0 个文档的 10 张原图、50 层和 1024² 输出；初次载入仍同步。每轮新建原生进程与 shared 输出流，实际格式为 48 kHz、双声道、32 bit、4800 帧缓冲，时钟频率 384000 单位／秒。

脚本播放约 450 ms 并按住 Z → 请求并等待暂停确认 → 记录基线 → 拖动、Esc 取消 → 第二次拖动产生 300 个不同草稿并释放提交 → 恢复 → 检查旧 held／repeat 不重放 → 释放后新按下 → 再观察约 450 ms。键盘和指针都是注入 egui 的合成事件；暂停／恢复通过与工具栏共用的控制方法发出，未验收物理按键、鼠标或工具栏点击。

## 后台加载接入审查

现有 `loading` 队列不能直接替换此处的同步加载：

- 旧 `Decoded` 是 `egui::ColorImage` 的预乘显示缓存，新合成器需要原始 straight RGBA8／sRGB。直接把前者当原图会重复处理透明度并改变颜色；反向恢复也可能损失透明像素和量化精度。
- 旧 `Workload::flatten` 将组透明度乘入每个叶子，丢弃隔离组结构。重叠子层会产生不同 alpha；新合成器必须保留完整组树。
- 当前 GPU 计划一次准备 40 MiB 源缓冲，不能继承旧纹理路径每帧 2 张／8 MiB 的上传保证。

已增加无窗口回归：半透明原图通过预乘缓存后不再等价；两张不透明重叠图层的 0.5 隔离组 alpha 为 128，旧展平结果为 191。测试保护两个不同实验的语义边界，未改变旧负载或历史测量口径。

下一迭代应先提供保留组结构的后台元数据结果和独立原始 RGBA 解码结果，再按文档请求代次交接。旧文档须在候选素材、GPU 上传和合成全部完成前继续显示；过期或失败结果不得替换当前视图。GPU 上传需单独执行有界策略，计入旧／新集合同时存活的成本，并验证快速切换、取消、关闭、缺失素材和暂停下刷新。此处是接入设计要求，尚无异步合成或文档切换实现。


第一项仅运行依赖边界、格式、Clippy、无窗口测试与构建；第二项显式打开 Windows 默认静音输出和自有 Vulkan 窗口，顺序运行，拒绝目录越界和已有输出覆盖。fixture 须预先生成；本轮实际使用已存在的 `standard-fixture-2cb51994`。

新增状态机 5 项、控件联动 1 项、加载语义边界 1 项、平台换算／HRESULT 1 项及 Python 边界／证据 2 项测试。默认原生 51 项、契约探针 10 项、Python 39 项和可选适配器 1 项测试通过；默认和启用 feature 的检查均通过。默认无音频原生手势回归见 `artifacts/p0/interaction-6b9a7e72`，其模拟和输入始终保持 0；真实音频设备三轮结果独立于无窗口测试。

适配器使用一个线程、8 项有界控制队列、单份最新快照；播放轮询 5 ms、暂停轮询 100 ms，仅状态变化或暂停漂移唤醒 UI。原生测试自身定期重画，未验证静止音频联动的 60 秒 CPU 预算。Drop 发送退出标志并 join，通常受轮询周期影响，尚未验证原生 API 阻塞或拔设备时的退出上界。

仍需可听输出与延迟、事件调度及欠载、设备失效／重建、物理输入、IME、DPI／全屏、后台切换、静止／关闭预算、最小离线谱面流程和 macOS／Linux 实机结果。默认端点可能为虚拟设备。本轮未调用真实 stable、未读取旧源码或客户端资源，不需要 F12 图片；当前 stable 兼容案例执行数仍为 0。
