# P0 stable 行为验证矩阵

日期：2026-10-20。状态：C00 版本／通道、C01 单一设置基线已记录，[C03／C08 三个定性子项](STABLE_C03_C08_RESULTS.md)已完成，完整行为范围仍有缺口。旧源码观察见 [研究报告](REPORT.md)，身份见 [source-inventory.json](source-inventory.json)。本矩阵不把旧代码的条件、常量或算法转成实现规范。

## 证据分栏

每项记录四个互不替代的来源：

- `D`：公开文档中的说明，带链接、访问日期，必要时固定文档提交。
- `L`：旧源码快照的观察，只登记库存文件、位置和待验证问题；不单独认定当前行为。
- `C`：当前 stable 实测，必须带真实发布版本、可执行文件哈希、系统、分辨率/DPI、输入素材哈希、操作步骤及结果。
- `P`：项目自有实现的自动回归；不能证明当前客户端如何运行。

每栏独立使用“待查 / 已记录 / 有冲突 / 不适用”。只有 C 的实际证据能将本轮某条规则标成当前目标客户端的实测结果；D 仍可作为带范围标识的公开规范实现依据。需要固定像素、时间或回退优先级的细节，先取得足够证据再进入 compatibility。

当前对照样本：`D:\osu!\osu!.exe`；用户提供的图片直接显示 **b20260924.1／Stable**，本次 exe 哈希与前次一致。文件版本资源 `1.3.3.8` 和旧日志不代替发布编号；截图与进程的关联依据用户来源，未自动验证。C01 已有单帧基线：Baseline、Mods 关闭、1920×1080 全屏、Windows 缩放 100%；跨 DPI／比例及精确几何验收待补。启动、身份、部分观察与规则验收分别记录。

后续已按用户要求改用 [F12 / 文件与日志流程](EVIDENCE_WORKFLOW.md)，不再依赖系统窗口捕获。可先准备和验证输入文件，图像证据在具体案例需要时由用户提供。自有原型另行通过其渲染目标回读验证，不能混入当前 stable 的 C 栏。

## 最小场景与素材范围

首轮已按 [范围基线 v1](PREVIEW_SCOPE.md#首轮范围基线-v1)定稿：先做 V0-A 占位编辑闭环，再做 V0-B 的 15 个静态 PNG 文件。V0-C 及其后内容是后续增量，不计入首批静态素材的支持承诺。

| 增量 | 场景 / 元素 | 验证目的与边界 |
| --- | --- | --- |
| V0-A | 自有占位场景，纯色/透明/非对称测试图 | 验证冻结与热刷新契约，不使用 stable 布局，已有无依赖探针 |
| V0-B | osu!standard 单击对象：`hitcircle`、`hitcircleoverlay`、`approachcircle`、`default-0` 到 `default-9`；光标 `cursor`/`cursortrail` | 验证图像尺寸/原点、颜色和数字叠加、光标选择映射；不宣称完整判定与游玩 |
| V0-C | 一个支持序列动画的界面元素；分辨率变体与 skin.ini 的相关项 | 验证动画/材质/时钟的独立性及文件解析；具体元素在查证条目后确定 |
| 后续 | 滑条、spinner、选歌/暂停/结算及声音 | P4/P5 所需，按元素与行为分别验证，不能由单击对象结果推断 |

元素名称研究入口为官方 [osu! 皮肤说明](https://osu.ppy.sh/wiki/en/Skinning/osu%21)、[界面元素](https://osu.ppy.sh/wiki/en/Skinning/Interface)及 [skin.ini](https://osu.ppy.sh/wiki/en/Skinning/skin.ini)。这些链接不表示本表所有默认值和交互条件均已查明。

## fixture 与执行记录要求

- 所有输入图片、音频和谱面使用自制或明确允许分发的内容；不从旧源码目录拷贝默认皮肤、图标、字体、声音或测试工程。
- 文件命名可以依据已查证的公开格式，图像采用角标、渐变、透明边缘等可辨识图案；尺寸与颜色是测试变量，不写入产品规则。
- 每次只改变一个维度，保留基线与变体清单和哈希。首次记录客户端事实时不先用旧源码生成“标准答案”。
- 不覆盖用户原有皮肤或谱面。先在项目输出目录生成测试包，再通过明确隔离的方式安装/加载；保留清单和恢复步骤。
- 记录场景、时间、客户端选项及操作顺序；截图须标注来源，定时验证区分人工录制误差、客户端变化和渲染差异。
- 不把截图字节相等当作像素相等；容差、遮罩、颜色/缩放和采样策略随案例记录。
- 有矛盾时同时保留 D/L/C 的各自结论，限定适用范围。规则进入 compatibility 前必须带相应 fixture 与回归测试。
