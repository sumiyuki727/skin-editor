# Ogg 尾部归因与准确定位

日期：2026-10-20。默认关闭的 P0 压缩实验续篇。此记录核对独立音频工具与自制 fixture，不是当前 stable 的音频兼容结论，也不更换正式后端。

本文的 222 项及六轮原生数据是当次固定快照；之后的 MP3 分步定位与取消交接见[后续记录](MP3_CANCELLATION.md)，不改写本文原始测量和待办状态。

## 尾部差异的控制方法

旧测量中，0.37 秒／48 kHz 双声道源有 17760 帧，Symphonia 输出 17760、FFmpeg 7.1 输出 17632。原始产物和旧报告保持不变；没有为对齐参考而裁切、补静音或改写编码文件。

本轮使用独立的 **libsndfile 1.2.2** 读取、解复用和 Vorbis 解码，与 FFmpeg 的原生／libvorbis 解码器共用 FFmpeg 解复用路径的旧对照分开。对原始短文件，libsndfile 输出完整 17760 帧，与原 P0 输出逐样本最大差异约 `2.38e-7`，包含原来未比较的 128 个尾帧；3 秒文件也匹配。

分页控制对同一自制 WAV 使用相同 libvorbis 编码参数，仅将 Ogg muxer 的 `page_duration` 改为 20000 微秒。重新拆包并核对**音频包序列的长度及字节哈希**，不能只因“听起来一样”认为控制有效。两种文件的 EOS granule 都是源帧数，页 CRC、序列号、单 stream serial、continuation 和首尾标志单独检查。

原 0.37 秒文件的所有音频包集中在一个 EOS 页；分页文件将同样的音频包放到多个页。前者 FFmpeg 7.1 输出 17632，后者恢复到 17760。此控制将差异定位到固定参考工具的单音频末页处理路径，而非必须在 P0 解码结果中删除的尾部。该结论针对本轮工具／编码／分页组合，不宣称所有短 Ogg 或所有 FFmpeg 版本都存在同样问题。

探索日志的正常 FFmpeg 输出首个有效块标为 PTS 128；`skip_manual` 诊断还暴露了首尾修剪相关数据。该选项的原始展开结果**不作为正确参考**，也不据其帧数自行加减 128。细分到具体内部缺陷机制仍属解释；已验证的证据是独立解码、EOS granule、相同音频包及分页改变后的差异消失。

## 可复现入口与工具成本

```text
python tools/check_p0_compressed.py
python tools/p0_vorbis_tail.py --fixture artifacts/p0/compressed-fixture-v2 --output artifacts/p0/vorbis-tail-audit-v1
```

输出目录须未存在，重复时改用新 `artifacts/p0` 直接子目录。输入必须是仓库生成且哈希匹配的 fixture。审计不打开设备、不读取客户端或私人音乐；不是性能测量，不能据审计进程耗时或内存评定播放预算。

独立参考工具的本机准备：

```text
python -m pip install --disable-pip-version-check --no-deps --only-binary=:all: --retries 0 --timeout 30 --index-url https://pypi.org/simple --target .p0-tools/audio-reference soundfile==0.13.1
```

当前使用 SoundFile 0.13.1 的 Windows x64 wheel 所附 `libsndfile_x64.dll`；审计通过 Python 标准库 ctypes 调用固定的只读 API，不调用 SoundFile Python 层，因此不增加 NumPy／CFFI 运行要求。已验证的安装使用本机已有 Python 3.12；审计和无窗口工具测试使用 Python 3.9。没有修改系统 Python。

SoundFile 包为 BSD-3-Clause，所附 libsndfile 的 COPYING 为 LGPL-2.1；与原有 GPL 配置 FFmpeg 工具分别登记，不将包许可当成内附二进制的全部许可。DLL 是**私有离线参考工具**，不进入产品、Rust 依赖、核心测试或分发包。源库版本、DLL 大小及哈希随审计产物固定；没有新增 Cargo 包、平台 API feature 或 Rust unsafe。

审计只接受当前 48 kHz 双声道短 fixture。Ogg 检查器是有 1 MiB／4096 页上限的测试工具，不是通用解复用器或产品导入器；核心回归直接使用便携自制压缩文件和冻结的 float32 参考，不需要加载 DLL。

## Ogg 定位路径

Vorbis 改用 Symphonia 的准确容器定位及其最大随机访问间隔预滚。解码器重置后，首个包可能只用于预热、不输出样本，因此定位锚点取**第一个实际输出 PCM 的包时间戳加 start trim**，再丢弃目标之前的样本；不能直接把请求帧或容器跳转回执当作实际第一帧。

本轮初次准确定位回归在近 EOF 处失败：Symphonia 0.6.1 的范围检查使用 `start_ts + num_frames`，Vorbis 的负起点包含 priming，导致部分末尾目标超出该 API 的检查范围。适配器按这两个元数据算出请求上界，在范围内定位后继续解码到真正目标，没有硬编码 128、改依赖源码或裁切有效 PCM。EOF 定位不要求读取额外尾部。

MP3 保留原来的前缀解码路径，未将 Vorbis 的预滚机制推广到 MP3 bit reservoir。WAV 仍使用原严格读取器。公开 Stream／后台 worker／Output 端口不变，固定缓存、代次、暂停与旧块拒绝仍由原边界负责。

新增回归覆盖完整短 Ogg（包括尾部）的独立参考，以及跨音频页的前后／非对齐／近 EOF／EOF 往返和跳转后的精确线性样本。一个远端定位同时限制实际解码的前缀工作量，避免只保留“数据正确”却悄悄退回从零解码。以上仍不代表任意起始时间、链式 Ogg、真实音乐、慢盘、重采样或其他平台已经通过。

## 本轮结果

两种分页在以下 12 个源帧数上各测试一次，共 **24** 个组合。全部 P0 输出与独立 libsndfile 的帧数、完整样本一致，绝对容差 `1e-5`，最大差异约 **2.68e-7**；完整线性读取后的四次前后／近尾部／EOF 定位也逐字节匹配本解码器线性结果。每对编码的音频包字节哈希相同，页 CRC、序列和结束 granule 通过。

| 源／P0／独立参考帧数 | FFmpeg 默认分页帧数 | FFmpeg 20 ms 分页帧数 |

| 480 | 512 | 512 |
| 960 | 1024 | 960 |
| 1023 | 895 | 895 |
| 1024 | 896 | 896 |
| 1025 | 897 | 897 |
| 4096 | 3968 | 4096 |

本批 **14** 个长度冲突均出现在只有一个音频页的产物中；既有少帧，也有多帧。改变分页设置不保证每个极短文件能形成多个音频页，因此不保证每一行都消除差异。其余十个多音频页产物的固定 FFmpeg 参考长度一致。所有比较保留原始文件，不裁切未对齐尾部后宣称两端完全相等；同一 libvorbis 编码器的这组控制也不替代其他编码器覆盖。

随后固定同一组 **119** 份源码／锁／便携 fixture／工具，顺序执行两组 180 秒 WAV／MP3／Ogg 的完整离线读取和原生输出，共 6 轮读取、6 轮原生。每个离线输出的完整 PCM 哈希仍与首轮实现一致，定位优化没有改变线性样本；原生参考取新线性输出，并按全部声道、源位置、代次、增益和哈希验证 **12321** 个接受包。每轮至少连续消费 30 秒，24 段暂停各至少 650 ms；欠载、解码失败和轨迹溢出均为 0，关闭后各五块 PCM 全归还。

180 秒 Vorbis 的定位对照：

| 指标 | 首轮前缀路径（两次） | 本轮准确定位（两次） |
| --- | --- | --- |
| 离线定位半程附近 | 71.6–87.5 ms | **0.332–0.351 ms** |
| 离线定位末尾前 9 帧 | 143.3–167.9 ms | **0.349 ms** 左右 |
| 原生请求至 90 秒数据预备好 | 110.3–121.0 ms | **22.4–42.0 ms** |
| 原生请求至 0.5 秒数据预备好 | 76.1–87.6 ms | **22.0–33.1 ms** |

原生计时包括流重开、设备控制确认和软件排队，不是纯解码或物理发声延迟。MP3 原生 90 秒预备仍为 **119.4–119.9 ms**，前缀路径没有优化；同轮 WAV 约 **22.0 ms**。两个日期的原始产物均保留，同源输入哈希一致，不将系统调度／轮询量化的变化全归因于解码优化。

本轮 Vorbis 离线历史工作集峰值 **5.543–5.559 MiB**、私有提交 **2.898–2.910 MiB**；原生历史工作集 **20.574–23.063 MiB**、私有提交 **14.941–18.090 MiB**。原生整轮 CPU 为 **0.047–0.094 核秒**、平均约一逻辑核的 **0.13–0.27%**，包含暂停／定位和有界诊断，低计数受系统时间粒度影响；不是稳态播放 CPU 或完整图形组合预算。参考 DLL 没有加载到 Rust 测量进程中，不能将私有工具安装大小计入这些原生进程数值。

无窗口共 **222** 项通过：GUI 74、WASAPI 22、媒体 19、契约 10、Python 97；默认、WAV、压缩 feature 的格式、Clippy、测试和 release 构建通过。新增两项媒体回归、四项工具回归；没有新增 Cargo 包或修改已有锁文件。两份新增便携 fixture 合计 **161837 字节**，独立工具 DLL **2364416 字节**；两者与固定 PCM 缓存／原生进程计量分开。

完整来源、源码／二进制、逐轮资源样本及审计文件哈希见 [windows-vorbis-tail-and-seek.json](windows-vorbis-tail-and-seek.json)。首轮未解决枚举和固定 FFmpeg `.reference.f32` 保持原样：旧单参考入口仍可报告长度冲突，新的完整判断来自独立审计，不静默放宽旧比较。

P0 尚未退出：MP3 定位／取消、广泛真实音乐／非零起点／链式流、重采样、图形组合长时、物理输入／声学延迟、设备变化及跨平台实测仍未完成。当前 stable 的音频行为也未由这些自有测试证明；首批图像对照和音频工具证据继续分开。未提交或推送 Git。
