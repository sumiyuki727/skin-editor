# Windows 桌面交互验收

本轮以独立 `desktop-proof` 窗口验证 Windows 桌面边界。它复用既有手势控件、命令会话及纯 Transport，用明确标记的合成时钟驱动占位预览，不打开音频设备，不是正式编辑器或 stable 内核。Linux 实测暂缓，macOS 待设备。

## 入口与记录

```text
python tools/check_p0_desktop.py
python tools/check_p0_desktop.py --interactive
```

第一项先检查格式、Clippy、无窗口测试及 release 构建，再打开自有原生窗口，读取自有渲染目标、保存 `smoke-own-renderer.png` 并退出。第二项在该检查后打开人工验收窗口。它不会自动注入按键或鼠标，也不使用系统窗口捕获。自动轮屏蔽窗口输入，避免意外输入出现在回读图中；人工轮不自动截图。

人工入口须从实际用户桌面上的终端运行。Codex 的受限执行可能将窗口放到 `CodexSandboxDesktop`：即便系统元数据报告窗口可见，也不代表用户桌面可见。本轮已遇到该情况，按用户报告关闭隔离桌面轮，再通过正常桌面启动同一已检查 exe；无需修改游戏、显示或系统输入设置。

每次使用新的 `artifacts/p0/desktop-smoke-*` 或 `desktop-user-*` 目录，保留 `result.json`、`assessment.json`、日志、源码和二进制身份。人工窗口可保存多个独立 `checkpoint-N.json`；点击“记录并结束”或正常关闭时保存最终记录，不覆盖既有证据。输出仅限 `artifacts/p0` 的新直接子目录，越界与重复路径拒绝后检查原文件哈希不变。

记录 schema 为独立实验 v1，和产品项目格式无关。`status: recorded` 表示完成记录；`assessment` 分开列出事件覆盖、用户确认和未验证项，始终不将本实验标作完整产品验收。真实输入法、拖放和全屏确认必须同时具有对应原生事件；收到普通文本不能替代 IME 事件。程序只保留文本字数、是否匹配测试短语及 IME 次数，不保存输入文本、候选文本、任意文件路径或内容，不收集全局按键。

拖放仅接受本轮目录自制的 `素材 日本語.png`，要求规范路径相同、大小有界、32×16 PNG 且像素与自制 fixture 相同。其他拖入文件只计拒绝次数，不读取其字节；不调用拖放句柄的通用字节接口。缩略图只存在于本轮 UI 中，不冒充素材库导入或正式 Command。

## 人工操作步骤

1. 默认暂停、Edit 模式。在中央预览拖动白框后松开，应增加一个节点；再次拖动后按 Esc，位置应还原且不新增节点。
2. 保持拖动且不松开鼠标，Alt+Tab 切走，松开后返回窗口。草稿应取消，节点数保持。
3. 选择 Interact、点击 Resume，在预览区域按 Z/X，游戏输入计数应增长。再点输入框输入 zx，游戏计数应保持；暂停后在预览按键也应保持。
4. 使用本机中文输入法输入中文，检查候选、提交和 Esc；有日文输入法时也实际测试。可输入完整短语 `皮肤 日本語 zx`，勿用粘贴代替输入法验收。缺日文输入法时勾选对应未验收项。
5. F11 进入全屏；在输入框内调出 IME 候选后按 Esc，应取消候选而保持全屏。在输入框外按 Esc，或再按 F11，返回普通窗口，检查布局与操作。
6. 点击“复制测试目录路径”，在资源管理器打开该目录，将 `素材 日本語.png` 拖入测试窗口。检查红蓝渐变缩略图；其他文件应被拒绝。
7. 调整窗口大小、切换 A 左侧／B 底部并试用。可调整 UI 缩放；如果有不同系统 DPI 的屏幕，移动窗口测试。没有该环境时明确勾选未验收，单一 DPI 或 UI 缩放不能证明跨 DPI 通过。
8. 只勾选实际观察正常的确认项，滚动至面板末尾点击“记录并结束”。有异常时保存进度，另说明操作和表现。

A/B 只验证简单面板重排、焦点和草稿取消，不是完整素材库／图层／历史布局比较；正式布局仍未定案，不引入停靠系统。跨原生 DPI 要观察到不同的 `native_pixels_per_point`，与 `ui_zoom`、有效像素比例分别记录。全屏要收到实际 viewport 回执才计数，发出请求不算完成。

## 当前结果与边界

自动检查已有 70 项原生、10 项契约、53 项 Python 及可选适配器 9 项无窗口测试，共 142 项；新增覆盖输入框和 IME 按键隔离、普通按钮焦点、失焦取消、全屏回执、原生 DPI 与 UI 缩放、重复 UI pass、拖放限制、不可覆盖证据、剪贴板功能配置及错误验收声明。原生画面与人工记录的实际结果登记于 [windows-desktop.json](windows-desktop.json)，未完成项目保持待验收。

`desktop-smoke-cabe0031` 完成 1200×820 自有渲染回读，模拟保持 0、暂停为真、项目节点保持 1；没有注入或记录人工按键／IME／拖放，未自动勾选确认。已直接检查该 PNG，中文／日文步骤和占位画布可见。该图只覆盖底部面板的一次显示，不证明输入法候选或另一屏幕 DPI 正常。

首个人工会话 `desktop-user-54f77415` 被用户报告“没有看到窗口”，进程元数据确认处于 Codex 隔离桌面；仅向该 PID 且标题匹配的自有窗口发送正常关闭。原始记录保留、排除人工验收。

同版本的实际桌面会话 `desktop-user-d1ea17cf` 完成：用户在窗口确认字体、中文／日文输入法的候选／提交／Esc、拖放缩略图及全屏返回正常；记录到 IME preedit 24／commit 4、拖放接受 1、全屏进／返各 6、失焦草稿取消 3，两面板均访问。记录的是人工勾选与事件计数，不扩展为声学或稳定内核验收。

该轮游戏按键接纳和 Esc 草稿取消均为 0，未记作通过。用户进一步复测同版本 `desktop-user-3610465a`，记录 **4 次** Esc 草稿取消，当前无未提交草稿；Esc 路径补上实际输入证据。游戏按键计数及复制按钮被用户报告异常，随后独立定位修复。没有观察到跨原生 DPI 切换；第一轮 64 项缩放轨迹达到上限，后续原生 DPI 不能由该轮推断，仍需单列实测。A/B 是实际访问，未获得布局偏好或完整编辑流程比较。

修复后 `desktop-smoke-52a6f5d0` 再次完成自有画面检查。实际桌面 `desktop-user-efdfd718` 定向复核中，游戏接纳 **16** 次 Z/X、播放交互期间输入框收到 **14** 次 Z/X、游戏输入泄漏 **0**，节点保持 **1**。用户直接回复三项均正常，另确认复制目录后可在资源管理器粘贴；该听取人工反馈的记录单列，不自动读取用户剪贴板。两项缺陷已完成修复与本机定向复测。

后续用户补充：在自己的两块屏幕之间拖动窗口，暂未发现异常。该观察登记为双屏移动的人工反馈，没有指定对应轮次、显示缩放值或截图，不能回填原始原生 DPI 计数。已有三轮人工记录均只观察到 `native_pixels_per_point = 1.0`（首轮轨迹另达上限）；“双屏拖动未见异常”与“不同原生 DPI 切换验收”保持分开。继续其他 P0 工作，不因此重复要求用户截图。

默认／`device-audio` 的格式、Clippy、无窗口测试及 release 构建全部通过，142 项为不重复计数；无关的硬件音频／GPU 预算流程未重复。汇总按各轮实际范围组合，不能说所有 IME、全屏及拖放在最终版本又完整重测，亦不将多轮合并成一个正式产品流程通过。

补测复现了 IME 在同一帧清空候选并发送 Esc 时，同时触发退出全屏的问题。修复保留帧开始时的编辑输入归属，取消候选的该次 Esc 不再成为全屏返回；回归先失败、修复后通过。重复 UI pass 的 Z/X 边界测试直接通过原有实现，只增加保护，未声称修复一个未复现的问题。

游戏按键问题以带焦点的普通按钮回归复现：egui 的 `egui_wants_keyboard_input` 对任何焦点控件为真，点击工具按钮后仍阻挡游戏键。改为文本编辑归属，并由桌面组装显式保留本次 UI pass 的编辑输入归属；普通按钮不再屏蔽 Z/X，文本／IME 取消帧仍被隔离。回归先失败后通过；既有脚本入口显式传入无外部文本编辑器状态。此变更仅在 P0 未发布适配接口，不改变项目／Command schema。

## 剪贴板配置与依赖影响

原型关闭 eframe 默认功能后未启用 `clipboard`，上游回退只保留应用内部字符串，无法向其他程序粘贴。启用正式 `clipboard` feature，并在检查入口锁定所需 UI features，避免按钮请求能编译而系统功能缺失；窗口同时直接显示测试目录，便于定位。实际系统粘贴只由用户操作验收，自动测试不读取或改写用户剪贴板。

Windows 激活锁中已有的 `arboard 3.7.0`（MIT／Apache-2.0）、`clipboard-win 5.4.1`（BSL-1.0）及既有 Windows bindings，不增加自写 FFI 或 unsafe。正式 feature 同时使锁文件新增六个 Linux／Wayland 依赖版本：`smithay-clipboard 0.7.3`、`smithay-client-toolkit 0.20.0`、`calloop 0.14.5`、`calloop-wayland-source 0.4.1`、`wayland-protocols-experimental 20250721.0.1`、`wayland-protocols-misc 0.3.12`；原有包版本没有升级或删除。它们不在本次 Windows 构建目标中，Linux 实测仍暂缓，恢复前补相应依赖与桌面验收。

这是明确的框架功能成本变化，旧资源记录保留旧锁和功能身份，不继承为新配置的完整预算。剪贴板初始化和数据缓冲的平台成本尚未独立测量，后续计入组合预算；不因没有新自建线程就宣称零开销。系统字体沿用 `system_fonts`，未另行复制或打包字体。仍没有新正式项目模块、平台后台服务或自写 unsafe。

桌面窗口不加载标准 100 PNG 负载，不能据此认定完整资源预算、物理输入到声音延迟、音频／GPU 联动性能或 stable 兼容通过。当前 stable 兼容案例仍为 0，本轮无需 F12；外部客户端、旧源码和资源均未用作构建或运行依赖。
